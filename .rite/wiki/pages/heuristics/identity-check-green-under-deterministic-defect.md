# 同一性・再現性を測る検証は正しさを測らない — 欠陥が決定論的なら同じ壊れ方が再現して green になる

## 概要

2 回実行して出力が一致することを確かめる検証は、欠陥が入力に依存しない限り健全な出力と壊れた出力を区別できない。時間軸を持つ成果物では終端状態が正常でも初期状態が壊れている形の欠陥が成立するため、検証は始端を明示的に読む。

## 詳細

### 起点

動画レンダリングパイプラインで、アニメーションの「入り」が一度も描画されないシーンが 3 本同時に成立した。全体を通した検証はすべて通っていた:

| 検証 | 結果 | なぜ通ったか |
|---|---|---|
| シーン契約ガード | pass | 宣言尺・フレーム数・非決定値の不使用はいずれも満たしている |
| 決定論チェック（2 回レンダして md5 比較） | pass | 壊れ方が決定論的なので、2 回とも**同じように壊れた**出力が出て md5 は一致する |
| 完成尺の実測照合 | pass | 尺は正しい |
| 最終フレームの目視 | pass | 終端状態は正常。壊れているのは冒頭だけ |

指摘が出たのは、reviewer が第 1 フレームを実際に抽出して computed style を読んだからである。

### 決定論チェックが測っているもの

「2 回実行して同一なら green」は**実行の再現性**を測る。欠陥が入力（時刻・乱数・環境）に依存しない限り、壊れた出力も完全に再現する。したがってこの検証の識別力は「非決定的な欠陥」に限られ、決定論的な欠陥に対しては原理的にゼロである。

同じ性質は次のいずれにも成立する:

- 冪等性テスト（2 回適用して差分ゼロ）— 1 回目から誤った状態でも差分はゼロ
- ゴールデンファイル比較で期待値を実出力から生成した場合 — 壊れた出力が期待値になる
- 「前回と同じ値が出る」ことを健全性の根拠にする marker

**同一性は正しさの必要条件ですらない**（正しい実装が非決定的でありうる）。同一性チェックを置いたら、それとは独立に「その 1 回の出力が正しいか」を測る検証を別に持つ。

### 時間軸を持つ成果物は始端を明示的に読む

動画・アニメーション・段階的に状態が進む UI では、**終端状態が正常なまま始端だけが壊れる**形の欠陥が成立する。人間の確認も自動チェックも終端に寄りやすい（終端が「完成形」に見えるため）。

起点事例の機序は CSS Animations の合成規則だった。1 要素に複数のアニメーションを宣言すると、同一プロパティはリスト末尾の宣言が支配し、その `animation-fill-mode: both` が delay 前の時刻から 0% キーフレームを backwards fill する。結果として前段の entrance アニメーションは一度も可視化されず、要素は最初から最終状態で表示される。終端は設計どおりなので、終端しか見ない検証には映らない。

検証としては「t=0 のフレームが背景のみであること」を明示的に測れば機械的に捕まる。時間軸を持つ成果物では、始端・中間・終端のうち**始端を最初に検証対象へ入れる**。

### 修正は分岐を足さず参照実装へ畳む

同じ機序に由来する指摘が複数出たとき、個別に guard や上書き指定で辻褄を合わせると 1 ケース専用の分岐が増え、次のサイクルでその分岐自体が指摘対象になる。

起点事例では、同じディレクトリに正しい書き方（1 要素 1 アニメーション + パーセンテージキーフレーム）で書かれた既存シーンが同居していた。新規シーンだけが多重宣言方式で書かれていた形である。修正は新規シーン側をその既存方式へ畳み、**宣言を削除する**ことで 3 件の原因を機構ごと消した。

参照実装が同居しているのに新規コードがそれに倣っていないときは、倣わなかった理由が明示されているかを確認する。理由が無ければ差異そのものが欠陥である可能性が高い。
