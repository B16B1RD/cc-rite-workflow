# 「A が不明」への修正は「A は X である」と書く — X の根拠を同時に用意しないと欠陥は 1 段深い位置へ移動するだけになる

## 概要

特定を求める指摘に応える修正は必ず新しい断定を書く。その断定自体の根拠を同じサイクルで用意しないと、指摘は形式的に解消されたまま欠陥の位置が 1 段深いところへ移り、次のサイクルで別の reviewer が同じ場所を指す。

## 詳細

### 起点

来歴ドキュメントに対して「配布物に実際に載る音源を特定できない」という指摘が出た。修正はこれに応え、「載っているのはこの音源である」「自家製なのでライセンス制約がない」「この延長レシピが唯一の再現手段である」と書いた。指摘の文言としては完全に応えている。

次のサイクルで、性格の違う 2 名の reviewer が独立に同じ位置を指した。書いた音源を**生成する手段がリポジトリのどこにも無い**。「唯一の再現手段」と称したレシピの入力が clean checkout に存在せず、その入力を作る手順も無い。特定は果たしたが、特定した対象への到達手段が無い。

前サイクルの欠陥は「対象が不明」、今サイクルの欠陥は「対象は判明したが到達不能」。ドキュメントの役目（読者が同じ物へ到達できること）は一度も満たされていない。位置が 1 段深くなっただけである。

### 構造

特定・同定を求める指摘は、修正側に必ず断定を書かせる:

| 指摘の形 | 修正が書く断定 | 同時に要る根拠 |
|---|---|---|
| 「どれを使っているか不明」 | 「X を使っている」 | X が実在し、読者が X に到達できること |
| 「なぜこの値なのか不明」 | 「Y だからこの値」 | Y が観測・実測されていること |
| 「制約の有無が不明」 | 「制約は無い」 | 制約が無いことの出所（ライセンス文・生成過程） |

断定を書く行為そのものが新しい検証対象面を作る。指摘は「不明」を潰せと言っているので、修正は「判明」を書く。書いた瞬間、その判明が正しいかという新しい問いが立つ。**指摘の文言を満たすことと、指摘が守ろうとしていた性質を満たすことは別**である。

### 判定手順

指摘に応える修正で新しい断定を書いたら、コミット前に次を通す:

1. 書いた断定を 1 文で抜き出す（「載っているのは X」「制約は無い」）
2. その文の根拠を、**この PR の中で読者が辿れる形**で示せるか確認する — 外部にしか無い、ローカルにしか無い、自分の記憶にしかない場合は根拠が無い
3. 無いなら、断定を弱めるのではなく**根拠を作る**（生成手順を記録する・実測を取る・出所を引く）。弱めて逃げると元の「不明」に戻る

### この形が cycle を伸ばす理由

修正は指摘に対して局所的に最適化される。指摘は「不明」という穴を指すので、修正は穴の形に合わせて何かを埋める。埋めた材料が検証されているかは、指摘の文言のどこにも書かれていない。

したがってこの failure mode は reviewer が悪いのでも指摘が曖昧なのでもなく、**「指摘に応える」という行為の構造そのものに内在する**。だから修正側で明示的に潰す手順を持たない限り再発する。両 reviewer が独立に同じ位置を指したのは、この位置が指摘駆動の修正が構造的に作る穴だからである。

### 実測アンカーを持たなくても対応する

この種の欠陥は成果物そのものは健全で、観測できるのは文書とリポジトリ状態の突合だけになりやすい。実測必須ゲートでは non-blocking へ落ちる。しかし severity と blocking は独立軸であり、non-blocking であることは「対応不要」を意味しない。ドキュメントの存在理由に直接反する欠陥は、blocking 判定に関わらずマージ前に潰す。
