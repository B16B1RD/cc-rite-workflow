# 「完了」を記録する手順が複数あるときは、同じマージ条件を全手順の先頭に同じ形で入れ、skip と置換漏れを marker で区別する

## 概要

完了を記録する手順（Issue クローズ、Projects Status の更新、作業メモリの最終化、親 Tasklist の更新）が複数あるとき、そのうち 1 つだけをマージ状態で分岐させると、残りの手順が「完了」を示したまま取り残される。同じ条件を全手順の先頭に同じ形で入れる。

## 詳細

### 条件を入れる位置と marker

- **全手順の先頭に同じ形で置く**: 手順ごとに条件の書き方が違うと、片方だけ直したときに残りが古い条件で動く。先頭に同一の形を置けば、差分が 1 か所の変更で追える
- **skip と置換漏れを marker で区別する**: 条件によって意図して skip したのか、値の置換漏れで空のまま進んだのかが出力から判別できないと、未完了の側へ倒れたことを見逃す。skip した事実を示す marker を出し、置換漏れは別の失敗として扱う
- **倒れる方向を確認する**: 手順書の bash を早期 exit で抜ける形にすると、複数ブロックを 1 回の呼び出しに連結したとき後続の marker が出なくなる。この場合の倒れる方向が「未完了」側であることを確かめる

### テストの固定

手順書の bash を抽出し、条件の値だけを変えて実行するテストで、マージ済みの経路が外部の script・helper を呼ばないことを呼び出し回数で固定する。マージ済みの経路では base と HEAD の実行記録が一致することも確認する。
