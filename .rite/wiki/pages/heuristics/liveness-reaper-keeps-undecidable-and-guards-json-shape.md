# 他セッションの成果物を回収する処理は、進捗時刻ではなく所有者の生存信号で判定し、判定不能は残す側へ倒す

## 概要

進捗のたびにしか更新されない時刻を回収条件にすると、1 工程が長い生存中の所有者の成果物まで消える。生存は所有者側で頻繁に動く別の時刻で判定し、その記録が読めないときは黙って消さず警告して残す。記録を読む前に JSON object であることを確かめ、後段の読み取り失敗で回収ループ全体が止まらないようにする。

## 詳細

複数セッションが同じ state ディレクトリを共有する環境では、各セッションの起動時処理が「古くなった他セッションの成果物」を回収することがある。このとき成果物自身の更新時刻（進捗が進んだときにしか書き換わらない時刻）を閾値と比べるだけだと、所有者が 1 件の作業に閾値以上かかった時点で、生きて処理中の所有者の成果物を消してしまう。消された側は次の工程で成果物を読み書きできず、処理が止まる。

生存の判定には、所有者が作業している間に頻繁に更新される別の記録（phase 遷移ごとに書き換わる状態ファイルの更新時刻など）を使う。判定は次の 4 通りに分けると、回収と保護の両方を保てる。

| 所有者の記録 | 扱い |
|---|---|
| 存在しない | 所有者は終了済み。従来どおり回収する |
| 読めない / JSON object でない | 生存を判定できない。黙って消さず、対象パス付きの警告を出して残す |
| object だが時刻が欠落・解析不能 | 生存を断定できないので成果物側の判定に従い、回収するなら理由を出す |
| 時刻が閾値以内 | 生存中。残す |

`set -euo pipefail` 下で所有者の記録を `jq` で読む場合、「JSON として読めるか」だけを確かめると `[]` や文字列のような非 object が通り、後段の `.field` 参照が失敗してスクリプトが回収ループの途中で終了する。残りの成果物は未処理のまま残り、呼び出し側が `|| true` で失敗を握りつぶしていれば痕跡も残らない。最初の検査を `jq -e 'type == "object"'` にし、非 object も「読めない」側へ落とす。

生存判定の位置は、削除前に記録を出力する処理（失敗リストなどの書き出し）より前に置く。後ろに置くと、残す成果物についても「削除前の記録」が出てしまう。

テストでは、判定の各分岐をセッションごとに分けた fixture で固定し、警告の assert は警告に出す全パス（成果物と所有者の記録の両方）を照合する。片方のパスだけを assert すると、もう片方を警告から落とす変異が生き残る。

所有者の記録が phase 遷移ごとにしか動かない場合、遷移のない長い工程では生存信号としても不十分になりうる。この制約は同じ信号を使う他の生存判定と共通であり、定期的な更新（ハートビート）を持たない限り残る。

**時間窓の内側も固定する**: 取得時刻と窓の長さで生存を判定するロックのテストは、窓の外側（古い時刻なら回収できる）だけでなく内側（窓の上端に近い時刻でも保持中と判定される）も assert する。取得直後のロックだけを使うテストでは、閾値を縮める変異が green のまま通る。

**現在時刻を取れないときは何も消さない**: 現在時刻の取得失敗を「生きていない」に倒すと、回収経路が他セッションの生きたロックを消してから停止する。時刻を取れないときは削除せずに止める。判定不能を残す側へ倒す原則を、比較の相手側（現在時刻）にも適用する。

現在時刻は、記録の時刻を解析するより前に読む。解析の途中で現在時刻を使う実装だと、時計が読めない失敗が「記録を解析できない = 古い」と同じ戻り値にすり替わり、回収経路へ流れる。判定に必要な値を取れないときは、判定関数の中で ERROR を出して止める（「古い」と同じ戻り値で返さない）。

失敗段（時刻の取得・書き込み）ごとに ERROR の文面を分ける。1 つの文面に束ねると、どの段で止まったかを診断できない。テストは件数ではなく文面で各分岐を照合する。

### 所有者ごと止まっている間は、どの時刻も生存を示さない

所有者側で頻繁に動く時刻を生存信号にしても、利用上限などで所有者のセッションごと止まっている間は、成果物の時刻も所有者の記録の時刻も動かない。時刻だけでは「再開を待っている」と「終了した」を区別できず、再開待ちの所有者の成果物（batch のキューなど）が回収される。

- 終了は時刻ではなく、終了時処理（SessionEnd など）が成果物の横に置く終了印で判定する。印のある成果物だけを従来の短い猶予で回収する
- 印の無い成果物は、成果物と所有者の記録の新しい方の時刻が長い liveness TTL（作業ツリーの回収と同じ値）を超えるまで残す。終了時処理を経ない強制終了は、この TTL で回収する
- 同じ id で再開したセッションは、起動時に自分の終了印を消して成果物を再び保護する
- 状態ファイルの `active=false` は後片付けの工程でも立つため、終了の信号には使えない
- 終了印の id は、終了時処理に渡される payload の値を使う。状態ファイルの解決結果から取ると、別セッションの成果物に印を置きうる
