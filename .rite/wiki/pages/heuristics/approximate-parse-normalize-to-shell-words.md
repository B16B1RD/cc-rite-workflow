# 解析しない部分の近似判定は shell が読む語に正規化してから行い、上限超過は超えた部分だけを判定不能として扱う

## 概要

コマンド検査で parser が解析しない部分を部分文字列で近似判定すると、引用やバックスラッシュで語を分割した綴りがそのまま素通りする。近似判定は shell が実際に読む語へ正規化してから行う。処理時間や入れ子の深さに上限を設けるときも、上限を超えたら全体を拒否するのではなく、超えた部分だけを判定できないものとして扱い、そこに隠れうる危険な操作だけを拒否する。

## 詳細

**近似判定の入力を shell の語にそろえる**: parser が解析しない置換の中身などを、生の文字列のまま部分一致で調べると、`g''it` のように引用で綴りを分割した語は検出されない。shell は引用・バックスラッシュ・行継続を外した語を読むので、近似判定も同じ正規化を通した文字列に対して行う。近似は parser より弱くならない向きにとる。

**上限は全体拒否ではなく部分の判定不能にする**: 上限を超えたら解析全体を拒否する実装は、上限の後ろにある無害なコマンドまで拒否し、既存の要件（更新しないサブコマンドは拒否しない）を壊す。上限を超えた部分だけを判定できないものとして扱い、そこに隠れうる危険な操作（例: HEAD の移動）だけを fail-closed で拒否すると、時間の上限と既存要件を両立できる。処理時間と入れ子の深さのように同じ形の上限が複数あるときは、同じ根因として同じ修正に含める。

**境界をテストで固定する**: 近似判定と上限は境界（例: 深さ 64 と 65）と条件の片側ずつをテストで固定する。

**主張の範囲を実装にそろえる**: 仕様に「どちらの上限でも拒否されない」と例外なく書くと、自分で定めた拒否条件（解析しない置換の中の危険な操作）と矛盾する。主張は実装が拒否する集合を除いた範囲に限る。
