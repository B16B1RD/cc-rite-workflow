# ガードの述語は「守りたい状態」そのものを測る — 存在ではなく内容を測る

## 概要

冪等性のためにガードを置くとき、述語が「守りたい不変量」ではなく「その代理指標」を測っていると、代理と実体が乖離した瞬間にガードが恒久的な無音 skip へ変わる。ファイルの**存在**は、そのファイルが**役目を果たしていること**を含意しない。

## 詳細

### 実例: 0 バイトの `.gitignore`

保護対象ディレクトリへ `*` だけの `.gitignore` を同梱する処理を、次のガードで冪等化した:

```bash
# ❌ 述語が不変量を測っていない
[ ! -f "$dir/.gitignore" ] && printf '*\n' > "$dir/.gitignore"
```

守りたいのは「除外が効いている」ことだが、測っているのは「ファイルがある」こと。`printf ... > F` は **redirect が先に truncate する**ため、ENOSPC で書き込みが失敗すると **0 バイトの `.gitignore` が残る**。以後このガードは存在を見て「作成済み」と読み、無音で skip し続ける。marker も二度と出ない。除外は一切効いていないのに、機構としては永久に「対応済み」になる。

```bash
# ✅ 述語が不変量を測っている
[ ! -s "$dir/.gitignore" ] && printf '*\n' > "$dir/.gitignore"
```

`-s`（サイズ非ゼロ）にすると、0 バイトが残った次の実行は必ず書き直しを試み、失敗すれば再び marker が出る。**ガード 1 つが自己修復と再通知を同時に担う**。

### 追加検査を足さないこと

「書いた後にサイズを検査する」post-write チェックを重ねたくなるが、これは不要である。redirect + rc 検査が既に失敗を捕捉しており、3 つ目の検査は次サイクルに「機構が多い」と指摘される面を増やすだけ。**述語を正しくすれば検査は 1 本で足りる**、というのが本ヒューリスティックの実利的な帰結でもある。

### 判定の目安

> ガードの述語を平叙文にしたとき、それが finding の failure scenario をそのまま否定できるか。

- 「ファイルがある」は「除外が効いている」を否定**できない** → 述語が不適
- 「ファイルが非空である」は「0 バイトで除外が効いていない」を否定**できる** → 述語が適

同型の問いは他の代理指標にも効く。「ディレクトリがある」は「書き込める」を、「プロセスが生きている」は「応答している」を、「設定キーが存在する」は「その値が適用されている」を、いずれも含意しない。

### 「新機構は次サイクルの指摘源になる」の一例

この finding が出たのは、前サイクルで新設した 6 行の同梱ブロック 1 つからだった。同じブロックから同時に「redirect のスコープ」「カバー範囲が片側だけ」「テストがゼロ」の 3 件も出ており、blocking 件数はそこで初めて増加へ転じた（13 → 10 → 5 → 7）。**新機構を足したサイクルは、その機構自身が次サイクルのレビュー対象面になる** — 機構を足す commit で TC を同時に足さないと、次サイクルで必ず「無検査」として返ってくる。
