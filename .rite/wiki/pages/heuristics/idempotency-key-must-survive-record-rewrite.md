# 冪等のキーを次の run で書き直される記録に置くなら、書き直す側が内容の一致で前の値を持ち越す

## 概要

作成済みの成果物の番号を判定記録に書き戻して再実行を冪等にしても、その記録が HEAD の変化などで書き直されると番号が消え、再実行の典型経路で重複作成が起きる。書き直す側が内容の一致で前の値を持ち越し、持ち越し先が複数にまたがるときは止める。やり直す手順では外部への書き込みを「既にあれば書かない」形にし、停止時の再開案内は失敗の種類ごとに事実と合う文にする。

## 詳細

**冪等のキーは、書き直しで消えない場所に置くか、持ち越す。** 外部に作った成果物（Issue など）の番号を判定記録へ書き戻し、次の実行で「番号があれば作らない」とする設計は、判定記録そのものが次の run で書き直される条件（HEAD の変化など）で番号を失う。再実行の典型経路で冪等性が効かなくなるため、書き直す側が内容の一致で前の値を持ち越す。持ち越し先の候補が複数の値にまたがるときは、1 つを選ばずに止める。

**書き戻しが空振りしていないかを確かめる。** jq の `select` への代入のような形は、一致が 0 件でも成功として終わる。書き戻しの空振りは次の再実行の重複に直結するため、一致の有無を確かめて 0 件なら失敗にする。

**やり直す前提の手順では、外部への書き込みを重複させない。** 途中で止まって最初からやり直すと、成功済みの追記やコメントがもう一度書かれる。各書き込みを「既にあれば書かない」形にするか、済んだ書き込みを記録して飛ばす。

**再開の案内は失敗の種類ごとに事実と合わせる。** 書き戻しに失敗した経路で「書き戻してある」と断定すると、案内どおりの再実行が重複を生む。書き戻せなかった番号は marker に載せて案内まで運ぶ。

**持ち越しは記録の寿命に結び付ける。** 冪等のキーを持ち越すかどうかを、書き込みの途中だけ存在する状態（保留ファイルなど）の有無で決めると、その状態が消えた後の書き直しで値を失う。持ち越しは記録そのものの寿命に合わせる。

**テストのスタブは stdout で結果を返す。** スタブがファイル経由で結果を返すと、環境差で失敗したときに原因が出力に残らない。stdout で返せば、失敗時の出力に原因が残る。
