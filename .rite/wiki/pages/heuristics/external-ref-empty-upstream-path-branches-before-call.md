# 外部参照を読む手順を足すときは、値が空になる上流経路を外部コマンドの前に専用の理由で分岐する

## 概要

手順に外部参照（PR 番号など）を読む段を足すと、その値が空のまま届く上流経路（「PR 未検出のまま続行」など）が既存の分岐に隠れていることがある。空値で外部コマンドを呼ぶと実態と違う失敗理由と実行できない復旧案内が出るため、呼ぶ前に空値を専用の理由で分岐する。

## 詳細

新しい段は「値が揃っている正常系」を思い浮かべて書かれやすい。しかし手順の前段には、利用者の選択で対象が見つからないまま続行する経路のように、参照値を空のまま後段へ渡す分岐がすでに存在しうる。その経路で空値のまま外部コマンド（例: `gh pr view ""`）を呼ぶと、コマンドは「取得に失敗した」という一般的な理由で落ちる。結果として報告される理由は実態（そもそも参照先が無い）と一致せず、付随する復旧案内も空の値を埋め込んだ実行不能なコマンドになる。

対策は 2 段で考える。

- 段を足す前に、その値を設定する上流の全経路を列挙し、空になりうる経路があるかを確かめる。
- 空になりうるなら、外部コマンドを呼ぶ前に空値を検出し、専用の失敗理由（例: `no_pr`）で分岐する。その理由には、空値を前提としない別の復旧案内（参照先に頼らずに対象の状態を確かめる手順）を対応させる。

外部コマンドの失敗理由にまとめてしまうと、テストでも「コマンドが失敗した」ことしか固定できない。専用の理由に分けておけば、外部コマンドが一度も呼ばれないこと（呼び出し回数 0）まで含めて固定できる。
