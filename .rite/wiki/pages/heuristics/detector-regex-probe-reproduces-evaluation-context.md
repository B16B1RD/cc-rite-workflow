# 検出器が正規表現を probe するときは実際の評価文脈を再現し、停止を固定する自己テストは理由まで assert する

## 概要

正規表現の終端を検査する検出器が、実際の reader と違う文脈（改行なし・フラグなし）で probe すると、`\s` や `$` を含む終端の判定が実挙動とずれる。検出経路をエンジン別に持つなら自己テストもエンジンごとに置き、停止を固定するテストは rc だけでなく止まった理由まで固定する。

## 詳細

### probe は評価文脈を再現する

設定ファイルの節の終端を正規表現で判定する reader は、複数行のテキストに対して行単位のフラグ（Python なら `re.M`）で照合していることが多い。検出器が終端の regex を 1 行だけの文字列で、フラグも改行も付けずに試すと、`\s` が改行に一致する・`$` が行末に一致するといった実際の効き方を再現できない。その結果、実際には節を閉じる終端を「閉じない」と判定する（またはその逆）。

probe 行には末尾の改行を付け、reader と同じフラグで照合する。ただし、フラグを足すのは評価結果を変えるときだけでよい。1 行と改行だけの入力を位置 0 から照合する場合は、行単位フラグを付けても付けなくても結果は変わらない。コメントで「評価文脈に合わせるため」と依存を主張するなら、実際に結果を変える要素（この場合は改行）に絞って書く。効かないフラグを根拠として書くと、どの assert もその主張を固定しない。

### エンジン別の検出経路には、エンジンごとに自己テストを置く

sed / awk / Python のように検出経路をエンジン別に分けている検出器で判定集合を広げたら、各エンジンの自己テストに 1 件ずつ置く。1 エンジンのテストだけでは、他のエンジンで同じ終端がどう効くかは固定されない。

### 「止まって気付ける」挙動は、停止の理由まで固定する

regex の構文エラーなどで検出器が止まることを許容した挙動は、その停止自体を自己テストで固定する。このとき rc が非ゼロであることだけを見ると、狙った例外で止まったのか、別の失敗で止まったのかを区別できない。stderr を捕捉し、止まった理由と場所を assert すると、診断と固定を同時に得られる。

停止を確かめる fixture は、他の assert と同じツリーに置くと検査全体を巻き込んで止めるため、別ツリーに置く。

### 変異で検出力を確かめる

変更を戻す変異（probe から改行を除く、見出し行の probe を外す、例外の握りつぶしを戻す）を入れて、新しい assert が落ちることを確かめる。落ちない assert は、主張している挙動を固定していない。
