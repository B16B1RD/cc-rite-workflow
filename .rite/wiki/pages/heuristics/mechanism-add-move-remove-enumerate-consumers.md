# 機構の新設・移設・撤去では、全ての停止経路と文書から消費者を列挙して確かめる

## 概要

出口や登録処理を新設・移設すると、その出口を読む消費者がいない停止経路で登録が消費されずに消える。機構を撤去すると、仕様書・設定説明・reference・再開案内に撤去前の記述が残る。変更のたびに機構名と帰結語で全文検索し、全ての出口と文書で消費者を列挙する。自分で書いた記録の失効判定は、書いた時点を起点にする。

## 詳細

### 出口の新設・移設

登録処理を別のステップへ移すと、修正ループが続かない停止経路（受入条件未検証での停止、単独実行など）では、登録が消費されずに消える。出口を開く条件は「その出口を読む消費者が全ての停止経路にいるか」で決める。消費者がいない経路は呼び出し元の明示フラグで閉じ、従来の保留に倒す。

### 撤去後の取り残し

機構を撤去した変更では、配布文書・設定テンプレート・reference・再開案内に撤去前の記述が残りやすい。撤去時は機構名と、その機構がもたらしていた帰結語の両方で全文検索し、長い 1 行の段落の中まで確認する。テストは旧文の存在を固定する pin を、現行文の pin と旧語の不在の pin に置き換える。

### 自分で書いた記録の起点

台帳のように自分で書いた行の失効を判定するとき、起点を入力側の commit にすると、判定前の変更だけで自分の行が失効扱いになり、再実行のたびに判定と追記を繰り返す。行を書いた時点の判定 commit を行に残し、それを起点にする。

### 名前の集合を読み書きでそろえる

書き手が読む名前の集合（壊れて改名された入力を含む）と、読み手・追記側の正規表現をそろえる。1 行の不一致で全行を捨てる契約では、網羅の漏れが記録の全損になる。

### 固定文字列の照合

表の行のような固定文字列を `grep -E` で照合し、文字列に生のパイプが含まれていると選言になり、どの非空ファイルにも一致する恒真の assert になる。固定文字列は `grep -F`（行全体なら `grep -cxF`）で照合し、変異を 1 つ当てて落ちることを確かめる。

### dogfooding の hook の版

dogfooding では commit 前の hook が main checkout の版で動く。検査記録のハッシュ計算を変えた PR では、hook と同じ版で検査と検証を取り直す。
