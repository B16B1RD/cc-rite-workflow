# リリースノートの項目はコミット件名の内部用語を写さず、利用者に見える効果で書く

## 概要

CHANGELOG の項目をコミット件名から起こすと、実装内部の用語（待機を区切る単位の名前など）がそのまま残り、利用者には何が変わったのかが読み取れない。項目は「利用者の操作で何が起きなくなった／できるようになったか」を主語に書き、内部用語は実装との照合にだけ使う。

## 詳細

リリース準備では、前回タグ以降のコミット件名を材料に CHANGELOG の項目を書く。件名は開発者向けに変更の仕組みを短く述べるため、`/rite:merge` の CI 待機を「ブロック境界で継続する」と書いたように、実装の区切り単位の名前が入りやすい。この語は利用者が目にしないので、読んでも効果（長い CI が実行中でも `/rite:merge` が未完了として止まらず、完了まで待つ）が分からない。

レビューでは tech-writer の観点が 1 回目で指摘 0 件でも、推奨として「内部用語だけで効果が読めない」を挙げた。同じ項目を、効果を主語にした文へ英日の 2 行だけ書き換えると、次の差分レビューで解消と判定され、指摘は再掲されなかった。書き換えは項目数・節構造・英日の対応を変えない最小の差分で済む。

書き方の手順:

- 項目の見出しを「利用者の操作で何が変わるか」の 1 句にする（内部の仕組みの名前を見出しにしない）。
- 本文は「どの条件で、何が起きなくなった／起きるようになったか」を 1 文で述べる。
- 内部用語は、実装が本文の主張と一致するかをコミットの差分で照合するときにだけ使い、本文には残さない。
- 過去の版の項目に同じ語が残っていても、過去の記録なので書き換えない。
