# 連言の拒否条件の受理側テストは、拒否の根拠となる記録が残った状態で受理させる

## 概要

「A かつ B なら拒否」という連言の条件で受理側を固定するテストは、B を満たす前段の記録がディスクに残ったまま A だけが外れる入力を受理させる順序で書く。記録を上書きする後続の処理を先に走らせると検査対象の状態が消え、A の判定を削る変異が生き残る。

## 詳細

連言の拒否条件は、どちらの項を削る変異に対しても受理側のテストが要る。「同じ context で、かつその context の逸脱を修正が処置済みなら、同じ commit での逸脱の再登録を拒否する」という条件では、「別の context なら受理する」テストが context の比較を削る変異を検出する役を持つ。

このテストが検出力を持つのは、前の cycle の計画検査の記録（処置済みを示す項）がディスクに残っている状態で、次の cycle の逸脱を登録させる場合だけである。次の cycle の計画検査を先に走らせると記録は新しい context のもので上書きされ、「処置済みの記録が無いから受理した」のか「context が違うから受理した」のかを区別できない。context の比較を削っても受理されるので、変異が生き残る。

書き方の手順:

1. 拒否側の状態（前段の記録）を作る。
2. 片方の項だけを外した入力を受理させる。
3. 記録を上書きする後続の処理は、その後に走らせる。

最後に片方の項を削る変異を当て、受理側のテストが落ちることで順序が正しいことを確かめる。

同じ fix では、手順書・参照文書・設計理由の 3 箇所に同じ受理条件を並べていたため、条件を 1 つ足したときに 1 箇所だけ取り残される指摘も受けた。条件の列挙は 1 箇所を正本にし、他はそこを指すようにすると取り残しが起きない。
