# 手順書の分岐行に書く理由欄は参照先 skill の停止規則を読み直してから書き、対になる記述を同時に揃える

## 概要

orchestrator の手順書に分岐行を追加するとき、行き先（どのステップへ進むか）が正しくても、理由欄に書いた断定が参照先 skill の実挙動より広いことがある。実行者はその文を読んで「参照先は通る場合がある」と誤解し、停止理由の転記を省きうる。理由欄は参照先の停止規則を読み直して限定し、同じ節で対になる記述は片側だけ直さず同時に開いて揃える。

## 詳細

### 失敗の構造

- 追加した行の理由欄が「失敗ではない」「人間にしか確かめられない条件だけが残ったときに限って止まる」と書いていた。参照先 skill は非対話の連続実行では、未検証の条件が 1 件でも残れば必ず停止すると定めており、断定が実挙動より広かった。複数の reviewer が独立に同じ食い違いを指摘した。
- 理由欄を直した修正が、同じ手順書の別の記述（停止報告の失敗理由欄）だけを書き換え、対になる行（default 行の「停止通知の内容を載せる」）を確認しなかったため、反対向きの食い違いを新たに作った。
- 文言を固定する pin は、その文言そのものは固定しても、対になる 2 記述の一致までは固定しないことがある。

### 防御

1. 理由欄を書く前に、参照先 skill の該当節を読み、停止・通過の条件を文言どおりに写す。断定語（〜ではない、〜に限って）は実装で列挙した集合と一致を確認してから書く。確認できなければ削除して行き先だけを書く。
2. 同じ表・同じ節で対になる記述（モード別の行と、共通の報告テンプレートなど）を修正前に同時に開き、同じ参照先を指すように揃える。
3. 対になる 2 記述の一致は、両方の文言を含む pin で固定する。片側だけの修正を検出できる。
