# 復旧ヒントに表示するパスは、処理が cd した先ではなく利用者が貼り付ける場所から正しく解決できる絶対パスで示す

## 概要

処理ロジックは cd 済みのディレクトリで正しく動いていても、同じ相対パスを復旧ヒントとして表示すると、利用者が貼り付けるシェルの cwd では別の場所を指す。表示用のパスは絶対パスに揃え、同じ strategy の全経路で同じ直し方を適用する。

## 詳細

失敗時に「このコマンドで直せます」と表示するヒントは、2 つの異なる cwd を前提にしている。1 つは処理ロジックが実行されている cwd（多くの場合、内部で cd した後の場所）で、もう 1 つは利用者がヒントを貼り付けるシェルの cwd である。後者は session worktree の中かもしれないし、main checkout かもしれない。処理ロジックと同じ相対パスや `git -C <相対パス>` をそのまま表示すると、処理自体は正しく動くのに、ヒントだけが別のリポジトリや存在しない場所を指す。

直し方は、表示するパスを絶対パスへ揃えることである。実際に操作する対象は変えず、表示だけを直せる。共有の helper がヒントを組み立てている場合は、helper を変えずに、呼び出し側が渡すパスを絶対化するだけで helper が出す全てのヒント（push / fetch / rebase / checkout など）に効く。

同じ strategy に複数の経路（旧来の経路と高速経路など）があるなら、指摘された 1 経路だけでなく全経路を同じ直し方で揃える。受入条件が「実行場所によらず正しいリポジトリを指す」なら、それはすべての経路についての主張だからである。追加したテストは、直した箇所をそれぞれ元に戻す変異で単独に落ちることを確かめてから確定する。
