# スキル文書の分岐規則は実際に注入される本文に書く — 注入されない rationale 段落だけに書くと reviewer にも実行時にも届かない

## 概要

スキル/prompt 文書で、ケースによって振る舞いが変わる規則（例: 付け替え先が無い場合の扱い）を、実行時に注入される mandate 本文と、注入されない rationale 段落の両方に分けて書くと、規則が注入されない側にしか書かれていない状態になりやすい。分岐規則は reviewer と実行時の LLM が実際に読む注入本文の側に書く必要がある。行形の pin に `.*` を使うと、補足句（例外の適用条件）を固定できず、適用範囲を狭める書き換えが green のまま通ることがある。

## 詳細

### 起きたこと

スキル文書の改訂で、注入される mandate 本文と、注入されない（rationale として references へ退避された）解説段落の間で、ケース分岐（付け替え先が無い場合の扱い）の記述が片側にしか無く、両者の結論が食い違っていた。3 名の reviewer が独立にこの不整合を検出した。あわせて、行形の pin（正規表現の `.*` を使った 1 行 match）が「base の取り込みが無くても起きる」という補足句（例外の適用範囲）を固定していなかったため、その補足句を狭める書き換えをしても pin が green のまま通ってしまう欠陥も検出された。いずれも実測アンカー（repro / failing_test）を伴わなかったため non-blocking に降格した。

### なぜ素通りするか

- rationale 段落は「設計判断の背景解説」として書かれるが、実行時に LLM が読むのは注入された mandate 本文だけであり、rationale にしか書かれていない規則は実行時に一切参照されない
- 文書のレビューは通常、注入本文と rationale の両方を人間が読んで整合性を確認するが、両者が別ファイル・別セクションに分かれていると見落としやすい
- 行形の pin は「その行が存在するか」までは固定できるが、`.*` のような緩いワイルドカードは行の一部（補足句）の内容までは固定しない。補足句を削る・狭める書き換えをしても pin の正規表現に一致し続けるため、テストは green のまま通る

### やること

1. ケースによって振る舞いが変わる分岐規則は、**実行時に注入される本文の側**に書く。rationale 段落に書くのは「なぜその規則にしたか」という背景だけにする
2. 分岐規則を rationale へ退避するリファクタでは、退避前後で「実行時に参照可能な規則の集合」が変わっていないかを確認する
3. 行形の pin で補足句・例外条件まで固定したい場合は、`.*` のような緩いワイルドカードではなく、補足句の具体的な文字列を pin に含める
