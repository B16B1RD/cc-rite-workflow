# 手順書を別経路へ転記するとき画像参照例と添付パスの解決基準を揃える — gh の添付置換は絶対パス同値でのみ成立する

## 概要

gh の添付置換は本文の画像参照先と `--attach` パスを双方絶対パスへ解決して一致したものだけ書き換える。手順書で参照例を相対形、添付を絶対パスと別基準で書くと参照が残り画像が末尾へ追記される。単発経路の手順を分解経路へ転記するときは参照例と添付側を同じ絶対パス形で写し、再添付の案内も本文に残った参照と同じ絶対パスへの再生成に限定する。

## 詳細

### 観測された挙動

`gh issue create --attach` / `gh pr create --attach` は、添付ファイルのパスと本文中の画像参照先（`![説明](...)` の宛先）をそれぞれ `filepath.Abs`（プロセスの cwd 基準）で解決し、一致した参照だけを添付 URL へ書き換える。一致しない添付は本文末尾へ画像として追記されるだけで、元の参照は壊れたまま残る。`/tmp/...` 形式の絶対パスはリモート宛先として扱われず候補に残るため、本文と添付配列に同一の絶対パスを書けば置換は成立する。

### 手順書で起きた矛盾

分解経路（親 Issue と Sub-Issue を一括作成する手順）の Write リストに図の添付手順を足したとき、参照例だけを共通規則の相対形 `./diagram.svg` から取り、添付側と spec 例だけを作業ディレクトリの絶対パスにした。同一ステップ内で「参照と添付は同じ絶対パスを使う」と規定しながら例が相対のままだったため、字義どおり実行すると参照が置換されず、新設した「未置換なら添付失敗報告」が毎回発火する状態になっていた。helper は cwd を変えずに gh を呼ぶので、相対参照はリポジトリ直下に解決され、mktemp 配下の添付とは別ファイルと判定される。

単発経路（PR 作成手順）の Write リストは「本文の参照と添付は同じ絶対パスを使う」で揃っていた。転記元を写すときは参照例と添付側を一組として同じ形で写す。片側だけを共通規則から取ると、対称位置の伝播漏れと同じ構造の矛盾になる。

### 再添付案内の限定句

添付失敗時の案内を「削除された一時 SVG を再生成して再添付する」と書くだけでは不十分である。helper の EXIT trap が作業ディレクトリを削除した後、本文には元の絶対パス参照が未置換で残っている。別パスに再生成して再添付すると gh は一致判定に失敗し画像を末尾へ追記するだけになる。案内には「本文に残った参照と同じ絶対パスに再生成する（必要なら作業ディレクトリを再作成する）」か「参照先を新パスへ書き換えつつ添付する」のどちらか一方を明示する。

### 退行検出

手順書で新設した文言（参照例の絶対パス形）には静的ピンを同時に足すと、次に基準がずれる退行を機械検出できる。ピンの literal は対象ファイル内で 1 箇所に一意にし、当該行を消す変異で該当 assert だけが失敗することを確認する。削除した前置文の再混入は負ピンで固定する。
