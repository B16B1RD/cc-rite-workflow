# ガードの識別力は「そのガード単独で発火する形状」の fixture とガード固有文言 assert で担保する

## 概要

エラーガードのテストが (a) rc の非ゼロ性と (b) 総称的な `grep -q 'ERROR'` しか assert していないと、**兄弟ガードが同じ rc・同じ総称文言で発火するため、対象ガードを削除してもテストは全緑で通る**。ガードの識別力（そのガードが実在し、その形状を捕捉していること）は次の 2 点で初めて立つ:

1. **そのガード単独で発火する形状の fixture** — 複数ガードが論理和で捕捉する fixture では、どのガードが発火したか判別できない
2. **ガード固有の診断文言の assert** — rc だけでは退行時の誤診断（別ガードの rc=1）と区別できない

## 詳細

### 失敗の構造（run 2 cycle 1〜2 で反復実測）

- TC-22 は複数ガードが論理和で捕捉する fixture に「このガードを pin する」というコメント宣言を付けていたが、宣言は過剰主張で、実際の発火順は別ガードが先だった。**境界検査だけが捕捉する形状**（セル数を満たす余剰フラグメント行)を追加して初めて pin になった
- 読み取り不能ガード（`-r`）は rc だけでなくガード固有の診断文言（`not readable`）を assert しないと、awk 失敗の rc=1 と区別できない
- mutation で実測: `-f` ガード削除が 39/39 green で素通り。ガード固有文言（`not found` / `--pages-root was not given`）を assert して初めて削除が fail 化した

### 転記規律: rationale をコメントに書いた時点で同型 TC への転記が必要

cycle 1 で TC-13b（読み取り不能）にガード固有文言 assert の rationale をコメントで書きながら、**同型の TC-13（不在）へ転記せず** `grep -q 'ERROR'` のままにした。結果、cycle 2 で同じ指摘が TC-13 に対して返ってきた。さらに cycle 3 でも兄弟 TC（TC-14 / TC-22 / TC-22b）と必須引数ガード 3 本への転記漏れが再発した。

**是正の対象は「その TC」ではなく「同じ assert 形を持つ TC 群」**。rationale を 1 箇所に書いた時点で、同型の assert を持つ TC を grep で列挙し、全件へ同時適用する。

### 対になる概念は両側に pin を置く

指摘は 1 本しか名指ししないが、守るべき invariant は通常その族全体に及ぶ。対になる概念（正常/異常、A/B の弁別、producer/consumer）を宣言したら両側に pin を置き、指摘された 1 本だけを直さない。片側だけ pin した対は次のサイクルで必ずもう片側が返ってくる（実測: 同じ helper の stderr 転送 3 本 (jq / mkdir / mv) のうち pin は mkdir だけで、cycle 2 で rm 側に捕捉を足して 4 本目が生まれた。「A と B を弁別する」と明記しながら判定不能側 B だけを pin し、A の文言を B へ潰しても全 green だった）。双方向チェック（agents/ ⇔ 表）も同じで、forward だけ pin すると reverse の report_diff 呼び出しを削除しても全 TC が green のまま残る。reverse は orphan 行を挿入して単独発火させ、方向ラベルを grep assert する明示 TC で固定する。

### チェックリスト

| 段階 | 確認 |
|---|---|
| fixture 設計 | 対象ガード**単独**で発火する形状か（兄弟ガードに先取りされないか） |
| assert | ガード固有の診断文言を含むか（総称 `ERROR` のみは不可） |
| コメント | 「このガードを pin する」宣言は実際の発火順と一致するか |
| 横展開 | 同じ assert 形を持つ兄弟 TC を grep で列挙し、同時に是正したか |
| 検証 | 対象ガードを削除する変異で当該 TC だけが fail するか |

**失敗を注入する shim は「何も出さずに失敗」にしない**: 外部コマンドの失敗分岐を shim で踏むとき、shim が何も出力せずに失敗すると、分岐の処理（fallback の呼び出し）を消した変異でも結果が空のまま進む。そのまま別の経路で同じ fallback に落ちるため、観測は元と変わらず、変異を見分けられるのは reason の 1 本だけになる。shim に実在の値を 1 行出させてから失敗させると、rc を見落とす変異は狭い側（incremental・一覧の書き出し）へ進む。その結果、状態を見る複数の assert がこの変異を捕らえる。同じ reason を複数の分岐が共有するときは、分岐固有の WARNING 文言も assert して、別の分岐で PASS する空振りを防ぐ。

### 新設した fail-loud 分岐は、実装と同じ PR で踏むテストを用意する

受入条件をすべて満たして blocking 0 件で通った PR でも、推奨事項には同じ型が繰り返し現れる。新設した fail-loud 分岐（例: producer 側の jq 読み取り失敗で止める分岐）を踏むテストが無い。実装方式を変えた後も、テストのヘルパー名が旧方式（copy など）を名乗り続ける。新しい停止 reason に復旧手順が添えられていない。どれも「正常経路のテストが通る」ことでは検出できない。分岐を足したら、その分岐単独で発火する fixture と reason 固有の文言 assert を同じ PR で揃える。方式を変えたらテスト側の名前も追従させ、停止 reason には利用者が次に取る行動を添える。

**ガードの有無で行き先が変わらない入力はガードを固定しない**: symlink を特別扱いするガードを壊れた symlink だけで検査すると、壊れた symlink は手前の種別判定で弾かれるため、ガードを消しても同じ結果になる。指す先を実在させた symlink を置いて初めて、ガードの有無で挙動が分かれる。

**検証対象より前段のフィルタを通過する fixture を作る**: run 境界の選別を検証するつもりで前 run の結果を仕込んでも、その結果が現在の run の識別子を持たなければ、手前の識別子フィルタが先に落として選別そのものに届かない。選別を無視する変異でもテストは緑のまま残る。境界を検証する fixture は上流のフィルタをすべて通し、検証したい判定だけが結果を分ける形にする。テストが名乗る保証の真偽は「そのテストは名乗った挙動を壊す変異で落ちるか」で分ける。一部の変異でしか落ちないなら誤りではなく網羅性の問題として扱う。

### fixture を 1 要素ずつ単独で効かせる配置（変異で当該ケースだけが落ちることで判定）

- **行内整合 vs 集合差分**: 一方向差し替えは集合系不変量（I1/I2）も同時に発火し、行内整合（I3）を分離できない。均衡入替（A 行 Agent=B かつ B 行 Agent=A）なら集合が保存され I3 のみが発火する。さらに「集合差分 finding（"only in ..."）が混入しない」負の assert で真に I3-isolated になる（TC-6）。「どの不変量が発火するか」をコメントに書くなら、実行して観測してから書く（推測コメントは事実不一致 MEDIUM になった）
- **双方向チェックの reverse 方向**: forward（agent 追加 → 表に無い）だけ pin すると、reverse の report_diff 呼び出しを削除しても全 TC が green のまま残る。reverse（表に行があるが agent プロファイルが無い = 存在しない subagent を spawn する failure mode）は、orphan 行を挿入して単独で発火させ、方向ラベルを grep assert する明示 TC で固定する（TC-9）
- **decoy は guard の射程内**: 行フィルタ（`/^\|/`）の検証用 decoy を抽出対象セクションの外へ置くと、セクション境界除外だけで落ち、行フィルタ削除の変異が生き残る。decoy はそのガードだけが除外を担う位置（セクション内側の非テーブル行）に置き、「finding に出ない」負の assert で固定する
- **連言 `A ∧ B`**: negative control を 2 本置いても両方が 2 つの conjunct を同時に false にしていると、片側だけ弱める変異は全部生存する（行アンカー `^`/`$` で 4 mutant、「1 行目 marker ∧ 最終非空行 sentinel」で 3 mutant）。「A のみ false」「B のみ false」を項の数だけ用意する（行アンカーなら「行頭に対象 + 後ろに散文」「前に散文 + 行末に対象」）。位置固定述語（前方一致 / 最終行の等値）には「値は含むが位置が違う」形も足す。学びで追加した fixture 自身が同じ穴を持ち得るので、追加後に必ず変異を当てる。選言（「空か `-`」等の OR）も同様で、fixture が片方の値しか使わないともう片方の項を落とす変異が生き残る。実データで多数派の値（null）を fixture に入れて各項を個別に固定する
- **除外側の対照は 1 条件だけを外す**: `find -type f -size 0c ! -perm -200 ! -perm -020 ! -perm -002` で 0464 / 0446 / 中身あり / 下位ディレクトリは各 1 条件だけを外すが、stub を指す symlink は lstat で mode 777・サイズ非 0・種別 symlink の 3 条件に同時に外れ、`-type f` を削る変異では落ちない（実際に `-type f` を固定したのは 0444 の FIFO）。対照ごとに lstat の mode・size・種別を実物で確かめ、複数条件に外れる対照を残すならコメントに「単独の条件は固定しない」と書く
- **集合の各要素**（while / until / for / select / case 等の構造語、パイプ右辺など）は他の構造を含まない最小入力形で 1 つずつ置く。1 形だけだと `(` グループや `{` ブロックなど別経路が同じ判定を支え、要素を外す退行が落ちない。要素を 1 つずつ外す変異でその要素のテストだけが落ちることで判定する
- **経路ごと**（例: fix commit の変更 + merge で競合解消したファイル）は各ファイルが 1 経路でだけ結果に入る形にする。競合解消ファイルを fix commit でも変えると、merge 経路を空にする変異で結果が変わらない
- **別経路で既に拒否される入力を選ばない**: `for i in; do cd X; done` は `do` が keyword として剥がれた時点で別経路が決めるため、`do true; cd X` のように対象要素を独立位置へ置く。「等価 mutant なのでテスト不要」と書く前に反例入力を 1 つ探し、構造語を 1 つだけ含む入力で差が出るなら「fail-open 方向にのみ等価」のような限定付きの主張に留める
- **複数キー比較**（PR 番号・commit SHA・取得元等）はキーごとに 1 つだけ値を変えた不一致 fixture を置く（1 本だけだと他キーを比較から外す変異が生き残る）。各 fixture が狙ったキー以外では基準と同一であることを常設 assert で固定する。変異は他の検査（placeholder 残留検査の正規表現等）に偶然かからない書き方を選び、対象ツリーをディレクトリ構成ごと一時コピーして、テストがコピー側を読むことと変異の適用件数を確認してから実行する
- **文字クラス**（例: printf のフラグ）は要素ごとに fixture を持たせる（未使用要素は外しても生き残る）。検出器の走査範囲と文書の表現も一致させる（文書が「書式に…」と書くのに実装が producer 段全体を走査すると、書式外の数字や `%%` 後の数字まで報告する）
- **連言の片側のみ**: 書き込み経路が A と B を必ず揃えて書くため「B だけ成り立つ」fixture が作れなくても、今は到達しない組合せの fixture を 1 つ置く（条件から A を外す変異が生き残る）
- **複合キーの列**は出典・id・位置それぞれ単独で違う行を置く。列数が想定と違う行を空列で補って照合すると旧形式と誤一致するので、その入力を拒否する分岐も個別に失敗注入して固定する
