# 件数の意味を変える変更は、その件数を表示・列挙する消費側を同じ変更で追随させる

## 概要

既存のカウンタへ別種の件数を合算するなど件数の意味を変える変更では、その件数を表示するラベル、helper の終了コードの記述、呼び出し側手順書の例外列挙とエラー表を同じ変更で更新する。追記は正本（契約・エラー表）へ足し、理由の補足側の列挙は例示として扱うと、追随の連鎖が止まる。

## 詳細

観測された事例では、lint の出力行の形式を保つため、新しく足した検出（index の節外にある登録行・重複行）の件数を既存の「孤児」の件数へ合算した。件数を表示する消費側のラベルは「孤児」のままで、別種の件数を孤児として示していた。形式を保つための合算は妥当でも、件数の意味が変わった以上、その件数を表示・列挙する箇所はすべて消費側として追随対象になる。

同じ変更で揃える対象:

- 件数を表示するラベル（呼び出し側スキルの完了レポートなど）
- fail-fast の経路を足したなら、helper のヘッダと usage の Exit codes、呼び出し側手順書の例外列挙とエラー表
- 手順書の JSON 例示。二択の説明を 1 つの文字列に並べず、種別ごとの例を示して、各フィールドに入れる値を 1 文で明記する

列挙は、正本（契約・エラー表）と理由の補足（rationale）で粒度が違う。追記は正本に足し、補足側の列挙は例示として扱う。補足側まで正本と同じ網羅性で追随させようとすると、追随のたびに次の食い違いが見つかり、連鎖が止まらない。事例では、検出ロジックを触らない文書・ラベルだけの追随 fix は 1 cycle で閉じた。
