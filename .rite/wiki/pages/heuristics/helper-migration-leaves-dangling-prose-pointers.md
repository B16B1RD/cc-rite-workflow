# シェルブロックを helper へ移したら、散文が旧コマンドを指していた箇所を grep で洗い、所在記述の書き方を揃える

## 概要

手順書のシェルブロックを helper の 1 行呼び出しに置き換えると、散文が「上記の `<旧コマンド>`」の形で指していた箇所が、参照先の無いポインタとして残る。移設では旧コマンド名を散文側でも grep して新しい呼び出し形に揃える。

## 詳細

シェルブロックの移設は、ブロック本体だけを見て確認しやすい。しかし同じファイルの散文には、ブロック内のコマンドを名指しする文が残り、移設後は指す先が消える。旧コマンド名を grep し、ヒットした散文を新しい呼び出し形（helper 名と、どのステップが呼ぶか）に書き換える。

所在記述の書き方は、同じファイルで先に直した箇所と揃える。形式がずれると、次の reviewer が形式の違いそのものを指摘する。また、規則の例外を述べる正本の記述は、受入条件や判断記録が定める例外の範囲（ブロック単位など）と同じ粒度で書く。コマンド名だけで例外を書くと、同じブロックの他の文が規則違反に見える。

「helper に git commit が入らない」ことを固定する検査は、`git -C <dir> commit` のようにグローバルオプションが付いた形も拾う必要がある。素朴なパターンでは変異が生き残るので、既存の commit 判定（commit の対象を解析する処理）と同じ判定を使う。
