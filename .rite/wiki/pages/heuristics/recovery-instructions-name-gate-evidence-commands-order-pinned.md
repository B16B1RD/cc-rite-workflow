# 再開手順は後段ゲートが要求する証跡を作るコマンドを名指しし、静的検査で順序も固定する

## 概要

停止通知やエラーメッセージが示す「再開手順」は、後段のゲートが検査する証跡（例: スコープ検証 helper の `check` と `verify --kind all` の実行結果）を実際に作るコマンドを名指しして並べる必要がある。手順が一般的な案内（「検証してから進めてください」等）に留まると、利用者は正しい順序で必要な証跡を作れず、同じゲートで再び止まる。

## 詳細

再試行権を発行した run が iterate から再試行の review に進めなかった不具合の修正では、再開手順を「後段のゲートが要求する証跡を作るコマンドを名指しして並べる」形に直した。単に「検証してください」と書くだけでは、利用者はどのコマンドがどの証跡を作るかを推測する必要があり、順序を誤ると証跡が欠けたままゲートに再度弾かれる。

さらに、この名指し自体が drift しないよう、静的検査で手順内のコマンド順序まで固定した。手順書の自由記述に任せると、後からの編集でコマンドの順序が入れ替わり、ゲートの前提（例: `check` の後に `verify --kind all` を実行する）が崩れても検出されない。順序を静的検査の対象にすることで、手順書の編集がゲートの前提を暗黙に破壊する経路を塞ぐ。
