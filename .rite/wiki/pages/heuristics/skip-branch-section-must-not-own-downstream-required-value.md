# 「本節を実行しない」分岐を持つ節の内側に、後続ステップの必須値の定義を置かない

## 概要

節を丸ごと飛ばす分岐があると、節の内側で定義した値は飛ばした経路で未定義のまま後続へ届く。後続が必須引数としてその値を使う場合、飛ばした経路でだけ毎回停止するため、値の定義は分岐の文そのものに書く。

## 詳細

### 起きたこと

手順書の節の冒頭に「関連 Issue が取れなかったときは本節を実行せず、対象外と表示する」という分岐があり、「対象外のときは受入条件の ID 一覧を空文字列とする」という定義は同じ節の手順の中にあった。字義どおりに実行すると、関連 Issue なしの経路では節に入らないので定義を読まず、値を持たないまま後続のステップへ進む。後続の検査は「ID 一覧を空文字列で明示すること」を必須にしていたため、この経路でだけ毎回、呼び出しエラーで止まった。

### 書き方

- 分岐が後続に渡す値は、分岐の文そのものに書く（「本節を実行せず、X を空文字列としてステップ N まで保持する」）
- 節の内側にある定義は、節に入る経路の値に限定して書く
- 後続の必須値を増やしたら、その値を作る側のすべての分岐（早期 return・skip・対象外）から定義に到達できるかを確かめる。契約テストで pin する場合も、節の内側の文ではなく分岐の文を pin する

### なぜ見落とすか

節の内側の定義は、節を上から読む人には「対象外なら空」と読めてしまい、分岐で節ごと飛ばされる経路が意識から外れる。後続の値を必須にする変更（省略を呼び出しエラーにする fail-loud 化）は正しいが、それによって値を作る側の到達性の欠陥が初めて表に出る。
