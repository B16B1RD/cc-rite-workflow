# 失敗経路の ERROR 文を段ごとに分けたら、分割後の各分岐に入るテストを 1 つずつ用意し、文面で照合する

## 概要

共通の ERROR 文を失敗段ごとに分けると、以前は共通の文面を介して間接に検出されていた分岐がテストから外れる。分割後の分岐ごとに入るテストを置き、件数ではなく文面で照合する。後続の実行を主張するテストは、後続が実際に観測できる fixture で書く。

## 詳細

診断しやすくするために 1 つの ERROR 文を失敗段（時刻の取得・書き込みなど）ごとに分けると、テストが検出していた範囲が変わる。分割前は、どの段で失敗しても同じ文面が出たので、1 本のテストが複数の分岐をまとめて覆っていた。分割後にそのテストが照合する文面は 1 つの段のものだけになり、残りの段（たとえば書き込み失敗側）はどのテストからも入られなくなる。分割したら、分割後の各分岐に入るテストを 1 つずつ置く。

分岐を増やした WARNING / ERROR のテストは、出力の件数ではなく文面で照合する。件数だけを数えると、分岐どうしの文面を入れ替える変異が生き残る。

テストのコメントが「後続の処理も実行される」のように後続の実行を主張するなら、その fixture で後続が実際に観測できるかを確かめる。前段と同じ理由で後続も失敗する fixture（識別子を解決できない等）では、後続を飛ばす変異を検出できない。現実に起きる失敗（時計が読めない等）を fixture にすると、後続の出力を assert できる。
