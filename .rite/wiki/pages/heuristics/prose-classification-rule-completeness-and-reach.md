# 散文で分類規則を追加するときは『規則の完全性』と『判断点への到達』を別々に点検する

## 概要

rite の reviewer 規則は散文の契約であり、LLM がそれを読んで判断する。この形の規則を追加する PR では、欠陥が 2 つの独立した軸に現れる — **規則本体に穴がある**（読めば適用できるが、ある入力クラスで意図と逆の帰結になる）と、**規則が判断点に届いていない**（正しく書かれているが、reviewer が判断する位置で読まれない）。前者だけを点検すると、文書上は完備なのに運用では一度も発火しない規則が merge される。PR #2122（テスト網羅性 Finding Gate の新設）で 3 reviewer が独立に両軸の欠陥を検出し、先行 PR #2095 が同じ「到達」欠陥を Target Files 外の 1 行追加で解消していた先例が確認された。

## 詳細

### 軸 1: 規則の完全性

散文の分類規則で繰り返し現れた穴は 4 種類ある。いずれも「読めば適用できる」ため通常のレビューを通過しやすい。

**(a) 既定の発火条件が入力欠損の全クラスを覆っていない**

規則が外部文書を判定材料にするとき、判定材料の「不在」は **2 層**で起こる — 文書そのものの不在と、文書内の該当節の不在。fail-loud 既定を「参照が無い / 取得に失敗」という *取得段階* の失敗だけで発火させると、「取得はできたが参照先に該当節が無い」という *内容段階* の欠損が既定を素通りし、規則が自ら掲げた原則と逆の帰結が既定になる。

PR #2122 では、blocking 判定を Issue の §4.4 MUST / §5 AC に照らす規則が、契約節を持たない Issue で全指摘を non-blocking へ落とす経路を持っていた。test-reviewer が実データで裏付けた — 直近 25 Issue のうち 10 件が両節を欠く。テンプレートが両節を `Always MUST` と宣言していても運用では守られない。**既定の発火条件を書いたら、判定材料が「無い」と言える形を列挙して 1 つずつ当てる。**

**(b) row の前提を検証する手順が無い**

分類規則の row が「既存の pin が保護している」型の**肯定的事実**を前提にするとき、判定手順にその事実を確認するステップが無ければ、reviewer は主張するだけで降格できる。前提の対応先が判定手順に無い row は、実質的に無条件の逃げ道になる。

**各 row の前提が判定手順のどのステップで検証されるかを対応付ける。** 対応先が無いなら、その row を「もう一方の row の検証済みの否定」として定義し直すと既定が安全側へ倒れる。

**(c) 判定の評価レベルが固定されていない**

「変異が無効化する挙動」のように、対象を *サイト*（変異箇所）で測るか *効果*（観測可能な挙動）で測るかで結論が反転する述語がある。判定手順が lexical 判定（対象名が文面に現れるか）で、判別子表が効果基準だと、同じ入力に対して 2 つの row が逆の結論を出す。**評価レベルを明示する 1 文を述語に必ず添える。**

**(d) 節再編で軸レベルの共通規定が旧クラス名を名指ししたまま残る**

既存節を「2 ドメイン構成」へ再編して小節を追加すると、その後ろに続く「他軸との関係」型の共通 bullet が旧ドメインのクラス名を名指ししたまま取り残される。H3 を挿入して既存の共通記述を下位へ押し込む再編では、**押し込まれた記述が全ドメインを覆う文言かを 1 件ずつ確認する。** PR #2122 ではこの 1 行を 3 reviewer が独立検出した。

### 軸 2: 判断点への到達

新しい Gate を SoT ファイルへ書いただけでは、reviewer が実際に判断する位置に届かない。rite の場合、その位置は `skills/pr-review/references/reviewer-prompt-generator.md` の自問直下に置かれた注意書きである。

先行 PR #2095（散文ドメインの Gate 導入）は、Gate 本体が `{shared_reviewer_principles}` 経由で prompt へ注入済みだった時点で、なお「判定ステップの『観測される誤動作』が grep を包含するため、これが無いと新ゲートが reviewer の判断点に到達せず不活性になる」として Issue の Target Files 外からこの注入行を追加している（Decision Log で承認）。PR #2122 は同型の Gate を追加しながらこの対を落とし、3 reviewer のうち 2 名が検出した。

**Gate を追加する PR は「SoT への記述」と「判断点への注入」を対で行う。**

さらに悪い形がある — 既存の注入行が「**散文への指摘では** …に限る」と *肯定的にドメイン限定*されている場合、新ドメインについては限定が存在しないと読め、**逆の signal**（無制限）を出す。単に「足りない」のではなく「反対のことを言っている」状態になるため、注入行がドメイン限定を持つときは新ドメイン用の同型行の追加が必須になる。

### 点検の順序

軸 1 と軸 2 は独立に失敗するため、片方の点検で他方は担保されない。規則を書き終えたら:

1. 判定材料が「無い」と言える形を列挙し、既定がすべてを覆うか当てる（軸 1a）
2. 各 row の前提を判定手順のステップへ対応付ける（軸 1b）
3. 述語の評価レベルを明示する（軸 1c）
4. 節再編があれば、押し込まれた共通規定の文言を全ドメインで検算する（軸 1d）
5. 規則が reviewer の判断点へ注入されているか、既存の注入行がドメイン限定を持たないかを grep で確認する（軸 2）
