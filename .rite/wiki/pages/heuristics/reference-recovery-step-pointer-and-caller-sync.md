# 他スキルから直接読まれる手順に工程を足すときは、回復手順の所在と呼び出し側の規定を合わせる

## 概要

節アンカーで複数スキルから直接参照される手順書に工程を挿入すると、スキル内でしか解決しない所在指示は読み手に届かず、番号で範囲を引く呼び出し側や一律の失敗規定を持つ呼び出し側と食い違う。

## 詳細

あるスキルの中にある回復規定（例: 「冒頭の手順からやり直す」）を、別スキルからも読まれる reference の手順へ移すと、「冒頭」がどこを指すかは元のスキルの中でしか決まらない。reference から直接その節へ来た実行者は回復手順を特定できず、即興の操作で状態を書き直しかねない。移すときは、回復手順と契約の所在を reference から辿れるリンクにする。

手順に工程を挿入して番号を繰り下げたら、手順の範囲を番号で引いている呼び出し側（「手順 1〜N」）を grep で洗い出して同期する。節アンカーだけで参照する呼び出し側は影響を受けない。

呼び出し側が「helper の非ゼロ終了は失敗として止まる」と一律に規定している場合、被呼び出し手順に「非 0 なら回復して続行」を足すと同じ事象に 2 つの指示が当たる。呼び出し側の明示規定が優先して読みが一義に決まるかを確認し、決まらないなら片方へ寄せる。

テストが文言の部分一致で手順を固定している場合は、参照を挿入する括弧の位置で固定された句を分断しない。
