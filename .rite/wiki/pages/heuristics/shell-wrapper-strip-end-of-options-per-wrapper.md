# シェルの前置きラッパーを剥がす判定は、ラッパーごとのオプション終端の扱いを bash の実挙動と突き合わせる

## 概要

シェルコマンドの先頭語を判定する処理で builtin / command / time などの前置きを剥がすとき、ラッパーごとに剥がす経路が分かれていると、オプション終端 -- を剥がさない経路が残り、同じ意味の変種が判定から漏れる。剥がし方の非対称は揃えるのではなく、各ラッパーの bash 上の実挙動と一致しているかを確かめる。

## 詳細

ディレクトリ移動を含むコマンドを検出して、commit の対象を「静的に決められない」と扱うガードがあった。代入前置きや `command` / `time` は、ラッパー直後の `-` で始まる語をまとめて剥がす経路を通っていた。一方 `builtin` は別の経路で先頭語だけを剥がしており、`builtin -- cd` では `--` が先頭に残って移動と判定されなかった。同じ意味の変種が、剥がす経路の違いだけで判定から漏れた形である。

直し方は、`builtin` の直後の `--` を 1 回だけ剥がすことだった。bash の `builtin` はオプションを取らず、`builtin -- -- cd` はエラーになる。したがって 1 回だけ剥がす実装が実挙動と一致する。`command` / `time` は後続の `-` 語をすべて剥がす。ラッパーごとに剥がし方が違うこと自体は正しい。確かめるべきなのは非対称の有無ではなく、各ラッパーの剥がし方が bash 上の挙動と一致しているかである。再レビューでは複数の reviewer が独立にこの一致を実測し、解消で合意した。

テストは変種ごとに、ガードの入口と commit 対象の解決の両経路で判定されることを並べた（`pushd` / `popd` / `builtin cd` / `command cd` / `time cd` / 代入前置き / `builtin -- cd` など）。修正を外した変異でテストが落ちることを確かめてから、全件の検証を回す。

変異確認でソースの更新時刻が変わると、Python のバイトコードキャッシュ（`__pycache__` の .pyc）が次の実行で再生成される。検証の入力にキャッシュが含まれていると入力変化とみなされ、検証がやり直しになる。再実行すれば通るが、検証入力の集合から生成物のキャッシュを外すのが根本の対処である。
