# 設定の読み込み位置は、同じ設定を読むすべての箇所で同じ解決手段に揃える

## 概要

同じ設定を関数ごとに別の位置（作業ディレクトリ相対と、共有の解決手段）から読むと、設定が片方の位置にしか無い構成でだけ判定がずれる。読み込み位置は共有の解決手段に揃え、その構成の fixture で固定する。

## 詳細

作業ツリーを分けて使う構成では、未追跡の設定ファイルが主のチェックアウトにだけ置かれることがある。同じ関数の中で、ある値は作業ディレクトリ相対で読み、別の値は主のチェックアウトへ戻る解決手段で読むと、その構成でだけ上限判定がずれる。単一の作業ツリーでは両方が同じファイルを指すため、通常のテストでは表面化しない。

修正では読み込み位置を共有の解決手段に揃え、分けた作業ツリー（linked worktree）の fixture で固定した。設定を読む箇所を足すときは、既存の読み手がどの解決手段を使っているかを grep してから同じものを使う。
