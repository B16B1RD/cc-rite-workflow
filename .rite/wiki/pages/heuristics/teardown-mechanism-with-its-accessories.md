# 機構を畳んだら、その機構のために作った付随物も同時に畳む — 名前を変えて残すと動機を失った構造だけが次の欠陥面になる

## 概要

ある機構のために新設した marker・専用 reason・報告文言は、その機構を畳んだ時点で棚卸しの対象に
なる。運ぶ値が無くなった marker を名前だけ変えて残すと、0 件時に最後の marker となって下流が
「未完了」と誤報告し、既存値の前置詞であれば判定表の前方一致で誤った行に吸われる。削除は
「消したもの」だけでなく「消したものが受けていた入力の行き先」も設計対象になる。

## 詳細

### 起点: 運ぶものが無くなった marker が 2 つの害だけを残した

サイクル 2 で「落とした件数」を運ぶために marker を新設した。サイクル 3 でその件数機構自体を
畳んだ（要素を落とす設計をやめた）が、marker は名前を変えて残った。運ぶ値は無いのに存在する
marker が、次のサイクルで 2 つの独立した害を生んだ:

1. **0 件時に誤報告**: 対象 finding が 0 件のときは finding 行が 1 行も出力されないため、
   この marker が最後の marker になる。下流の判定表は「判定 marker が最後に来ていない」ことを
   もって「未完了」と読むので、正常な 0 件サイクルが毎回「未完了」と報告される。
2. **前方一致で誤った行に吸われる**: marker 値が既存値の**前置詞**（`done_extract` に対する
   `done`）だったため、判定表を前方一致で読む消費者が誤った行に routing した。

**機構を畳むときは、その機構のために作った付随物（marker・専用 reason・報告文言）も同時に
棚卸しする。** 名前を変えて残すと、動機を失った構造だけが次サイクルの欠陥面になる。

### marker 値の照合は前方一致を既定にしない

上の 2 番目の害は、marker を消せば同時に消えるが、照合規約の側にも一般則がある。

**照合は区切り文字（`;` または行末）まで含めた完全一致で規定する。** 前方一致を既定にすると、
既存値の前置詞になる値を後から足した瞬間に、新値が既存行へ吸われる。この事故は値を足した側の
変更では検出できない（既存行のテストは緑のまま通る）。

### 削除したら、その機構が受けていた入力の行き先を追う

marker を廃止したとき、その marker が拾っていた経路は「marker が無いとき」の分岐へ移った。
ところが分岐の説明を旧来の 1 ケースのままにしたため、**移ってきたケースが無言で成功扱い**に
なった。

**削除は「消したもの」だけでなく「消したものが受けていた入力の行き先」も設計対象になる。**
移った先の分岐が、移ってきたケースを正しく扱う文面・実装になっているかまで確認する。

### 兄弟分岐との突き合わせ

同一ファイル内に「marker 不在で警告を付記する」兄弟分岐が複数あるとき、新設・改変した分岐だけが
空文字列を返す形は規約違反として検出される。**分岐を触ったら兄弟分岐の扱いと突き合わせる。**

### 撤去のチェックリスト

| 確認 | 内容 |
|---|---|
| 付随物の棚卸し | 畳む機構のために新設した marker・reason 語彙・報告文言を列挙し、同時に消す |
| 被覆の行き先 | 消した経路が受けていた入力がどの分岐へ移るかを特定し、移り先の文面・実装を更新する |
| 照合規約 | marker 値の照合は区切り文字まで含めた完全一致。前方一致を既定にしない |
| 兄弟分岐 | 同型の兄弟分岐と扱いを突き合わせ、新設・改変分岐だけが非対称にならないようにする |
