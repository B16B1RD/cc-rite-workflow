# 同じ対象の識別子を積み上げる台帳は、キーごとに最新だけ残す対応表にする

## 概要

同じ対象に付く識別子を追記し続ける台帳は、古い値と新しい値の衝突で処理が止まりやすい。キーごとに最新だけを残す対応表にし、JSON 全文をキーにするときは欄の順序を正規化し、機械照合で拾えない言い換えは分類役に台帳を読ませて紐づける。

## 詳細

### 追記型の台帳は古い値との衝突で止まる

起票済みの Issue のように、同じ対象へ run ごとに識別子が付く記録を追記型で持つと、同じキーに古い値と新しい値が並び、照合側が「どちらが正か」を決められずに止まる。記録の目的が「いまの対応」を引くことなら、キーごとに最新の値だけを残す対応表にする。更新は上書きになり、古い値との衝突は起きない。

### JSON 全文をキーにするときは欄の順序を正規化する

指摘の本文を JSON にしてそのままキーに使うと、書き手が LLM の場合は欄の順序が run ごとに変わりうるため、同じ内容でも別キーになる。キーを作る前に欄の順序を正規化する（例: キーをソートして直列化する）。

### 言い換えは警告で補わず、分類役に台帳を読ませる

同じ根因が別の言い回しで再提出されると、機械照合では同一と判定できない。ここに「似ているかもしれない」という警告を足しても、判断は結局どこかで行う必要がある。判断する主体（採否を決める分類役）に台帳を読ませ、既存の対応に紐づけさせる。
