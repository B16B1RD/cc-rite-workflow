# シェル字句の判定器は bash を実際に実行する差分検証で規則を合わせ、字句器を 1 つに集める

## 概要

シェルの字句処理を自前で書くと規則の 1 つずつが bash とずれ、規則を足す修正のたびに反対方向の退行が出る。偽のコマンドを PATH に置いて bash で実行した結果と判定器を突き合わせる差分検証を先に作り、同じ構文を読む経路は 1 つの字句器に集め、追えない構文は判定不能として拒否する。

## 詳細

コマンド文字列から「実際に実行される git / gh の呼び出し」を読み取る判定器を直すサイクルで、CRITICAL の指摘が 4 → 6 → 8 件と増え続けた。規則を 1 つ足すたびに、別の入力で反対方向（見逃し ↔ 誤拒否）の退行が出たためである。

### 差分検証（オラクル）を先に作る

偽の `git` / `gh` を PATH の先頭に置き、入力を bash で実際に実行して呼ばれた引数を記録する。同じ入力を判定器に通した結果と突き合わせ、差分が 0 件になるまで手元で回してから review に出す。規則を 1 つずつ足すより、先に差分検証を用意したほうが収束する。

差分検証の入力は作者が思いついた例に限られ、reviewer は毎回その外の入力を見つける。入力は「構文 × 文脈」の格子で作る。文脈は最上位 / `$(` の中 / 二重引用の中 / heredoc 本文の置換の中のように列挙する。

### 同じ構文を読む経路は 1 つの字句器に集める

最上位だけを bash に合わせて書き直しても、同じ構文を別の簡易スキャナで読む経路（heredoc 本文の置換の終端探索など）に同じ欠陥が残る。簡易スキャナを消して字句器を 1 つにし、各経路はそれを呼ぶ。

入力を別の引用規則に包み直して後段パーサに渡すのもやめる。引用符なし heredoc 本文を二重引用符で包むと、エスケープと引用の意味が変わる。本文は bash の heredoc 規則（`\` が特別なのは `$` `` ` `` `\` 改行の前だけ）で走査し、実行される置換だけを取り出して元の位置に置く。

### 追えない構文は判定不能として拒否する

閉じない heredoc や、本文の置換の中の `case` のように字句器で確実に追えない構文は、規則を足して追わず、判定不能として拒否する（fail-loud）。どこまで bash に合わせるかは、エージェントが実際に書く形を基準に決め、合わせない形は仕様に明記する。

### テストは helper に届く形で書く

hook の fast path が helper を呼ばない条件（cwd がすでに対象の中にある等）のテストは、helper の規則を何も固定しない。回帰テストは cwd を外に置くか `cd` を含めて helper に届かせ、規則を 1 つ壊すと落ちることを変異で確かめる。
