# エラー文に書く確認コマンドは検出に使ったコマンドと同じ形にし、テストは出力から取り出して実行する

## 概要

検出コマンドに設定の上書きなどを足すと、エラー文の「対処」に書いた確認コマンドが古い形のまま残り、利用者が実行しても検出と違う結果になる。確認コマンドは検出と同じ形を独立した行で示し、テストは出力からその行を取り出して実行して、解除前と解除後の両方の結果を検査する。

## 詳細

### 起きること

未追跡ファイルの有無を `git status` で検出する処理が、利用者の設定で未追跡ファイルが表示されない場合に備えて、検出側だけ `-c status.showUntrackedFiles=normal` を付けるよう直された。エラー文の「対処」には、素の `git status` で確認するよう書かれたままだった。利用者がその確認コマンドを実行すると、自分の設定では何も表示されず、エラーの原因が見つからない。

検出の条件と、利用者に見せる確認手順は、同じ事実を見ていなければ意味がない。検出を変えたら、案内も同じ形にそろえる。

### 書き方

- 確認コマンドは、検出に使ったコマンドと同じオプションで、文の途中ではなく独立した行に出す
- 補足を全角括弧の挿入句で文中に入れない。補足は別の行に出す
- `git -c status.showUntrackedFiles=normal status` の `-c` は submodule 側の status にも届く。`--untracked-files=normal` は親にしか効かない。検出がどちらを使うかも案内と一致させる

### テスト

テストは、エラー出力から確認コマンドの行を取り出して実際に実行する。検査するのは次の対である。

- 原因を解除する前は、そのコマンドが原因の対象を表示する
- 原因を解除した後は、そのコマンドが何も表示しない

片方だけを検査すると、コマンドがエラーで偶然それらしい出力を返しても通ってしまう。対で縛れば、検出と案内が食い違ったときにテストが落ちる。

既存のテストが文言の一部を固定している場合は、その部分文字列を残す形で文言を直す。
