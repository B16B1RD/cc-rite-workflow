# 一致検証の照合先は判定対象の識別子から取り、確認した値を後続の実行コマンドに固定する

## 概要

「レビュー済み commit と head の一致」のような検証を手元のチェックアウトの状態で代用すると、別 commit から実行しただけで誤拒否し、対象側の未検証の更新は見逃す。照合先は判定対象の識別子から取得し、確認した値を後続の実行コマンドへ渡して、検証と実行の間に対象が動く窓を塞ぐ。

## 詳細

### 照合先を対象から取る

gate が確かめたいのは「この PR の head がレビュー済みか」であって「いま立っているディレクトリの HEAD がレビュー済みか」ではない。両者は普段一致するため手元の値で代用したくなるが、一致しない場面で 2 方向に壊れる。

- 別ブランチ・別 worktree から実行すると、対象は正しくレビュー済みでも拒否される（誤拒否）。
- 対象側に未レビューの push があっても、手元が古い commit のままなら通る（見逃し）。

照合先は PR 番号とリポジトリから API で head の OID を引く。リポジトリは必須引数にし、省略時に cwd から推測させない。

### 正常を確認できなければ止める

取得値の検査は「40 桁 hex の OID である」ことを正とし、それ以外をすべて同じ拒否経路へ送る。API 失敗・空・null・短縮 SHA を個別に列挙するより漏れにくい。取得できないときに手元の HEAD へ代用しない。head 照合を明示的に省略する override があっても、後続が対象の識別子を必要とするなら解決自体は省略しない。

### 確認した値を実行に固定する

gate を通過した事実は「その OID がマージされる」ことを保証しない。照合とマージの間に push が入れば、未レビューの commit がマージされる。gate の出力から照合済み OID を取り出し、`gh pr merge --match-head-commit` に渡す。取り出せなければマージしない。取り出しは一致を示す marker 行に anchor し、診断出力は捨てずに再表示する。

### テストでの固定

比較に関与しないはずの値（ローカル HEAD）を、全ケースで照合先とも期待値とも異なる値に固定する。こうすると既存のテスト群全体が「その値が判定に関与しない」ことの検証を兼ね、元の実装へ戻す mutant が広い範囲で失敗する。
