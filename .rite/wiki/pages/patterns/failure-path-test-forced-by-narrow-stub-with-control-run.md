# 失敗経路のテストは、対象の 1 経路だけを失敗させる差し替えで強制し、差し替えなしの対照実行で空振りでないことを確かめる

## 概要

失敗処理のテストは、目的の 1 経路だけを失敗させる差し替えで強制する。差し替えなしの対照実行が成功することを確かめれば、テストが空振りしていないことを示せる。テスト名は、強制している失敗の範囲と同じ広さにする。

## 詳細

一時ファイルの作成や書き込みの失敗は、実環境では再現しにくい。PATH の先頭に `mktemp` の差し替えを置き、引数（例えば対象ファイル名の接頭辞）が一致した呼び出しだけを失敗させ、それ以外は本物へ委譲すると、目的の 1 経路だけを失敗させられる。差し替えはコマンド 1 回の環境変数か、`try/finally` で戻す範囲に限る。

空振りの確認は 2 つで行う。差し替えあり: 対象の失敗処理が実際に走ったこと（非ゼロ終了、警告文、記録が残る／消える）を assert する。差し替えなし: 同じ条件で成功し、記録が作られることを対照として確かめる。差し替えが効いていなければ、差し替えありの assert が落ちる。

テスト名は強制した失敗の範囲に合わせる。「一時ファイルを残さない」と名乗りながら、強制しているのが一時ファイルの作成失敗（残るものが無い状況）だけなら、名前は検証範囲より広い。読み手は、後段の失敗で一時ファイルを消す枝まで検証済みと誤解する。

### 新しい失敗経路を足したら、その経路を通るテストを同じ変更で足す

Issue を作った後に記録を消費できなかったときの警告という失敗経路を足したとき、その経路に入るテストが無く、実測の無い指摘を 2 件受けた。書き込み不可のディレクトリと stub の失敗フラグで実際に失敗を起こすテストを足して解消し、reviewer が変異を入れて検出力を確かめた。

- stub には失敗側の分岐を選べる knob を持たせる
- stub だけで組み合わせ挙動を確かめている箇所は、実体どうしを組み合わせたケースを別に置く
- chmod による失敗の注入は root で実行すると効かず、テストが誤って FAIL する側に倒れる
- 失敗の案内文は、原因を判定する側に 1 か所だけ置く。呼び出し側 2 か所に置いた案内は文言がずれ、session の解決に失敗したときにも「スキルを起動して」と誤って案内していた
