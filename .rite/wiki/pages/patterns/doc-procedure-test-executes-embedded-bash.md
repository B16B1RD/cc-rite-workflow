# 文書の手順を検証するテストは、埋め込んだ bash ブロックを実行して固定する

## 概要

手順書（スキル文書）に新しい検査を差し込むとき、そのテストが文字列の出現回数だけを数えていると、手順に埋め込んだ bash ブロックの引数の綴りやスクリプトのパスの誤りは検出できない。テストは、手順から bash ブロックを抽出して実際に実行し、終了コードと案内を固定する。

## 詳細

- **ブロックを実行する**: 手順の節から fenced bash を抽出し、プレースホルダーを実値に置き換えて実行する。違反入力では作成用の処理へ進まずに止まる（終了コードが伝わる）こと、直した入力では先へ進むことの両方を確かめる。
- **文の語句一致は文の境界で切り出す**: 同じ行に別の文があると、行単位の語句一致は片方の文を消しても通る。照合する文を句点などの境界で切り出し、その範囲だけで語句を検査する。
- **追記した全経路で順序を確かめる**: 同じ検査を複数の経路（単一・分解・別の作成手順）に差し込むと、経路ごとに順序が食い違いやすい。仕様が定める順序と、書き直し後の再検査の前提が両立するかを、追記した全経路で確かめる。
- **終了コードと案内は別に固定する**: 終了コード 2 の分岐とエラーメッセージを固定するテストが無いと、変異で素通りする。
