# 持ち越した識別子の単位の変化は束ねと分けの両方向で止め、同じ規則を書き手の手順に優先順位付きで書く

## 概要

run をまたいで持ち越す識別子は、今回の単位と前の run の単位が 1 対 1 のときだけ安全に使える。束ね（多対 1）だけ止めて分け（1 対多）を止めないと、2 件目が書き込み済みと誤判定されて黙って欠落する。機械の停止規則は入力を書く側の手順にも、既存規則との優先順位をすべて並べて書く。

## 詳細

### 両方向を 1 つの不変条件にする

前の run で別々の key を持った候補を 1 つの記録に束ねると、どちらの印で照合するかを決められない。逆に 1 つの key の候補を複数の記録に分けると、同じ key が 2 つの記録に出て、2 件目は 1 件目の印を自分の印と読み「書き込み済み」として黙って飛ばす。書き込み済みの表示は失敗に数えないので、後段は完了扱いにして欠落が永久に残る。束ねの停止だけを入れた修正は、この逆向きを新たに作った。

「記録の単位を前の run から変えない」を 1 つの規則として両方向で止め、停止メッセージに要素ごとの前の識別子を出して回復の手がかりにする。分けた 2 件目に新しい key を振って書く案は、前の run が 1 行で記録した根因をもう 1 行書くことになるので採らない。

### 書き手の手順に同じ語彙で書く

停止規則が stderr にしかないと、記録を書く分類役は規則を知らないまま同じ単位の変化を繰り返す。さらに手順が「止まった run が書いた記録から再開する」と指示していると、止まった原因の記録から始めて同じ停止を繰り返し、回復経路が無くなる。規則を書き手の手順にも置き、止まった run の出力から始めるときもその単位に直してから書くと明記する。

### 優先順位はぶつかる既存規則をすべて列挙する

新しい規則に「〜より優先する」と書くとき、同じ手順の中でぶつかりうる既存規則を 1 つでも列挙から漏らすと、その規則との衝突経路では規則どおりの出力が存在せず機械の停止が繰り返される（ここでは「prior の違う候補を 1 つの記録にまとめない」が漏れていた）。優先された側の欄が単一値なら、複数の候補からどれを写すかも決めておく。根拠を括弧書きで添えるときは、常に成り立つ事実（ゲートが何を比べるか）に絞り、状況次第で崩れる言い切りを書かない。

### テスト

「止めて理由を出す」型の要求は、止まること（終了コード）だけでなく理由の出力まで assert しないと、理由の出力を消す変異が生き残る。持ち越しの保存範囲も「新しく作った値」だけでなく「既存の値を継いだ要素も保存される」ことまで固定する。
