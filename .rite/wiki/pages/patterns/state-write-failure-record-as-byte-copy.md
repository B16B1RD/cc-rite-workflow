# state の書き込み失敗は別ディレクトリに state のバイト複製として記録し、読み手が cmp で照合する

## 概要

書き込みに失敗した state を中断として扱わない要件は、state を書く全経路（終了時だけでなく後片付けの回収も）に及ぶ。書き込み自体が失敗する経路では、別ディレクトリに失敗時点の state のバイト単位の複製を残し、読み手が現在の state と cmp で比べる。以後の書き込みで state が変われば自動的に一致しなくなるので、記録を消す処理が要らず、正当な中断も妨げない。

## 詳細

**要件は全書き込み経路に及ぶ**: 「書き込みに失敗した state を中断として扱わない」要件を 1 つの経路（セッション終了時）だけで満たしても、後片付けの回収など別の経路が同じ state を書く。state を書く経路を列挙し、すべてに同じ扱いを適用する。

**失敗の記録はバイト複製にする**: 書き込みそのものが失敗する経路では state 自体に印を付けられない。別ディレクトリに失敗時点の state の複製を残し、resume 側は現在の state と cmp で比べて一致したときだけ「書き込み失敗の state」とみなす。state が以後更新されれば一致しなくなるので、記録の消去処理が要らない。

**上書きで成功扱いにする fallback は採らない**: in-place の上書きで失敗を成功に変える fallback は、非 atomic であり失敗経路を隠す。

**一時的な印は消す経路を全部テストで固定する**: state に一時的な印を足す設計では、印を消す経路（set の再構築、deactivate、回収）を全部列挙してテストで固定すると、mutation で主要な変異がすべて検出された。抑止の分岐・同一性の照合・記録の書き込みをそれぞれ外した mutant がテストで落ちることを確かめる。
