# エラーメッセージが案内するコマンドは、テストで出力から抽出して逐語実行する

## 概要

エラーメッセージが利用者に打たせるコマンドを文字列の部分一致だけで固定すると、案内先 CLI の必須引数が欠けていても検出できない。テストは出力から案内コマンドを抽出してそのまま実行し、文言と実行可能性を 1 つの assert で結ぶ。

## 詳細

停止時に「次にこのコマンドを実行してください」と案内するエラー経路では、案内文そのものが利用者の復旧手順になる。案内したコマンドが案内先 CLI の必須引数を欠いていると、書かれたとおりに打った利用者は別のエラーで止まり、復旧経路が行き止まりになる。

観測された失敗の形は次のとおり。

- テストは案内文字列を substring で固定していた。このため、案内が引数を欠いていても文字列一致は通った。
- 「案内どおりに実行できる」ことを確かめる別のテストは、テスト作者が手で引数を補ったコマンドを実行していた。案内文と実行したコマンドが別物になり、欠陥を隠していた。
- 複数の reviewer が、案内文を書かれたとおりに実行して独立に失敗を再現した。

有効な書き方は、案内文から実行するコマンドを stderr 等の出力そのものから抽出し、加工せずに実行することである。これで「何と案内したか」と「それが実行できるか」が同じ文字列に結び付き、どちらか一方だけが正しい状態をテストが許さない。

同じレビューでは、次の 2 つの関連する取りこぼしも見つかった。

- 新しい列挙値（停止理由のトークン）を導入したとき、既知の値を明示的に列挙している consumer（再開案内）と仕様書の列挙表への反映が漏れた。列挙値を足す変更では、その値を列挙している箇所を grep で洗い出す。
- 受入条件が「選び方とコマンド」を要求していたのに、テストはコマンド名だけを固定し、条件句を固定していなかった。条件句を削る変異がテストをすり抜けた。受入条件が文言の複数要素を要求するときは、要素ごとに固定する。


### 案内コマンドの値は引用符の要らない 1 語にする

エラーメッセージが JSON 文字列として出力される経路では、案内コマンドの値に引用符を入れると出力に `\"` が残り、コピーして打つとコマンドが壊れる。案内コマンドに埋める値は引用符なしで 1 語になる形に選ぶ。修正ではテストが stderr から案内コマンドを抽出して shlex で分割し、そのまま実行する形にした。文言と実行可能性を同じ確認で結ぶことで、引用のされ方が変わって打てなくなる乖離も検出できる。

### 修正の解消は逆向き変異で確かめる

再レビューでは、案内コマンドを逐語実行する形に直したテストが本当に欠陥を捉えるかを、修正を戻した隔離コピーで確かめた。必須引数を外すとテストが案内先 CLI のエラーで落ち、列挙値の分岐を外すと再開案内のテストが「未知の値」表示を観測して落ちた。修正を戻すとテストが落ちることを示せば、テストが空振りしていないと言える。一方、仕様書の列挙表（SoT）への値の追記漏れは文書同士の突合でしか示せず、実測アンカーを持てないため non-blocking として残る。consumer 側の列挙を直しても、SoT 文書は別の経路で拾う必要がある。
