# 件数を入れる変数を「存在し照合も通った」フラグとして兼用すると helper の非空契約に暗黙依存する

## 概要

helper が返す件数を入れた変数の非空を「対象が存在し照合も通った」判定に流用すると、helper が成功時に必ず非空を返すという明文化されていない契約へ依存する。case の各アームに複製した同じ判定を前へまとめるときも、前段の失敗経路を判定から外す条件を残さないと停止理由の名前が変わる。

## 詳細

件数変数をフラグとして兼用する書き方は短く見えるが、helper の出力仕様が「成功時は 0 件でも `0` を出す」から「0 件なら何も出さない」に変わった瞬間、「存在しない」と「存在するが 0 件」が区別できなくなる。判定に使う状態は、件数とは別の変数（または helper の終了コード）で明示的に持つ。

case の各アームに同じ判定が複製されているのを case の前へまとめる整理では、前段の失敗経路（例: collect が失敗した）を判定から外す条件が必要になる。これを落とすと、失敗経路でもまとめた判定が走り、停止理由が別の名前で報告される。この条件の偽側はテストで固定されにくいので、stub の終了コードを差し替えられる形にしておき、前段失敗時の停止理由を assert で固定するとよい。
