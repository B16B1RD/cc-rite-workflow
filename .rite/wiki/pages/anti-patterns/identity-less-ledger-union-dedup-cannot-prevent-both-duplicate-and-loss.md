# identity を持たない判定台帳で複数 cycle の和集合を重複除外すると、重複防止と欠落防止を同時には満たせない

## 概要

判定台帳が最終回の id と位置しか持たないまま、複数 cycle の指摘を連結した集合から「既に処理済み」の指摘を除こうとすると、id や位置で推定した除外は別の指摘まで黙って落とす。除外は台帳が実際に判定した入力に由来する要素に限り、それ以外は転記して重複しうる件数を出す。

## 詳細

**前提の形**: 転記元は全 cycle の結果を連結した集合で、各要素の id は cycle ごとに振り直される連番。一方、処理済みを記録する台帳は最新の結果 1 本だけを読んで `[id, 位置]` の組を残し、cycle 属性も指摘の内容も持たない。

**推定による除外は 3 通りとも壊れた**。それぞれ別の cycle のレビューで実測された。

1. **組の完全一致だけで除外する**: 先行 cycle の同じ指摘は別の id で載っているため照合から漏れ、重複して転記される
2. **照合を位置だけに緩める**: 同じ位置に並ぶ別判定の指摘（台帳上は「記録のみ」で、処理はされていない）まで巻き込んで消える
3. **「最新結果でその位置が全件処理済みなら位置で除外」「組の照合を連結集合全体に当てる」**: 先行 cycle にしか載っていない別の指摘や、たまたま同じ id・同じ位置になった先行 cycle の別の指摘が消える。残りが 0 件になると「全件処理済み」という正常完了を返し、警告も出ない

id も位置も cycle を跨ぐ identity ではないので、「同じ指摘の再報告」と「同じ位置の別の指摘」を台帳から区別する手段がない。このため 2 つの要件は機械的に両立しない。

**収束した形**:

- 連結するときに各要素へ出典（どの結果ファイル由来か）を持たせる
- 除外は「台帳が読んだ最新結果に由来し、かつ台帳の組と一致する要素」だけに限る
- 先行 cycle の要素は id や位置が同じでも転記する
- 同じ位置に並ぶ先行 cycle の要素数を「重複しうる件数」として出力する

欠落は本文が共有経路から消えて取り返しがつかない。重複は人が閉じれば済む。この非対称が、欠落防止を優先する根拠になる。

**往復を止めたもの**: 規則の条件を足しても削っても、次の cycle で逆向きの指摘が出た（重複防止を固定するテストと、欠落を指摘するレビューが衝突する）。止まったのは、優先順位を Issue と設計理由の文書に 1 文で明記し、逆向きだった旧テストの期待値を理由付きで反転してからだった。

**テストで固定するときの注意**:

- fixture が衝突しない id しか使っていないと、id 衝突の経路は未検証のまま通る。同じ id・同じ位置の別指摘を含む fixture を置く
- id が振り直された fixture を用意し、旧照合へ戻す変異でテストが落ちることを確認する
- 除外ルールを変えたら、同じルールを説明する周辺文書（仕様・設定リファレンス・スキーマ説明）を同じ変更でまとめて同期する
