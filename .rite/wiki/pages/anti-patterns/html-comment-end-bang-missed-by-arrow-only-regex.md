# HTML コメントの閉じ記号を `-->` だけで判定すると、`--!>` で閉じた後に続く本文を見逃す

## 概要

HTML コメントは `-->` だけでなく `--!>` でも閉じる。「コメント 1 つだけの行」を正規表現で判定するときに `-->` だけを閉じ記号にすると、`--!>` で閉じた後に見える本文を続ける行を、コメントだけの行と誤判定する。閉じ記号は HTML の定義どおり 2 種類とも扱い、複数言語で同じ判定を持つなら同じ行集合を受理する形にそろえる。

## 詳細

### 何が起きるか

`<!-- a --!> 見える本文 <!-- b -->` のような行を、閉じ記号を `-->` だけとする正規表現で見ると、先頭の `<!--` から末尾の `-->` までが 1 つのコメントに見える。判定は行全体を「コメントだけの行」とみなし、途中の見える本文を取りこぼす。marker 形の行を機械が書いた行として扱う照合では、見える本文を持つ行が検査の外へ出る。

### 根拠は仕様と実際の描画の両方にある

`--!>` での閉じは WHATWG の HTML 構文の comment end bang state が定めている。GitHub の描画（`gh api markdown`）でも、`--!>` の後ろは本文として表示される。つまり `-->` だけを閉じ記号とする判定は、読者に見える本文を「見えないコメント」と数える。

### 直し方

閉じ記号を HTML の定義に合わせて 2 種類とも扱う。

- Python 側は、コメント本体を否定先読みで `(?:(?!--!?>).)*` と書き、どちらの閉じ記号も本体に含めない
- BRE の sed 側は否定先読みを持たないため、「閉じ記号の後ろにさらに `-->` が続く行」を別のアドレス `--!\{0,1\}>.*-->` で外す。こうすると両者が同じ行集合を受理する

値に `>` を一切含ませない単純化は採らなかった。閉じ記号を持たない壊れた marker まで本文扱いにしてしまい、既存の必須規則に反するためである。
