# 抽出述語の厳格化は「壊れた入力」と「入力なし」を同一経路へ畳み、fail-loud を構造的に壊す

## 概要

「散文中の同形文字列を誤検出しない」ために抽出述語へアンカーや厳密条件を足すと、**正規の入力でも表記の揺れ（行末 CR・字下げ・末尾空白）があれば不一致になる**。不一致は抽出結果の空として現れ、それは「対象が最初から存在しない」= 正常系と同じ値である。両者が同じ経路へ落ちた瞬間、その述語が守っていた保証は WARNING 1 行も出さずに失われる。

厳格化は精度の話に見えるが、実際には **fail-loud が成立する条件そのものを壊している**。「一致しない」を 1 本の経路に畳んだ設計は、どれだけ診断を足しても loud にならない。

## 詳細

### 実測された症状（cycle 1 → cycle 2）

cycle 1 で、PR body から durable id を読む marker 行の抽出式へ行アンカー（`^` / `$`）を足した。目的は「散文の中に marker と同形の文字列があっても拾わない」こと。

cycle 2 のレビューで、GitHub の web UI で PR 説明を編集すると本文が CRLF で返るため、**素のアンカーでは正規の marker 行がすべて不一致になる**ことが判明した。抽出も除去も同時に外れ、抽出結果の空は「marker 不在＝初回 cycle の正常系」と区別できない。同定手段を本文照合から id へ移すという PR の中核変更が、無音で従来経路へ縮退していた。

最も示唆的なのは、**同じコードのコメントが既にこれを禁じていた**こと — 「厳格な regex で抽出すると『壊れた marker』が『marker 不在』と区別できず破損が無音になる」。禁止を書いた本人が、次の cycle でその禁止を厳格化そのものによって破った。禁止事項を散文で書いても、それを守らせる機構が無ければ守られない。

### 対処

**厳格化した式と、緩い probe の 2 本立てにする。**

- 厳格な式は値の抽出に使う
- 緩い probe は「対象らしきものがあるか」だけを判定する
- probe に当たったのに厳格な式が空を返したら、それは異常系なので **loud に落とす**（この事例では `id_malformed` として reason 付きで surface した）

probe の緩さには適正がある。**元の式から「値の抽出」だけを外した形が過不足ない** — それより緩くすると誤検出が新しいノイズになり、厳しくすると差集合が生まれる。

### 受理集合の関係は先に決めて 1 本から導出する

cycle 3 で、この 2 本立て自体が次の欠陥を出した。probe の受理集合が除去式の受理集合を**真に含んだ**ため、差集合の行（行頭が marker 形で末尾に散文が続く行）は「破損」と判定されるのに除去できない。「破損を検出したのに直せない」状態が生まれ、案内文の「張り直します」が偽になった。

同じ対象に対する複数の正規表現は、**受理集合の包含関係を先に決めて 1 つの定義から導出する**。この事例では最終的に `抽出 ⊆ 除去 = 破損検出` に固定した。別々の文字列リテラルとして並べると、片方だけを触った編集で関係が崩れる。

### 判別の指針

厳格化の diff をレビューするときは、次を機械的に問う。

1. この述語が「一致しない」を返す入力を、**正常系と異常系に割れるか**
2. 割れないなら、異常系を検出する別の経路が同じコミットにあるか
3. 表記の揺れ（CR / 空白 / 字下げ / 大小文字）を許容するなら、**抽出側と除去側で対称に許容しているか**
