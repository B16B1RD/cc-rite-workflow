# 「後続ステップで生成するものに検査を適用せよ」を生成地点より前に置くと一度も実行されない

## 概要

散文手順を線形に実行する LLM は、**対象がまだ存在しない地点に置かれた指示**を、対象が生成される地点で思い出さない。「後続ステップ X で生成するものに検査を適用せよ」を X より前のセクションに書くと、実行地点側に導線が無い限り、その指示は**書かれているのに一度も実行されない**。

## 詳細

### 対処

- 検査の指示は**実行地点（生成コードの直前）に置く**。
- 移設できない事情があるなら、**実行地点側にポインタを張る**。
- どちらもできないなら**スコープから外して削除する**。実行されない指示を残すより、範囲を狭めて明示するほうが良い。

### 同型の失敗: フローの制御構造と突き合わせていない

散文手順を新設・修正するときの最大の欠陥源は、手順が実行されるフローの**実際の制御構造**と突き合わせていないことである。文面は単体では正しく読めるのに、フロー上に置くと成立しない形が 3 種類ある。

| 形 | 内容 |
|---|---|
| 分岐で迂回されるステップの値を要求する | 「ステップ N で確定した値を使う」と書いた手順が、N を通らない分岐パスからも参照されている |
| 承認ゲートを跨いで書き換える | 表示 → 承認 → 適用 のフローで、表示後・承認前に本文を書き換える |
| 対象がまだ存在しない地点に指示を置く | 本ページの主題 |

手順を書いたら、**それを参照する全 consumer が本当にその前提ステップを通るかを分岐表まで遡って確認する**。分岐が排他なら、片方だけが通る前提を全体に書いてはいけない。

### 「提示する」と書いたら提示先を持たせる

訂正案を「提示する」と定めた処理が、合流先の経路に質問も出力欄も持たないと dead instruction になる。提示先が無いなら、**既に出力する予定のもの（付記本文など）に載せる形へ設計を変える**。出力を増やさずに要件を満たせる。

### ある行を到達不能にする変更は、その行が唯一持っている情報を移す

「あるコマンドを開始点にしてはならない」と順序を変えたことで、その失敗を条件とする行が死文化した。行自体は無害でも、**その行にしかない訂正案の構築手順と保護文が生きた経路から失われた**。到達不能化は削除と同じなので、行が持つ固有情報の移設まで含めて 1 セットで行う。

### ガードの根拠が自分の別の修正で偽になっていないか確認する

冪等ガードの理由として挙げた経路が、同じ cycle で入れた別の修正によって到達不能になっていた。**根拠が偽のガードは「デッドな指示」と読まれて削除される**ため、ガードは実際に効く経路を根拠にする。修正を入れたら、その修正が他の記述の前提を壊していないかを確認する。
