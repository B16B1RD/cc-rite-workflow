# 停止 marker に現在値を載せると、後段の不変検証がその値を基準に使って自己比較で必ず通る

## 概要

停止分岐の marker に後段検証の基準と同じ名前で現在の値を出すと、基準値が手元に無い状況では実行者がその値を基準として代入し、「変化していないか」の比較が自分自身との比較になって、実際に変化していても検証が成功を返す。

## 詳細

リリース用スキルの復旧手順では、事前確認段が `before_tree=` を出し、最終検証段が「事前確認段の `before_tree=` をリテラル置換して、復旧後のツリーと比較する」と定めていた。取り込み済みの状態で止まる新しい分岐を追加したとき、他の分岐に揃えて停止 marker にも `before_tree=` を載せた。

しかしその停止分岐に到達するのは、back-merge が既に着地した後である。この時点の `before_tree` は back-merge 後のツリーそのもので、検証が必要とする「back-merge 前のツリー」ではない。案内は「復旧前に得た値を使う」と限定していたが、別セッションで作業した場合や文脈が失われた場合、手元に残っているのはこの marker の値だけになる。一般則に従ってそれを代入すると比較は自己比較になり、main 単独の内容でツリーが変わっていても検証は成功を返す。修正前はこの経路が ERROR で止まっていたため、揃えただけの追加が検証の空洞化を新たに作った。

対策は 2 つある。後段で意味を持たない状態では、基準値と同名の値を marker に出さない。あるいは基準値の取得元（merge commit の第 1 親のツリーなど）を定義し、取得できなければ検証を実行せずに止まると明記する。

見分け方: marker に載せる各値について「どの段がこの値を読むか」と「その段が期待する時点の値か」を確かめる。分岐間で出力フィールドを揃えるときは、形の対称性ではなく各分岐に到達した時点の意味で判断する。
