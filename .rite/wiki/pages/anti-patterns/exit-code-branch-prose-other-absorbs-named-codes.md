# 終了コードの分岐を散文で書くと「other」が名指しした値まで取り込む — 兄弟の手順書と同じ表で 0 / 1 / 2 / other を列挙する

## 概要

終了コードの分岐を散文の「rc=2 なら停止、それ以外の非ゼロも停止」と書くと、「それ以外」が別の行で個別に案内している値まで含んでしまい、案内同士が衝突する。兄弟の手順書が表で列挙しているなら同じ表形式に揃え、各行の範囲が互いに重ならないことを構造で保証する。

## 詳細

### 何が起きるか

ヘルパーの終了コードに応じて手順を分ける記述で、兄弟の手順書は 0 / 1 / 2 / other を表で列挙していた。一方の手順書だけが散文で「rc=2 のときは停止する。その他の非ゼロ rc でも停止する」と書き、別の行で rc=1 の復旧案内を書いていた。

表の「other」は表に並んだ値を除いた残りを指す。散文の「その他の非ゼロ」は、その文で名指しした値（rc=2）を除いた残り全部を指す。rc=1 も含まれるため、「rc=1 は復旧案内に従って続ける」と「rc=1 でも停止する」が同じ手順書に並ぶ。読み手のエージェントはどちらに従うかを文面から決められない。

### 検査も一緒に弱くなる

散文の 1 行が 2 つの分岐（rc=2 と実行不能）をまとめて書いていると、行単位で取り出す静的検査は、片方の分岐の停止語だけで両方の条件を満たしてしまう。分岐ごとに行を分けると、検査も分岐ごとに独立する。

停止語を部分一致（`*stop*` のような glob）で探す検査は、否定形（「停止しない」「do not stop」）にも一致する。散文の語句マッチは肯定と否定を区別できない。

### 対処

- 分岐の記述形式を兄弟の手順書と揃え、0 / 1 / 2 / other を互いに重ならない表の行として列挙する。「other」の範囲が表の行から機械的に決まる
- 形式を揃えると、テスト側で散文用に用意していた別パターン（語句マッチ）を削除できる。1 行が 2 つの検査を同時に満たす構造が消える
- 散文で分岐を残す必要がある場合は、「それ以外」の範囲を名指しした値の集合で明示し、個別に案内している値を除外対象として書く

### 見分け方

同じ役割の手順書が複数あり、その一部だけが違う形式で分岐を書いているときは、形式の違いが範囲の違いを生んでいないかを疑う。散文の「それ以外」「other」「any other」が出てきたら、同じ文書の中で個別に扱われている値を列挙し、範囲が重なっていないかを確かめる。

### 表に揃えても行の意味は固定されない

散文を表に揃える修正を「表の行パターンが存在すること」で固定しても、各行の中身（rc=1 の行が停止を含まないこと、catch-all の停止行が rc=1 の行より前に無いこと）は固定されない。rc=1 の行を停止に書き換える変異や、rc=1 の行の前に停止の行を差し込む変異は、形の検査を素通りする。意味を守りたい行は、その行を取り出して禁止語・必須語と行順を検査する。
