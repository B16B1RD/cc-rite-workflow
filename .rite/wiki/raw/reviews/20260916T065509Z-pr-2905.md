### Finding Patterns
- LLM が実行する手順書の fenced bash で判定入力をシェル変数に捕捉するだけで stdout に出さないと、直後の判定表は実行者から観測不能な値で分岐する「入力の無い手順」になる。fix で marker を削るときは「消費者が無いか」だけでなく「次の手順が読む値か」を見る。値は `[CONTEXT] KEY=` marker で emit し、判定表はその marker を表頭に置く。
- 手順書の「設定不正なら skip」は散文だけでは機構にならない。bash block 側で sentinel 値（`<invalid-config>` 等）を立て、判定表に対応行を置いて散文と同じ 1 つの機械条件に揃える。
- cycle 2+ の差分スコープでは、前 cycle に non-blocking として記録された未修正指摘を reviewer が NOT_FIXED として再掲することで最新 JSON に carry-forward される。fatal でない移送分（demotion_reason=non_fatal）は解消検証の対象から外れるため、次 cycle の JSON からは消える。
