### Finding Patterns

本 cycle で最も再現性の高いパターンは **「同一の契約主張が複数ファイルへ複製されており、実装を変えたとき一部だけが更新される drift」**。6 reviewer 中 4 名が独立に同じクラスタを検出した（`references/common-error-handling.md` の canonical jq snippet / `skills/fix/references/assessment-rules.md` / `skills/pr-review/SKILL.md` の 4 箇所）。canonical を名乗る snippet が実装と機械照合されていないことが根本原因で、doc↔code の contract test が無い限り同型の drift は再発する。

第 2 のパターンは **「リファクタで既存の rc 検査・stderr 捕捉が黙って落ちる」**。同一 PR 内で 2 箇所（`cleanup/SKILL.md` 6.0.V の最終射影 jq、`cleanup-follow-up-issue.sh` の jq stderr）が develop にあったガードを失っており、いずれも「失敗が成功と区別できない」方向へ倒れていた。SKILL.md 内 bash はテストの grep assert が唯一の強制層のため、ガードを持つ行はリテラル assert で pin しておかないと落ちても気づけない。

第 3 は **「識別子の安定性に関する前提の取り違え」**。cycle ごとに振り直される連番 id を cycle 跨ぎの identity として畳み込み key に使う実装が入り、別々の指摘が黙って 1 件に潰れていた。この repo では cycle を跨ぐ finding identity は `sha1(file:category:message)` の fingerprint が担う。

その他: 新設したエラー分岐にテストが 1 件も無い（2 箇所）、`x=$(mktemp) || x=""` 形で確保失敗が別の reason へ誤帰属する、非ブロッキング分岐が到達不能化したのに WARNING 文言が残る。
