### Finding Patterns
- bash テストで Markdown の見出し行から fence / 段落を切り出すとき、非 ASCII（日本語）の見出しを `awk -v h=… '$0 == h'` で照合すると、Linux (gawk) では通るが macOS 標準 awk では別の日本語行に一致してまったく違う fence を返す。ASCII 見出しは同じコードで正しく動くため、英日 2 言語の README を並べて pin するテストで日本語側だけが CI の macOS leg で落ちる。見出しは `grep -nxF` で行番号に解決してから awk に整数で渡し、一致数が 1 でなければ即 fail にする。
- レビュー時点で CI が pending だと reviewer は失敗 job を読めず、Linux ローカルの PASS だけで受入条件を充足と判定する。CI 完了後に失敗 job が本 PR の追加テストに対応するなら、その reviewer を CI 状態付きで reroll し `Verification: failing_test` アンカーで blocking にする。CI leg が advisory（`continue-on-error`）でも降格理由にはならない。
- 「read 側は放置、write 側は書く」という二分法で consumer の挙動を文書化すると、helper を呼ぶ hook（post-compact / 親 Issue 同期 / watchdog）が read 側に見えて全称文が偽になる。判別軸は read/write ではなく「現在列の role を先に解決する caller は未マップ列を skip + WARNING、destination の role だけ解決する helper は書く」。
