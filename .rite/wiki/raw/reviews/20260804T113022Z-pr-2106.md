## Review Results

- **PR**: #2106 — docs: 実測必須ゲート導入後に残った「0 findings」未修飾記述を blocking 定義へ修飾する
- **Type**: review
- **Reviewers**: tech-writer (cycle 1, 3), prompt-engineer (cycle 2)

### Finding Patterns

「A を B に修飾する」型の docs 修正で、修飾語を足すたびに別種の不正確さが入った。
cycle 1: 追記した「— see below」に解決先が無く、直下に現れる同名概念が別機構だった
（この PR の目的が「2 種類の非 blocking を取り違えさせない」ことだったため目的と逆行）。
cycle 2: 残留の原因を 1 機構に帰属させたが、実体は 2 経路（gate が降格して移送する分と、
gate 対象外でそのまま残る分）で、正常終了時に実際に残るのは後者だった。

収束したのは、短い箇所では機構名を出さず上位概念（non-blocking findings）で述べ、
機構の内訳は SoT ポインタを持つ 1 箇所にだけ書いた版。結果として文字数も減った。

- **同名概念が近傍に複数あるとき、「see below」型の相対参照は最も近い誤答へ誘導する。**
  既存の解決可能なアンカー idiom が同一ファイルにあるなら必ずそれに揃える
- **「〜されたもの」という原因帰属は、経路が 1 つであることを暗黙に主張する。**
  経路が複数あるなら上位概念で述べるほうが短く、かつ実装変更に強い
- 修飾を N 箇所に展開する作業では、機構の詳細を全箇所に書くと N 箇所の drift site が
  できる。詳細は SoT ポインタを持つ 1 箇所に集約し、他は上位概念で済ませる
