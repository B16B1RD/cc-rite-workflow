### Finding Patterns

cycle 1 で入れた修正そのものが cycle 2 の指摘の 3 分の 2 を生んだ。修正が新しい欠陥面を作る形に 3 つの型があった。

**1. 述語の厳格化は「壊れた入力」と「入力なし」の区別を壊す**

cycle 1 で「散文中の同形文字列を誤検出しない」ために regex へ行アンカー (`^`/`$`) を足したところ、行末 CR・末尾空白・行頭インデントを持つ正規の marker がすべて不一致になり、抽出結果が空 = 「marker 不在 = 正常系」と同一経路へ落ちた。結果、機能の中核保証が WARNING 1 行も出さずに失われる。しかも同じコードのコメントが「厳格な regex で抽出すると『壊れた marker』が『marker 不在』と区別できず破損が無音になる」と自ら禁じていた。

再発防止: **抽出述語を厳格化するときは、「一致しない」の内訳を必ず 2 つに割る** — 「対象が存在しない (正常系)」と「対象らしきものはあるが述語を満たさない (異常系)」。後者を前者に畳むと fail-loud が構造的に成立しなくなる。厳格化の diff と同じコミットで、prefix 検出だけの緩い probe を足して異常系を loud に落とす。

**2. fixture は述語の論理積しか pin しないことがある**

行アンカー `^` と `$` を pin したはずの fixture は、decoy を「行の途中」にしか置いていなかったため、**両方を同時に外す mutation は落とすが、片方だけを外す 4 mutant はすべて生存**した。cycle 1 で「assertion は正しいが fixture が failure mode を再現していない」を学んだ直後に、その学びで追加した fixture 自身が同じ穴を持っていた。

再発防止: **連言の述語を pin するときは、各項を独立に殺す fixture を項の数だけ用意する**。`A ∧ B` に対し 1 つの fixture では `¬A ∧ ¬B` しか検出できない。行アンカーなら「行頭 marker + 後続散文」(`$` を殺す) と「先頭散文 + 行末 marker」(`^` を殺す) の 2 形状が要る。mutation は項ごとに当てる。

**3. read 経路を差し替えたとき落ちる不変条件は 1 つとは限らない**

cycle 1 で「旧経路が URL パスの形で暗黙に保証していた PR スコープ」を補ったが、それは旧経路が持っていた不変条件のうち 1 つに過ぎず、「対象が期待する種類のオブジェクトか (= 記録コメントであること)」という別軸が丸ごと残っていた。旧経路は 3 述語 (author ∧ 見出し前方一致 ∧ 末尾 sentinel) で対象を絞っていたのに、新経路は 2 述語 (author ∧ 所属) しか持たない。

再発防止: **差し替え前の経路が満たしていた述語を列挙してから、新経路で 1 つずつ対応を確認する**。「スコープを補えば済んだ」と早期に打ち切らない。1 件ずつ後から見つかる形になると cycle 数だけ消費する。
