### Finding Patterns
- squash 昇格後の main → develop back-merge は、develop 側でリリース範囲内の行を再編集していると 3-way merge が必ず衝突する。ツリー不変の back-merge は `git merge -s ours` でしか作れず、GitHub PR マージでは生成できない。手順書に「PR 経由のマージコミット」を書く場合は衝突ケースの帰結を明記する必要がある
- `git merge --no-commit` の dry-run では HEAD が動かないため、abort 成否を HEAD 比較で検証しても発火しない。abort の rc と MERGE_HEAD の不在を直接検査する
- `git merge ... >/dev/null 2>&1` で失敗を一律「衝突」と報告すると、dirty tree 等の別原因が消える。stderr は捨てず、`--abort` は MERGE_HEAD がある場合のみ実行する
- 診断コメントで「main 側コミット件数 = 健全性」のように件数を判定材料に書くと、マージコミット昇格を連続した正常形で偽陽性になる
