### Finding Patterns

純粋抽出リファクタ（SKILL.md のインライン bash → helper 3 本）に対する 6 レビュアー並列レビューで、
抽出の忠実性そのものは高い一方、**抽出に付随して混入した契約逸脱と記述の陳腐化**に指摘が集中した。

1. **テストが仕様の逆を固定するクラス**: 抽出中に fail-loud 方向の改善（分類 helper 失敗時の marker 値を
   `none` から `unknown` へ）を入れたが、Issue の「振る舞い不変」MUST に対する逸脱として Decision Log へ
   記録されておらず、新規テストが新挙動を正として assert しているため逸脱がスイートで永久に検出されない。
   純粋抽出 Issue で「改善したくなる silent fallback」を見つけたときは、実装を変える前に契約側
   （Decision Log + AC の例外）を先に更新すると往復が止まる。4 レビュアーのうち 3 者が独立に同じ逸脱を
   認定し、対応方針は全員「revert せず記録」で一致した。

2. **rc 捕捉 idiom の非対称**: `if ! var=$(cmd); then rc=$?` は bash 仕様上 `$?` が常に 0 になる。
   同一 PR 内で呼び出し側（SKILL.md）3 境界は `rc=0; cmd || rc=$?` の正しい形を使い、helper 内部の
   1 境界だけが否定形になっていた。診断が「rc=0 で失敗しました」と自己矛盾し、直後に列挙している
   原因候補（127 / 126 / 2）を切り分けられなくなる。テスト側も `rc=` prefix までしか pin しておらず
   変異が生存した（兄弟テストは `rc=127` を値で pin していた）。

3. **移設に伴うドキュメント所有権の伝播漏れ**: 実体を helper へ移したとき、その実体を名指ししていた
   別ファイルの記述（trap 採用 site 一覧、reason 語彙の emitter 帰属）が古いまま残る。同一 PR が
   一部のファイルでは正しく更新していたため、漏れは「気づいていない」ではなく「網羅していない」形で出た。
   ドキュメント影響調査を新規シンボル名の grep だけで済ませると、この「旧記述への参照」クラスを取りこぼす。

4. **配布物への開発リポジトリ固有番号**: helper 本体からは前サイクルで Issue 番号を除去済みだったが、
   同時に追加したテストファイルのヘッダに残っていた。marketplace 配布物に含まれるディレクトリでは
   説明的な Issue 番号参照は配布先で解決できない。`T-xx` / `AC-x` のような契約アンカーは維持し、
   番号だけを落とすのが正しい切り分け。

5. **消費側配線の網羅性**: 新しい marker 値（`unknown`）を導入したとき、消費側の判定表 6 本のうち
   1 本だけが marker 不在の受け皿を持たず、「実行していないのに完了」と描画されうる穴が残った。
   兄弟 check がすべて marker 不在行を持つという既存の対称性が、漏れを見つける手掛かりになった。
