### Finding Patterns

リリース準備 PR (version bump + CHANGELOG) で 2 cycle 収束。cycle 1 の唯一の blocking 指摘は、CHANGELOG エントリ末尾の括弧内参照番号に **PR 番号を書いてしまった**こと。squash merge 後の `git log --oneline` に現れる末尾番号は PR 番号であり、そこから CHANGELOG エントリを起こすと自動的にこの誤りが入る。本リポジトリの既存慣行 (v0.12.1〜v0.12.3 すべて) と `/release` skill のテンプレート指定 `(#{issue_number})` はいずれも Issue 番号であるため、`gh pr view {n} --json body` の `Closes #N` で PR→Issue を解決してから書く必要がある。

2 reviewer が独立に同一箇所を検出し cross-validation で MEDIUM → HIGH に昇格した。tech-writer は追加で `number-reference-check.sh` が CHANGELOG を number-free surface として `DEFAULT_TARGETS` に列挙している点を指摘し、`/release` テンプレートとの spec-vs-spec 矛盾 (既存違反 322 件) を surface した。canonical SoT 表記のある `/release` skill 側を採用し、矛盾自体は別 Issue へ切り出す判断とした。
