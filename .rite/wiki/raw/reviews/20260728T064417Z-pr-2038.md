### Finding Patterns

本 PR は「gate と、それを検証する pin の設計」そのものを対象にした変更で、レビューの指摘も同じ層に集中した。

1. **件数 pin は配置を拘束しない (CRITICAL)**: `grep -cF '<literal>' <file>` によるファイル全体件数 pin は、対象の文を別スコープへ移動しただけで件数が保たれるため緑のまま通る。「関数 X の内側にこの文が 1 本ある」という不変条件を守りたいなら、区間を awk で解決してから区間内 1 本 / 区間外 0 本を等値 assert する必要がある。本リポジトリでは同一ファイル内の TC-5a / TC-5h が既に「区間解決 + 件数等値」idiom を採用済みで、後から追加された pin だけが旧方式に退行していた。

2. **同型 coupling のうち 1 本だけ pin が抜ける (HIGH)**: 3 者 (生成側 / 削除側 / 検査側) で結合するパス導出式のうち、2 本は「片側から抽出して他方に照合する」pin を持ちながら 3 本目だけ無い、という抜けが起きた。同種の coupling を列挙して網羅を確認する工程が要る。

3. **死に分岐化を検出しない存在検査 pin (HIGH)**: 行頭 anchor なしの部分一致 pin は、対象行に `# ` を付けるだけの死に分岐化を検出できない。同ファイル内で既に「行頭 anchor + fence 到達性追跡」へ移行した pin があるのに、新規追加分だけが旧方式で入った。

4. **markdown 埋め込み bash が実行可能になった時点で「実行テスト不能」の前提が失効する (MEDIUM)**: prose gate に実行可能な bash block を入れたのに、テストは静的 pin のままで、gate の分岐を 1 つも実行していなかった。AC の検証欄が別テストを誤って対応付けており、トレーサビリティの誤マッピングが「検証済み」の外観を作っていた。

5. **非ブロッキング契約と機械強制の分類境界を exit code で引く誤り (HIGH)**: 「caller 契約違反は差し戻す / 外部要因は非ブロッキング」という設計判断を、実装が exit code (trap 設置前後) で近似していたため、trap 設置後に検出される決定論的な caller 契約違反が外部要因と同じ扱いになり gate を素通りした。境界は原因で引く必要がある。

6. **cycle 跨ぎ marker の選択規則を片側にだけ書く (HIGH)**: 同一 gate 節の中で、一方の marker には「複数ある場合は epoch 最大のもの」という選択規則があり、もう一方には無い、という非対称。review-fix loop では会話に前 cycle の marker が残るため、選択規則が無い側は cycle 2 以降で判定が非決定になる。

7. **rationale の「限界」記述が実挙動と逆になる (MEDIUM)**: gate の保証範囲を説明する文書が「degraded に倒れる」と書きながら実装は silent pass する、という食い違い。可視な縮退と無音の pass では運用者の対応が変わるため、保証範囲の記述は実装と等価に保つ必要がある。

8. **単一経路への断定が SoT の多経路定義と矛盾する (MEDIUM)**: 上位仕様書が「この値は X から来る」と単一経路に断定したが、SoT 側は 4 経路を定義しており、しかも名指しされた経路は同じ PR の別契約により当該値を構造的に一度も供給しない、という自己矛盾。

9. **前方一致 + author 条件でも人間起筆コメントは除外できない (MEDIUM)**: `startswith(marker) and (author == me)` は、同一 author が marker で始まる見出しのコメントを書いた場合を除外できない。機械が PATCH で上書きする対象の同定には、人間が書き得ない機械専用 sentinel が要る。
