### Finding Patterns

cycle 2 と同じ構図が続いた — blocking 6 件のうち 5 件が cycle 2 の修正自身に起因する。ただし型は前 cycle と違い、**「pin の観測経路」と「述語の受理集合」に集中している**。

**1. 連言述語を pin するとき、fixture が全 conjunct を同時に false にすると識別力がゼロになる**

「1 行目が marker ∧ 最終非空行が sentinel」の 2 連言を導入し、negative control を 2 本置いたつもりだったが、片方の fixture は marker も sentinel も外し、もう片方は marker あり sentinel 無し — つまり**どちらも 2 つの conjunct を同時に false にしていた**。結果、marker 側 conjunct の削除・`startswith` を `contains` へ弱化・`==` を `contains` へ弱化、の 3 mutant がすべて生存した。

再発防止: **`A ∧ B` を pin する fixture は「A のみ false」「B のみ false」を項の数だけ用意する**。「A も B も false」の fixture は連言全体の削除しか検出できない。位置固定（`startswith` / 最終行の等値）を持つ述語では、さらに「値は含むが位置が違う」形が要る — 前方一致を `contains` へ弱める mutation はそれでしか落ちない。

**2. 「派生した述語」は元の述語と受理集合の関係を明示的に決める**

厳格化した抽出式と対で緩い probe を足したが、probe の受理集合が除去式の受理集合を真に含んだ。差集合の行（行頭が marker 形で末尾に散文が続く行）は、probe が「破損」と判定するのに除去式は削除しない — つまり「破損を検出したのに直せない」状態が生まれ、hint の「張り直します」も偽になった。

再発防止: **同じ対象に対する複数の正規表現は、受理集合の包含関係を先に決めて 1 つの定義から導出する**。「probe ⊇ extract」だけでなく「probe と strip の関係」も決める。定義が別々の文字列リテラルとして並ぶと、片方だけを触った編集で関係が崩れる。

**3. 早期 exit する consumer と `pipefail` の組み合わせが判定を壊す**

`... | sed -n '<probe>' | grep -q .` は、`grep -q` が最初の一致で exit して上流に SIGPIPE を送るため、`set -o pipefail` 下ではパイプライン rc が 141 になる。すると「一致があった」のに `if` が else へ落ちる。入力が小さいと sed が先に書き終わるため発火せず、**入力サイズがバッファ境界を超えた地点で挙動が反転する**。

再発防止: **`set -o pipefail` が有効なスクリプトで `grep -q` / `head` / `tail -1` のような早期 exit consumer をパイプ終端に置かない**。真偽判定なら出力を最後まで読む形（コマンド置換の結果が非空かを見る）にすると SIGPIPE 経路自体が消える。

**4. 静的 pin は「現行表記の denylist」ではなく「意味の allowlist」で書く**

「変数が `local` 宣言に含まれていないこと」を pin したが、bash では `declare` / `typeset` も関数内で同じスコープを作る。表記を変えるだけで pin の両半分を通過したまま欠陥を再導入できた。

再発防止: **静的 pin は禁止したい表記を列挙するのではなく、成立させたい性質を書く**。「関数スコープを作りうるキーワード全体」を対象にするか、より強く「定義位置が関数の外側であること」を行番号比較で固定する。

**5. code comment の rot は「結論は真だが根拠が偽」という形で残る**

関数の docstring が「本文を一切読まずに同定するため安全」と書いていたが、修正で本文を読むようになった。結論（安全である）は別の理由で真のままなので、テストもレビューも素通りしやすい。同じ主張は姉妹ドキュメントでは削除済みで、コード側のコピーだけが取り残された。

再発防止: **機構を変えたら、その機構を根拠として挙げているコメントを grep で洗い出す**。「結論が変わっていない」ことは「根拠が生きている」ことを意味しない。

### 手法として効いたもの

- **reviewer 間の cross-validation が pin の穴に効いた**: 同じ述語の pin 不足を test と security が別の mutation 軸（conjunct 削除 / 位置固定の弱化）で独立に検出した。片方だけなら片側の mutant が残っていた。
- **「空振りしている assert」の検出**: negative control を名乗る TC が、fixture の都合で目的の分岐へ一度も到達していない（assert が常に真）ケースが 2 件見つかった。**negative control は「到達したうえで発火しない」ことを確認しないと意味がない**。
- **転記時のアンカー破損を実測必須ゲートが捕捉した**: reviewer の実測アンカーを統合時に書き写す際 `=>` を落とし、ゲートが `anchor_unparseable` として降格を検出した。ゲートが LLM の転記ミスに対する検出層としても機能している。
