### Finding Patterns
- シェルコマンドの静的解析による拒否ガードでは、bash 側の高速パス（部分文字列による前段フィルタ）が helper の判定集合より狭いと、helper が fail-closed でも全体が fail-open になる。前段フィルタの語彙は helper のディレクトリ変更集合（cd / pushd / popd / env --chdir）と揃える必要がある（4 名が独立に検出）。
- 「git が失敗した」と「リポジトリでない」は git rev-parse の終了コードでは区別できない。.git の有無で区別しないと、判定不能が適用除外に化けて silent fallback になる。
- リテラル代入の追跡は、代入だけのセグメント以外の再代入（if/then 内、export、for、read）を見逃すと古い値で誤判定する。証明できない値は判定不能に倒す。
- 解析予算超過の fail-closed は、対象（git / gh / スクリプト）を含まないコマンドまで止めると AC の MUST NOT に反する。既存 commit-guard-uninspectable と同様に粗い存在検査を前置する。
- スキル fenced bash のコーパステストでプレースホルダを一律チェックアウト内に置き換えると、チェックアウト外を指すプレースホルダのブロックを検出できない。
