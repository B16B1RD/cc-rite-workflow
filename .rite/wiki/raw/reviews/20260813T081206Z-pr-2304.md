### Finding Patterns

本 cycle の blocking 1 件は、**producer 側のリテラルを変えたのに、そのリテラルを字面で pin している consumer 側の契約テストを更新しなかった**という形だった。`assemble.sh` の preset シーン列を `"out/NN.mp4"` から `"$scene_dir/NN.mp4"` へ変えたところ、`check-contract.sh` が awk で assemble.sh を**テキストとして**読んで期待値と等値比較する `full-preset-order` ケースが必ず失敗するようになり、`package.json` の `check` が `&&` 連鎖の第 1 段で死んで決定論チェックまで到達しなくなった。4 レビュアーが独立に同じ file:line へ収束した。実行経路（`-P` 単体の挙動）は完全に不変で、壊れたのは静的 pin のほうだったため、動作確認だけでは検出できない種類の破壊である。

派生パターンとして、**新設した sibling 群がガードの対象集合から漏れる**形も出た。`scenes-en/*.html` 7 本を追加したが `package.json` の決定論スイープ glob は `scenes/*.html` のままで、英語シーンだけが契約ガードの外側に置かれた。DESIGN.md が「契約ガードを 1 組に保つため同一ディレクトリへ置く」と書いた直後に、その主張が実装で成立していない状態になっている。

もう 1 つは、**同じ PR の中で宣言した不変条件を同じ PR の別ファイルが破る**形。DESIGN.md に「レイアウトも 2 本で同一」と書いた一方、`scenes-en/07-closing.html` の `inset` は英語ラベル長を吸収するため JA と異なる値になっていた。誤っていたのは CSS ではなく断定のほうで、Issue の error handling 節が明示的に許容していた調整だった。
