### Finding Patterns

- **negative assertion を足したら positive control も同時に足す**: 「違反が見つからなければ PASS」の検査は、検出器自体が壊れると守っているはずの違反があっても緑になる。本 cycle では検出器を never-match に置換したうえで前 cycle の HIGH 修正を差し戻す二重 mutation で全 TC が緑のままだった。**教訓: negative assertion は必ず「既知の違反 probe を同じ検出コマンドに通して報告されることを確認してから」本スキャンを実行する。典拠にした既存テストが positive control を持っているなら、除外規約だけでなく control も一緒に継承する。**
- **検出器の入力層を pin しないと環境変数で silently 無効化される**: `perl -ne '/[\x{80}-\x{FF}]/'` は `PERLIO=:utf8` / `PERL_UNICODE=SD` があると多バイト文字がクラス外に出て検出しなくなる。`LC_ALL=C awk '/[^ -~]/'` は同じ env でも検出する。**教訓: バイトレベルの検査は入力デコードを明示的に無効化する（`LC_ALL=C` + awk、または `perl -Mbytes`）。検出器を書いたら意図的に壊れた env で走らせて挙動を確認する。**
- **抽出アンカーの非一意性は「アンカー破損を検出する」契約を偽にする**: 閉じアンカー `^esac$` が同一ファイルに 5 箇所あるため、ガードの esac を 1 文字変えるだけで抽出が別ブロックまで膨張し、markdown 散文が bash として実行され他ステップの marker まで emit されたのにテストは緑だった。**教訓: 抽出の閉じアンカーは一意性を確認する。一意にできないなら「抽出結果が想定外の構造（fence terminator 等）を含まないこと」を別途 assert する。**
- **静的検査の grep スコープを判定ブロックに限定する**: ファイル全体を対象にすると、判定を支配する箇所から文を削除してもファイル内のどこかに同じ文字列が残っていれば通る。実際に AND ルール文を「過去の設計では…」という歴史メモへ格下げする mutation が素通りした。**教訓: 契約を pin する grep は、その契約が効力を持つ範囲（判定ブロック）に scope する。**
- **ツール依存を増やすときは可用性プローブを置く**: perl を無プローブで呼ぶと、不在時の rc=127 が「違反あり」分岐に落ち、存在しない欠陥を名指しする誤帰属 FAIL になる。リポジトリの契約（CONTRIBUTING が「timeout か perl のいずれか」と明記）にも反する。**教訓: 新しい外部ツールを使う前に `command -v` で確認し、ツール不在と内容違反の診断を分離する。既存ファイル内で使われているツール（awk 等）で書ければ依存を増やさない。**
- **sandbox fixture は兄弟テストの規約を踏襲する**: `commit.gpgsign false` を設定していないと、gpg 署名を強制している開発者環境で初期 commit が失敗し、前段 TC が偶然 PASS したうえで後段 TC が真因を外した帰属で落ちる。**教訓: 新しい fixture テストを書くときは同ディレクトリの既存テストの setup を読んで揃える。**
- **レビュアーの自己訂正を歓迎する**: security reviewer は前 cycle の「アンカー化により marker 偽造は構造的に不可能」という positive finding を、`git check-ref-format` の実測（`$(...)` / バッククォート等は ref 名として許可される）に基づき「偽造不能なのは literal 注入に限られる」と下方修正した。**教訓: 前 cycle の自分の結論も検証し直す。過大な安全主張は次サイクルの探索を止める点で誤った rationale と同じ害を持つ。**
- **subagent の途中終了は incomplete として明示する**: 5 名中 1 名が API エラーで途中終了した。担当領域が他 reviewer と重複していたため実害は限定的だったが、完了扱いにすると「その観点はレビュー済み」という誤った安心を生む。**教訓: 起動した reviewer の完了状況を報告に明記する。**
