### Finding Patterns
- スキルの fenced bash を scripts/ 配下の helper へ移すと、CI の shellcheck（scripts/ の *.sh を blocking で走査）が新たに対象にする。SKILL.md の中では検査されていなかった既存行（二重引用符内のバッククォートなど）が、移設した瞬間に CI を赤にする。移設前に helper 候補を shellcheck にかけると検出できる。
- 1 ブロック = 1 シェルだった caller を「dispatch + 関数」に移すと、引数検査を dispatch に集めた結果、元はブロック内で `[fix:error]` 等の sentinel を出していた検査より先に usage error（exit 2）で止まるようになる。スキル側にその exit 2 の分岐が無いと、手順に従う実行者がどの分岐にも一致しない状態で止まる。先例（iterate）が持つ「exit 2 は引数を直して再実行」の共通規則を同時に移植する必要がある。
- 移設に合わせてテストの参照先を振り分けるとき、SKILL.md の caller ブロックを実行していたテストを「helper の関数本体を抜き出して直接実行」に置き換えると、dispatch arm から関数への対応が検査されなくなる。dispatch arm を壊す変異が全スイートを素通りした。fake plugin に helper を置いて SKILL.md の 1 行呼び出しをそのまま実行する形にすれば、同じ観測を保てる。
- 共通 reference に「X の各ステップは helper の形を取る」と書くとき、X の一部（references 配下の手順）がまだ未移行なら言い過ぎになる。検査対象を SKILL.md 本体に限った事実と、reference の文言の範囲を揃える。
