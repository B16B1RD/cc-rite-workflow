### Finding Patterns

marker ライフサイクル（生成 → EXIT trap で消費 → 残存検査 gate）で防御層を足す変更に、反復して現れた癖:

1. **caller から full path を受け取る helper は、sibling が内部導出していた保証を失う** — 内部導出 helper に課されていた形状 allowlist と制御文字中和が、full path 受け取りへ設計変更した側へ引き継がれず、機械可読 sentinel へ無加工で埋め込む経路が生まれた。値に改行を入れると sentinel を 2 本出力でき、後段 gate の入力そのものを偽造できる。**同一 phase の sibling helper が既に防いでいる脅威は、設計変更時にチェックリスト化する**
2. **prefix guard を glob `*/prefix-*` で書くと部分文字列一致になり `..` traversal を通す** — guard のコメントが「無関係なパスの削除を防ぐ」と目的を明記していても、実装が basename に anchor していなければ目的を果たさない。`case "${VAR##*/}" in prefix-*)` が正解
3. **テストの期待値に `.*` ワイルドカードを置くと、その位置のフィールドは実質未検証になる** — 「sentinel が出ること」は pin されるが「正しい値を載せていること」は pin されない。値が gate の判定入力そのものである場合、ワイルドカードは検査層の穴と等価。過去に同型の弱化が全 assertion green で生き延びた実績が同ファイルのコメントに記録されていたのに、新設 gate へ教訓が引き継がれなかった
4. **assert に使われない診断変数を置くと「pin 済み」の誤った安心を生む** — 未使用変数は shellcheck の warning 帯で CI の error-only gate を通過するため機械検出されない。直後の if/else が pass/fail を伴うと、読み手には検査が成立して見える
5. **ゲート番号の改番が rationale 退避先へ伝播しない** — 本体が「8.0.5 以降を追加する場合は」へ改番されても、`rationale:` ポインタが指す references 側が「8.0.4 を将来追加する場合」のまま残り、既に追加済みのものを未来形で語る。**改番は本体・references・テストのコメント引用の 3 箇所を同時に見る**
6. **canonical 契約ファイルは双方向に drift する** — 「marker が残るのは trap 設置前の exit 1 のみ」と書いた同じ PR が exit 0 の残存経路を 2 本追加し、しかも PR 自身のテストがその反例を assert していた。逆方向にも、隣接 bullet の語彙（「引数欠落」）が別 helper の 7 種定義と混線して過剰包含を招いた
7. **signal 中断経路は reason emit を持たないと下流の整合性ネットが全て外れる** — marker は消え `saved=false` は出るが失敗 reason が無いため、転記義務も skip 通知の hard fail gate も入力を持たず、存在しないファイルを「保存済み」として提示する経路が成立した
