対象: wiki-ingest ステップ 6 の index 操作を helper へ降ろすリファクタ PR。サイクル 5 のレビューで blocking 6 件 / non-blocking 26 件。4 レビュアーが同一根本 (positional 抽出の短セル行) に独立収束した。

## 観測された指摘のパターン

- **fail-loud ガードは「同じ帰結を持つ全出口」に張る**: 前サイクルで silent 空文字化の 1 出口 (行末区切り欠落 = 捨てフラグメント非空) に exit 1 ガードを入れたが、同じ帰結に至る兄弟出口が 2 本 (セル数不足での早期 return とループ 0 回転) 残っていた。ガードを追加するときは「この関数が異常値を返す経路は他に何本あるか」を出口網羅で洗う。症状 (空文字が返る) 側から遡ると出口が列挙できる。
- **安全網の主張は全経路で成立を確認する**: 「失敗しても後段の lint が拾う」という記述は新規追加経路でしか成立せず、更新経路では登録行が旧値のまま残ってもどの lint 観点にも載らないことが実測で判明。復旧手順や安全網を文書に書くときは、その安全網が発火しない経路を先に探す。
- **marker enum の説明は原因非依存に書く**: 同じ marker 値に複数原因が畳まれている場合、表に単一原因を書くと他原因の発火時に直前の WARNING と矛盾する。原因は WARNING に委ね、表は「読者が次に取る行動」だけを書く。
- **docstring の不変条件は変異テストで pin する**: 「FIRST link のみが同定に使われる」「回収は毎回走る」という docstring 明示の性質に TC が無く、述語を last-link 化する変異・追加経路だけ回収を止める変異が全 green で生存した。文書化した不変条件 1 つにつき最低 1 本の狙い撃ち TC を対応させる。
- **trap は canonical 4 行形 + mktemp 前武装**: EXIT 単独 trap を mktemp 後に武装すると、SIGINT のタイミング次第で exit 0 (成功 marker なし・仕事もしていない) が返る。実測で 12 回中 6 回。exit code を契約にする helper では trap 逸脱が silent no-op に直結する。
