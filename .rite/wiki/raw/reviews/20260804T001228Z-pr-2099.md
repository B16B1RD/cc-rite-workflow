### Finding Patterns

1. **helper 委譲時に「判定不能の理由」が caller で捨てられる**: 判定を bash helper へ移す設計で、helper が stdout に載せた `reason=` を caller (SKILL.md) が 2 フィールドしか sed 抽出せず、残りが構造的にどこにも surface しない。「判定不能なら安全側に不発火」自体は正しい縮退だが、正常系と異常系の marker が byte 一致するため、機構の全面不作動が無観測になる。委譲リファクタでは「判定値」だけでなく「判定できなかった理由」の到達経路も同時に配線すること。

2. **run 境界を「件数の一致」で復元する設計の脆さ**: ファイル名に run 識別子を持たないまま `cycle_count` とファイル総数の比較で run を切り出すと、同一 PR の過去 run が同居した時点でガードが素通りし、境界を跨いだ列を読む。件数ベースの境界復元は「単一 run であることの証明」にならない。証明できないときは判定を降ろす (fail-loud) か、run 開始点を明示 pin する。

3. **counter と永続成果物の非同期が run 単位で恒久化する**: LLM 側の counter を increment してから成果物を生成する順序だと、中断で counter だけが進み、resume 経路に再同期がないと skew がその run の間ずっと残る。counter を新機構の入力にする際は、中断からの復帰で skew が解消するかを設計時に確認する。

4. **決定論テストが「同じ出力か」しか見ないと識別力がゼロになる**: 同一入力 2 回の一致だけを assert すると、実装が無出力になっても PASS する。決定論の assert には「何が決定論的に出るか」の中身固定を必ず併記する。ミューテーション検証 (22 変異) で実測したところ、当該 assert は 1 度も落ちなかった。

5. **役割再定義の文書同期は grep スイープで機械的に洗う**: 「hard limit → backstop」のような役割変更は同義記述が 10 箇所以上に散在する。本 PR では 6 箇所が同期され、同一ファイル内の隣接行を含む 6 箇所が取り残されて新旧が矛盾した。キー名 grep での全出現洗い出しをリリース条件にすると再発が止まる。
