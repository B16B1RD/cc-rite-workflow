1. **「なぜ消したか」の考古学は、消した機構と同じ速度で腐る**: cycle 4 の指摘 9 件のうち 4 件

   経緯説明は、廃止後の読み手には要らない一方で**主張の正しさを検証され続ける負債**になる。
   残すのは現在のコードを読むのに要る 1 文だけにする。

2. **共有 helper の挙動を主張する前に、その helper を実際に走らせる**: cycle 3 の F-32

   C1 を閉じるモードが無い」。**同種の欠陥を修正した commit の中で同種の欠陥を再生産する**のは、
   「主張を書く」動作と「主張を検証する」動作が分離しているために起きる。

3. **交替腕を 1 本落とすときは、その腕だけが救っていた入力を数える**: 記法 2 の診断述語から
   「見出しそのものを名指しする」腕を外したところ、値行が 1 行も無い空セクション
   (テンプレートを途中まで埋めた Issue) で WARNING が完全に消えた。外した理由「見出しは解釈
   できているので是正先にならない」は**値行が存在する場合にしか成り立たない**。腕の削除は
   「その腕が唯一のマッチだった入力クラス」を列挙してから決める。

4. **awk の `exit` は END を実行する — 早期終了と END フォールバックを併用すると二重出力になる**:
   レビュアーが提案したパッチは `f && /^#/ { print h; exit }` と `END { if (f) print h }` を
   併用しており、実測すると正常系で `3\n1` を出す。呼び出し側の数値 guard
   (`case "$v" in ''|*[!0-9]*) : ;;`) が改行込みの値を非数値として飲み込むため、**修正したはずの
   正常系で診断が丸ごと消える**。early-exit と END を併用するなら、print する**全**規則が
   「出力済み」フラグを立てなければならない。

5. **レビュアーの提案パッチは指摘と同じ強度で検証する**: 本 cycle では 2 つの独立した提案が

   合成形が確定した。指摘の実測アンカーは「欠陥が実在すること」を示すが、**suggestion 欄の
   実測は誰もしていない**。統合側 (Critic) が提案パッチを走らせる工程を省くと、次 cycle の fix が
   壊れたパッチを適用して新しい blocking を生む。

7. **awk のデフォルト FS は `\r` を含まない — CRLF 入力で「空行」判定が壊れる**: `f && NF` は
