### Finding Patterns

前 cycle の修正そのものが退行を導入した回で、修正レビューに固有の癖が濃く出た:

1. **入力を狭める guard は、その値を作る側の alphabet と突き合わせないと wedge を作る** — 「危険な入力を弾く」allowlist を消費側だけに足すと、生成側が正当に作れる値まで拒否する。しかも拒否の帰結が「消さない」= gate の残存判定と噛み合うと、**成功しているのに永久に失敗と判定される**非収束ループになる。防御を足すときは (a) 生成側の値域、(b) 拒否時の帰結が既存 gate とどう合成されるか、の 2 点を必ず確認する
2. **full path を caller から受け取る helper は、内部導出する sibling が構造的に持っていた免疫を失う** — sibling が「path を内部で組み立てる」設計なら形状不一致というクラス自体が存在しない。full path 受け取りへ変えた時点で guard・中和・errno 退避が芋づるで必要になる。**インタフェースを sibling に揃える方が、guard を足すより小さい**
3. **signal handler は「何が完了済みか」を見ずに失敗を宣言してはならない** — 中断は「失敗」ではなく「未完了かもしれない」。完了フラグを見ずに一律 failure reason を出すと、成功済みの処理を下流が失敗として扱う。sibling が「未投稿と断定しない」と明示設計していたのはこのため
4. **1 箇所の語彙を増やすと、それを数える全箇所が同時に腐る** — reason を 1 つ足しただけで「14 種」と書いた 5 箇所が一斉に stale 化した。件数を書かない表現（「既存語彙を増やさない」）にしておくと以後の増減で腐らない
5. **禁止句の除去は「番号を消す」ではなく「現在形の制約散文へ書き換える」** — 番号だけ消しても過去イベントの叙述（「先行 PR では〜だった」）は違反として残る。主語を機構側に移して現在形で書く。加えて lint が裸の `#NNNN` を拾わないため、lint clean は完了の証明にならない
6. **テスト fixture が安全側に偏っていると、その経路は構造的に検出できない** — 全 fixture が `mktemp -d` 由来だったため、空白や非 ASCII を含む path での wedge は 474 assertion 全 green のまま素通りした。guard を足したら**弾かれる側の正当な入力**も fixture に入れる
7. **guard の各条件を独立に pin するには、条件ごとに「その条件だけが判定を決める」fixture が要る** — 3 条件を 1 つの fixture で試すと、どれを弱化しても他の条件が拾ってしまい変異が検出できない。条件 N を pin する fixture は条件 N 以外をすべて通過する形にする
