### Review Patterns

**静的 pin は「いくつあるか」ではなく「どこにあるか」で書く。** 本 run の blocking 3 件（cycle 4）はすべてこの一形で、いずれも mutation で実証された。ファイル全体の `grep -c` == N は、要素を**移動・複製する**変異に対して盲目になる。実測された 3 つの生存変異はすべて「総数は変わらないが帰属が変わる」形だった:

- 2 テンプレに 1 本ずつ → verification 側を削って full 側へ複製（総数 2 のまま）
- 指示節 + 出力フォーマットに同じ literal → 指示節だけ削除（残り 1 本で条件成立）
- 同じ marker が複数箇所 → 検出対象の 1 箇所だけ削除

処方も一形で、区間を切ってから数える。同ファイルに既に `_section_of` idiom があったのに新規 pin だけが継承していなかった — **既存の硬化済み idiom を探してから新しい pin を書く**。

**契約を守る唯一の防壁が pin なら、その pin 自身を変異で検査する。** 「テストが green」は「契約が守られている」ではなく「今の実装がテストを通る」でしかない。契約対応の pin は、契約を壊す変異を隔離コピーで当てて初めて有効性が確かめられる。本 run では実装側とレビュアー側が独立に同じ 3 変異を実行し、修正前は素通り・修正後は捕捉を双方が実測した。

**区間の終端はレベル述語で書く（特定の次節へハードコードしない）。** 終端に `^## 変更概要` のような具体名を置くと、その手前に新節が挿入されたとき区間が新節を飲み込んで vacuous に pass する。同レベル以上の見出しで閉じる述語なら挿入に耐える。この教訓は同ファイルのコメントに既に書かれていたが、新規 pin 3 本のうち 2 本が踏襲していなかった（cycle 5 の non-blocking として記録し follow-up へ）。

**「開示」は「識別」ではない。** 決定論的に組まれたパスを marker に併記しても、健全な状態と stale な状態で同じ文字列が出るなら、それは残余の緩和にならない。開示が診断価値を持つのは、開示される値が状態によって**変わる**ときだけ。緩和策を書いたら「この値は問題が起きているときと起きていないときで違う値になるか」を確かめる。
