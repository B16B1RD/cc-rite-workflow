### Finding Patterns

前 cycle の 4 指摘は全て解消（devops・security が実測で確認、指摘 0 件）。一方、**修正そのものが新しい同型の問題を生む**パターンが cycle をまたいで反復したため、経験則として記録する。

1. **「防御を書いた PR が、同じ PR 内で自分の防御に引っかかる反例を作る」**（F-02、MEDIUM、実測再現済み）
   `run-tests.sh` の skip 会計は「診断文が `SKIP: N` に見えるのを防ぐため、サマリ行に anchor する」とコメントで明言している。ところが同じ PR が新設した `_test-helpers.test.sh` TC-15.1 の**失敗診断**が `print_summary` の生出力を改行込みで echo するため、`SKIP: 2` が行頭に着地して自分の parser に食われる。結果、テストが 1 件落ちただけなのに「summary format drift」という誤った原因が表示され、skip 総数も 0 件が 2 件と表示される。
   → **規則: parser を書いたら、同じ PR 内で「その parser の入力になりうる文字列を出力する箇所」を grep する。** 特に「変数の生出力を診断に埋める」箇所は改行を潰す（`tr '\n' '|'`）のが安全。

2. **「却下理由が、採用した案にも等しく当てはまる」**（F-03、MEDIUM、3 レビュアーが独立に検出）
   `| tee` を却下した理由として「背景プロセスが残っているとパイプが EOF を待ち続ける」と書いたが、採用した `$(...)` も同じくパイプを張るため同一の性質を持つ。実測すると direct（変更前、fd 直接継承）= 0 秒、`$( )` = 6 秒、`tee` = 6 秒で、**変更前が唯一ハングしない形だった**。コメントは逆の安心を与え、将来ランナーが停止したときの調査を誤誘導する。
   → **規則: 「A を却下して B を採用した」と書くときは、却下理由が B に当てはまらないことを実測で確認する。** 当てはまるなら、それは differentiator ではないので理由から外す。

3. **「新しい規約が、その規約を強制する機構より弱く書かれている」**（F-01、HIGH）
   CONTRIBUTING の手順 6 は「skip を使え、bare echo は禁止」とだけ書くが、実装した契約は「⏭️ 数とサマリ件数が一致しないと**スイート全体が exit 1**」であり、件数抽出は厳密に 2 形のみ。この 2 点（サマリ行の形が load-bearing、制裁がファイル局所でなく全体）が未文書。in-tree には `print_summary` を使わないテストが 48 本、うち 25 本は "skipped" 文字列を持たず、そこへ手順どおり `skip` を足すと blocking gate が落ちる。さらに実際のアンチパターンは bare `echo` ではなく `pass "... skipped"`（PASS を水増ししたうえで突き合わせも素通りする）で、こちらが規則の対象外のまま。
   → **規則: 機械的な制裁を伴う規約を文書化するときは「何をすると落ちるか」「落ちる範囲はどこか」を必ず書く。** 禁止事項を列挙するときは、実際にリポジトリで見つかるアンチパターンを grep してから書く。

4. **「同じ PR で追加した 2 つの記述が矛盾する」**（F-04、MEDIUM、2 レビュアーが独立に検出）
   「blocking gate がどちらの leg かは ci.yml が宣言するので、この規則は入れ替わっても生き残る」と書いた段落と、「a shadowed or missing tool **on Linux** must not silently drop coverage」と Linux を名指しした手順 6 が、同一ブロック内で共存している。実装は後者（floor 6 箇所すべて `[ -d /proc ]`）。
   → **規則: 「SoT を参照するので将来も有効」と書いたら、同じ文書内の他の記述がその抽象を破っていないか grep で確認する。**

5. **「緑/赤を決める機構自身にテストがない」**（F-05、MEDIUM）
   この PR は「テスト基盤自体をテストする」方針を採り、`_timeout` に専用テスト、`skip()` の計数に TC-15 を新設した。その論拠は「壊れると緑が嘘になる」。ランナーの集計（skip パーサ 2 形式・marker 突合・bail 順序・終端 exit code、約 90 行）はまさに同じ性質を持つが、駆動するテストが 1 件も無い。
   → **規則: 「これが壊れると緑が嘘になる」という論拠でテストを新設したら、同じ論拠が当てはまる他のコンポーネントを列挙する。** ランナーは fixture ディレクトリへコピーして駆動できる（再帰しない）。
