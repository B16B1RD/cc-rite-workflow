### Finding Patterns

**「カーネル内解決をシェル文字列処理へ移す」書き換えは、パス表現のバイト保存という新しい不変条件を生む**（HIGH、実測で退行確認）。`realpath` を `readlink` + 既存の物理解決 walk への委譲に置き換えた結果、コマンド置換が末尾 LF を全除去する性質により「hook が評価するパス」と「カーネルが辿るパス」が乖離し、セキュリティガードが allow に倒れた。移植性のために外部コマンドを別のものへ差し替えるとき、解決のセマンティクスだけでなく **値の受け渡し経路（コマンド置換 / パラメータ展開）が持つ暗黙の正規化**まで比較する必要がある。`$(cmd)` は末尾改行を全除去し、`$(dirname X)` も同様。バイト厳密に受け取るには sentinel 方式（`$(cmd && printf 'X')` → `${v%X}`）を使う。

**mutation test が「新規に導入した分岐」を狙って初めてカバレッジ欠落が見える**（HIGH + MEDIUM）。テストスイートが 36 passed / 0 failed で green でも、本 PR が新設した 2 分岐（相対 target の絶対化、hop cap）はどちらも mutation が生存した。新規実装分岐ごとに「潰しても green のままか」を確認する mutation を回すことが、追加 TC の非 vacuous 性検証と対で必要。

**skip ガードを撤去するときは、撤去した floor が守っていた対象と、新設した skip 分岐が晒す対象を区別する**（MEDIUM）。本 PR は「platform gap 解消により無条件実行になった TC 群」の floor を正しく撤去したが、同時に新設した capability ゲート（`command -v realpath` 不在時 skip）には floor を付けなかった。撤去と新設が同一 PR 内で起きると、規約（blocking gate では security TC を silent skip させない）からの後退が見えにくくなる。

**reviewer 間の矛盾は「revert test を実測したか」で決着する**。同一現象（コマンド置換の LF 除去）について security reviewer は「本 PR 由来の退行」、test reviewer は「旧実装も同性質だから既存」と結論が割れた。orchestrator が origin/develop 版と PR HEAD 版に同一入力を投入して直接比較したところ、control が両方 deny になる健全なハーネス上で 3 形すべて OLD=deny / NEW=allow となり、本 PR 由来と確定した。分析ベースの帰属判断より実測の revert test が優先する。
