### Finding Patterns
- bash テストの EXIT trap が rm -rf に渡す変数を command substitution の入れ子（cd と mktemp）で初期化すると、mktemp の失敗が握りつぶされて cwd を削除しうる。兄弟テストは 2 ステップで回避済みなので、新規テストでも同形にする（security と error-handling が同根として指摘）
- テストの前提ガードが return 1 だけだと、set -e 下で出力なしに終了し、CI の失敗サマリが原因を拾えない。ガードにも ERROR を出す（code-quality と error-handling が指摘）
- CI 設定の静的検査（grep ベース）は、matrix 行と continue-on-error の不在だけでは両 OS の leg が実際に走ることを守れない。runs-on が matrix.os であることと job 直下の if が無いことも pin する（test が変異実験で確認）
- 到達不能な分岐の assert（marker 不在の fixture で警告が出ないことを確認）は検証力ゼロで誤った安心を与える。警告を検証するなら 2 回起動して 1 回目の marker を 2 回目の既存 marker にする（test が実測、devops と tech-writer も同旨）
