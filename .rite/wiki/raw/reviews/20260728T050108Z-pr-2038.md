### Finding Patterns

同一 PR の最終 cycle で実装のデータ構造を拡張したとき、その拡張手順を謳うドキュメント側 (SKILL.md の「将来 gate を追加する手順」と rationale ファイル) が追随せず drift する、というパターンが 2 名のレビュアーから独立に検出された。位置依存の区切り文字列 (`見出し:データ行数:pass 行数:ERROR 行数`) はフィールドを 1 本足すたびに参照箇所すべてへ伝播が要るため、この drift を構造的に招きやすい。key=value 形式にすれば書き落としを `${...:-}` で loud に検出できる。

静的 pin の品質については、先行 PR が作り込んだ 4 つの failure mode (tautology / pin コメントの過大表明 / `-ge N` 下限判定 / 存在検査のみで到達性を見ない) がいずれも再発していないことを、テストレビュアーが 21 件の mutation 実測で確認した。「pin を追加した PR 本文に mutation matrix を残す」運用が有効に機能している。一方、prose gate の `**On ERROR**` ブロック自体は pin されておらず、削除しても全テストが緑のまま通る (参照と被参照の非対称)。

bash helper の非ブロッキング契約は、`|| true` を 0 箇所に保ち全失敗経路で `[CONTEXT] *_FAILED=1; reason=...` を emit する形で実装されており、「失敗しても止めない」と「失敗を無音にする」の区別が守られていた。EXIT trap の terminal sentinel + `outcome` 初期値 `aborted` により、早期終了が success を騙れない構造になっている。

PR コメントの update-in-place では、`startswith` による 1 行目 marker 前方一致に加えて author 条件 (`.user.login == $me`) を連言することで PATCH 先の乗っ取りを防ぐ設計が有効。同型の lookup が `issue-comment-wm-sync.sh` では `contains` かつ author 条件なしで残っており、横展開の余地がある。
