### Finding Patterns

新規 bash helper (431 行) + test suite (601 行) + 横断的な skill/docs 同期という構成の PR で、
判定ロジック本体はレビュアーの実測 (backtest 7 本の再現、19-30 変異の mutation testing) で堅牢と確認された。
指摘が集中したのは判定ロジックではなく「契約文言」と「診断サーフェス」の 2 領域:

1. **新機構導入時の意味論の伝播漏れ (最頻)**: ブレーカーの意味論を「cycle 上限が唯一の安全網」から
   「発散検出が主 / 上限は backstop」へ変える PR で、10 箇所以上の対称位置は同期されたが、
   停止通知の「もう N cycle 回る」(2 reviewer 独立検出)、Placeholder Legend の判別子、
   中断経路の等価列挙、marker 意味表の「前 2 者」が旧前提のまま残った。
   Asymmetric Fix Transcription の典型で、**新旧の意味論が同一ファイル内で数行しか離れずに共存する**
   のが本 PR 固有の形。

2. **「格下げ」の断定が既定値の据え置きと両立しない**: 「滅多に発火しない純粋な保険」と書きながら
   既定値 5 を据え置いたため、PR 自身が「保護対象」と名指しした実測列がその backstop に殺される。
   役割を再定義する PR では、**再定義の断定文とパラメータの実値を同時に検証する**必要がある。

3. **signal trap の canonical 形からの逸脱**: `trap '...' EXIT INT TERM HUP` の 1 行形は
   INT/TERM/HUP の action に `exit` を持たないため bash が signal を consume し、
   スクリプトが継続実行して exit 0 で終わる。実測では Ctrl-C が in-flight の jq を殺し、
   **valid な入力に対して偽の異常 reason を報告**した。sibling helper (review-measured-gate.sh /
   review-result-save.sh) は 4 trap 形 + signal_aborted reason を持つ。
   「reason を必ず出す」設計は、この経路では「間違った reason を出す」に反転する。

4. **診断行の出力順序の非対称**: 診断転記を WARNING より先に出すと、直前の別 WARNING の
   継続行位置に着地して原因が誤帰属する。sibling は「WARNING → インデント診断」の順。

5. **テスト assertion の identification power**: 「原因行が届くこと」を pin すると称する grep が
   隣の assertion が pin 済みの文字列の部分文字列でしかなく、守ると称する変異を通す (dead assertion)。
   また PR の最新コミットの主題 (jq 診断の抑止解除) が 1 件も exercise されておらず、
   当該関数を no-op にしても全 assertion が緑のまま。
   **mutation testing は判定式には効いていたが、診断サーフェスには適用されていなかった**。

6. **コメント品質**: review-fix loop 自身の履歴 (finding ID `F-06`、`cycle 4`、同 PR 内で削除された
   識別子への「旧実装」参照) が製品コード・テストコードに焼き付く。マージ後に参照先を失う。
