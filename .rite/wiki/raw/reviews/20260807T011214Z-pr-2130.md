### Finding Patterns

cycle 1 で blocking 7 件 / non-blocking 7 件。指摘の重心は「新設 gate の degraded 境界」に集中した。

1. **degraded 境界の不一致（3 reviewer が独立検出）**: Issue が定めた degraded 条件は「解決できない / 読めない」だが、実装は「解決できない」側しか degraded に倒さず、「results dir は存在するが読めない（permission）」が fail に落ちた。しかも fail の差し戻し先を何度実行しても permission は解消しないため非収束ループになる。helper 自身の docstring が「置換漏れを fail にすると非収束になるので degraded に倒す」と書いているのと正面から非対称であり、**同一ファイル内で自ら宣言した論拠を別経路に適用し忘れる**形の伝播漏れ。

2. **新設 gate を `case` の 1 arm にだけ置くと、守るべき Given がその arm に来ない**: positive 検査を marker 検査の `*)` arm 内に置いたため、Issue の AC が名指しする「marker が一度も設置されていない」状態（marker 値が空文字 / placeholder）では新 gate が一度も走らない。positive 検査の入力は marker に一切依存しないのに、marker 層の分岐に従属させたことで判定できるのに降ろしていた。**「gate を守る対象の内側に置くな」の変種で、今回は「独立な判定を従属分岐の内側に置くな」**。

3. **等値比較を load-bearing にしたら両辺の形式を固定する**: 40 桁 SHA と JSON の `commit_sha` を厳密一致で比較して不一致を blocking にしたが、schema の正典例は 7 桁短縮であり、書き手側に形状検査も値源の指示も無かった。**新しく等値判定を導入するときは、比較する両辺の生成規約が同一の形式を保証しているかを先に確認する**。

4. **production の呼び出し形をテストが一度も通らない**: helper のテストは全 leg で `--results-dir` / `--since` を明示していたが、本番の呼び出しはどちらも渡さない。結果、既定解決経路（run pin の読み取り）を壊す変異が無検出で通った。**parameterized 表面を網羅しても、production が実際に使う唯一の引数形を通らなければ配線は pin されていない**。

5. **診断出力に外部由来の値を無改行化せず埋めると、自分のテストが pin した不変条件が破れる**: `[CONTEXT]` marker を機械契約として使う設計では、走査対象の値に改行が入ると桁 0 に marker 行を偽造できる。同リポジトリには制御文字中和の canonical helper があるのに新規 helper がそれを通していなかった。
