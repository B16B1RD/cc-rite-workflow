### Finding Patterns

**prose 依存 gate は実運用で守られない**。本 PR が構築中の post-condition gate 群 (8.0.1/8.0.2/8.0.3) は LLM が ERROR text を読んで自主的に差し戻す設計だが、同 PR 自身の 14 review cycle を実測すると、記録が実際に PR へ届いたのは 1 cycle だけだった (残り 13 cycle は non_blocking_findings を 1 件以上持ちながら記録コメントが作成も更新もされていない)。gate が「守る対象の外」に置かれていても、強制手段が prose である限り遵守率は保証されない。機械強制 (pending marker の touch/rm + 非ゼロ終了) へ移す必要がある。

**pin の被覆は「本数」ではなく「軸」で確認する**。Routing 表の 4 行のうち 2 行だけを canonical 完全一致で固定し、残りは行数の等値でしか守っていないケースが見つかった。行数 pin は Action 列を変えずに Condition 列だけを書き換える編集を一切検出しない。同様に、双方向の等値比較を片方向の fixture だけで pin すると前方一致への退行が無検出になる。「この軸の唯一の pin」とコメントに書いた箇所ほど、その軸が本当に両方向を覆っているかを実測で確かめるべき。

**テスト用 helper の正規表現は `awk -v` を通さない**。`awk -v re='^### 8\.0 '` はバックスラッシュを awk 側が解釈するため、警告が出るうえに実際のアンカーが弱まる (`\.` → 任意 1 文字)。区間解決 helper のように多数の pin が土台にする関数でこれをやると、pin 群全体が見た目より弱くなる。`ENVIRON[...]` 経由で渡すのが安全。

**レビュー由来の帰属タグを in-source コメントに残さない**。`(F-01, cycle 4 review, error-handling-reviewer)` のような接頭辞は該当 review run が閉じた時点で解読不能になる。WHY 散文は残し帰属だけを削る。経緯の受け皿は commit message / PR description。

**設定リファレンスは SoT の best-effort 性を落とさない**。「必ず投稿される」と読める記述は、投稿失敗 5 経路を持つ実装と食い違い、ユーザーに取りこぼしを生む。
