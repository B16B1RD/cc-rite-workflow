### Finding Patterns

cycle 3 の 14 件を修正した結果、11 件の新規指摘。件数は横ばいだが、内訳は「同一 bullet / 同一行内の後続文の未追随」と「新設契約の無 pin」に収斂した。

1. **同一 bullet・同一行の後続文が最も漏れやすい**: 4 レビュアーが独立に同じ箇所を指摘した。前半だけを新契約へ書き換え、直後の 2 文が旧契約のまま残って自己矛盾する。しかもそれが operator 向けの remediation 文だったため、「永続する手当て」を明示的に否定して「非永続な手当て」を勧める状態になっていた。**書き換える単位は「文」ではなく「その主張が閉じる範囲（bullet / 段落）」**。

2. **新設した契約は既存の pin 機構から構造的に外れる**: 前 cycle で pin 語句を壊して CI を赤にした反省から文言を復元したが、同じ表に**新しく足した行**には pin が無い。削除しても全 111 テストが緑のまま通ることが変異注入で実測された。「唯一の下流検出器」と自称する行が無 pin という非対称。**pin されている表に行を足すときは、その行の pin も同時に足す**。

3. **限定を足すと、その限定が掛かってはいけない入力にも掛かる**: 冪等化のため「直前が `\` でない生のパイプのみ」という限定を足したが、これは保持値経路にだけ必要な限定で、frontmatter 由来の生値にも掛かってしまった。結果、前 cycle では列崩れとして loud に露見していた壊れ方が silent 化した。**限定句は「どの入力に掛かるか」をスコープと一緒に書く**。

4. **カウンタを新設したら「定義・実行地点・表示・等式」の 4 点セット**: 前 cycle でカウンタ表・内訳・等式の 3 点に配線したが、**実行地点（中止時の報告手順）に加算指示が無かった**。しかもその手順は加算対象を明示列挙していたため、列挙が網羅的に読めて新カウンタは加算されない解釈になる。等式直後の説明文も未追随で、記述どおりに自己検算すると新カウンタ分を「訂正」して落とす。

5. **サイクル単位のセマンティクスを per-item ループに置かない**: 統計同期は「全 Raw Source 処理後の状態」を前提にしているのに per-source ループ本体に置かれており、N 件あると N 回走って guard が評価不能・カウンタが N 倍・レポート行が N 行並ぶ。同一ファイルに先例（push を全 source 後の 1 回へ集約）があった。

6. **成功経路に marker が無いと「成功」と「未実行」が区別できない**: 中止経路にだけ marker を出す設計にしたため、marker 不在が両義的になった。同じ表の push 側は marker 不在を「⚠️ 未確認」として扱っており、同一表内で非対称。
