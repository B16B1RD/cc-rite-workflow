### Finding Patterns

新設 bash helper + skill 定義変更の PR で、6 レビュアーが独立に同一の欠陥クラスへ収束した。

1. **enum 外の値を `case ... *)` で無言 continue する分岐が gate 自体を迂回させる**。値の生成者が LLM で、enum が散文 1 箇所にしか無く閉じた列挙として宣言されていないとき、表記ゆれ 1 つで検証機構全体を素通りできる。同じ帰結（対象が検証されない）を持つ兄弟出口が fail-loud している一方、この出口だけが無音という非対称が目印になる。3 レビュアーが独立に同一箇所を指摘した。

2. **`git diff` の出力形状を前提にしたパーサは、git の設定と変更種別で黙って空振りする**。`+++ b/<path>` の literal prefix 一致だけを入口にすると、(a) `core.quotePath=true`（既定）下の非 ASCII パスは引用符 + 8 進エスケープになり一致しない、(b) pure rename（similarity index 100%）は `+++` 行を 1 つも出さない、(c) `diff.noprefix=true` では prefix が消える。いずれも「判定不能」が「未対応」に化ける silent degradation になる。同リポジトリの先行パーサ（number-reference-check.sh）は unquote と条件付き prefix 剥がしを既に持っており、新規パーサがそれを継承しないと同じ穴を再生産する。

3. **ファイル単位の一致判定は、1 ファイル内で削除と追加が混在する変更で恒久的な偽陰性を生む**。「削除のみは通す」を「そのファイルが + hunk を 1 つも持たない」で実装すると、散文削除と追記が同時に起きる典型変更で削除側の修正が永久に検証されない。判定単位は hunk へ下げる。

4. **AC の `Then` が 2 節から成るとき、第 1 節だけが pin され第 2 節が抜ける**。helper の marker / JSON（第 1 節）は手厚くテストされる一方、それを消費する側の契約（件数除外・記号付与・sentinel 昇格）が未 pin のまま残る。同一 PR で 4 件が同型で発生した。加えて静的 pin の `grep` を section 限定にしないと、同じ literal が別節に増えた時点で assertion が名乗った対象を検証しなくなる（本 PR で実際に 1 件が空振り状態に到達していた）。

5. **LLM 生成 JSON を `--argjson '...'` の single-quote 内へ直接埋め込むと、値中のアポストロフィで引用が閉じて bash 構文エラーになり、任意コマンド実行にも到達する**。同一ファイル内に mktemp + HEREDOC + `jq --rawfile` の安全パターンが既に確立されていても、新規追記がそれを継承しない形で入りうる。
