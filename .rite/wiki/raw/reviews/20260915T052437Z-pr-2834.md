### Finding Patterns
- helper の出力契約（reason 語彙・成功 marker の suffix・除外入力源）を手順書へ書き写す同期 PR は、reason 列挙を helper docstring の Reason SoT と突き合わせて過不足 0 を確認すれば blocking 指摘が出ない（3 reviewer とも 19 種一致を独立に確認）。
- 手順書の文言を固定する static assert は、base 側の手順書に同じ条件式を当てて全件が不成立になることを確認すると tautology でないことを示せる（mutation worktree と base 評価の 2 経路で一致）。
- 推奨として残ったのは assert の精度（source の代入文照合、not-triggered 側の実行時 pin 欠落、配置の未区別）と、観測専用 marker の限定句不足。いずれも検出網・文書整合の粒度で、実行時挙動は変わらない。
