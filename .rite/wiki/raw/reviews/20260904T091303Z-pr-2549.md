### Finding Patterns

**新設ゲートが同一ファイル内の確立済み規約から外れる**: 検出文法を外部 helper へ委譲し、混入防止のゲートを書き込み側（wiki-ingest）へ新設した PR で、そのゲートだけが同じスキル内の姉妹サイトが例外なく持つ安全規約を欠いた。欠けたのは (1) placeholder-residue gate（他 3 サイトは helper 不在を ERROR + exit 1、新設サイトのみ WARNING + 続行）、(2) quoted heredoc の終端子衝突ゲート（既存 heredoc には「実行前ゲート（必須）」が明記されている）、(3) 呼び出し元からの marker 読み取り（commit ステップは散文で新ゲートを名指しするだけで、marker を読む機械的 gate を持たない）。いずれも「新しい機構を足すとき、同型サイトが何を持っているかを先に数えていない」ことから生じる。

**ゲートの anchor を強制される側が渡すと自己無効化する**: 委譲先 `--label` はパス除外判定にも使われるため、呼び出し側（LLM）が raw のパスを label に渡すと内容に番号があっても無条件 clean が返る。ゲートの判定基準を、ゲートされる側が選べる値に取った形。

**検出網の変更に追随しない negative assertion**: 診断値の arity を 4→3 に変えた際、肯定 assertion は追随したが `assert_not_grep '4 値を返しませんでした'` が残り、到達不能文字列を検査する恒久的に緑の assertion へ退化した。3 名の reviewer が独立に検出。

**mutation test の vacuity ガードを前処理が無効化する**: mutant に共通の後処理（委譲先の絶対パス固定）を `assert_mutant_changed` より前に適用すると、本来の変異が 1 文字も適用されなくても mutant は原本と異なるため「変異セレクタが何にも一致しなかった」を検出できなくなる。

**除外撤廃の同期は enum 説明文に取り残される**: 検出範囲を広げた際、検出カテゴリ表・カウンタ表・完了レポート・SPEC は更新されたが、`read_ok` enum の説明文の括弧内に旧除外が 1 箇所残った。同一文言を持つ SPEC 側は更新済みだったことが、意図的据え置きでなく同期漏れである証拠になった。

**変更動機散文への退行**: 番号を消して Why を残す作業の rationale 自体が「委譲で変わったことは 3 点ある」「E2 は撤廃した」という変更イベントを主語にした文体になり、「番号の代わりに経緯を書かない」規約と衝突した。内容（実測値・却下理由）は残すべきもので、余分なのは変更ナラティブの外皮だけ。
