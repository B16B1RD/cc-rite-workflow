### Finding Patterns
- resume 後の入口（batch-run 再開段階・pr-review E2E 判定・Stop の watchdog）の判定を揃えるとき、稼働中の失敗処理（`[ready:error]` → ステップ 8）と再起動時の再開（`ready_error` → ready 再試行）は別々の契約なので、同じ phase でも続行先が違ってよい。受入条件に「一致」を書くときは対象 phase を列挙して、この種の意図的な差を外しておく
- exit 0 の SessionStart hook の stderr はデバッグログにしか残らない。ユーザーやモデルに行動を促す失敗通知は stdout にも出す必要がある
- レビューの途中で受入条件を改訂したら、受入条件確認の reviewer だけを改訂後の本文で再実行すると、改訂で増えた要求（stdout 通知）が同じ cycle で blocking として拾える
- state に一時的な印を足す設計では、印を消す経路（set の再構築、deactivate、reap-issue）を全部列挙してテストで固定すると、mutation で主要な変異がすべて検出された
