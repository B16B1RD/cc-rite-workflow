### Finding Patterns

- **同一箇所への 2 サイクル連続指摘 (finding cycling) は「書き直し」ではなく「削除」の合図**: 実行時に消費されない rationale 散文が、call site の実態について全称・唯一性の主張をすると、書き換えても別の主張が偽になって再指摘される。cycle 1 で「3 主張のうち 2 つが偽」→ 書き換え → cycle 2 で「なお 2 つが偽」という循環が実測された。2 reviewer が独立に「削除」を推奨した。散文の主張を書くたびに全 call site を Grep で列挙する運用コストより、主張自体を持たない構造のほうが安い。
- **観測性を足す修正は、それ自体が 3 種類の新規指摘面を作る**: cycle 1 で「縮退が沈黙する」に対し WARNING を 1 本足したところ、cycle 2 で (a) 発火条件が広すぎて成功時にも出る false positive、(b) その WARNING を pin するテストが無い、(c) call site の `2>/dev/null` で破棄され届かない、の 3 件が出た。WARNING を足すときは「発火条件が縮退のケースだけに一致するか」「テストで pin するか」「その stderr が実際に届く経路か」を同時に決める。
- **同一 PR 内でテストと WARNING が矛盾しうる**: corrupt 判定でも carry-forward が成功する経路をテストで固定しながら、同じ経路で「縮退しました」と WARNING を出していた。テストが正常と宣言する動作に対して警告を出していないか、追加した warning のたびに既存 TC の fixture と突き合わせる。
