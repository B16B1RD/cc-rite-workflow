# レビューサイクル 4 raw source (wiki-ingest ヘルパー委譲 PR)

対象: wiki-ingest ステップ 6 の index 操作を helper へ降ろすリファクタ PR。サイクル 4 のレビューで blocking 5 件 / non-blocking 1 件。

## 観測された指摘のパターン

- **前サイクルの修正が新たな過剰一般化を生む**: サイクル 3 で導入した placeholder residue gate が「brace で始まり brace で終わる」形状ヒューリスティックを free text (title/description) に転用し、正当な brace 含みタイトルを棄却する。residue 検出は呼び出し側が渡す literal (`{title}` 等) との exact 突合で十分であり、形状判定は enum やブランチ名のような閉じた値域にのみ適用すべき。
- **marker 契約の自己矛盾**: helper が stderr に「統計行欠落 WARNING」を出しつつ stdout marker は `stats_sync=synced` を返す。marker は LLM への唯一の機械可読チャネルなので、WARNING と marker の意味が食い違うと LLM 側は marker を信じて続行する。marker 契約を新設したら「異常系で正常値を返す経路が残っていないか」を全経路で突合する必要がある。
- **位置抽出の前提と同定述語の非対称**: 行の同定述語 (行頭区切りのみ要求) と位置抽出 (行末区切りの存在を前提) の前提が食い違うと、同定は通るが抽出が空になる中間域が生まれ、silent データ損失に至る。捨てるフラグメントが空白のみであることを検査して fail-loud にする。
- **文書アサーションの変異耐性**: 継続行コマンドの literal assert を行単位断片で書くと、行を繋ぐ継続 backslash の脱落 (最も起きやすい Edit 崩れ) を検出できない。継続行を join して 1 論理コマンドに正規化してから assert する。
- **exit code 別の復旧手順を統合しない**: LLM 起因のエラー (引数不正 = substitute 漏れ) と環境起因のエラーを 1 行の復旧手順に統合すると、再実行すれば 1 回で直る失敗が恒久スキップになる。復旧手順は失敗の帰責先ごとに分ける。
