### Finding Patterns
- 「失敗の記録と現在の state がバイト単位で一致するときだけ抑止する」設計は、「以後の書き込みは正当な作業の再開」という前提に依存する。実際には印を残したまま state を書き換える書き込み（SessionEnd の deactivate、session-start の dangling worktree の参照クリア）があり、1 回目の resume では抑止できても、その後に一致が崩れて回収済みの state が作業中に戻る。2 名の reviewer が別経路で独立に実測した。
- テストの fixture が review 履歴を持たないため、SessionEnd が state を削除し、この経路に届いていなかった。fixture が「本番で普通に起きる状態」を含むかを確認する必要がある。
- 抑止を 1 回で終わらせず、抑止したときに印そのものを消して回収を完了させる方が、後続の書き込みに依存しない。
