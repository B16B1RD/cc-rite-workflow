### Finding Patterns
- 完了レポートの「なし」行の条件を「WARNING を出していない」だけで判定すると、WARNING を出さずに失敗する経路（自セッション保持のまま release が失敗する）が「なし」に化ける。失敗を rc で返しても、利用者が最後に見るレポートまで運ぶ経路が無ければ silent failure になる。未完了事項の表は WARNING の有無ではなく、各段の失敗（rc 非 0 を含む）を網羅して条件を書く。
- SKILL の bash block を抽出して placeholder を置換し、実際に実行して文面・行順・rc を assert するテストは、文面入れ替えや分岐外しの変異を確実に検出する。一方で fixture がテストファイル内の先行 TC の状態（stub、書き出した session id）に依存すると、単独実行・順序入れ替えで壊れる。
- 同じ文面を 2 つのテストスイートが重ねて固定すると、文面変更時に両方の同期が要る。表の行の存在はレポート契約テスト側、実行時の文面との照合は実行テスト側に分ける。
