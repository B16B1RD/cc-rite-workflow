### Finding Patterns

- **入力検証の述語を「後置条件」として節末に置くと、同じ節の内側にある consumer を守れない**: `{branch_name}` の charset 束縛が Phase 2 末尾に置かれた結果、Phase 2 の内側 (:137) の fenced bash への literal substitute が未検査のまま通った。束縛は「値が代入される時点」に置き、節境界で表現しない。後置条件は定義上それより前の置換を遡って守れない。
- **終端 Status への冪等分岐は state だけでなく stateReason で割る**: `CLOSED` を単一分岐にすると、`Closes #N` のマージで GitHub が自動クローズした `COMPLETED` Issue が、`NOT_PLANNED` 用の経路へ系統的に流れ込む。board の終端行は drift-check が母集団から除外するため誤記録が復元不能になる。
- **散文の判定表だけで fail-loud を強制しない**: fenced bash の else 経路が `echo ... >&2` で終わると block の exit status は 0 になり、停止の強制が LLM の散文読解に依存する。同一プラグイン内に `exit 1` を置く先例 (`skills/open/SKILL.md` の WORKTREE_INVARIANT gate) があるなら、それに揃える。
- **grep pin は「消費側」ではなく「生産側」にアンカーする**: 同一リテラルが emit 行と判定表行の両方に現れる場合、file-wide の `assert_grep` は他の pin によって恒真化する。実行行アンカー (`assert_grep_in_section` + 節スコープ) に移す。
- **否定 pin は動詞の列挙ではなく class 述語で書く**: 削除処理の複製を禁じる pin を 4 動詞の列挙にすると、列挙外の削除手段 (リモート ref 削除・`find -delete`) のインライン化を検出できない。
- **英日ペア / 双子ドキュメントの片側更新**: `CLAUDE.md` と `CONTRIBUTING.md` のように同一列挙を 2 言語で保持する構造では、片側だけの更新がパリティを破る。
