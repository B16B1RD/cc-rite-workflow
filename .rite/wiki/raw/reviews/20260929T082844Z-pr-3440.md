### Finding Patterns
- 完了済み run を fix へ戻す新しい経路（逸脱記録）に、同じレビュー済み commit での再投入を止める記録が無かった。倣った兄弟経路（PR 内推奨）は「一度渡した commit」を記録して再投入を防いでいる。新しい再入経路を足すときは、兄弟経路が持つ再入防止の記録も同時に移植する必要がある。
- fix が push せずに戻る sentinel（返信のみ / non-fatal のみ）は HEAD を変えないため、完了前確認へ戻る分岐は同じ判定を繰り返す。cycle counter を進めない戻り経路には明示的な終端条件が要る。
- 手順書が JSON 入力の一部のフィールドにだけ「絶対パス」を指示すると、実行者は隣接フィールドも絶対パスで書く。helper が diff 表記（リポジトリルート相対）で照合するフィールドは表記を明記する。
- 設定値の読み込み位置が関数ごとに違う（cwd 相対 vs rite-config-path.sh による main checkout フォールバック）と、session worktree で untracked config を使う配布先構成でだけ上限判定がずれる。
- Complexity S 宣言に対し、共有 scope gate・公開 CLI・state schema へ波及する変更だという指摘が 2 reviewer から出た（実測なしのため non-blocking）。
