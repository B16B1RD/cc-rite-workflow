### Finding Patterns
- 手順書の 1 行で方式を変えると、同じ契約を述べる別の記述（reviewer prompt テンプレートの自問、helper の ERROR 文言、reference の説明）が旧方式のまま残りやすい。方式を変えたら旧語彙を repo 全体で grep して全 hit を読む。
- 「方式が同じ（既存の retry と同じ置き換え）」でも、フロー上の位置が違うと後続の再実行範囲が変わる。後段（5.1.2.A / 5.2 / 5.2.2 / Fact-Check / 5.3.0）を終えた後の reroll は、再実行の連鎖を明記しないと置き換えた出力が後段を素通りする。
- 自然言語の pin は逐語の denylist だと言い換えた相反文を通す。肯定 pin も句点まで含めて文単位で固定しないと、極性反転や例外の追記が生存する。
- PR 本文の「〜が無いことを検査します」は、測った mutation の範囲に合わせて書く。
