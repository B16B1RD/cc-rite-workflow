### Finding Patterns
- 同じ判定を複数実装で持つ場合、判定式（行単位の述語）を揃えても、節を出たあとの制御（exit するか、フラグを戻して読み続けるか）が違うと「同じ範囲を読む」とは言えない。コメントや同期テストの主張は述語の一致と制御の一致を分けて書く。
- 実装の文字列形を固定する静的 pin（denylist の grep）は、空白の有無や被演算子の順序を変えた書き換えを素通りする。禁止形の denylist だけでなく、使う側の肯定形（期待する規則行そのもの）を件数で pin すると回帰を捕まえやすい。
- テストで helper の出力を `2>/dev/null | grep -c` に流すと、helper が fail-loud に失敗しても期待値 0 の fixture では assert が通る。終了コードを別に検査してから件数を数える。
- CRLF 本文の見出しを `grep -c '^見出し$'` で数えると、CR が残った行は一致しないため「重複していない」assert が重複を見逃す。CR を除いてから数える。
- macOS の CI ジョブが continue-on-error のとき、macOS 固有の awk 挙動（ロケール照合）の回帰は実行結果では止まらないため、式の形の pin が唯一の防御になる。
