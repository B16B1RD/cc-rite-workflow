## レビュー結果（cycle 1）

- 総合評価: マージ可（blocking 0 / non-blocking 0）
- レビュアー: application / error-handling / prompt-engineer（XS/S 軽量レーン、上限 3 名。tech-writer と security は関連度順で除外）
- 変更: 記録コメントの降格理由の説明を正本の 3 値へ揃える文言修正 4 行（文書 2 箇所は 3 値を括弧で並べ、hook コメント 2 箇所は「降格理由」と総称）

### 観察
- 同じ 3 値を複数の文書へ書き写した記述は、正本側の値が増えたときに写しだけが取り残される。コメントのように削除しない理由を述べるだけの箇所は、値を列挙せず総称で書くと食い違いが起きない
- 記録コメントに書き込む経路が 2 つある（pr-review 自身の生成は 2 値、fix の update-in-place が 3 値目を足す）。説明文で 3 値を挙げるときは、どの経路がどの値を書くかを併記すると誤読を防げる
- 正本の表現（判定文）と実際のラベル（接頭辞付き）の差は、写しを揃える変更の範囲では直さず、正本と写しをまとめて直す別作業として扱う
