# レビュー結果: pipefail 下で echo の出力を grep -q へパイプしない（cycle 1）

## 判定

fix-needed（reviewer 2 名、XS/S 軽量レーン、ブロッキング 1 件、非実測 2 件）

## 変更の要旨

pipefail 下の `echo "$output" | grep -q` が CI で SIGPIPE により不定期に失敗した。テストの該当箇所を here-string に機械置換し、lint の echo 例外を展開なしに絞った。

## レビューで得た知見

- 機械置換の対象をツールの出力文字列で絞り込むと、出力の書式に依存した取りこぼしが起きる。lint が報告する producer 文字列を「echo / printf で始まる」で絞ったため、`if echo …` / `! echo …` のように前置語が付く行が丸ごと漏れた。対象の選別は出力の表層ではなく、ツールと同じ字句解析で producer の実体を取り出して行い、置換後に同じツールを再実行して対象クラスが 0 件になることを完了条件にする。
- 置換後の確認を「置換した行が正しいか」だけで行うと、置換しなかった行の漏れに気付けない。完了条件は「対象が残っていないこと」を同じ検出器で測る形にする。
- 文書の一部を実測に合わせて直すときは、同じ節の反対方向の記述（「この場合は変換不要」の表など）も探す。片方だけ直すと、同じ節に真逆の指示が並び、読んだ実装者が直した形を書き戻す。
- 例外条件を変えたら、その例外を列挙している設計根拠文書も追従させる。
