### Finding Patterns

新設スキルが既存 helper へ委譲する設計は正しく配線されていたが、**helper を呼ぶ手前の「対象の同定」で 2 件の CRITICAL** が出た。共通する形は「Issue 番号を引数で受ける新しい入口が、Issue 番号でスコープされていない既存クエリ／セッションスコープの state をそのまま流用した」こと。

1. `gh pr list --search "linked:issue:{N}"` は GitHub が `:{N}` を無視する boolean qualifier で、どの Issue 番号でも同一集合を返す。既存 skill (`issue-close`) からコピーされた形だが、あちらは集計表に使うだけで破壊的判断には使っていなかった。`--head "*issue-{N}*"` の glob も exact-match オプションのため常に空を返す。**gh のフィルタオプションはワイルドカードを解釈しない**、が横断的な教訓。
