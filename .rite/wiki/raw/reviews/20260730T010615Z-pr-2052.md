### Finding Patterns

1. **分岐条件のキーを揃えないと、分岐とフォールバックが互いの禁止事項を生成する**（CRITICAL、2 レビュアーが同一 anchor で独立検出）
   「節見出しの有無」で新設分岐を書き、「登録行の実形式」でフォールバックを書くと、**見出しは無いが旧形式で登録済み**という実在形状がどちらの分岐にも一意に落ちない。字義実行すると新設分岐が成立して新旧形式が混在し、それはフォールバック自身が禁じている状態になる。しかも検証 helper が形式非依存（リンク target の grep）だと混在は lint で検出されない。
   教訓: 同一ステップに複数の分岐がある場合、**全分岐の条件キーを 1 つの観測量に統一**する（見出しの有無と中身の形式は別の観測量）。統一できないなら precedence を 1 文で明示する。分岐条件を書いたら「その条件が偽になる実在形状」をプロジェクト自身の test fixture から探す — 今回は `wiki-lint-orphans.test.sh` TC-9 が該当形状を検証していた。

2. **旧形式の仕様を削除しつつ旧形式へのフォールバックを残すと、参照先のない指示になる**（HIGH、3 レビュアーが独立検出）
   「実形式を検出して従え」というフォールバックは、従うべき形式の書式定義が同一 PR で削除されていると実行不能になる。`grep -c` で旧形式の書式定義が 0 件（削除前は 1 件）であることが機械的に示せる。さらに冒頭の無条件禁止文と併存すると、フォールバックに従う行為そのものが禁止違反になる。
   教訓: フォールバック分岐を残すなら、**その分岐が参照する仕様も残す**か、フォールバックを一方向の移行規定（「旧形式は新形式へ移行する」）に置き換える。無条件禁止文と条件付き許可を同一ステップに置くときは precedence を必ず書く。

3. **カウント規則は「ファイル数」ではなく対象の拡張子・除外を明記する**（HIGH、2 レビュアーが独立検出）
   「`pages/` 配下の実ファイル数」と書くと、初期化時に置かれる `.gitkeep` 等の非ページファイルが混入し、現に正しい値が毎回ずれた値へ上書きされる。実測で 301（全ファイル）vs 298（`*.md`）の差 3 が各ドメインの `.gitkeep` と一致した。統計値を読む consumer が存在しない場合、乖離を検出する主体がいないため silent に固定化する。
   教訓: 数値の同期規則は**母集団を拡張子・除外条件込みで書く**。既に正しい値が入っている成果物を上書きする指示は、現行値と指示の計算結果を突合してから書く。可能なら件数を helper へ委譲して機械産出にする（同スキルの孤児検出・skipped refs は既にその慣習）。

4. **規約を bullet の入れ子に置くと兄弟経路に届かない**（HIGH、2 レビュアーが独立検出）
   セル破壊防止の規約を「新規追加」bullet 配下の sub-bullet に書くと、兄弟トップレベルの「既存更新」bullet には textual に適用されない。見出しに「全セル共通」と書いても、それは列の範囲を指す語で書き込み経路の範囲を指さない。同じ列を上書きする更新経路に同じ欠陥が残る。
   教訓: 複数の書き込み経路に共通する規約は、**全経路の親（「更新ルール」直下等）に置く**。「共通」という語は係り先（列 / 経路 / ファイル）が曖昧なので、係り先を明示する。

5. **生成物自身が旧形式を宣言していると、実行時に相反する 2 契約が同時に渡る**（HIGH、2 レビュアーが独立検出）
   テンプレートから展開される成果物の散文が旧形式（箇条書き / メタデータ非重複 / 統計は別レポート）を宣言したまま、書き手の指示だけを新形式へ変えると、初回実行時の LLM は成果物自身の指示と skill の指示という 2 契約を受け取る。しかも別ステップでその成果物を Read してコンテキストに載せる経路があると、単なる docs 陳腐化ではなく形式判定の競合入力として作用する。旧形式を 1 行書いた時点でフォールバックが「実形式=旧形式」を検出し、収束意図が silent に片方向へ破棄される。
   教訓: 書き手の生成規約を変えるときは、**その成果物を生成するテンプレートの散文も同時に変える**。テンプレート側で新形式の骨組み（見出し + ヘッダ行）まで生成してしまうと、書き手側の新設分岐が防御的 fallback に退き、混在経路も同時に閉じられる。

6. **等値の言い換えは、片方に変換規則を導入した時点で偽になる**（LOW-MEDIUM）
   「A は B と literal 一致させる」と書いた括弧書きの等値関係は、B 側にエスケープ等の表記変換を義務付けた瞬間に成立しなくなる。突合を行う lint が無ければ検出されない。
   教訓: 表記変換規則を導入したら、**その値を「等値」と説明している全箇所を grep して SoT 側を明示**する（「変換適用前の値が基準」等）。
