# レビュー結果: fix の非実測指摘の記録で既存コメントの却下台帳を引き継ぐ（cycle 1）

## 判定

fix-needed（reviewer 3 名、XS/S 軽量レーン、ブロッキング 1 件）

## 変更の要旨

fix の非実測指摘の記録は、却下台帳を含まない本文で既存の記録コメントを全文置換しており、台帳が消えていた。helper と同じ規則で関連 Issue を解決し、既存記録の台帳を extract → merge-into で新本文へ引き継いでから helper に渡すようにした。

## レビューで得た知見

- 外部コマンドを stub で置き換えるテストで、stub が引数の一部（ここでは gh の `--jq` 式）を評価せず固定の fixture を返すと、その引数が担う選択ロジックは実質テストされない。選択述語を壊す変異が suite を通過し、本来直した不具合がそのまま再現しても green になる。stub は受け取った式を実物の処理系（jq）で fixture に適用し、fixture には選択で結果が変わる要素（対象外のコメント）を混ぜておく。
- 同じ記録コメントを書き換える経路が複数ある場合、「どのコメントを読み、どのコメントを書くか」の選択規則が経路ごとにずれやすい。読み手（台帳の取得）は marker の前方一致だけで全件を連結し、書き手（helper の PATCH）は author・sentinel・最新で 1 件に絞っていたため、記録が重複した状態では古い台帳を引き継いでしまう。読み手と書き手の同定規則は 1 か所にまとめる。
- 修正対象と同じ形の既存経路（pr-review の同じ手順）が失敗を `|| true` で握りつぶしていても、新しく書く経路まで合わせる必要はない。新しい経路は fail-loud で書き、既存経路の是正は別に扱う。

## ブロッキング指摘

- test / HIGH: テストの gh stub が `--jq` の選択述語を評価しないため、台帳を取るコメントの選択が固定されていない
