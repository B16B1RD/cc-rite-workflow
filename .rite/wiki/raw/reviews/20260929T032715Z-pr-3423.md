# PR #3423 cycle 1 レビュー結果

- 評価: fix-needed（blocking 2 件、非実測 0 件、受入条件 AC-1〜AC-4 すべて充足）
- レビュアー: application / error-handling / test / acceptance

## 指摘
- HIGH（application）pre-tool-bash-guard.sh の字句解析で、`&` の次が `>` なら直前の語が何でも `&` を語に連結する条件にしたため、`git push&>/dev/null` の `push&>/dev/null` が 1 語になり、reviewer の状態変更チェックを素通りした。bash では `&` はメタ文字で push は実行される。base では拒否していた退行。
- MEDIUM（error-handling）同じ条件が、クォートを外した後の語の末尾で `<` / `>` を判定するため、`echo '->'& git push origin HEAD` のようにクォート内の `>` で終わる語の直後の背景実行 `&` まで語に連結し、push を見逃した。

## 学び
- 字句解析で区切り文字を語に取り込む条件を広げるときは、取り込みを「リダイレクトの形がソース上で成立しているとき」に限定する。クォート除去後の語の末尾や次の文字だけで判定すると、区切りとして働くべき `&` を語に吸収し、後続コマンドがコマンド位置から外れる。
- 検査を緩める方向の変更は、base の hook との差分比較（同じ入力で deny→allow に変わる形の列挙）で回帰を見つけられる。
- bash と別言語の解析器の間で語を受け渡すときは、区切りに改行を使うと語中の改行で行数がずれる。NUL など語に現れない区切りを使う。
