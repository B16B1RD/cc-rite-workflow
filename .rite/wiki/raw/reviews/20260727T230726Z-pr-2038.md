### Finding Patterns

- **markdown 埋め込みテンプレートの字下げと、それを消費する helper の行頭 anchor 検査が乖離する**: SKILL.md の本文テンプレートが番号付きリスト項目内の fence に置かれると全行が字下げされて提示される。消費側 helper が `case "$(head -n 1 ...)" in "$MARKER"*)` や `grep -E '^...'` のような列 0 anchor で検査していると、LLM が表示どおり転記した本文が毎 cycle 検査に落ちる。テンプレート側を字下げ許容の正規表現で pin する静的テストは、この乖離を構造的に検出できない (pin 自身が字下げを許容してしまうため)。テンプレートを提供する側に「本文は列 0 から書き出す」の明示指示を置くのが低コストな塞ぎ方。

- **静的 pin の「合計下限 + 自己導出の等値」は削除軸に無反応になる**: `assert count -ge N` を複数 gate の合計に対して置くと、1 gate 分のデータ行が丸ごと消えても他 gate の行数で閾値を満たして通る。また `assert "$total" "$conforming"` の両辺を同一集合から導出すると、行を削除しても等値が保たれる。結果として「各 gate が最低 1 本のデータ行を持つ」という pin コメントの主張を実装が保証しない状態になる。gate ごとに区間を切り出して個別に assert する形 (sed で見出し区間を抽出) が正しい規律。

- **mutation matrix は軸ごとに網羅する必要がある**: 置換軸 (述語の書き換え・文言の差し替え) の変異だけを当てて「pin は落ちる」と結論すると、削除軸 (行の削除・節の全削除) に対する無反応が残る。pin を追加するときは最低でも「置換」「削除」「死に分岐化」の 3 軸で実測すること。

- **単一 invocation 化は「中間状態が存在しない」ことを構造的保証に変える**: lookup / 判定 / 書き込みを 1 プロセスに閉じ、EXIT trap で terminal sentinel を emit し、outcome の初期値を `aborted` に置くと、「途中まで実行して成功を名乗る」経路が定義上消える。gate は動作前 marker ではなく terminal sentinel を検証する形にできる。

- **gate の pass 行が終端を名指しすると gate 追加のたびに全 pass 行の書き換えが必要になる**: 評価順序を 1 箇所に規定し、各 gate の pass 行は「次の gate へ進む」とだけ書く形にすると、gate 追加時の書き換え漏れによる到達不能を構造的に防げる。この不変条件は静的 pin で固定できるが、pin 自体を区間ごとに切る必要がある (上記 2 点目)。
