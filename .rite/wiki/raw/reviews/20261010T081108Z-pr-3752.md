### Finding Patterns
- 前 cycle の「黙って捨てる」退行は直ったが、直し方が「1 つの形を見つけたら即座に止まる」だったため、別の 2 つの欠陥が出た（3 名が独立に再現した）。
  - 停止しすぎ: 追記専用のログで、同じ日付節の後ろに正しい記録が足されても止まり続ける。復旧の手順（手動 lint で記録を書き直す）が効かなくなり、ERROR にも対処の案内が無い。
  - 停止しなさすぎ: 停止の対象を `* **lint:` で始まる一形に限ったため、`-` の bullet や太字なしの見出しの下の記録は今も黙って消える。
- 教訓: 停止条件は、観測した崩れ方の一形ではなく欠陥の類（選んだ記録に取り込まれない未解消の行が読む範囲にあるか）で書く。追記専用のデータでは、「より新しい正しい記録で解消できる」ことを停止の設計に含める。さもないと、fail-loud が復旧不能な停止になる。
- 受入条件は、独立した fixture repo で取り込みの経路を実際に動かして 6 件すべて充足を確認した。独立 repo の中では state root が fixture 側に解決されるので、共有 state を汚さずに観測できる。
- 文書の限定句不足（SPEC の記録から外れる条件）は 3 cycle 続いて non-blocking のまま残っている。
