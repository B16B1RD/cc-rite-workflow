### Finding Patterns
- 冪等化の印（判定記録ごとの key）を照合する処理は、「同じ key なら飛ばす」だけでなく「別の key なら書く」側のテストが無いと、照合から key を落とした変異が生き残る。印の判別を 2 方向（一致なら飛ばす / 不一致なら書く）で固定する。
- key を生成する filter のテスト入力は、出口の種類（record / file / fix）をすべて含めないと、生成対象を狭める変異を検出できない。
- 外部 CLI の出力形状（`gh api --paginate --slurp` のページ配列の配列）に依存する照合では、mock が引数に関係なく同じ形状を返すと、フラグを落とした変異が生き残る。mock は argv を完全一致で受ける。
- 再実行で判定記録の構成（候補集合）が変わると、候補全文から作った key が変わり、同じ根因を別の記録として書く。「同じ判定記録」の範囲を仕様で決めずに key を設計すると、再レビューで言い換えられた候補が混ざる経路で冪等性が崩れる。
- 3 件の指摘はいずれも実装の誤りではなく検出網の欠落（class B）として降格した。
