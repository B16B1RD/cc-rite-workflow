### Finding Patterns

- **「markdown 散文を静的 pin で守る」は 4 巡しても収束しなかった**: 合計下限 → gate ごとの下限 → 厳密等値 + 共起 + denylist + 構造 pin → セル分割の構造述語、と 4 世代にわたり pin を強化したが、各世代とも「実測された穴は塞ぐが隣の穴を開ける」を繰り返した。4 世代目のセル分割ですら (a) 対象行が 0 本のとき「違反 0」と区別できない、(b) `一致` を含み `不一致` を含まない否定形言い換えを通す、(c) Action 列の先頭を固定していない、の 3 経路が残った。**この繰り返し自体が「散文への substring 検査というアプローチの限界」を示す実証データ**であり、次に採るべきは pin の強化ではなく、(i) canonical セル文字列そのものをリテラル pin して言い換えを loud fail にする、(ii) 表を機械可読形（`sentinel_present ∧ iteration_id == current` のような固定式）に構造変更する、のいずれか。

- **「違反 0 件」を期待する pin は domain の非空性も同時に assert する**: `count(violations) == 0` 形の述語は、検査対象の行が存在しないときも 0 を返して pass する。対象行を削除する変異と全件正常が観測上同一になるため、必ず「対象行が N 本存在すること」を対で固定すること。本 PR では 8.0.x 区間には行数 pin があったが 6.1.d 区間には無く、ERROR 行を丸ごと削除しても緑のままだった。

- **区間 pin の終端 anchor をハードコードすると「新節の挿入」で無音に広がる**: `sed -n "/^### 8\.0\.3 /,/^### 8\.1 /p"` は、8.0.3 と 8.1 の間に新しい節が入ると区間が新節を飲み込む。`assert_grep_in_section` 系は新節の該当行を拾って vacuous に pass するため、元の節の該当行を削除しても検出できなくなる。「次の同レベル見出しまで」を awk で動的に求める idiom が正しく、同一ファイル内で 2 つの idiom が混在すると、正しい方だけを見て「この形なら安全」と誤読する。

- **pin 追加と同時に「その pin が凍結する対象の変更手順」を書くと、手順自体が新たな over-claim になりうる**: cycle 3 で「8.0.4 追加は (1)(2)(3) の 3 点」と手順を明記したが、実測すると 4 点目（TC-5b の区間終端）が必要だった。手順を書くときは、書いた手順どおりに実行して緑になることを実測してから commit すること（手順そのものが検証対象）。

- **SoT が pin の層構成を列挙するときは実装の層数と一致させる**: 文書が「2 層で固定する」と述べ「残存ギャップは X のみ」と完全性まで主張していたが、実装は 3 層で、宣言された 2 層はいずれも AC の中核 failure mode を捕捉できず、捕捉するのは列挙から漏れた第 3 層だけだった。層の列挙は「どれが何を守るか」の対応まで書かないと、読み手が守備範囲を誤認する。
