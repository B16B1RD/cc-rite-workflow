## PR #2052 レビュー (cycle 5/5) の知見

### 1. pin(静的 assert)の literal は「その行に固有」でなければ契約を守れない
`assert_grep` のラベルが主張する契約より pin literal が広いと、対象行を消す変異が全緑で生存する。
cycle 4 で `WIKI_INGEST_STATS=aborted` (bash ブロックにも同一文字列) が kill しないことを発見し
固有文字列へ差し替えたが、cycle 5 で `n_stats_abort` (SKILL.md 内 5 箇所) が同じ理由で再発した。
**教訓**: pin を足したら必ず (a) `grep -c` で SKILL.md 内 hit 数が 1 であることを確認し、
(b) 対象行を削除する変異を注入して自分の assert が FAIL することを実測する。ラベルの文言を
書き換えたら pin literal も追随させる。

### 2. 契約の pin は consumer 側だけでは意味を成さない (producer/consumer 対称性)
`WIKI_INGEST_STATS` の 3 値契約で consumer (展開表) 2 行だけ pin し producer (`=ok` emit /
`skipped; reason=` 規定) が無 pin だった。producer が消えると正常系でも「marker なし → ⚠️」が
毎回誤発火するので、consumer の pin は producer 保証なしでは守るものが無い。
**教訓**: marker 契約を pin するときは emit 側と解釈側を対で pin する。

### 3. `=ok` marker は「計算成功」ではなく「副作用の完了」を attest させる
bash ブロック末尾で `WIKI_INGEST_STATS=ok` を emit すると、その後に LLM が行う Edit を落としても
「失敗なし」と報告される。対照の `WIKI_INGEST_PUSH=ok` は helper の rc=0 を見てから emit しており
非対称だった。**教訓**: 成功 marker は「その marker が保証したい状態」が確定した後に emit する。
LLM の Edit を含む手順では marker の emit も LLM 側の契約に移す。

### 4. 「なし」行の条件 gloss は marker 値で書き切る
「かつ統計中止なし」のような自然文の否定は marker **不在** のときも真になり、3 値設計
(ok / skipped / aborted / 不在) が塞ごうとした「未確認を失敗なしと断定する」経路を復活させる。
**教訓**: 表の既定行の条件は `A=ok` / `A=skipped` **かつ** `B=ok` / `B=skipped` のように
取りうる値を列挙して書く。

### 5. ループ本体に置いた散文 guard は「一度も実行されない」方向に壊れる
「最後の Raw Source を処理したときにのみ実行する」は数え上げ不能な述語。top-level ステップ
(構造的に 1 回) と同一視できない。**教訓**: ループ内 guard は既存カウンタとの照合
(`処理済み件数 == n_raw_sources`) へ落とし、ループ本体側にも 1 行の相互参照を置く。

### 6. ガードを前倒しすると元の防御分岐が到達不能になる
`total=0` ガードをループ前へ移した結果、ループ内の `if [ -z "$pages_list" ]` が dead code 化した。
**教訓**: 早期 return / 早期 exit を追加したら、それが無効化する下流分岐を同じ commit で畳む。

### 7. 中止経路が成功経路と同形の payload を出してはならない
`domain_sum` 不一致で中止する経路でも `patterns=N` 等の内訳 3 行が既に stdout に出ており、
「前サイクルの値のまま」という中止 literal と両立しない。**教訓**: 部分結果はループ内で変数へ溜め、
全 guard 通過後に一括出力する。

### 8. 同一 PR 内で同じ事実を別の確度で書かない
「箇条書き bundle が残る」を SPEC と rationale では「本リポジトリでは未観測＝防御的サポート」と
caveat 付きで書き、wiki-patterns だけ観測事実として断定していた。**教訓**: 網羅スイープで
編集集合を確定してから語彙を 1 度決め、機械的に全箇所へ適用する (cycle 2 の学習の再確認)。

### 9. GFM code span の入れ子はバッククォート数で回避する
`` `... `## 統計` ...` `` は途中で span が閉じる。同一表の隣接行が二重バッククォートで正しく
回避していたため書式不整合として 3 レビュアーが独立検出。**教訓**: literal がバッククォートを
含む場合は必ず二重バッククォートで包む。
