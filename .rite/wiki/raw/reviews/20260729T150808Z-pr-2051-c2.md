1. **rc 契約を変えたのに読み手側の記述が 4 箇所取り残された**: 走査不能を rc=2 で surface する変更を入れたが、(a) lint の per-check rationale、(b) 姉妹 script の header/usage、(c) 呼び出し側 skill の DoD 注記、(d) lint の汎用 exit code 契約、が rc=0 時代の記述のまま残った。**exit code を 1 つ増やす変更は、その値を読む全レイヤ（script header / usage / rationale / caller の注記 / 汎用契約表）を同時に更新する**必要がある。1 箇所直すと残りが相対的に「更新漏れ」として確定するため、レビューで必ず露見する。

2. **mutation testing でしか見つからないテストの空振り**: cycle 1 で恒真アサーションを直したが、cycle 2 では別の 2 件が mutation で判明した。(a) セクション境界ガードを名指しするアサーションが、fixture の順序（`other:` を対象セクションより前に置いた）のせいでガードを一度も通っていない、(b) rc=2 に至る 3 経路のうち awk fatal の arm だけテストが無く、そのカウンタを削除しても全 assertion が緑のまま。**「アサーションが存在する」と「そのアサーションが対象コードを通る」は別**であり、後者は該当行を壊して赤くなるかを実測しないと確認できない。
