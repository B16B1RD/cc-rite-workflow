### Finding Patterns

cycle 1 で 6 件の blocking を修正した直後の cycle 2 で blocking が 8 件へ**増加**した。
増加分の大半は cycle 1 の fix 自体が導入・放置したもので、Wiki の
「累積対策 PR の review-fix loop で fix 自体が drift を導入する」が実測どおり再現した。

**cycle 1 の fix が生んだ新規指摘の型**（次回の予防対象）:

1. **canonical を「形」だけ写して「順序」を落とす**: 1 行 trap を canonical 4 trap 形へ差し替えたが、
   同じ canonical doc が Instantiation Checklist で必須項目に挙げる「trap 設置は mktemp の**前**」を
   満たさなかった（差し替えは in-place で、位置を動かさなかったため）。sibling helper 4 本は全て
   順序も満たしている。**canonical を引用するときは checklist を項目ごとに照合する**。
   copy-paste 同形性は契約一致を保証しない。

2. **fix した挙動そのものが未 pin**: trap の signal 契約（rc=130/143/129 + stdout 無出力）を
   pin する assertion を書かなかったため、1 行形へ戻す変異がスイートを緑のまま通る。
   実挙動は `rc=0 + 偽 verdict` へ反転するのに検出されない。
   **fix の rationale に書いた挙動は、その場でテストに落とす**（[CONTEXT] flag の 3 点セット
   = emit / consume / **test** の test を欠いた形）。

3. **同一 invariant の伝播が 1 箇所で止まる**: 「上限は滅多に発火しない純粋な保険」という断定を
   1 site で是正したが、同じ断定を持つ 6 sibling site（同一ファイル 4 箇所 + helper header +
   別 skill の reference）が残った。**是正前に `git grep` で invariant の全出現を列挙し、
   fix はその全件に対して atomic に当てる**。1 箇所だけ直すと「同一ファイル内で正反対の断定が
   28 行離れて並ぶ」という、修正前より悪い状態になる。

4. **fix が新規 ID / 番号を既存と衝突させる**: 追加したテストブロックのラベルと fixture の
   PR 番号が既存ブロックと重複した（3 reviewer が独立検出）。**新規 ID を採る前に既存の
   連番の空きを grep で確認する**。

5. **片側だけ pin した diff が「対称位置の穴」を転写する**: 診断転記の pin を 1 つの redirect site に
   だけ足したため、sibling の redirect site は未 pin のまま残った。
   **同じ形の site が何箇所あるかを先に grep してからテストを書く**。

6. **fix 文が repo 自身の lint に引っかかる**: 修正文に `Issue #N` の説明的参照を書いて
   `comment-journal-check` の新規 finding を作った（同 cycle 内で自己検出・是正）。
   **fix 後は変更行に repo の lint を回し baseline との差分ゼロを確認する**。

**cycle 1 が正しく閉じた欠陥**（再発防止の実績として記録）: 1 行 trap による signal consume →
偽 reason + exit 0 は、修正後 5 回連続で rc=130 / 無出力を実測。診断転記の順序是正も
`_lost > 0` WARNING と併発させて継続行位置への誤着地が消えたことを確認。
