### Finding Patterns
- 新しい helper が git / gh の出力を「既定の形」と仮定していた。非 ASCII のファイル名（core.quotePath による引用符付きパス）、利用者の diff.mnemonicPrefix / diff.noprefix 設定で diff ヘッダが変わり、抽出が rc=0 のまま 0 件になった。fixture が ASCII 名・既定設定だけだったためテストで見えなかった
- 外部 API の応答の分類を誤った。gh api graphql は存在しない番号でも exit 1（NOT_FOUND）を返すため、「存在しない」が「取得失敗」に化けた。mock が実際の応答形と違う形で答えていた
- GitHub の closing keyword によるリンク（closedByPullRequestsReferences）は既定ブランチ向けの PR でしか作られない。Git Flow（develop ベース）の repo では解決済み Issue のリンクが空になる
- 件数上限（first:100 等）で一覧を黙って切り、切り捨ての印を付けなかった。上限を持つ取得は「不完全である」ことを必ず記録する
- 受理側の正規表現（[^=]）が生成側（prompt）の自然な出力（コマンドに = を含む）を拒否した。同じアンカーを受理する既存ゲートの式と揃えていなかった
- str.lstrip("./") は接頭辞ではなく文字集合を剥がす
