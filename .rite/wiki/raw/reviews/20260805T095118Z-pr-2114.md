### Finding Patterns

本 cycle の dominant pattern は **静的 pin / assertion が「守っていると名乗る対象」を実際には検査していない** 形で、3 件が独立に検出された。

1. **部分文字列 match による vacuous assertion**: `assert_grep ... "$ERR" 'mkdir'` が、同じ stderr に出る reason marker `reason=..._mkdir_failure` に match してしまい、検査対象 (helper の stderr 転送) を削除しても green。**assert の pattern が、同じチャネルに出る別の行に当たらないか**を追加時に確認する必要がある。転送行に固有の形 (`^  mkdir` = `sed 's/^/  /'` 由来の 2 スペース + program-name prefix) へ anchor するのが対策。
2. **文字クラスが対象集合を狭めすぎる静的 pin**: placeholder allowlist が `\{[^}[:space:]]+\}` で抽出しており、空白を含む placeholder (`{finding full description}`) を 1 件も拾わない。pin が守る対象 (全文の再掲載禁止) の反例が、pin の抽出正規表現の外側に落ちていた。**mutation matrix が「pin が拾える形の mutation」だけで構成されると、この抜けは実測でも露見しない**。
3. **未到達分岐 + 件数申告の不一致**: helper の reason 語彙 4 種のうち 2 種 (`_rm_failure` / `_archive_name_collision`) に assertion が 0 本。うち `name_collision` は GNU coreutils の `mv -n` が衝突時に rc=1 を返すため Linux では構造的に到達不能で、BSD/macOS 専用の分岐が Linux CI では壊れたまま配布されうる。`mv -n` の rc は実装差があるという前提が、テスト側の到達性検討に反映されていなかった。

次点は **inline → helper 委譲リファクタで「呼び出し自体の失敗」という新しい clause が落ちる** 形 (Asymmetric Fix Transcription の一種)。旧 inline コード (`rite_rm`) が持っていた error handling は helper 側へ完全に転写されていたが、subprocess 化によって新たに生まれた失敗モード (rc=127 = helper 起動不能) を caller が検査しておらず、marker 不在を「完了」と読む判定表が silent に成功を報告する。**委譲リファクタでは「移した処理の error handling」だけでなく「委譲という行為が新たに生む失敗モード」を数える**。

3 つ目は **同一契約を述べる複数箇所の drift**。cleanup の挙動を「一律削除」から「条件付き退避」へ変えた際、6 ファイルには伝播したが同一ファイル内の別節 (しかも Acceptance Criteria の双方向 anchor 先) が旧記述のまま残り、4 reviewer が独立に検出した。**契約を変えたら、その契約を anchor 参照している箇所を先に grep する**。

4 つ目は **bash 引数 parse loop の `shift 2` 無条件呼び出し**。値のない末尾オプションで `shift` が失敗して `$#` が減らず、`while [ $# -gt 0 ]` が無限ループする。出力ゼロで永久にハングし、宣言している `exit 1` に到達しない。fail-loud を宣言する CLI helper で最も観測しにくい失敗形。各 arm に `[ $# -ge 2 ]` guard を置く。
