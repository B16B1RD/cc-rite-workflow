### Finding Patterns

本 cycle で 6 レビュアーが独立に検出したパターンには、rite プロジェクト固有の再発クラスが 3 つ含まれる。

**1. 「未走査を clean bill として報告する」検出器欠陥（3 レビュアーが独立検出）**

新規 lint 検出器が `awk ... 2>/dev/null || true` / `[ ! -f "$t" ] && continue` / `grep` の rc=2 を silent に吸うため、1 ファイルも走査していなくても `findings: 0` / rc=0 を返す。lint の Execution policy が rc=0 を `success` に写して出力を surface しないため、操作者には「検査して問題なし」としか見えない。

一般則: **検出器を新規に書くとき、走査失敗と「指摘なし」を同じ exit code に潰してはならない。** rite には既に正解の先例がある — `dollar-zero-check.sh` は `SKIPPED` カウンタを持ち「走査できなかったものを clean と束ねるのは、この guard が防ごうとしている欠陥クラスそのものを guard の内側で再現する」と header に明文化し、findings=0 かつ SKIPPED>0 で rc=2 を返す。新規検出器はこの形を写すべきで、より古い `bash-heaviness-check.sh` の形（`2>/dev/null || true`）を写すと教訓が伝播しない。**同じ機能の実装が複数あるとき、どれを写すかで欠陥が決まる。最新の・レビューを経た方を写す。**

**2. 「規約と検出器の射程がずれる」契約内部の不整合**

同一 PR が (a)「新規 helper は lib を使え」という規約と (b) lib で消せない残余を拾う検出器を同時に導入したが、検出器は raw `mktemp` 由来のハンドルしか追跡せず、規約に従って lib で書いた helper の派生パスを検出しない。**規約に従うほど検出器の盲点に入る**という反転が起きた。

一般則: **「こう書け」という規約と「こう書いたら警告する」という検出器を同時に入れるとき、規約が推奨する書き方が検出器の入力ドメインに含まれているかを必ず確認する。** 検出器の正規表現は「今ある書き方」に対して書かれがちで、同じ PR が導入した新しい書き方は視野に入らない。

**3. signal handler のテストが handler の有無を区別できない（mutation で発覚）**

bash は untrapped な INT/TERM/HUP で死ぬときも EXIT trap を実行し、終了コードも 128+signum を返す。したがって「INT を送って rc=130 かつ tempfile が消えている」を assert しても、EXIT trap 1 本だけで両方満たされる。lib から signal trap 3 行を削除した mutant でテストは全件 green のままだった。

一般則: **signal 経路の cleanup をテストするなら、EXIT trap が効かない状態を作ってから signal を送る**（child 側で `trap - EXIT` してから `kill -INT $$`）。あるいは `trap -p INT` の出力に cleanup 関数名が現れることを直接 assert する。rc と副作用だけを見る assertion は、bash の EXIT trap 仕様のせいで signal handler の存在を判別できない。

**4. 免除規則の根拠と実際の判定軸がずれる**

検出器が `printf`/`echo` 先頭のパイプラインを SIGPIPE 免除にしたが、根拠は「短い in-memory 文字列が pipe buffer に収まる」であるのに、実装も文書も**コマンド名**で免除している。payload がリポジトリ規模に比例する `printf | grep -q` は根拠が成立しないまま無警告になる（payload 70000B で rc=141 を実測、10000B では rc=0）。加えて免除判定が「パイプライン全体の先頭」を見ており「grep -q の直前段」を見ていないため、多段パイプラインが丸ごと免除される。

一般則: **免除を入れるときは「何が真の判定軸か」と「実装が何で判定しているか」を突き合わせる。** proxy（コマンド名）で判定するなら、proxy が成立する条件を文書に書く。書かないと、次の書き手が proxy を真の軸だと信じる。
