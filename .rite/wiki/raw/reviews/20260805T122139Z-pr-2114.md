### Finding Patterns

blocking の推移は 13 → 10 → 5 → **7 で初めて増加**した。増加分はすべて **cycle 3 で新設した 1 つの機構（保存先への `.gitignore` 同梱）** が持ち込んだもので、「新機構は新しいレビュー面である」ことの実例になった。

**(1) 新機構を足した cycle は、その機構自身が次 cycle の指摘源になる**

cycle 3 で追加したのは 6 行の `.gitignore` 同梱ブロック 1 つだけだったが、そこから 4 件の blocking が出た:

- **ガードが不変量と一致していない**: `[ ! -f ]`（存在）で守ろうとしたが、守りたいのは「除外が効いていること」。`printf > F` は redirect が先に truncate するため ENOSPC で **0 バイトの `.gitignore` が残り**、以後の全 cycle が存在ガードで無音 skip する。**ガードの述語は「守りたい状態」と同じものを測る** — 存在ではなく内容（`[ ! -s ]`）。
- **リダイレクトのスコープ**: `printf ... > F 2>/dev/null` は**単純コマンド**なので、bash は redirect 自体の失敗（EACCES）を `2>/dev/null` 適用**前**に報告し、`printf` の書き込み失敗（ENOSPC）だけを捨てる。つまり「原因が最も要る側だけを捨て、要らない側を漏らす」。先例として引いた形は `{ printf ... > F; } 2>/dev/null` の**グループスコープ**で挙動が違った。**「先例と同型」を名乗る前に、先例の redirect スコープまで一致しているか読む。**
- **カバー範囲が片側だけ**: 保存経路には同梱したが、同じディレクトリを作る**退避経路**には同梱しなかった。保存を挟まずに cleanup が走る既存 install では保護が一切効かない。**同じディレクトリを複数の経路が作るなら、保護は全経路に置く（または 1 箇所に集約する）。**
- **テストがゼロ**: 新機構に TC が 1 件も無く、機構を丸ごと殺しても全 suite green。**新機構を足した commit で TC を足さないと、次 cycle で必ず「無検査」として返ってくる。**

**(2) pin の「弱め方」は 2 方向あり、片方だけ直すともう片方が空く**

cycle 3 で TC-8 の pattern から行継続バックスラッシュを外した（整形結合の解除）が、`grep -cF` のままだったため**コマンド行をコメントアウトしても 1 のまま通る**。整形依存を外すことと、コマンド位置へ anchor することは別の要件で、前者だけ直すと後者が空く。**`^[[:space:]]*bash <path>` のように「実行される位置」へ anchor する。**

**(3) 射程の委譲は、委譲先が構造的に受け取れるか確かめる**

allowlist assert のコメントが「literal な散文だけで再掲載する形は下の row-scoped pin が担う」と射程を委譲していたが、委譲先は placeholder の出現回数しか数えないため **placeholder を 1 つも含まない散文はどちらの pin でも落ちない**。委譲先が測っている量を確認せずに射程を渡すと、両方の pin が「相手が見ている」と仮定して穴が残る。

**(4) platform 限定の assert は、限定を宣言した直後でも入り込む**

cycle 2 で「ラベル自身が platform 限定を表明する assert を無条件評価してはならない」として 1 本削除したのに、同じ cycle で追加した `^  mv` pin が同じ性質（BSD の `mv -n` は rc=0 で stderr を出さない）を持っていた。**規約を書いた直後の追加ほど、その規約の適用対象か確認する。**

**(5) 文書側の drift は「同じ PR 内での自己矛盾」として現れ始める**

cycle 3 で setup 側にエントリを足しながら、同じ PR の helper コメントは「setup は sessions/ と worktrees/ しかカバーしない」と書いたまま（Comment Rot）。同様に、public PR へ出る所在行が「実装が不確実と宣言した経路」だけを読者に案内し、常時働く実機構に触れていない。**同一 PR 内で 2 つの hunk が互いの前提を壊していないかを、hunk 単位ではなく契約単位で確認する。**
