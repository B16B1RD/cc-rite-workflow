### Finding Patterns
- blocking / non-blocking 指摘 0 件。テスト用の偽コマンド（comm shim）が入力を読まずに終了すると、入力を書くプロセス置換側の sort が EPIPE を受けて stderr に Broken pipe を出し、原因行の検査が macOS でだけ非決定的になっていた。shim が入力を EOF まで読み切れば構造的に消える。
- Linux の GNU sort は SIGPIPE で黙って終わるため、同じ競合が Linux CI では再現しない。macOS ランナーの結果だけが修正の前後を区別できる。
- プロセス置換 `<(...)` 内のコマンドの stderr は、外側のコマンドに付けた `2>file` には入らず、スクリプト全体の stderr に出る（reviewer が bash 5.2 で確認）。helper の原因行ブロックに sort 自体の失敗は載らない。
- 受入条件に CI ランナー依存の Then がある場合、レビュー開始時点で CI が pending だと AC は未検証になる。同一 HEAD で CI 完了後に acceptance reviewer に 1 回だけ再判定させると充足にできた。
