### Finding Patterns

cycle 1 の 9 件はすべて解消され、test reviewer が mutation matrix を独立に再現して全一致を確認した。
cycle 2 の 14 件は**ひとつの原因に収束する**: cycle 1 の修正が「コードは直したが、その不変条件を
語っている文書・pin・SoT が旧状態のまま」という伝播漏れ。

1. **不変条件を変えたら、その不変条件を主張している文をすべて探す (最重要)**

   cycle 1 は「marker 削除は記録の成否に依存しない」という不変条件を意図的に破った。ところが
   その不変条件を明文で主張している箇所 — gate の Pre-Check 診断、reason 表、SoT docstring、
   canonical な error-handling 契約文書 — が更新されず、**同一 run で矛盾する 2 つの機械信号が
   同時に出る**状態になった (「6.1.d は完走した」と「6.1.d は完走していない」)。

   最も危険だったのは reason 表が「この reason では gate は pass する / 再実行は任意」と断定して
   いた点。gate の ERROR text 自身が「reason 表に従い」と参照先に指定しているため、LLM が
   ERROR を「表が pass と書いている以上これは誤報」と読んで機械強制を無効化しうる。

   一般化: 不変条件を変える変更では `grep` で「その不変条件を述べている文」を機械的に列挙してから
   コードを触る。特に **gate の診断文・ERROR text は、それ自体が routing の入力**なので、実装と
   食い違うと機械強制が言葉で無効化される。

2. **「3 段 → 4 段」のような数詞は、変更のたびに全 artifact を横断する**

   検査段数を 1 つ増やしただけで、`本文検査 3 段` / `本文不備 3 種` / reason 列挙が 9 箇所以上に
   散っていた (SKILL.md 2 箇所、helper 3 箇所、test 2 箇所、reference 2 箇所、CONFIGURATION.md)。
   数詞と列挙は drift の温床。

   ただし**一括置換は危険**: 同じ「3 段」でも「却下した旧設計を叙述している文」が混じっており、
   機械的に置換すると歴史的経緯の記述が壊れる。sweep 時は個別判断が要る。

3. **SoT に指定した文書が自分の変更を反映していないと、次の保守者が正しい実装を「不整合」として消す**

   `reason 語彙の SoT は helper docstring` と明示指定しておきながら、その docstring の retain 列挙に
   新 reason 自身が入っていなかった。SoT が過小列挙していると、将来の fixer が「この reason は
   marker を消すはずだ」と読んでコードを削り、cycle 1 で HIGH 指摘された欠陥がそのまま再導入される。

4. **write 側と read 側に条件を足したら、その 2 者を結ぶ coupling pin も足す**

   sentinel を lookup 述語 (read) と本文検査 (write) の両方に足したが、**write 側テンプレートと
   helper 定数を結ぶ coupling pin** が無かった。同型の coupling は 2 本 pin されているのに 3 本目
   だけが抜ける、という cycle 1 とまったく同じパターンの再発。

   さらに「step 1 が Write するパス」と「step 2 が `--content-file` に渡すパス」という
   別の 2 箇所 coupling にも pin が無かった。**coupling は変更のたびに列挙し直す**。

5. **位置非依存の `contains` は同定に使えない — anchor が要る**

   人間可視文字列の代わりに機械専用 sentinel (HTML コメント) を needle にしたが、`contains` は
   本文のどこにあってもマッチするため、人間が元記録の raw markdown を貼り込むと sentinel が同伴し、
   結局 PATCH 先を奪われる。実際に fix の完了報告コメント自身が sentinel を verbatim で含んでいた
   (sentinel を扱う finding を報告するたび機械的に再現する)。**needle は位置まで固定する**
   (末尾 anchor)。write 側テンプレートが末尾に置く契約なら read/write が対称になる。

6. **同定条件を変えると既存データが silent に孤児化する**

   lookup 述語に条件を 1 つ足した瞬間、その条件を持たない既存レコードは検出されなくなる。この
   helper は他の全 degraded 経路で WARNING を出す規律なのに、この縮退だけ `degraded=0` で完全に
   無音だった。**述語変更は migration 問題を伴う** — 「条件 A∧B は満たすが新条件 C に落ちた件数」を
   数えて WARNING に載せると観測可能になる。

7. **retain 系の変更は「同一 cycle 内の再実行」を新たに生み、tie-break 規則が要る**

   差し戻しを導入すると、同じ cycle 内で同じ識別子を持つ sentinel が複数並ぶ状態が初めて発生する。
   選択規則が cycle 間 (epoch 最大) しか規定されていないと、解決済みの古い sentinel を拾って
   誤報告する。**選択規則は「層をまたいで同一」かつ「同一識別子内の tie-break」まで書く**。
