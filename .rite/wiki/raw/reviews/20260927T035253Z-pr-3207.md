# レビュー結果: レビュー後の状態検査の判別子（cycle 1）

- 総合評価: 修正必要（blocking 2 件 / non-blocking 1 件）
- reviewer: prompt-engineer / application / code-quality / acceptance（S 軽量レーン）
- 受入条件: AC-1 / AC-2 / AC-3 すべて充足

## 主な指摘

- 他 worktree で checkout 中の branch を一律に除外すると、reviewer 自身が `git worktree add -b` で漏らした branch も除外され、改修前は検出できていた違反が見えなくなる。並列セッションの除外と reviewer の違反検出は、判別子の設計で両立を確認する必要がある。
- stash を「元 branch の件名」だけで数えると、reviewer が別 branch へ切り替えて stash し、元に戻る違反が見えなくなる。branch_list と対称に「他 worktree で checkout 中でない branch の件名」で数える案が出た。

## 経験則の候補

- 共有 ref（refs/heads・refs/stash）を worktree 単位に絞る判別子を入れるときは、除外対象に自セッション由来の操作が紛れ込まないかを、改修前の helper と同じ操作で比較して確かめる。
