### Finding Patterns
- 前 cycle の指摘（re.ASCII により UTF-8 ロケールの grep が受理する全角空白などを Python 側が拒否していた）は全レビュアーが解消を確認。新規の blocking 指摘は 0 件。
- Python の `\s` と glibc の `[[:space:]]` は文字集合が一致しない。re.ASCII を外すと grep が受理する入力はすべて受理するが、Python だけが受理する文字（U+001C–U+001F、U+0085、no-break space 類、`i` の位置の U+0130）が逆向きに残る。BMP 網羅照合で実測された。「cleanup と同じ判定」と書くなら、どの向きのずれが残るかまで書く必要がある。
- 一致規則の parity 試験はロケールに依存する（C ロケールでは grep は U+3000 を空白として受理しない）。
- 空白の連続に対する正規表現のバックトラックは二乗時間だが、単一ユーザーの開発機という運用前提で guardrail により除外。
