# レビュー結果: fix の非実測指摘の記録で既存コメントの却下台帳を引き継ぐ（cycle 2）

## 判定

mergeable（reviewer 2 名、XS/S 軽量レーン、差分スコープ、ブロッキング 0 件）

## 変更の要旨

前 cycle の指摘（テストの gh stub が `--jq` の選択式を評価しない）に対し、stub が受け取った `--jq` 式を実物の jq でコメントの JSON 配列 fixture に適用するよう変更した。fixture の先頭には台帳を持つ非記録コメントを置いた。

## レビューで得た知見

- 変異テストで修正を検証するときは、前 cycle で生存した変異を再適用するだけでなく、同じ選択ロジックを別方向に壊す変異（全件連結、末尾要素、台帳の有無で選ぶ）も足す。どれも同じ assert で落ちるなら、その assert が選択を固定していると判断できる。
- 否定の assert（「この呼び出しが含まれない」）は、対象の誤りが先に別の assert で落ちる場合、単独では落ちうる assert になっていないことがある。変異を入れて実際にその行まで到達するかを確かめ、到達しないなら検出力を持たない行として扱う。
- stub が引数の個数と順序を厳密に要求すると、呼び出し側の引数変更はテスト失敗として現れる。これは意図どおりの厳格さで、呼び出し形を契約として固定する効果がある。
