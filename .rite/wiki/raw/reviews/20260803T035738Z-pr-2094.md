### Finding Patterns

本 cycle で確定した 3 件は、いずれも「防御機構を追加した diff の中に、その防御が効かない縮退経路が残る」型だった。

1. テストスイート自身の自己切断 (HIGH): `set -euo pipefail` 下のテストファイルで、コマンド置換内の grep 非マッチが errexit でスイートをプロセスごと中断させる。同ファイル内の同型 7 site のうち 1 site だけが `|| true` guard を欠いており、非対称が漏れの証拠になった。アサーション FAIL ではなく中断のため PASS/FAIL サマリごと消え、以降のアサーションが「実行されていない」ことすら観測できない。この PR では baseline の Red 件数計測が実際に歪んでいた (9 件と報告されたが実測 16 件)。教訓: bash テストでコマンド置換内に grep を書いたら、guard の有無をファイル内の同型 site と突き合わせる。

2. 数値比較ガードの fail-open (MEDIUM): `[ "$x" -eq 0 ]` は `$x` が非数値のとき rc=2 を返すため、`if` の else 分岐へ倒れる。「読み戻し不能なら既定値へ」という fail-closed の意図で書かれたガードが、入力が壊れているときにだけ逆向き (処理続行) に作用する。教訓: bash の算術比較をガードに使うなら、非数値入力の rc=2 が意図する分岐へ倒れるかを必ず確認する。`[[ $x =~ ^[0-9]+$ ]]` を前置する形が安全。

3. 兄弟 WARNING の片肺 hedge (MEDIUM): 同一 diff で追加された 2 つの WARNING のうち、片方だけが「env override / flow-state 読み取りが無い場合のみ」という条件を明記し、もう片方は無条件に断定していた。縮退時の診断メッセージが誤情報になると、既に degraded な状況でのトリアージを誤らせる。教訓: 同じ前提を語る WARNING が複数あるなら文言を 1 変数に括り出す。
