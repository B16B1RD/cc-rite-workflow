### Finding Patterns

**「案内先を書く」形式も、案内先が経路ごとに違うなら同じ罠にはまる**: 条件の列挙をやめて案内先を書く形に畳んだが、自動回収が外れる 3 経路（未マージ / dirty / 記録漏れ）はそれぞれ案内先が違うため、1 つに名指しすると必ずどれかで外れた。**条件も案内先も列挙できないときは、退路そのもの（手動コマンド）を示して案内を書かない**。3 名の reviewer が独立に同じ経路の誤りを検出し、全員が削除を推奨した。

**同じ 1 文に 3 サイクル連続で指摘が付いたら、その文を書き足す方向をやめる**: cycle 4「条件が足りない」→ cycle 5「条件が多すぎる/存在しない案内先」→ cycle 6「案内先が経路で違う」と、加筆・言い換えを繰り返しても指摘が終わらなかった。最終的に解になったのは削除。Simplification-First の Escalation trigger は「前 cycle の fix が導入した箇所への指摘」で発火するが、実務上は**同じ箇所への 2 回目の指摘**で加筆をやめる判断をすべきだった。

**assert を差し替えたら、その assert を説明するコメントも同時に見る**: pin 対象を条件節付きの文から無条件の文へ差し替えた結果、「条件節ごと pin して無条件の約束へ戻る退行を検出する」というコメントが、いま assert が固定している当のものを「退行」と呼ぶ自己矛盾になった。テストコメントは assert の説明であり、assert を触ったら必ず一緒に読む。
