### Finding Patterns
- git 失敗を「不在」にせず error として記録する修正では、「git が成功して対象が無い」側の分岐（従来どおり不在を返す経路）を、失敗経路のテストと対にして固定する。片側（path:line）だけ固定されて節側が未固定という非対称が生じやすい。
- 失敗の記録キーを集計する際、同じキー（行 ID と節）に複数の文書が当たると上書きされて件数と WARNING が過少になる。キーに文書名を含める。
- git の失敗を不在へ寄せる経路は他にも残りうる（コミット SHA の存在確認が git 失敗と SHA 不在を区別せず GitHub 照会へ進む）。同種の修正では隣接する経路も洗う。
