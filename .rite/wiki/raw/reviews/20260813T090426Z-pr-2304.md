### Finding Patterns

4 cycle を回して blocking 件数は 1 → 2 → 1 → 0 と収束した。cycle 2 以降の blocking はすべて **前 cycle の fix が触った箇所** に対する指摘で、しかも共通の形をしていた: **producer 側のリテラルや述語を変えたのに、それを消費する側（契約テスト・文書）を追随させなかった**。

cycle 1 は preset のシーン列を `out/NN.mp4` から `$scene_dir/NN.mp4` へ変えたのに、その配列を **awk で字面抽出して等値比較** していた契約テストを更新しなかった。実行経路（`-P` 単体）の挙動は完全に不変だったので、動作確認では検出できない。

cycle 2 は、その修正で順序 pin から探索先の接頭辞を外した結果、**`-d` が実際に効いているかを確かめる経路がリポジトリから消えた**。同時に追加した `-d ""` 拒否ガードにも契約ケースが無く、どちらのガードを消しても `npm run check` は green のまま通った。契約テストのファイル自身が「ガードごとに 1 ケース。fixture を置くだけでは pin にならない」を存在理由に掲げているのに、新設したガードだけがその規約の外にあった。

cycle 3 は、その 2 ケースを足したときに **診断の原因を畳んだ**。「`-P -d out/en` が非ゼロ終了した」と「実行は成功したが完了診断が出ていない」を同じ `else` へ落とし、後者で「連結できません」という事実に反する原因を名乗った。同ファイルの冒頭コメントが「(1) を満たすが (2) を満たさない場合は『契約が壊れた』ではなく『契約を検証できなかった』——見出しを分けないと初回実行者が誤った原因を読む」と明文で禁じていた形そのものだった。

**この 3 cycle に通底するのは「pin の対象と pin の表現を分離できていない」こと**。cycle 1 の修正で順序 pin を basename 比較へ寄せたのは、期待値に探索先の接頭辞を書き写す最小パッチだと「次に表現を変えた時点で同じ誤報が再発する」構造が残るためで、pin が守る対象（M1〜M7 の順序とファイル名契約）と pin が観測する表現（パスの接頭辞）を切り離す方向へ動かした。これは「追加より削除・単純化を先に検討する」がテストの pin にも同じ形で効く事例である。

もう 1 つの反復形は **新設した guard 自身が defect class の隣接メンバーを取りこぼす**。`-d` を黙って無視しないための guard を足したが、述語が `[ -z "$scene_dir" ]` で「未指定」と「明示的な空文字」の sentinel を共有していたため `-d ""` で不発した。しかも preset 側の既定値代入が空文字を `out` へ silent 置換するので、変数が空だと **日本語素材から組んだ mp4 が `-en` の名前で exit 0 完成する**。下流の fail-loud 検査（シーン存在・尺・フレーム周期・BGM 尺・出力実尺照合・可聴性）は素材の言語を見ないので全部通る。修正は guard を「消費する場所」から「値が入る場所」（getopts の解析時点）へ移す 1 行で、両分岐の穴が同時に閉じた。

文書側の反復形は 3 つ。**恒久記録簿へ未了工程を完了形で書く**、**同じ PR の中で宣言した不変条件を同じ PR の別ファイルが破る**、**既定義語を別義で再利用する**（本文書で「2 本のカット」がフル / SNS を指すのに、日英対の意味で使った）。いずれも成果物は壊れないが、字義どおり守る後続作業者を誤った方向へ動かす。

運用の学びとして、**実測必須ゲートで non-blocking へ降格した指摘でも `scope=current-pr` なら同一 cycle で直す**判断を採った。文書の記述内容・glob の対象集合・空文字の sentinel 共有は、静的に確認できる事実であって runtime 実測が付く見込みが構造的に無い。放置すると次 cycle で再指摘されるだけで永久に blocking にならず、記録だけが増える。ゲートが決めるのは merge を止めるかどうかであって、直してよいかではない。
