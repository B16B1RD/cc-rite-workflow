### Finding Patterns
- 指摘 0 件（cycle 1 で mergeable）。7 名とも「可」、受入条件 5 件は全件充足。
- 「レビュー済み commit と HEAD の一致」を確かめる gate は、実行場所のチェックアウトではなく対象 PR の head（リモートの headRefOid）と照合しないと、別 commit の checkout から実行しただけで誤拒否し、逆向きには PR 側の未レビュー push を見逃す。照合対象は「判定したい対象の識別子」から取り、手元の状態で代用しない。
- 照合とマージ実行の間に対象が動く窓は、照合で確認した OID をマージコマンドに固定（`gh pr merge --match-head-commit`）して塞ぐ。gate の通過だけでは「その OID がマージされる」ことを保証しない。
- fail-closed は「正常（40 桁 hex の OID）を確認できなければ止める」形にすると、API 失敗・空・null・短縮 SHA を 1 本の経路で拒否できる。
- テストでは、比較に関与しないはずの値（ローカル HEAD）を常に別の値へ固定すると、既存テスト群が「その値が判定に関与しない」ことの検証を兼ねる（元バグ復元 mutant で 34 件 FAIL）。
- reviewer への依頼文で機械検査される語彙（受入条件の判定値）を helper の受理値と違う言語で指示すると、内容が正しくても形式検査で 1 cycle 分の再回収が発生する。機械検査される値は helper の受理値をそのまま依頼文に写す。
