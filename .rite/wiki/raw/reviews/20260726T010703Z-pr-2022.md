### Finding Patterns

- **ローカルのフルスイート green は CI マトリクスの green を意味しない**: orchestrator は Linux で 105/105 を確認して「テスト green」と報告したが、実 CI の macOS leg は failure だった（develop は success → 本 PR で退行）。reviewer が GitHub Actions の job を直接引いて発見した。**教訓: マトリクス CI を持つリポジトリでは、ローカル実行ではなく実 CI の job 単位の結論を確認する。`gh run list` の run 結論は `continue-on-error` のレグを隠すため `gh run view --json jobs` まで見る。**
- **brace 無し変数展開が多バイト文字に隣接すると非 UTF-8 ロケールで壊れる**: `"...: $_ls_err。削除は..."` は bash が `。` の先頭バイト 0xE3 を変数名に取り込み、変数が未定義化して機能が丸ごと無効になる。さらに残った不正バイトが BSD sed を落としてスイートランナー自体を中断させた。本リポジトリはこの invariant をテスト（TC-8b-h）で持っていたが、走査対象が `*.sh` のみで SKILL.md の bash fence が blind spot だった。**教訓: 日本語文中に変数を埋めるときは常に `${var}` で囲む。既存の invariant テストがあっても走査範囲の外なら守られない — 範囲を確認する。**
- **静的 grep による契約 pin は「緩い substring 一致」に退化しやすい**: `grep -qE 'MARKER=1.*手動削除'` は救済文言が残っている限り判定値の反転を通す。前 cycle で「救済文言を要求すれば `x` 判定には存在し得ないので堅い」と書いた rationale が、値だけを反転する最小 mutation で反証された。**教訓: pin は「その状態でしか成立しない文字列」ではなく「判定値そのもの + 処方の組」を要求する。コメントに書いた rationale も mutation で検証する — 誤った rationale は次サイクルの reviewer の探索を止める。**
- **同型の欠陥は姉妹分岐にも当てる**: TC-3 に原因テキスト assert を入れたが、同じ構造を持つ TC-2b（push 失敗経路）には入れなかった。**教訓: 1 つの分岐に検証を足したら、同じ契約を持つ他分岐にも横展開する（Asymmetric Fix Transcription）。**
- **前 cycle の指摘対応が新たな診断品質の劣化を生むことがある**: `|| true` を撤去して FATAL 化した結果、(a) 同じ状態を正しい帰属で検出する後段 TC と役割が重複し、(b) 誤った原因を指し、(c) 後続 4 TC のカスケード中断を招いた。**教訓: 「握り潰しをやめる」修正は、既に別の場所で正しく検出されていないかを確認してから入れる。二重防御より正しい帰属を優先する。**
- **診断メッセージの分岐順序が実挙動と食い違う**: 両端チェックで rc ゲートを空チェックより先に置いたため、開始アンカー消失時にも「閉じアンカー未到達」と報告された。**教訓: 複数のゲートを並べるときは、それぞれが実際にどの入力で発火するかを列挙してから順序を決める。**
