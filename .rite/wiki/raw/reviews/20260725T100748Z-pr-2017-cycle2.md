### Finding Patterns

**cycle 1 の修正が持ち込んだ「テスト側の移植性違反」を 3 reviewer が独立に検出した**。前 cycle で追加した TC が bare `timeout` を使っており、macOS（本 Issue がまさに対象とするプラットフォーム）に `timeout(1)` が無いため、TC は skip ではなく hard FAIL する。リポジトリは同一問題に対し portable shim (`_timeout`) を確立し、その byte 同一性を専用 test で機械検査していたが、その drift guard は「shim を**定義する**ファイル」を discover する設計だったため、bare binary 呼び出しは全てすり抜けた。**規約の機械 guard が「正しい形の複製」しか見ていないと、「規約を無視した新規呼び出し」は素通りする**。

**「安全装置の存在」を pin する TC は「安全装置の値」を pin しない**。cycle 1 で追加した cycle-termination TC は hop cap を削除すると kill されるが、cap の値を 40 → 8 に下げても suite は green のまま通った。cap がカーネルの ELOOP 上限を下回ると、その差分のチェーン長で hook は解決を諦めて allow を返す一方カーネルは追従するため、多段バイパスが silent に再開する（reviewer が 9 ホップで実書き込み成功まで実証）。閾値を持つ安全装置は、**存在の TC とは別に「境界ちょうどの入力が期待どおり扱われる」TC** が要る。over-pin を避けるため、下限側（cap 相当のチェーンが deny）だけを固定し上限側は assert しないのが正しい粒度。

**バイト保全を一箇所で徹底しても、同じ関数内の別行で同じ切り詰めが残る**。deref ループでコマンド置換を排除した 2 行あとに `_tdir=$(dirname "$ABS_PATH")` が残っており、ディレクトリ名が LF 終端の場合に同種の乖離が起きる（reviewer が親 working tree への実書き込み成功まで実証）。ただし当該行は変更行ではなく origin/develop でも同一挙動のため revert test 不成立 = 本 PR の finding ではない。**「同じバグ型が同じファイルの未変更行に残っていないか」は伝播スキャンの対象**であり、見つかった場合は別 Issue として切り出す。

**reviewer の 0 findings は「フィルタで消えた」のか「反証した」のかを区別して報告させる**。security reviewer は 7 種の mutation と 20 件超の敵対的プローブ（CR / 多重 LF / TAB / UTF-8 / glob メタ文字 / 不正 UTF-8 / 先頭ハイフン / 二重スラッシュ）を実行した上で「指摘ゼロは Finding Quality Guardrail による全件フィルタの結果ではない」と self-assessment を明示した。この区別があると 0 findings の信頼度が判断できる。
