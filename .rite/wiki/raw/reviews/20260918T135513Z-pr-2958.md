### Finding Patterns

曖昧さを解消するための断定文が、別の軸で新しい誤読源を作る型が観測された。「X は Y のサブコマンドではない」を「Y のサブコマンドは Z だけ」と書き換えると、対比の文脈を外したとき Y の受理集合そのものへの主張になり、同一ファイルが実行している他の動詞と矛盾する。限定句（「時計の CLI 動詞は」等）を添えないと、記述が実装より狭くなる。

文書契約テストで繰り返し出た型が 3 つある。(1) 禁止形の走査 ERE が、実リポジトリで使われている起動形のバリアント（クォート付きパス `bash "$root/x.sh" verb`、接頭辞なしの bare inline code）を拾わず、宣言した契約より狭い範囲しか守れない。(2) 走査の self-check が scan 本体の正規表現を変数共有せず独立コピーで持つため、scan 側だけが drift したときに「走査が死んでいる」ことを検出できない。(3) ヘッダ/インラインコメントが実装より広い走査範囲を宣言し、コメントと実装が食い違う。いずれも実行時には発火せず検出網の弱さに留まるため、帰結クラス降格政策で class B として non-blocking に落ちる。

negative control は「literal を削った mutant で同じ grep が外れること」を見るが、literal がそもそも存在しない場合も mutant == source で pass する（vacuous pass）。共通ヘルパーの `assert_mutant_changed` を挟むと閉じる。

fenced block のラベル行を抽出キーにしている既存テストがある場合、同じ文書へ `# <label>` 形の見出しを増やすと抽出が ambiguous になって落ちる。散文追記はインライン backtick に留める。
