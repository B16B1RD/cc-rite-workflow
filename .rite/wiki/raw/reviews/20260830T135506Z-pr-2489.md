### Finding Patterns

- **散文カウントの drift（3 レビュアーが独立検出、最多合意）**: 判定式のループ対象を 5 → 4 変数に縮めたが、同一ファイル内の exit code 契約表とエラー処理表に残る「`n_*` 5 種」が更新から漏れた。追加した静的 pin テストは「判定基準散文 / bash if / residue gate」の 3 サイトを相互突合していたが、**契約サマリー系の散文（「N 種」という数詞要約）を pin 対象に含めていなかった**ため機械検知されなかった。集合を数詞で要約した散文は、集合そのものを列挙した散文とは別サイトとして pin する必要がある。
- **降格の波及が rationale アンカーまで届かない**: 本体の「informational 指標として完了レポートの内訳にのみ表示する」を修正しても、その 1 行ポインタが指す `references/rationale.md` の同じ主張が残る。CLAUDE.md の「rationale は references/ へ退避し本体に 1 行ポインタ」という構造は、**振る舞いを変えたとき本体とアンカー先の両方を直さないと偽の記述が 1 レベル下に残る**という特性を持つ。
- **whitelist ベースの集合抽出テストが AC を満たさない（mutation で実証）**: 「3 箇所が同一の変数集合を指す」ことを測るテストで、抽出を固定 whitelist の alternation にすると「whitelist ∩ 各サイト の一致」しか測れない。whitelist 外の変数名を 1 箇所にだけ足す mutation が全 assert を素通りし、しかも residue gate のループ変数リストにも無いため runtime backstop も効かず、整数比較の rc=2 が論理和に飲まれて `lint:clean` が silent emit される経路が残った。**集合一致を測るなら抽出は開いた regex にする**。
- **否定 pin と肯定 pin の重複・デッドコード**: 新規テスト 15 assert のうち、既存テストと byte 一致の複製 1 件、無効化されたパイプライン段 2 箇所、実際には測っていない性質を主張するコメント 1 件があった。集合一致 assert は否定 pin を強包含するため、両方書くと階層的な重複が生じる。
