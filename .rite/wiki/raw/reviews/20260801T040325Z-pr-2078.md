### Finding Patterns

cycle 5 (最終サイクル)。前 cycle で「防御を足す方向の修正がその防御自体を次の指摘面にする」型を
自覚して削除方向へ振ったが、今 cycle も同じ型が 3 件出た。今回明確になったパターン:

- **判定を直したが判定結果を載せる場所を直していない**: signal handler の「保存済み」分岐は
  3 条件 AND で正しく判定するのに、その結論を `json_saved` へ書き戻さないため
  `saved=false` / `JSON_SAVED=false` が emit される。**述語の正しさと sentinel の正しさは別**で、
  述語を直したら同じ turn で「その判定を読む下流」を全部辿る必要がある。
- **guard を足したがその guard を pin していない**: `--pending-id` の allowlist と
  `neutralize_ctrl` は、どちらを削除しても全 assertion が green のまま通った。既存 arm が
  brace 節で先に捕捉されるため allowlist 本体に assertion が届いていなかった。
  **「テストが通る」と「その防御が測られている」は別**。防御を足したら、その項だけを外す
  mutant で red になることを実測するまで完了ではない (前 cycle で 3 条件について実施した
  手続きを、同じ PR の別の防御には適用していなかった)。
- **コメントが保証を過大に主張する**: 新設した squat 検査のコメントが「TOCTOU を塞ぐのは
  set -C」と書いたが、bash の noclobber が拒否するのは既存**通常ファイル**だけで FIFO には
  効かない。実測 (300 回並走) で 18/300 が競合窓でハングした。**塞いだ範囲を実測より広く
  書かない** — 先置きケースを塞いだなら「先置きケースを塞いだ」と書く。
- **同一 PR 内での方針の逆行**: 説明的 Issue 番号参照を一方のファイルから削除しながら、
  同じ diff で別のファイルに 2 件追加していた。lint に pre-existing hit が多いファイルでは
  新規追加分が埋もれるため、削除と追加が同居していても気付きにくい。
