### Finding Patterns
- jq が emit する sentinel（`<no-status>` 等）を、新設した「未マップ列」分岐の前で intercept しないと、sentinel が列名として誤診断され、skill 側の routing 例外句（「列名が入っていれば再実行しない」）と組み合わさって既存の自動回復が抑止される。sentinel と列名を区別する分岐は role 変換の前に置き、skill 側の例外句は sentinel を明示列挙する。4 reviewer が独立に同一根本原因を検出した。
- 新規 bash block を skill に足すとき、その skill に `{plugin_root}` の解決行が無いまま placeholder を使うと literal 実行で失敗する。兄弟 skill の直 `source ... || { ERROR; exit 1; }` 慣習に揃える。
- 静的テストの検出文法は「実装の判定形」だけでなく「base 側に存在した形（定数代入 + 変数比較）」でも hits することを positive control で確認する。base 版に当てて 0 hits なら網が狭い。
- LLM が実行する散文手順書（references の判定表・option lookup）は shell の grep 文法で捕まらない判定サイト。AC「判定・書き込み 0 件」を満たすには reference の判定表も対象に入れる。
- pipefail 下のテストで `grep -n ... | head -1 | cut` を capture するときは `|| true` を付けないと no-match で suite が abort し else 診断も後続 TC も走らない。
