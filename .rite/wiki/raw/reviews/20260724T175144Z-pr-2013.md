### Finding Patterns

クロスプラットフォーム CI（macOS/BSD）green 化 PR に共通して現れた、rite プロジェクト固有の指摘パターン:

1. **canonical 化イディオムが fail-fast を反転させる**: `TEST_DIR="$(cd "$(mktemp -d)" && pwd -P)"` / `d=$(cd "$d" && pwd -P) || true` は、bash の `cd ""` が rc=0 で cwd を変えない性質により、mktemp/cd 失敗時に「実行時 cwd（= リポジトリ checkout）」を掴む。直後の `trap ... rm -rf "$TEST_DIR"` や `git init/commit` が repo 本体に着弾する。しかも `git status --porcelain` は clean のままなので、reviewer の post-condition invariant（porcelain hash / branch / stash）では検出できない。macOS 対応で `pwd -P` 正準化を入れるときは必ず 2 段階（`X=$(mktemp -d) || exit 1` → `X=$(cd "$X" && pwd -P) || exit 1`）に分けること。

2. **GNU ツールの shim は「契約」を全部再現しないと fail-open になる**: GNU `timeout` 不在環境向けの perl シムで `exit($? >> 8)` はシグナル死を exit 0 に写像する（GNU は 128+N）。呼び出し側の hang 検出イディオムが `[ "$rc" != "124" ] && pass` のような fail-open 形だと、シムのあらゆる故障（perl 不在の rc 127、シグナル死の rc 0）が「合格」に化ける。shim を書くときは (a) 全 exit code 契約の再現、(b) 依存コマンドの `command -v` ガードと不在時の明示 fail、(c) shim 自身の自己テスト（fallback 分岐を強制実行）の 3 点セットが必要。

3. **非 blocking leg でしか実行されないコードは死にコードと同じ**: `continue-on-error: macos-latest` の状態では、macOS 専用 fallback 分岐も、macOS 専用ロケール修正も、blocking gate である ubuntu leg では一度も検証されない。「informational leg 向けの修正」を入れるときは、blocking leg で revert を検出できるテストを併せて用意するか、検証されない旨を skip 台帳に明記する。

4. **否定アサーションに `|| true` を足すと signal がゼロになる**: 「出力が空であること」を検証する TC では、被テストコマンドの exit code が唯一残った crash signal。`|| true` を付けると abort と正常な無言が区別できなくなり、mutation を注入しても PASS する。肯定アサーション（grep で特定文字列を要求）の TC は crash で fail するため同じ変更でも安全 — この非対称を見落としやすい。

5. **環境依存 skip の台帳は「degrade 経路と同じ出力を返す TC」を取りこぼす**: スクリプトが GNU ツール不在時に `n_stale=0` + rc 0 で短絡する設計だと、「0 件を期待する TC」は degrade 経路でも PASS してしまう。skip ガードを入れる際は「期待値が degrade 時の出力と一致する TC」を全数洗い出し、機械可読な判別子（`stale_check_ok=true` 等）を assert に加えて fail-closed にする。

6. **skip 件数が集計されないと green の意味が痩せる**: `print_summary` が PASS/FAIL のみを数える設計では、20+ TC を skip しても「PASS: N, FAIL: 0」と表示される。クロスプラットフォーム対応で skip を増やすときは SKIP カウンタの導入をセットで検討する。
