### Finding Patterns

- **markdown 散文への grep pin は「隣の穴」を開け続ける — 3 巡した実例**: cycle 1 で「合計下限が削除軸に無反応」を指摘 → gate ごとの `-ge 1` に細分 → cycle 2 で「下限判定のまま・フレーズ有無のみ・除外理由が虚偽」を指摘 → 厳密等値 + 共起要求 + denylist + 構造 pin に置換 → cycle 3 で「構造 pin が Action セルの極性を固定していない・pass 行 Condition をどの層も拘束していない・denylist 列挙が同義表現を通す」を指摘。**各 fix は実測された穴を確実に塞いだが、同じ pin の隣接する穴を開けた**。共通の根は「pin が検査しているのはトークンの**出現**であって、行の**意味**ではない」こと。塞ぐには pattern 層を積むのではなく、行をセルに分割して Condition 列と Action 列の対応（「Condition が不一致なら Action は ERROR で始まり Gate passes を含まない」）を 2 値で検査する**構造的な述語**へ置き換える。

- **pin stack の過剰制約は別種の欠陥として跳ね返る**: 厳密等値 pin を積むと gate 表が事実上凍結され、実行手順書が謳う保守手順（「順序規定に 1 行足すだけ」）と両立しなくなる。pin を強めるときは、その pin が凍結する対象の**変更手順**が文書のどこかに書かれていないかを同時に確認し、書かれていれば同じ commit で更新すること。

- **mutation は「軸 × row class」の直積で当てる**: 削除・部分削除・意味反転・移動の 4 軸を揃えても、**どの行に当てるか**が漏れると死角が残る。実例: pass 行の極性反転は実測したが ERROR 行の極性反転は当てておらず、まさにそこが次 cycle の CRITICAL になった。pin が覆う row class（pass / ERROR / legitimate-skip）を列挙し、各軸を各 class に当てること。

- **denylist は SoT で禁じておきながら実装で使うと自己矛盾になる**: 「現行表記への係留を避けるため denylist ではなく allowlist で書く」という規約を自ら新設した PR が、次の cycle で denylist を第 1 層として導入した。allowlist で向きを固定できないなら、それは allowlist の書き方（肯定形の規約文言を必須トークンにする）を詰めるべきで、denylist で補うのは規約の実質的な放棄になる。

- **実測必須ゲートは「構造的にアンカーを持てない指摘」を永久に non-blocking にする**: 文書規約違反（行番号参照など）は再現コマンドも failing test も原理的に作れないため、実測必須ゲート下では 3 cycle 連続で fix が起動しなかった。これはゲートの設計どおりの挙動だが、**その種の指摘は記録コメント経由で人間が拾わない限りマージまで残る**ことを運用として認識しておく必要がある。
