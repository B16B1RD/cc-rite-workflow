### Finding Patterns

収束は 3 cycle。blocking の推移は 2 → 1 → 0 で、各 cycle の blocking はいずれも「前 cycle の fix が持ち込んだもの」だった。fix そのものではなく、fix の意図を説明するために書き足した文言（コメントの行番号参照、診断ラベルの原因断定）が新たな指摘面になっている。修正を書くときは、修正本体と同じ厳しさで「その修正を説明する文」も見る。

診断メッセージのラベルは、テストが 1 つも pin していない状態で 2 度書き換わり、そのつどスイートは全 green のままだった。文字列は無音で書き換わる。ただし契約（Issue の MUST / AC の Then）に現れない文言まで pin すると、次の正当な言い換えのたびにテストが落ちる。網羅的 pin 強化として記録に残し、契約に現れる出力（findings 行・件数 sentinel）だけを行まるごと固定する切り分けが機能した。

実測必須ゲートの効き方: cycle 2 で HIGH の指摘が実測アンカーを持たず non-blocking に落ちた。その指摘（自分が書いたコメントの行番号が同一コミット内で既にズレている）は事実として正しく、ゲートは「merge を止めるか」だけを決めるものなので、自分が書いた文の事実誤りは blocking 集合の外でも訂正した。ゲートを「直さなくてよい」と読み替えない。
