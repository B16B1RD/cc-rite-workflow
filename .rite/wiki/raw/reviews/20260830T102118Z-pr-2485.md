### Finding Patterns

リリース準備 PR（バージョンバンプ + CHANGELOG）のレビューで指摘 0 件。両 reviewer とも「件数一致」ではなく「集合一致」で検証したことが有効だった: `git log v0.13.2..HEAD --no-merges` の各 commit subject 末尾番号（PR 番号）を `gh pr view --json body` の closing keyword で Issue 番号へ解決し、その集合と CHANGELOG の `(#NNNN)` 集合を要素単位で突合することで、転記漏れ・余剰・PR 番号の混入を同時に検出できる形にした。件数だけの照合では「1 件漏れ + 1 件余剰」が相殺されて通る。

英日 CHANGELOG のパリティ検証も `(section, issue)` の組で比較しており、「番号は両方にあるがセクションが違う」ドリフトを検出できる形になっている。

最新タグの判定では `git describe --tags` を使わず `git tag --sort=-v:refname | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$'` を使う必要がある（リリースタグは develop→main マージコミットに付くため develop から到達不可能）。この経路は release skill が明文化済みで、両 reviewer とも従っていた。

バージョンバンプの網羅性検証は `grep -rn "{OLD_VERSION}"` を 5 ファイルスコープで実行するだけでなく、リポジトリ全体でも実行して「CHANGELOG の過去セクションと比較リンクのみが残存」を確認する二段構えが有効だった。
