### Finding Patterns

cycle 4。cycle 3 で修正した項目（negative control の行頭 anchor 化 + positive control、owner_repo allowlist、signal_aborted の loud emit、degraded 案内の分離、gh stub の --slurp 分岐）は 3 reviewer が独立に mutation で有効性を再確認した。新たに検出されたのは以下のパターン。

1. **テストの同期機構が観測不能な信号を待っている**: TC-4.9b が stub の hang marker を親 stderr で待つが、helper が gh の stderr を tempfile へ退避するため marker は到達しない。ループは上限回転して固定 sleep に退化し、時間依存同期になっていた。`_mktemp-stderr-guard.sh` 経由の stderr 退避は rite の 4 helper で共通の idiom であり、「stub の出力を親 stderr で観測する」テストは同じ罠を踏む。

2. **assertion が識別力を持たない**: `rc=143` は trap 由来の exit 143 と trap 設置前の signal death (128+15) を区別しない。狙った状態が作れていなくても PASS する。rc 単独を合格条件にせず、terminal sentinel の存在と対で評価する必要がある。

3. **hint / 案内文を判定分岐より前に出すと結末を断定してしまう**: degraded 縮退の案内が「記録は投稿されます」と言うが、count=0 の経路では投稿されない。案内は結末が確定した後に出す。

4. **カバレッジ穴は「reason 語彙 × test 参照数」で機械的に検出できる**: 文書化した reason のうち test 参照数 0 のものが 1 件だけ残っていた（unknown_option）。同じ集計で `rc >= 128` の分岐も無検査と判明。

5. **同じ事実の記述強度が箇所ごとに割れる**: 「1 件のコメント」「exit-1 reason は 6 種 / 7 種」が同一 PR 内・同一ファイル内で不一致。SoT を 1 つ決めても、追随更新の網羅は grep で確認しないと漏れる。

6. **gate の述語とテストの negative control の非対称**: gate は散文の部分一致、テストは行頭アンカー。診断出力が sentinel 形を再出力しうる場合、テストでは検出できず gate だけが騙される。
