### Finding Patterns

本 PR は reviewer の分類規則（散文の契約定義）を追加するもので、実行コードの変更ゼロ。3 reviewer が独立に検出した指摘のパターンは以下に集約された。

**1. 新規則の「既定（fallback）」が入力の欠損クラスを覆っていない**（2 reviewer 独立検出、HIGH）
規則本体が fail-loud 既定を持っていても、その発火条件が「参照が無い / 取得に失敗」といった *取得段階* の失敗しか列挙していないと、「取得はできたが参照先に該当節が無い」という *内容段階* の欠損が既定を素通りする。test-reviewer は実データで裏付けた（直近 25 Issue のうち 10 件が §4.4 / §5 を欠く）。**規則が外部文書を判定材料にする場合、判定材料の「不在」は 2 層（文書の不在 / 文書内の節の不在）で起こる**。片方だけを既定に載せると、規則が自ら掲げた原則と逆の帰結が既定になる。

**2. 判別子が「肯定的事実」を前提にするのに、その事実を確認する手順が無い**（HIGH）
分類規則の row が「既存 pin が保護している」型の肯定的前提を持つとき、判定手順にその確認ステップが無ければ、主張するだけで降格できる。**分類規則を書くときは、各 row の前提が判定手順のどのステップで検証されるかを対応付ける**。対応先が無い前提は、実質的に無条件の逃げ道になる。

**3. 判定の「評価レベル」が固定されていない**（HIGH）
「変異が無効化する挙動」のように、対象を *サイト（変異箇所）* で測るか *効果（観測可能な挙動）* で測るかで結論が反転する述語がある。手順側が lexical 判定（文面に現れるか）で、判別子側が効果基準だと、同じ入力に対して 2 つの row が逆の結論を出す。**述語を書くときは評価レベルを明示する 1 文を必ず添える**。

**4. 規則を追加しても、判断点（reviewer prompt）へ届いていなければ不活性**（HIGH）
新しい Gate を SoT ファイルへ書いただけでは、reviewer が実際に判断する位置（`reviewer-prompt-generator.md` の自問直下の注意書き）に届かない。同 repo の先行 PR #2095 は同じ理由で Target Files 外からこの注入点を追加している（Decision Log で承認）。**Gate を追加する PR は「SoT への記述」と「判断点への注入」を対で行う**。片方だけだと、文書上は存在するが運用では発火しない規則になる。しかも既存の注入行が「散文への指摘では」と *肯定的にドメイン限定* されている場合、新ドメインについては逆の signal（無制限）を出す形になる。

**5. 節構造の再編で、軸レベルの共通規定が旧ドメイン名を名指ししたまま残る**（3 reviewer 独立検出、HIGH）
既存節を「2 ドメイン構成」へ再編して小節を追加すると、その後ろに続く「他軸との関係」型の共通 bullet が旧ドメインのクラス名を名指ししたまま取り残される。**H3 を挿入して既存の共通記述を下位へ押し込む再編では、押し込まれた記述が全ドメインを覆う文言かを 1 件ずつ確認する**。

**6. 英日ペア文書で、片方だけが余分な限定を持つ**（MEDIUM）
`docs/SPEC.md`（英語）に「the fix itself introduced」という限定が入り、SoT（日本語 2 ファイル）には無い。この限定は過去データ表で 8 行中 2 行を特徴づける語であり判別子ではなかった。**同一主張を複数言語で持つ記述では、片方に「例示由来の語」が判別子として混入しやすい**。
