### Fix Patterns
- 判定関数（resolver）に値を通す前に、上流が出す sentinel を列挙して先に intercept する。sentinel を「未マップの値」として扱うと、診断が存在しない対処（列の role 宣言）を案内し、caller の routing 例外句と形が一致して既存の自動回復を止める。修正は「sentinel 専用の分岐を 1 つ足す + caller の例外句を sentinel を名指しして限定する」の最小差分で済み、他消費側は resolver 前に空値で短絡していたため伝播不要だった。
- 参照文書の手順（Markdown の判定表 + option lookup + 直接 `item-edit`）を role 化するとき、判定表を role 列に置き換えるだけでなく、書き込みは既存 helper（`projects-status-update.sh` に `status_role`）へ委譲すると、field-list / option id 抽出 / item-edit の 3 手順と未使用 placeholder がまとめて消える。追加より削除で解消できた例。
- 新規 bash block を skill に足すときは、その skill に `{plugin_root}` 解決の導線があるか grep してから置く。無ければ兄弟 skill の直 `source … || { ERROR; exit 1; }` 形に揃え、Plugin Path Resolution へのポインタを 1 行添える。
- 静的 pin の検出文法は base 版の実装に当てて hits が出るか確認する（0 hits なら網が狭い）。「識別子への定数代入」形は変数比較 1 段の間接で判定文法から漏れやすい。
- 修正中に emit した `[CONTEXT]` marker に消費者が無ければ削る（no_speculative_structure）。実装ではなく手順書への追加でも同じ。
