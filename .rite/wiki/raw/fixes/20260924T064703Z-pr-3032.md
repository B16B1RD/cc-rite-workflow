# fix 結果: if / ! が前に付く echo の grep -q パイプも here-string にする

## 対応した指摘

- test / HIGH: `if echo "$x" | grep -q` / `! echo ... | grep -q` の形が置換から漏れ、受入条件を満たしていなかった
- documentation / MEDIUM: 同じ節の「変換不要」表が修正後の記述と矛盾していた
- documentation / LOW-MEDIUM: lint の設計根拠文書が旧い echo 例外を挙げていた

## 修正

lint と同じ字句解析で producer を取り出し、`if` / `!` などの前置語を外してから判定し直した。残りを here-string に置き換え、同じ lint を tests/ に当てて対象が 0 件になることを確認した。文書は矛盾行を削除し、lint の例外判定をヘッダー・設計根拠文書と一致させた。

## 知見

- 機械置換の対象をツール出力の文字列の先頭で絞ると、前置語付きの行が丸ごと漏れる。対象の選別はツールと同じ解析で行い、完了条件は「同じ検出器で残件 0」にする。
- 変換スクリプトの対象はディレクトリで明示的に制限する。スキャン結果に範囲外（本番コード）の行が混ざっていると、制限しない変換は範囲外まで書き換える。変更後は計画の範囲と実際の変更パスを突き合わせる。
- テスト全体の実行が Python のキャッシュ（`__pycache__`）を作ると、入力ツリーのハッシュで変化を検出する検証が「入力が実行中に変わった」と判定する。キャッシュができた後の再実行で安定する。
