trend 8 → 5 → 4 → 6 → 3。blocking 3 件はいずれも cycle 4 の修正自身が対象で、うち 2 件は「閉じたはずの欠陥がアンカー / 分岐の選び方 1 つで開いていた」型だった。

1. **`jq` の `$` は文字列末尾ではなく「末尾または末尾改行の直前」に match する**（最重要・可搬性のある知見）。Oniguruma / PCRE 系の既定挙動で、`test("^foo$")` は `"foo\n"` に対して true を返す。この 1 点のせいで、marker 行の分断を防ぐために入れた形 allowlist が、まさに分断を起こす値（末尾改行付き）を通していた。教訓: **jq / Ruby / Perl 系の正規表現で「文字列全体の一致」を要求するときは `\A` / `\z` を使う**。`^` / `$` は行アンカーであって文字列アンカーではない。値を単一行の channel へ出す用途では、この差がそのまま欠陥になる。

2. **fail-safe を足すときは「倒れる向き」を既存の全経路と揃える**。7 つの reason はすべて広い側（フルレビュー）へ倒れるのに、あとから足した pin 読取だけが無音で狭い側へ倒れていた。しかも同じファイル内で、同じ resolver の失敗は別の箇所では WARNING 付きで扱われていた。教訓: **新しい情報源を足したら、その取得失敗が既存の fail-safe と同じ向きに倒れるかを確認する**。「情報が無い」と「情報が読めない」を同一視すると、片方の意味論だけが規範から外れる。

3. **「不在」と「読めない」は別物**。pin ファイルが無いのは正常系（新規 PR）だが、あるのに読めないのは異常系。区別せずに `[ -f ] && var=$(head -1 ...)` と書くと、両者が同じ「空」に潰れる。教訓: **存在チェックと読取を 1 行に畳むイディオムは、読取失敗を不在に化けさせる**。読取の rc を見るなら `if ! var=$(...)` の形へ分ける。

4. **production が通る経路と、テストが固定している経路は別のことがある**。consumer が `--pr` のみで呼ぶのに、テストは全ケースで `--since` を明示していた。結果、production 唯一の経路（既定 pin 読取）を無効化しても 4 スイートが全 green だった。教訓: **consumer の呼び出し形をテストに 1 本は写す**。オプションを明示するテストは「その分岐」を守るだけで、「既定でその分岐に入ること」は守らない。契約テストが呼び出し literal を pin していても、それは呼び出し側の記述を守るだけで helper 側の既定解決を守らない。

5. **語彙の drift 検査器は、新語を足すたびに登録しないと目的を失う**。reason 語彙の 3 コピー同期を守るループがあったのに、新設 reason がそこに登録されず、一行 pin も `A.*B` の形で新語を跨いで vacuous に PASS していた。教訓: **`.*` で繋いだ列挙 pin は、間に挿入された要素の削除を吸収する**。順序ごと明示するか、ループ側で 1 語ずつ回す。そして**検査器そのものが「新要素の登録漏れ」を検出できない**以上、新要素追加時のチェックリスト（何箇所に複製があるか）をコード側のコメントで持つ必要がある。

6. **到達不能な分岐を足す判断は、同じファイルで「到達不能コードを作らない」を根拠にした変更と両立しない**。cycle 3 で 2 機構を 1 本に畳んだ根拠が「2 本目の fail-safe が到達不能コードになる」ことだったのに、その統合で新しい到達不能 arm を作っていた。教訓: **1 つの commit で採った基準は、その commit が触る全箇所に適用する**。片方だけに適用すると、次サイクルのレビューで内部矛盾として指摘される。

7. **過去形のコメントは、制約の中身を保ったまま現在形へ書き換えられる**。「〜と書いた版では無音 drop された」は「〜と書くと無音 drop される」にすれば journal ではなく制約になる。教訓: **journal コメントの正しい処理は削除ではなく時制の変換**。削除すると再発防止の情報まで失う。
