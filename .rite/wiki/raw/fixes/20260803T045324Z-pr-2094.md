### Fix Patterns

本 cycle の中心は「前 cycle の修正が defect class より狭かった」2 件の是正で、いずれも**ガードを足すのではなく既存の述語を一般化する**形で解決した。

1. **文字クラスの一般化 (`0x1f` → C0 全域)**: 前 cycle は「区切り文字が値側でエスケープされない」列ずれを特定の 1 バイトの除去で塞いだが、**NUL で同じ迂回が残っていた**。NUL は列をずらさない — bash の command substitution が*削除*するため断片が連結し、`12<NUL>34` が `1234` という実在しない数値に化けて降格も WARNING も発火しない。迂回の *形* は違うが「区切り 1 種類だけを潰す実装では捕捉できない」という点で同一クラス。**教訓**: 特定の 1 バイト/1 条件で書いた防御は、その 1 件を直した直後に「defect class 全体を覆っているか」を問う。文字なら文字クラス、条件なら包含述語へ広げるのが定石で、広げると副次的に別経路 (本件では LF による herestring 切断) も構造的に閉じることが多い。

2. **遮断述語の一般化 (mismatch → identity 未確認全体)**: cross-Issue 転写の fail-closed ガードが「identity が*食い違う*」ときしか発火せず、**identity 判定に使うキー自体を削除すれば迂回できた**。しかも書き戻しがキーをファイル名側の値で再生成するため、次回 parse は valid に戻り痕跡も消える。**教訓**: fail-closed ガードは「異常を検出したら止める」ではなく「**正常を確認できなければ止める**」で書く。前者は検出材料の欠落で無効化されるが、後者は欠落そのものが停止条件になる。over-block の懸念は、到達しうる異常種別を列挙して確認すれば解消できる (本件では 2 種類しかなく、identity 無関係な種別は影響を受けないことを確認した)。

3. **診断文言は「リテラル」ではなく「振る舞い」で pin する**: 前 cycle で WARNING を条件付き表現へ直したが、その文言が宣言する挙動を通る走行が存在せず、文言を旧断定形へ戻す変異でも全アサーションが生存した。**同じ一文が同一 commit 内で既に 1 バイト drift していたこと**が未検査の直接証拠になった。**教訓**: 診断文言の修正に対しては、文言リテラルを assert するのではなく、その文言が主張する挙動を走行させて assert する。リテラル pin は他コンポーネントのメッセージ形式への結合を増やすだけで、drift には弱く保守コストだけが増える。
