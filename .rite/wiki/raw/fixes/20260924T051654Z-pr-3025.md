# fix 結果: 台帳を取るコメントの選択もテストで固定する

## 対応した指摘

- test / HIGH: テストの gh stub が `--jq` の選択式を評価せず固定の本文を返していたため、台帳をどのコメントから取るかがテストされていなかった

## 修正

stub が受け取った `--jq` 式を実物の jq でコメントの JSON 配列に適用するようにした。fixture の先頭には、台帳を含む非記録コメントを置いた。選択式を別の marker や先頭コメントに変える変異は、どちらも suite を失敗させるようになった（修正前は 2 つとも通過していた）。

## 知見

- 外部コマンドの stub は「どの引数を無視しているか」を明示的に確認する。引数の一部だけで分岐して固定出力を返す stub は、無視した引数が担う処理を丸ごとテスト対象から外す。フィルタ式・クエリ・選択条件のような引数は、stub の中で実物の処理系に通して評価する。
- 選択ロジックをテストするときは、fixture に「選ばれてはいけないが、選ばれると結果が変わる要素」を入れる。対象だけが並んだ fixture では、選択式が壊れていても結果が同じになり、テストが区別できない。
- 修正後は、レビューで生存が報告された変異を scratch 複製で再適用し、1 箇所に適用されたことを確かめたうえで suite が失敗することを確認する。
