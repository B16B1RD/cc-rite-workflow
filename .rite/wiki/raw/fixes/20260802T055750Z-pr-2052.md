### Fix Patterns

散文で定義した「機械的述語」が実データの外れ値を取りこぼす欠陥と、形式反転に伴うコメント陳腐化の 2 クラスに集中した。

1. **述語の定義軸を誤ると自己修復の対象そのものを掴めない**: 登録行の同定を「`|` で分割した最初のセル」で定義したため、まさに是正対象である「title に生パイプを含み列がずれた行」だけが同定できなかった (実測 333/342 一致、9 行取りこぼし)。是正は追加パッチ (破損行検出 → 中止分岐) ではなく**述語の一般化**で行うのが正しい — ページ列を「行内で最初に現れる `](pages/...)` まで」と位置で定義すると、壊れた行も掴めるうえ「他セルのリンクに一致させない」禁止条項が「最初に現れる」に吸収されて不要になる (実測 342/342)。分岐を足すと 1 ケース専用の面が増え、次 cycle でその追加自体が指摘対象になる。

2. **パイプを含み得ない列を anchor にすると列ずれ行でも決定的に読める**: サマリー列の位置は、更新日 (ISO 8601) と確信度 (enum) が構造的にパイプを含まない性質を使い**末尾から数える**と、サマリーに生パイプが残る行 (実測 29 行) でも 342/342 で正しく分離できた。先頭から数える設計は最初の壊れたセルで破綻する。

3. **到達不能な fallback は削除する**: サマリー決定順の候補 (2) が「新規ページ作成時にのみ実行されるステップ」を参照しており、更新経路では構造的に到達しなかった。dangling 参照を残したまま (3) の挙動だけ規定すると、読み手は到達しない分岐を前提に判断する。

4. **形式反転は遠くのコメントを一斉に陳腐化させる**: テンプレートのカタログ形式を反転させた結果、その形式を前提に書かれた rationale が実装 helper・SPEC・consumer・テストの 4 箇所で逆の主張をする状態になった。特に rationale が「reference md と実装 helper header」の双子で複製されている場合、md 側だけ更新すると canonical と名指しされている実装側が取り残される。形式を変える PR では旧形式の語で横断 grep し、コメント / テスト / SPEC の同型記述をすべて洗い出す。

5. **経緯は成果物に書かない**: 形式変更の経緯 (「#N で X へ変更したが実体は未移行のまま残り、#M で回帰させた」) を散文へ書き込む例が 4 箇所に現れ、`comment-journal-check.sh` が実検出した。PR 本文の「変更ファイルへの指摘なし」という自己申告と矛盾していた。経緯は PR description / commit message へ置き、成果物には現在形の制約だけを残す。前方ポインタ (未解決の追跡 Issue) だけは例外として維持してよい。

6. **同一ファイル内の確立済みパターンから外れない**: 同じファイルの別ステップが mktemp + trap + stderr 退避 + WARNING を確立しているのに、新規追加ブロックだけが `2>/dev/null` で rc と stderr を捨てていた。是正は `find` を 4 回から 1 回へ減らし、総数と内訳を同じ出力から数える形にした — 両者のズレが構造的に起きなくなるため、ズレ検査を別途足す必要がない。

### スコープ宣言との衝突

Issue の Non-Target 宣言 (MUST NOT modify) に載るファイルを、形式反転の帰結として変更せざるを得ないケースが発生した。3 レビュアーとも「変更内容は正しく、Issue 側の宣言を改訂すべき」で一致し、ユーザーもその方針を選択した。Non-Target は起票時点の前提に基づくため、PR がその前提自体を変える場合は宣言の改訂が正しい解決になる。宣言の根拠が「helper 委譲のため実害なし」のように *動作* についての判断である場合、*記述の正確性* には成り立たない点に注意する。
