### Fix Patterns

14 件すべてが「コードは直したが、その不変条件を語っている文・pin・SoT が旧状態のまま」という
単一の失敗モードに収束した。修正から抽出できる原則:

1. **不変条件を破る変更では、その不変条件を主張している文を先に grep で列挙する**

   最も危険だったのは、gate の ERROR text 自身が参照先に指定している reason 表が
   「この reason では gate は pass する / 再実行は任意」と断定していた点。実装は差し戻すのに
   文書が「誤報だ」と教えるため、**機械強制が言葉で無効化される**。gate の診断文・ERROR text・
   reason 表は単なる説明ではなく routing の入力なので、実装と食い違うと機械そのものが効かなくなる。

2. **同定に使う needle は位置まで固定する**

   人間可視文字列を避けて機械専用 sentinel (HTML コメント) を導入しても、位置非依存の
   `contains` では守れない。rendered view に出なくても **raw markdown の copy-paste では同伴する**
   (Edit view / `gh api` / `gh pr view --comments`)。実際、sentinel を扱う finding を fix が
   報告するたびに、その報告コメント自身が sentinel を verbatim で含んで機械的に再現していた。
   末尾 anchor にすれば、本文中に引用として現れた sentinel は構造的に除外される。

3. **同定条件を変えると既存データが silent に孤児化する — migration は述語変更の一部**

   条件を 1 つ足した瞬間、その条件を持たない既存レコードは検出されなくなる。「条件 A∧B は満たすが
   新条件 C に落ちた件数」を数えて WARNING に載せると観測可能になる。他の全 degraded 経路で
   WARNING を出す規律を持つコードで、述語変更由来の縮退だけ無音、という非対称は見つけにくい。

4. **read 側と write 側の条件は同時に、同じ強さで変える**

   read を末尾 anchor にして write を位置非依存のままにすると、条件を満たさない本文が投稿され、
   次 cycle の read が自分の投稿を miss して**レコードが増殖する**。片側だけ強めるのは
   「両方弱い」より悪い。

5. **数詞と列挙は変更のたびに全 artifact を横断する。ただし一括置換は危険**

   検査段数を 1 増やしただけで 9 箇所以上に散った。ただし同じ「3 段」でも「却下した旧設計を
   叙述している文」が混じっており、機械置換すると経緯の記述が壊れる。**rationale の過去形叙述は
   そもそも現在形の原則に書き換える**のが根本対処 (drift 源そのものを消す)。

6. **差し戻し機構は「同一 cycle 内の再実行」を新たに生む**

   retain 系の変更を入れると、同じ cycle 内で同じ識別子を持つ sentinel が複数並ぶ状態が初めて
   発生する。選択規則が cycle 間しか規定されていないと、解決済みの古い失敗を拾って誤報告する。
   選択規則は「層をまたいで同一」かつ「同一識別子内の tie-break」まで書く。

7. **coupling は変更のたびに列挙し直す**

   同型の coupling が 2 本 pin されているのに 3 本目だけ抜ける、が 2 cycle 連続で起きた。
   「write 側テンプレート ⇄ helper 定数」「step 1 の出力先 ⇄ step 2 の入力元」のように、
   2 箇所で同じ文字列を持つ関係は変更のたびに洗い直す。

### 手法上の知見

- **取り消せない外向き操作は fix に含めない**: legacy 孤児コメントの削除は reviewer の推奨に
  含まれていたが、GitHub コメント削除は不可逆なので実行せず、削除コマンドを報告に載せて
  ユーザー判断に委ねた。engineering fix (WARNING による可視化) と operational cleanup は分けられる。
- **live データでの検証**: mock だけでは migration 問題が見えなかった。実 PR のコメント一覧に
  新述語を適用して `legacy_orphan=1` を確認したことで、WARNING 機構の必要性が具体化した。
