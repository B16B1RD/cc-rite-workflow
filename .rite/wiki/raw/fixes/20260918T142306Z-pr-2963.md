### Fix Patterns
- 実測を伴わず merge を止めない分類になった指摘でも、その PR 自身が新しく足した誤記であれば同じ PR で直す。分類（blocking かどうか）と「直す価値があるか」は別の軸で、保存済みの分類は変えずに修正だけを正規の修正工程へ通せる。
- 対応表の列へ項目を足す前に、その表が自分で持つ列の定義（何を載せる列か）を読む。「消費する側」の列は読み取って分岐する側だけを載せ、上位の工程が経路を説明するだけなら載せない。
- 受け口の無い責務を足してしまったときの最小修正は、機構を足すことではなく、足した句だけを削ること。残すべき契約（理由と設定案内の保持、成功扱いの禁止）と削る句を文単位で切り分ける。
- レビュー中に自分で追記する記録行は、仕様照合で除外される定型書式に揃える。書式が外れると、同じ run の修正工程が「仕様が変わった」と判定して編集前に止まる。
