### Fix Patterns

- ガードを追加するとき `if ! cmd` の短絡形は「失敗」と「判定不能」を融合する。存在確認系コマンド（`git show-ref` は不在=1 / リポジトリ外=128、`git ls-remote --exit-code` は不在=2 / 通信失敗=128、awk は不一致=1 / 異常終了>=2）では rc を明示捕捉して 3 分岐にしないと、判定不能が「不在＝正常系」に丸まり「やっていないことを完了と報告する」false-success を生む。これは #2016 の元欠陥と同型で、修正のたびに別の場所へ再導入されやすい。
- 前 cycle の修正が新しい安全経路を足したとき、その経路には回帰 pin が付いていないことが多い。実際「新経路を無効化しても全 TC 緑」が 3 経路で成立していた。新経路を足したら同じ commit で pin も足す。
- 静的 pin は `literal` の存在だけを見ると、分岐を `if false; then` で殺す mutation を素通しする（literal は死んだ分岐に残る）。**条件式そのもの**を pin すると殺せる。
- 構造アンカーに `^esac$` のような閉じトークン単体を使うと、入れ子が増えたとき「組数」が変わっても検出できない。開始アンカーと組数の両方を要求する。
- 「N 経路すべてが marker を emit する」のような数を含む散文は、経路を足すたびに嘘になる。数ではなく marker 名の列挙で書く。
- テスト fixture のコメントが「この fixture が X を直接 pin する」と書いていても、実際の発火経路は別のことがある（同名タグは「タグが消える」ではなく「ambiguous dst で push が失敗する」経路で効いていた）。fixture を足したら実際にどの assertion が落ちるかを mutation で確かめてから説明を書く。
- `sed 's/^/  /'` によるインデントは改行区切りの行頭にしか効かない。外部由来テキストに CR が混じると表示上は列 0 に着地するため、インデントを security boundary にするなら `tr -d '\r'` を挟む。
