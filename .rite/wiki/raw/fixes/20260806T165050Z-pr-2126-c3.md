### Fix Patterns

trend 8 → 5 → 4（下降）。cycle 3 の blocking 4 件のうち 3 件が「cycle 2 で追加した検査機構そのもの」への指摘だった。ここで個別パッチではなく**機構を 1 本に畳んだ**ことが本サイクル最大の判断で、以下はその周辺で得られた知見。

1. **「検査してから使う」を 2 つの式に分けると、必ず 3 種類の欠陥が同時に生える**（最重要）。検査述語と使用側条件を別々に書いた瞬間に、(a) 両者がずれても気付けない（検査は「非 null」、使用側は `type == "string"` と書いた版では非文字列が検査を通って使用側で無音 drop された）、(b) 検査が真を返した後の使用側は構造的に失敗しえず、そこに置いた fail-safe が到達不能コードになり、それを pin していたテストが空振りする、(c) 検査が「不正あり」で**正常終了**する主経路では stderr が空なので、`2>$err` + `head` 形式の原因出力が構造的に常にゼロ行になる。教訓: **検査と使用は同一の式に畳む**。畳むと使用側条件がそのまま検査述語になり (a) が消え、fail-safe が 1 本になり (b) が消え、違反要素の id を同じ式内で列挙できるので (c) も消える。3 つを個別に直すより行数も分岐も減る。「guard を足す」修正は「二重機構を足す」修正でもある。

2. **`$probe_err` に原因を求めてよいのは「外部コマンドが異常終了した」経路だけ**。述語が偽になっただけの経路では jq も grep も正常終了するので stderr は空。同じ診断イディオムを全経路にコピーすると、この経路だけが「対象は出るが原因が永久に出ない」状態になり、しかも見た目は他の経路と同一なので気付けない。教訓: 診断出力を書くとき、**その経路で stderr に何かが入る保証があるか**を経路ごとに確認する。無い経路では原因を自前で作る（違反した要素の id を列挙する等）。

3. **移送を伴うゲートの consumer は 2 箇所ある**。cycle 2 で「finder を選ぶ側」の母集団を 2 配列の和に広げたが、「同じ指摘を reviewer に渡す側」を旧定義のまま残した。結果、reviewer は再起動されるが検証対象を渡されず、再導出も禁じられているので指摘が消える — 直そうとした喪失が半分残った。教訓: **同一データを読む箇所を grep で数え上げてから直す**。「選ぶ」と「渡す」は別の consumer で、片方だけ直すともう片方が silent に契約を破る。5 reviewer が独立に報告したのは、この非対称が下流のあらゆる観点から見えるため。

4. **新機能の「範囲を絞る」指示は、同じ prompt に届く既存の原則ブロックと衝突する**。共通レビュー原則の revert test は `{base_branch}...HEAD` を literal で指定しており、新しい mandate の `{cycle_base_sha}..HEAD` と 2 つの baseline が同時に reviewer へ届いていた。同じ行が一方では「追加行」、他方では「context 行」になるため判定が反転し、削ろうとしていた重複調査がそのまま再現する。教訓: **prompt に注入される全ブロックを列挙し、同じ概念（baseline / スコープ / 基準）を定義しているものが他に無いかを確認する**。あれば読み替え規則を明示する。cycle 2 の「identity 宣言と handoff 文字列」と同じクラスの failure で、2 サイクル連続で出た。

5. **post-condition の skip 条件が新機能の強制値と噛み合うと、最も要る場面でだけ検査が消える**。差分スコープは `review_mode = "full"` を強制し、解消検証の silent skip を検出する post-condition の skip 条件は `review_mode == "full"` だった。結果、解消検証が要求される cycle 2+ でだけ検査が必ず skip される。教訓: **既存の分岐変数に新しい値を強制代入する変更を入れたら、その変数を読んでいる箇所を全部洗う**。特に「skip 条件」は、強制代入と組み合わさると無効化の形で現れて green のまま素通りする。

6. **肯定リテラルの grep pin は加法的否定を原理的に検出できない**。cycle 2 で「文の続きまで pin を伸ばせば撤回節の追記に対処できる」と書いたが、実測では pin の後ろに撤回節を足す変異が素通りした。パターンを足しても同じ理由で必ず失敗する。教訓: **検出不能なクラスは「検出不能」とコメントに明記して、次のサイクルが同じ試みで空転するのを防ぐ**。手法の限界を pin の書き方の問題と誤認すると、無限に pin を足し続けることになる。
