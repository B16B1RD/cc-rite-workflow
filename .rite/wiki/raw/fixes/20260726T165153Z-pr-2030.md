### Fix Patterns

「cycle 1 の修正が cycle 2 の指摘を生んだ」構造への対処として有効だったパターン:

1. **canonical パターンは「置き場所」と「識別子」まで含めて踏襲する**: gate や sentinel を新設するとき、既存 canonical の *存在* だけを真似て *構造* (result-emit boundary の外に置く / iteration_id で cycle を識別する) を落とすと、gate は形だけになって機能しない。新設前に「同型の既存 gate はどこに、どんな鍵で置かれているか」を必ず読む。

2. **二層 gate は「内側 = integrity check」「外側 = 全体 skip の fallback」と役割を明記する**: 本リポジトリの 7.7 ⇄ 8.0.2 が canonical。内側だけだと守る対象と運命を共にし、外側だけだと部分実行を見逃す。6.1.d も step 3 (内側) + 8.0.3 (外側) の二層に揃えた。

3. **降格を緩めずに可視化する**: 「no-match なら降格」は fail-safe として正しいので regex を緩める方向には直さず、「アンカー文字列はあるが full regex が no-match」を 2 段判定で切り出して WARNING + cause 付き marker を出す方向に直した。**fail-safe の維持と観測性の追加は両立する**。

4. **判定語彙を変えたら sweep 範囲は「判定ルール本体 → 出力境界 → escalation 経路 → few-shot 例」まで**: blocking の定義変更で、5.3.x は修飾したが 8.1 の override 指示・5.1.1.1 の「全件 blocking 扱い」・finding-examples.md の模範例が漏れた。判定基準を変える PR では**その基準を参照する側を全部 grep する**のがコスト最小。

5. **サブシェル内で fail を呼ばない**: コマンド置換から呼ばれる helper で `fail` を呼ぶと (a) カウンタ加算が親に伝播せず (b) 出力が呼び出し元変数に吸収されて sentinel と連結する。stderr に出して自己説明的な sentinel を返し、判定は親の比較に委ねる。

6. **「同一ロジック」と書いたら実際に同一化する**: 3 重化ブロックのドリフトは、コメントを事実に合わせるより実体を揃える方が良い (差分がラベル語と変数名だけになれば同期契約が機械的に守れる)。

7. **markdown 埋め込み bash は静的 pin で最低限の網を張る**: helper 抽出が本 PR のスコープを超える場合でも、述語・marker・gate の存在を grep ベースで pin すれば drift は検出できる。完全な hermetic テストは follow-up に切り出す。
