### Fix Patterns

**機械的な述語を文書化するときは、意図の語彙ではなく字句の語彙で書く。** 本 cycle の 8 findings のうち 5 件が同一根で、いずれも「判別子は字句的 (marker から `=>` までの間に改行 / `<br>` / 句点があるか) なのに、記述側が意味論の語彙 (「書き損じ」「散文中の言及」「折り返しアンカー」) で言い換えていた」ことに起因した。意図の語彙は読みやすいが、判別子が意図を読めない以上、必ず「そう意図していないのに同じ帰結になる入力」を生む — 実際、折り返していない 1 行アンカーでも LHS に句点が 1 字あれば降格し、実測済み CRITICAL が merge を止めなくなる経路が「安全」と読める形で残っていた。日本語で散文を書くリポジトリでは句点は最も踏みやすい文字であり、この乖離は理論上の話ではない。

**修正方針として「条件節の追加」ではなく「語彙の一本化」を選んだ。** 3 cycle かけて帰結記述を条件付きに直してもなお同型の指摘が出続けたのは、面ごとに条件節を足すたびにその追加自体が次 cycle の指摘面として再生産されるため。意味論の言い換えを削除して字句条件 1 本へ寄せると、面の数は変わらないが記述の自由度が消えるので drift の再生産が止まる。Simplification-First の Escalation trigger (同一 PR の前 cycle fix が導入した箇所への指摘) はこの判断を明示的に要求する。

**同一文言を 2 箇所に持つ場合は機械的に一致検証する。** helper の WARNING 文言とその SoT (assessment-rules.md) は literal 一致が契約なので、編集後に `grep -o` で両者を抽出して文字列比較した。目視同期は必ずずれる。

**pin の欠落は変異注入でしか見つからない。** test reviewer が 18 種の変異を注入し、survivor は 1 件 (`MEASURED_DEMOTED_ON_ANCHOR` の `cause=` フィールドが pin から外れていた) だった。前 cycle の編集で assertion を別 TC へ移した際に literal の一部が落ちており、通常のテスト実行では検出できない。
