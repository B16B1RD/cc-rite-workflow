### Fix Patterns

今回の 13 件は、根っこを 2 つに束ねられた。

**(1) 「成立条件そのもの」ではなく「その影」を検査していた**。update-in-place コメントの同定を
marker の前方一致だけで行っていたが、前方一致は「rite が書いたか」を表現できない。投稿本文の検査も
非空だけで、「1 行目に marker があるか」を表現できない。どちらも update-in-place が成立する条件の
影であって条件そのものではないため、第三者コメントの掴み取りと marker 消失が両方通り抜けた。
**修正の型**: lookup に author 条件を連言で足し、本文検査を「非空 → 1 行目 marker」の 2 段にする。
検査したい性質を直接述語にする。

同じ形が静的 pin にも出た。「対象文字列が存在するか」「区間内に N 回出るか」は gate が live かどうかの
影であり、コメントアウト（部分一致が通る）でも散文追加（数が相殺される）でも欺ける。
**修正の型**: 出現数の等値ではなく `**Check**: ...` のような load-bearing な行そのものを
`assert_grep_in_section` で要求する。副産物として「無害な散文追加で落ちる」false positive も消える。

**(2) caller 契約違反と実行時失敗を同一条件に潰していた**。`[ ! -s "$file" ]` は「ファイル不在
（Write 呼び出し漏れ = 定義バグ）」と「存在するが空（IO 失敗）」を区別しない。前者を非ブロッキング
側に潰すと、記録が一度も行われないまま「評価された」として gate が pass する。
**修正の型**: 契約違反は loud な exit 1、実行時失敗は非ブロッキング、と reason を分ける。同じ helper 内で
placeholder residue は exit 1 なのに本条件だけ非ブロッキング、という内部非対称は設計ミスの兆候。

### 派生して見えた 3 点

- **gate が読む機械可読 control line は、その値を作る引数側で完全性を担保する**。改行入りの値を
  無検証で sentinel に埋めると完全な形の偽 sentinel を生成できる。denylist では防げず allowlist が要る。
  さらに **gate の ERROR 診断が値を verbatim に echo すると、診断行の中に偽 sentinel が再現する** —
  制御文字の無害化まで含めて 1 セット。
- **SoT の列挙・件数・「唯一の〜」型の断定を変えたら、consumer を grep で洗い出す**。今回は
  「記録先 3 経路 → 4 経路」で 6 箇所が旧値のまま残り、うち 1 箇所は SoT と正面から矛盾する断定文に
  なった（同一ファイル内の自己矛盾も 1 件）。
- **文書の式から修飾を落とすと、同じ段落の散文と衝突する**。SoT の式が持つ inline caveat と追加の
  連言を落とした結果、式のとおり読むと 2 文あとの記述と矛盾する状態になった。読者は太字の式で読み
  止まるため、補足に頼らず式そのものに修飾を残す。
