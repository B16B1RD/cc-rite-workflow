### Fix Patterns

新規 bash helper + skill 配線 + 横断文書同期という構成の PR に対する cycle 1 の修正。
6 件の blocking 指摘はすべて「判定ロジック本体」ではなく「判定の結末を人間へ正しく伝える層」に
集中しており、修正も同じ層に閉じた。

1. **1 行 trap 形の見落とし**: `trap '...' EXIT INT TERM HUP` は INT/TERM/HUP の action に
   `exit` を持たないため bash が signal を consume し、スクリプトが**継続実行して exit 0 で終わる**。
   Ctrl-C は foreground プロセスグループ全体へ届くので in-flight の子プロセス (jq) が殺され、
   valid な入力に対して**偽の異常 reason を rc=0 で返す**。呼び出し側の `rc -ne 0` guard も
   素通りするため、誤った原因が停止通知まで運ばれる。sibling helper が canonical 4 trap 形
   (`EXIT` は rc 保存、`INT`=130 / `TERM`=143 / `HUP`=129) を持つ領域に新規 helper を足すときは、
   trap 形の一致を copy-paste ではなく **signal を実際に送って rc を観測**して確かめる。
   非ゼロ終了は既存の caller 分岐がそのまま backstop へ縮退させるため、新しい fallback は要らない。

2. **診断転記の出力順**: 「WARNING 行 + 後続インデント行 = 1 単位」の継続行規約を採る
   コードベースでは、診断を WARNING の**前**に出すと直前の別 WARNING の継続行位置に着地して
   原因が誤帰属する。転記呼び出しを各 call site に散らすと順序が site ごとにブレるので、
   WARNING を出す共通関数 (`_undecidable` 等) の内側へ**集約**するのが正しい形 (3 site → 1 site)。
   これは追加ではなく削除方向の修正であり、Simplification-First と一致する。

3. **「格下げ」の断定とパラメータ実値の乖離**: 機構の役割を再定義する PR
   (「上限は滅多に発火しない純粋な保険」) で、断定文だけを書き換えてパラメータ既定値を
   据え置くと断定が偽になる。しかも評価順 (上限を trend より先に見る) のせいで、
   その PR 自身が「保護対象」と名指しした実測列が backstop に殺される。
   **役割再定義 PR では「断定文」「既定値」「評価順」の 3 点セットを同時に検証する**。
   既定値を触らない判断をしたなら、断定文の側を実態へ落とす。

4. **定量的約束の伝播漏れ**: 停止通知の「もう N cycle 回る」のような**定量的な約束**は、
   発火条件が cycle 数と無関係な機構へ移った時点で偽になる。この種の文言は
   (a) テンプレート本体 (b) それを引用する差し替え規則 (c) 実装コメント内の引用
   の 3 箇所に散るため、grep で literal を洗って同時に直す (Asymmetric Fix Transcription)。

5. **診断サーフェスの assertion が dead になる典型**: 「原因行が届くこと」を pin すると称する
   grep が、**隣の assertion が pin 済みの文字列の部分文字列**でしかないケース。守ると称する
   変異 (`2>/dev/null` の再付与) を通す。needle は**その出力元にしか現れない形**を選ぶ
   (ここでは resolver 自身が出す `bash: <path>:` prefix。ENOENT 本文はロケール依存だが prefix は不変)。
   mutation testing が判定式には適用されていても診断サーフェスには適用されていない、という
   偏りが起きやすい。

6. **自分の fix が新規 lint 違反を導入する**: 修正文中に `Issue #N` の説明的参照を書いたところ、
   リポジトリ自身の `comment-journal-check` が新規 finding として検出した。fix 後は
   **変更行に対して repo の lint を回し、baseline との差分がゼロであることを確認する**。
