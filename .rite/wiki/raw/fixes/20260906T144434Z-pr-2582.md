### Fix Patterns

実測付きの指摘が 2 件あったが、いずれも severity が非 fatal のため修正対象にならず記録のみで cycle が終わった。

1. **実測の有無と severity は別軸で、両方を満たさないと修正対象にならない**。実測必須ゲートは「測っていない指摘を blocking にしない」ためのもので、測ってあっても重要度が閾値に届かなければ fatal にはならない。帰結クラスが A（実行時に何かが壊れる）であっても、severity が MEDIUM なら fix ループは動かない。この設計は収束を保証する代わりに、class A の非 fatal 指摘を記録へ送り続ける。

2. **修正コミットが無い cycle でも state の永続化と記録は必須**。fatal 0 件は「何もしない」ではなく「移送件数と記録先を報告して通常完了へ進む」。ここを 0 件終了に丸めると、記録契約が空文になる。
