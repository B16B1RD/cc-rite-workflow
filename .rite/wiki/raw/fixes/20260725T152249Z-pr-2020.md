### Fix Patterns

`set -euo pipefail` 下のシェルテストで `var=$(cmd | jq -r '... // empty' 2>/dev/null)` を書くと、jq が非ゼロ終了した瞬間に代入コマンドの終了ステータスがスクリプト全体を落とす。`2>/dev/null` が診断も捨てるため出力ゼロで死に、後段に置いた「想定外の出力形式」検出分岐は不正 JSON の経路では構造的に到達しない dead branch になる。runner が exit code で集計していれば silent pass にはならないが、どのテストケースで何が起きたかは完全に失われる。

修正の型: 判定を JSON パースではなく **stdout の形状**（空か / 特定文字列を含むか）で行い、jq を介在させない。適用の前提として「判定に使う文字列が payload 内に 1 回だけ現れ、自由文フィールドには現れない」ことを実測で確認する必要がある。確認できれば部分一致はパースと同じ厳密さを保つ。

分岐順序も設計対象になる。exit code を出力形状より先に見ると、「非ゼロ終了しつつ正しい判定結果を返す」経路（fail-closed の deny + exit 2 等）が「クラッシュ」と誤診断される。出力形状を先に、exit code を後に置くと両者が正しく分かれる。

診断メッセージには stderr（`$(cat -v "$STDERR_FILE")`）を含める。空出力 + rc=0 で落ちるケースでは rc と抽出値が何も語らないため、原因は stderr 側にしか残らない。
