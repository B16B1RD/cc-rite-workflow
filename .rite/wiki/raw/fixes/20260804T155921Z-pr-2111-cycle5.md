blocking 6 件をすべて修正し、変異 3 本の fail 化 + SIGINT 12 回の明示中断を実測してからコミットした。

## 適用した修正パターン

- **fail-loud ガードは出口網羅で張る**: 「異常値 (空文字) が返る」という症状側から関数の全 return 経路を列挙し、同じ帰結に至る兄弟出口 (セル数不足の早期 return・ループ 0 回転) を 1 本のセル数ガードに畳んだ。ガードの下限は境界 TC (正当な空セル 5 列行が rc=0) で pin し、過剰発火側への倒れも同時に固定する。
- **文書化した不変条件 1 つに TC 1 本**: docstring が明示する性質 (FIRST link 同定・回収は毎回走る) は、その性質を壊す変異を書いてみて現行スイートが green のままなら未 pin。狙い撃ち TC を足してから変異で殺せることを確認する。
- **trap は canonical 4 行形 + mktemp 前武装**: exit code を契約にする helper では、EXIT 単独 trap は INT を exit 0 の silent no-op へ変換しうる。宣言 → cleanup 関数 → 4 行 trap → mktemp の順序を守り、後段での trap 再武装 (上書き) を排除する。cleanup 対象は空文字宣言 + `[ -n ]` ガードで mktemp 失敗経路にも安全。
- **安全網の主張は不成立経路を先に探す**: 「後段の lint が拾う」と書く前に、lint が発火しない経路 (更新経路の旧値残存) を探し、不成立側では「表示した ERROR が唯一のシグナル」と明記して完了レポートへの転記を義務化した。
- **marker 表は行動だけを書く**: 複数原因が畳まれた marker 値の説明に単一原因を書かない。原因は WARNING に委ね、表は読者が次に取る行動 (WARNING を表示して続行) だけを規定する。
