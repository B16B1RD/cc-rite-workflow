### Fix Patterns

1. **ガードの向きを反転させる修正は、旧 failure mode の再現条件を鏡像にして必ず確認する**:
   「不足側で判定を降ろす」恒久無効化を撤去した次の cycle で「過剰側で判定を降ろす」ガードを足し、
   同じ恒久無効化を逆向きに再導入した。向きを変える修正では、直した失敗の再現条件をそのまま
   反転させて新実装に当てて、成立しないことを実測する。

2. **判定を降ろしてよいのは「入力そのものが未知」のときだけ**: 境界（pin）が既知なら、
   カウンタとの不一致は別の量のズレであって境界の不確かさではない。両者を 1 つのガードに
   畳むと、既知の入力でも判定を捨てることになる。ガード条件は「何が未知か」で書く。

3. **状態の開始を別状態の値で代理判定すると、その値をリセットする経路の数だけ穴が空く**:
   run 開始を `cycle_count == 0` で代理していたが、counter が 0 に戻るのは「発火時」だけで
   正常終了時は残るため、次 run が前 run の pin を引き継いだ。開始/終了は対で明示的に書く。

4. **「原理的限界だから直せない」と書く前に、その限界自体を実測する**: 順序契約のテストで
   「非 C locale なら検出できる」と書いたが実機の ja_JP も CI の C.UTF-8 も同順で検出できず、
   en_US.UTF-8 を明示すれば塞げた。限界の主張はコメントとして残り後任の修正を止めるため、
   通常のコードより検証の要求水準が高い。

5. **`od -c` のアドレス列は 8 進**: `grep -c '033'` は ESC 0 バイトでも入力サイズによって
   マッチする。バイト検査には `od -An -c` を使う。
