## 経験則

- 手順書に bash step を追加するときは「その値がどの Bash 呼び出しで確定し、どこで消費されるか」の呼び出し境界を必ず確認する。境界を跨ぐ値は brace placeholder + marker emit の既存 idiom 一択で、marker の fallback sentinel (`:-none` 等) はリテラル置換経路で誤真判定を誘発するため空文字に統一する
- LLM 手順書内で複数の map を突き合わせる場合、全 map の入力源 (正規化前/後) を明記して揃える。helper が tempfile 上でのみ normalize する構成では、原ファイルから独自構築する map に normalize 前の値が混入する
- canonical サンプルを追加したら、同 PR が定めた invariant (除外規則・写像の非対称) との突合を必ず行う — サンプルの自己契約違反は 4 者検出されるほど目立つ一方、書いた本人は見落とす
- 静的 parity テスト (出現数 + 行順) は到達性と emit 内容を守れない。predicate の直前行 pin と emit 行の固定文字列 pin を対で追加する
