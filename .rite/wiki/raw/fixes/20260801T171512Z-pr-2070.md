### Fix Patterns

本 cycle の 2 件は同型だった: **「正しさを宣言したが、その宣言自体を固定していない」**。

1. **anti-pattern 回避が新しい欠陥を生む** — テストが旧表記 `ステップ 3-7 を skip` を anti-pattern として禁じていたため、著者は `ステップ 3-7.4` という新表記で回避した。しかし `## ステップ 7.4` という見出しは実在せず、読み手が「7.4 という段階が別にあるのか」を推測で解く余地が生まれた。**教訓: anti-pattern の assert_not_grep を追加したら、回避策が別の欠陥へ逃げないよう positive 側 (置換後の表記が実在見出しへ解決するか) も同時に pin する。** 修正では「7.4 を説明する注記を足す」のではなく「実在しない段階への参照そのものを消す」方向を採り、`ステップ 3-7 (7.5 を除く)` へ統一した (端点が実在見出しのみを指し、旧 anti-pattern にも該当しない)。

2. **cross-file 契約をコメントで宣言してテストで pin しない** — helper のコメントが「リンク regex は `wiki-lint-orphans.sh` と同一定義にする」と宣言していたが、既存 TC-40 は自分側が拾えることしか測っていなかった。狭める変異は kill できるが、広げる変異と相手側の drift は 1 件も検出しない。片側だけ drift すると entries が部分的にしか減らず `entries >= 1` が保たれるため、同 PR が新設した検出失敗ガード (`entries==0 && linkrows>0`) も skipped_rows も発火せず hits が無言で過少集計になる — その PR 自身が塞ごうとしていた silent-0 と同型の穴が、ガードの内側に残っていた。**教訓: 「2 実装で同一定義」とコメントに書いたら、その literal のバイト一致を突合するテストを対にする。片側の振る舞いテストは parity を保証しない。**

### Fix Strategy Notes
