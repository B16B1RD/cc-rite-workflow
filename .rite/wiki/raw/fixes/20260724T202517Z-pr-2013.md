### Fix Patterns

1. **規約を書いた変更自体が規約を破っていないか、書いた直後に grep する**: CONTRIBUTING に「capability probe には blocking gate の床を付ける」と明文化した同じ PR が、4 つの probe のうち 1 つに床を付けていなかった。しかもそこは相互排他という並行性不変条件のカバレッジで、skip ラベルに「不変条件が破れた観測値」を書き込みながら緑を返していた。規約を追加したら `grep` でその規約の適用対象を全列挙し、自分の差分が全件満たしているか確認する。

2. **フィルタしたストリームに `grep -n` すると行番号が壊れる**: `grep -v '^#' file | grep -n pattern` は「コメント除去後の何行目か」を返す。単一ファイルなら気づくが、走査対象を数百ファイルに広げると数百行ずれた無関係な位置を指し、診断が誤誘導になる。元ファイルに採番する単一 awk パス（`awk '!/^#/ && /pattern/ { print FILENAME ":" NR ": " $0 }'`）にすれば構造的に起きない。

3. **「拒否した」つもりの exit code が caller に「成功」と読まれていないか確認する**: perl の `die` は 255 を返す。`_timeout` の caller は全員「124 でない = hang なし」と読む契約なので、`die` による拒否はそのまま silent pass になる。拒否・エラーを追加するときは、その exit code が既存 caller の判定表でどこに落ちるかを確認し、テスト対象外の専用コード（125 等）を選ぶ。

4. **集計 parser は summary 行の形に anchor する**: `sed -n 's/.*, ([0-9]+) skipped.*/\1/p'` は行内容を無差別に拾うため、失敗診断文が `, 7 skipped` を含むと +7 誤カウントする。`^[^❌]*Results:[^❌]*, ([0-9]+) skipped` のように「summary 行であること」を要求すると誤検出が消える。あわせて「可視マーカーはあるのに解析結果が 0」を format drift として WARNING にすると、将来書式が増えたときの取りこぼしが可視化される。

5. **`| tee` によるストリーミング化は `set -euo pipefail` の runner では危険**: 失敗テストがパイプライン経由で runner 自体を中断させ、以降のテストが走らず summary も出ない。さらにパイプはテストが残すバックグラウンドプロセスを待つため実行が不安定になる（実測でタイムアウト）。可観測性の改善案でも、runner の制御フローを壊すなら採用しない判断が要る。採用しなかった理由はコメントに残す。

6. **ファイル全体を `exit 0` で skip すると PASSED に計上される**: 前提ツール不在で `echo "SKIP: ..." >&2; exit 0` する形は、runner から見れば「成功したテストファイル」であり skip 集計にも現れない。counted な形（`SKIP: 1` を stdout に出す等）にしないと、可観測性の改善が届かない死角が残る。
