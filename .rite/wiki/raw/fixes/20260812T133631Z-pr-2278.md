### Fix Patterns

「証明する機構」を新規に足す PR では、証明が成立しない経路が複数同時に残る傾向がある。本 cycle の 14 件中 7 件が「checker が green を返すが実際には何も検証していない」形だった: 抽出述語が行頭 0 桁アンカーで対象の大半を取りこぼす / base ref 未解決を clean skip に潰す / 空 base ref が git index (`:path`) と比較して常に一致する / rail 0 行でも等値比較が成立する / テストの assertion が exit code のみで「一致」と「not applicable」を区別しない。いずれも単体では小さいが、合成すると「証明が空回りしても緑」という同一の帰結に収束する。

有効だった修正戦略:

- **抽出述語は sibling helper と正規表現を揃える**。`bash-heaviness-check.sh` は同じ SKILL.md 群に対し既にインデント fence を扱っており、新規 checker だけが後退していた。同じ対象を走査する helper が既にあるなら、その述語を流用するのが最短かつ drift しない。
- **exit 0 の多義性を潰す**。「一致」と「対象が無いので skip」を同じ exit code に載せると、呼び出し側の assertion は必ず片肺になる。skip 側を減らす (base ref 未解決は exit 2) か、呼び出し側でメッセージ照合を足す 2 段判定にする。
- **削除で直せる指摘は削除で直す**。未使用 `--quiet` は TC を足すのではなくフラグごと削除した (呼び出し元ゼロ + regression proof なし)。
- **CI の赤は「テストが落ちた」だけでなく「テストが走らなかった」形で来る**。GNU 専用 `sed -i` は macOS で TC-005 を中断させ、drift 検出を証明する 6 ケースが一度も実行されないまま suite が落ちていた。ローカル (GNU sed) では 17/17 green のため、この形は実行環境を跨がないと観測できない。

過剰反応の傾向: 検出された「証明の穴」に対して guard を積み増すのではなく、証明対象を一度も読めていない状態で停止する (exit 2) 方が短く、fail-loud 原則とも一致した。
