blocking 1 件の直し方が本 cycle の主眼だった。`assemble.sh` の preset 配列リテラルを変えたことで、そのリテラルを **awk で字面抽出して等値比較**していた `check-contract.sh` の pin が壊れた。ここで期待値側に新しい接頭辞（`$scene_dir/`）を書き写す最小パッチを当てると、次に変数名や探索先の表現を変えた時点で同じ誤報が再発する構造が残る。そこで **basename 列の比較へ寄せて接頭辞への依存自体を外した**。pin の意図（M1〜M7 の順序とファイル名契約）は保ったまま、pin が守る対象と pin が観測する表現を分離した形になる。「追加より削除・単純化を先に検討する」が、テストの pin にも同じ形で効く事例。

もう 1 つは **新設した guard 自身が defect class の隣接メンバーを取りこぼす**形。`-d` を黙って無視しないための guard を足したが、述語が `[ -z "$scene_dir" ]` で「未指定」と「明示的な空文字」の sentinel を共有していたため `-d ""` で不発した。しかも preset 側の既定値代入が空文字を `out` へ silent 置換するので、`-d "$EN_DIR"` の変数が空だと**日本語素材から組んだ mp4 が `-en` の名前で exit 0 完成する**。下流の fail-loud 検査（シーン存在・尺・フレーム周期・BGM 尺・出力実尺照合・可聴性）は素材の言語を見ないので全部通る。修正は getopts の解析時点で空値を拒否する 1 行で、guard を足す位置を「消費する場所」から「値が入る場所」へ移すと両分岐の穴が同時に閉じた。

**新設した sibling 群がガードの対象集合から漏れる**形も出た。`scenes-en/*.html` 7 本を追加したのに決定論スイープの glob は `scenes/*.html` のままで、英語シーンだけが契約ガードの外側にあった。同じ PR の DESIGN.md に「契約ガードを 1 組に保つため同一ディレクトリへ置く」と書いた直後にその主張が実装で成立していない、という非対称が生まれていた。
