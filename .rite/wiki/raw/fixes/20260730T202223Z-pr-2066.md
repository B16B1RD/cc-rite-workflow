### Fix Patterns

**診断行を足すこと自体が新しい攻撃面になる**: 「読出失敗の理由が消えるのは良くない」という正しい動機で入れた `sed "s|^|  ${page}: |"` が、外部由来のパスを sed のプログラム文字列へ補間する形になっていた。区切り文字が `|` なのでパス中の `|` が s コマンドを終端させ、GNU sed の `e` コマンドで残りがシェルへ渡る。**変数を sed の式側へ入れてはならない。式は定数にして、変数は別行で中和して出す。** sibling が例外なく定数 sed だったのに 1 ファイルだけ逸脱していた点も、parity を主張するヘッダコメントがあるだけでは守られないことを示している。

**規約のガードが自分自身の違反を構造的に見落とすことがある**: 診断スニペットの中和 parity を測る test は `grep -v 'neutralize_ctrl'` で行を落としていたため、同一行に `neutralize_ctrl` を含む違反行が検査対象から外れていた。**「規約を守っている印」を除外条件にすると、印を持つ違反が不可視になる。**

**CI の platform leg を実リポジトリ走査に依存させない**: positive control が「実リポジトリ全体の `--all` が 1 件以上返す」ことに依存していたため、awk 実装差で 0 件になる macOS leg が red 化し、しかも同 leg では後続の除外 assert 6 本が丸ごと vacuous になっていた。**片方の platform でだけカバレッジが消えるテストは、赤くなるより静かに無効化されるほうが害が大きい。** sandbox に fixture を置いて測る。

**レビュー指摘に応えて足した機構こそテストが抜けやすい**: 「検出器の破損を read_errors へ伝播させる」ゲートは前 cycle の指摘に応えて追加したものだったが、他の全機構が mutation で赤くなる中でこのゲートだけが変異しても全緑だった。**指摘対応で足したコードにも、既存機構と同じ mutation discipline を当てる。**

**同じ規則の 2 実装は、片方だけテストされている状態になりやすい**: 左語境界は片方の検出器では振る舞いテストがあり、もう片方では静的 pin すら無かった。regex literal の一致を測る drift test も、抽出範囲が語彙 alternation の中間に限られていたため両端の追加を取り逃がしていた。**drift test の抽出範囲は、実際に起きる変更の形（末尾への語彙追記）を含むか確認する。**

**実測値は書いた時点のベースラインに紐づく**: 「EOF 打ち切りとの差 81 hits / 13 ページ」は書いた時点では正確だったが、後続 cycle で見出し規則が変わりベースラインが動いた結果 28 hits / 7 ページになっていた。**同一 PR 内でも、後続の変更が前の実測値を stale にする。**
