### Fix Patterns

1. **人間に渡す手順で SoT helper を「同等品」に置き換えない**: `state-path-resolve.sh` の代わりに `git rev-parse --show-toplevel` を書くと、linked worktree では前者が main checkout へ unify するのに対し後者は worktree root を返す。結果、復旧コマンドが rc=0・無出力で別ディレクトリに stray な state を作り、直すべき対象は手つかずで残る。「同じ値が得られそうな標準コマンド」は worktree・symlink・sandbox のいずれかで必ず分岐する。SoT helper を呼び、さらに対象ファイルの実在を gate にして空振りを明示エラーへ倒す。

2. **差し替え規則は「単位」を物理構造に合わせて書く**: 「コマンド行を差し替える」と書いても、対象が 1 物理行の注意文の内側にコマンドを埋め込んでいる場合、独立した「コマンド行」は存在しない。部分置換すると注意行に注意行が入れ子になり、さらに同じ bullet 内の別の参照（探索先パス等）が置換から漏れて到達不能な案内が残る。差し替え単位は「bullet 全体」「注意行全体」のように、実際の物理構造に対応する語で書く。

3. **「直接確認するほかない」と書く前に、その確認が事後に可能かを検証する**: flow-state の handoff キーは Stop hook の consume-handoff が `jq 'del(.handoff)'` で**再注入と同時に**削除するため、事後に覗いても常に不在で確認手段にならない。診断手段を提示するときは「その時点でまだ観測可能か」を確かめる。特に one-shot consume される値は、消費後の確認が構造的に不可能。

4. **SoT 委譲チェーンの終端ノードは他から訂正されない**: CONFIGURATION.md → contract.md のように「正確な条件は委譲先が SoT、ここでは再掲しない」と明示委譲すると、委譲先の誤りは他のどのドキュメントからも訂正されない。終端ノードの記述精度は、中間ノードより高い基準で保つ必要がある。
