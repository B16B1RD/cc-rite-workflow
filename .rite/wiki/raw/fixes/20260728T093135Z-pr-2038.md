### Fix Patterns

1. **同じ述語を 2 言語で並行実装しない — 定義を 1 本に寄せる**

   read (jq) と write (shell) で「最終非空行が X と等しい」を別々に実装していたため、
   4 cycle にわたって「両側は同一述語」と書きながら受理集合が割れ続けた。乖離軸は
   (a) 正規表現エンジンの空白クラス (Oniguruma は locale 非依存、glibc grep は locale・実装依存)、
   (b) 文字除去の範囲 (`sub("\r$";"")` = 行末 1 個 ⇄ `tr -d '\r'` = 全 CR)。
   **定義を 1 本にすると同値性が検証項目ではなく構造的な帰結になる。** 述語を 3 回差し替えても
   構造を変えなければ同型の欠陥は再発する。

2. **`assert_not_grep` は「対象が fixture に存在する」ことを前提にしないと恒真になる**

   直前 run のログを読む assertion が、その run の fixture に対象 id を含まないため、述語を
   退行させても pass し続けた。**not_grep 系には必ず positive control を対で置く**
   (「掴んではいけない id を掴まない」の隣に「掴むべき id を掴む」)。
   加えて、run を共有する assertion は隣に別の TC を挿入した瞬間に壊れる — 各 assertion 群の
   直前に自前 run を置く規律を全体に適用する。

3. **canonical 完全一致 pin は、非対称な状態を「正解」として固定してしまう**

   ドリフト検出のために置いた pin が、片側だけ更新された文言を canonical として固定したため、
   非対称そのものが検出不能になっていた。**pin を追加した後に「両側が同一であること」を別の
   assertion で担保する**か、少なくとも pin 更新時に対になる側も確認する。

4. **「両側に置いた」と書いたら grep で両側を確認する**

   commit メッセージ・Retained flag mapping・Routing 表の 3 箇所が「両 gate に置いた」と
   宣言していたのに、実際には片側だけだった。宣言と実体の照合は 1 コマンドで済む。
