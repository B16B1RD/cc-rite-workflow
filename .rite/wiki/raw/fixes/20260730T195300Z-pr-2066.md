### Fix Patterns

**`grep -c` を終端に置いた pipeline は rc を検査対象にできない**: `grep -c` は no-match で rc=1 を返すため、pipeline の rc では「0 件」と「途中の異常終了」が区別できない。結果、検出器そのものが壊れたときだけが「実測済みの 0 件」として未実測ゲートをすり抜けた。計数を同じ awk 内に閉じると rc が意味を持つ。**「0 件が実体を反映しているか」を surface する enum を設けるなら、検出器自身の破損もその enum に載る形にする。**

**除外の rationale と実装のスコープがずれると、rationale が正当化していない範囲まで落ちる**: 「`sources[].ref` は provenance のファイルパス」を根拠に frontmatter 全体を落としていたが、実データの `description:` 散文には本物の参照が 22 件あった。しかも ref 値はファイルパスで検出規則に元々一致しないため、除外は防御的で実効ゼロだった。**除外を書くときは、rationale が名指しした対象と実装が落とす範囲が一致しているかを実データで確認する。**

**同じ exit code を返す gate が複数あると、exit code だけの assert は当の gate を pin しない**: placeholder residue gate を削除しても後段の別 gate が同じ exit 1 を返すため、テストは緑のまま通った。**gate を pin するなら、その gate 固有の診断 marker まで assert する。**

**`cd ""` は rc=0 を返す**: sandbox 生成の rc を検査していないと、失敗時に空文字列が返り `cd "$SBX" || exit 1` のガードが素通りする。以降の相対パス操作（`git add -A` / `commit` / `rm -f`）がテストプロセスの cwd = リポジトリに対して走る。**command substitution で作ったパスは、使う前に rc または非空を検査する。**

**同じ規則を 2 実装に持つなら、drift を検出する仕組みを同時に置く**: 語彙を 1 語足すたび 2 箇所の同期が要るのに、ずれを検出する手段が無かった。実装の共通化が難しい（読出元も計数単位も違う）場合でも、literal の一致を assert する test は置ける。

**契約の gloss を sibling からコピーすると、発火条件の違いが消える**: `io_error` の条件が「1 件でも失敗」と「全件失敗」で違うのに、sibling の gloss をそのまま流用したため、部分失敗時の警告経路が到達不能に読める記述になっていた。
