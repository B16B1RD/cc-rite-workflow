### Fix Patterns

1. **「count が state と一致する」前提に依存した境界復元は、非ブロッキング契約と中断経路で必ず破れる**:
   同一ディレクトリに複数 run のデータが同居する状況で、run 境界を「末尾 N 件」(N = LLM 側の
   counter) で切り出す設計は、「1 cycle につき成果物 1 件が必ず保存される」を暗黙の前提にする。
   本リポではその前提を破る経路が 2 本ある — (a) 保存 helper の D-04 非ブロッキング契約
   (保存失敗でも exit 0)、(b) counter を成果物生成の**前**に increment する順序 + resume が
   counter を戻さない設計。境界は counter ではなく「run 開始時点の実データ」で pin する。

2. **ガードを足すより境界の定義を変える**: 「total > N なら判定不能」型の追加ガードは、複数 run
   同居が通常運用である以上、機構を恒久的に無効化して終わる。指摘が「ガードが素通りする」形で
   来ても、ガードの強化ではなく**そのガードが守ろうとしている代理値を捨てられないか**を先に見る。

3. **helper 委譲時、判定値だけ配線して「判定できなかった理由」を捨てると全面不作動が観測不能になる**:
   helper が stdout に載せた reason= を caller が 2 フィールドしか抽出しないと、機構が完全に
   死んでいる状態と正常系の marker が byte 一致する。委譲リファクタでは verdict と reason を
   セットで配線し、正常系の不足 (無音でよい) と異常 (WARNING を出す) を入力値で切り分ける。

4. **「A ⇒ B」を前提にした差し替え条件は、A の一部が B を満たさない瞬間に無言で壊れる**:
   「insufficient なら推移は空」を前提に空判定で分岐していたが、insufficient の 1 種
   (need_3_cycles) だけが非空の部分データを返すため、判定にかけていない値が判定済みとして
   描画された。判別子は導出値 (空か) ではなく一次値 (verdict そのもの) を使う。

5. **決定論テストは「2 回同じ」だけでは識別力ゼロ**: 実装を無出力にしても両辺が空文字で一致して
   PASS する。決定論の assert には必ず「何が決定論的に出るか」の中身固定を併記する。
   本 cycle は 22 変異のミューテーション検証で当該 assert が 1 度も落ちないことが実測された。

6. **境界条件の両辺を同時に踏む fixture しか無いと片側変異が通る**: `>` の a 側・b 側を
   同時に満たす列 (4,4,4,4) だけを pin していたため、a 側だけを `>=` に緩める 1 文字改変が
   全 PASS のまま通った。片側だけを踏む列 (4,4,5) を独立に pin する。
