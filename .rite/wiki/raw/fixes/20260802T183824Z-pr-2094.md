### Fix Patterns

- **分岐を足すときは、その分岐を覆っている既存コメントの射程を読み直す**: `if`/`else` 全体を統べる位置にある解説ブロックに「rc は条件に使わない」と書いてあると、`else` 側に rc を条件とする新分岐を足した瞬間、その解説が新分岐を「誤報」と宣言する形になる。コメントの適用範囲は物理的な配置で決まるので、分岐追加は既存コメントの意味も変える。
- **診断文の主語は発火条件が保証している対象に限る**: 「値を carry-forward しました」は、発火条件が「parse が corrupt かつ .data が読めた」だけなら保証されていない。実際に採用されるかが後段の override 次第なら、そう書く。
- **コメントの例示は一般命題が真になる側から選ぶ**: 「個別 key の欠落は無警告」は非必須 key では真だが必須 key では偽。例示に必須 key を挙げると、例だけが命題の反例になる。
- **同型の guard は同型に pin する**: 隣接する 2 つの guard (python3 側と jq 側) が同じリスク構造を持つのに片方だけテストで固定していると、もう片方の除去が無検知で通る。同一 diff 内で非対称を作らない。
- **到達不能な防御コードはテストで殺せない — 削除が正しい対処**: mutation で生存した防御コードを「テスト不足」と読むと不要な TC が増える。到達可能な入力を構成できないなら coverage hole ではなくデッドコード。
- **WARNING が断定した挙動はそのまま assertion にできる**: 「sync_revision を 1 から採番し直します」と書いた分岐で、その値を assert していなかった。診断文は仕様の宣言でもあるので、テストの assertion に変換する。
- **否定・既定値の assertion は、値が偶然一致しない fixture で書く**: 「1 に採番し直す」を検証する fixture の元値が 1 だと、mutation を入れても Green のまま通る。seed を 2 回回して 2 にしてから壊すだけで判別力が出る。
- **PATH shim は選択的にする**: 外部コマンドを全面的に失敗させる shim は、そのコマンドに依存する無関係な TC を巻き込む。対象の呼び出しを引数で見分けて、それだけを失敗させる。
