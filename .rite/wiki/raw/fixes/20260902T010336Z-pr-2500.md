### Fix Patterns

- **入力検証・停止強制・pin は「守る対象に隣接する位置」に置く**: 検査を書いたかではなく、どこに置いたかで効果が決まる。charset 述語を節末の「後置条件」に置くと同じ節の内側にある consumer を守れない（後置条件は定義上それより前の置換を遡れない）。述語は「値が変数に代入される時点」に置く。
- **fenced bash の停止を散文の判定表に委ねない**: `echo ... >&2` で終わる else 分岐は block 全体の exit status が 0 になり、停止が LLM の読解に依存する。同一プラグイン内に `exit 1` を置く先例があるなら揃える。
- **grep pin は「生産側」（emit 行）にアンカーする**: 同一リテラルが emit 行と判定表行の両方に現れる場合、file-wide の `assert_grep` は他の pin によって恒真化する。
- **既存の同型行と衝突する pin は隣接性で絞る**: 節スコープの `^  exit 1$` は同節の別ガードにも一致し、追加した exit だけを消す変異を素通しする。marker emit 行からブロック終端 `fi` までの範囲に限って要求する。
- **否定 pin は動詞の列挙ではなく class 述語で書く**: 4 動詞の deny では列挙外の削除手段（リモート ref 削除・`find -delete`）のインライン化を検出できない。例外も「自ブロックが mktemp した一時ファイルの後始末（削除対象が shell 変数のみ）」のような class として書く。
- **awk の正規表現で `\[` は文字クラス開始に潰れる**: `/\[CONTEXT\]/` は `[CONTEXT]` = 文字クラスになり意図した行に一致しない。marker 名だけでアンカーする。
- **終端 Status の冪等分岐は state ではなく stateReason で割る**: `CLOSED` を単一分岐にすると自動クローズされた `COMPLETED` Issue が中止経路へ流れ込む。
