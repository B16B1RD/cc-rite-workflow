# fix 結果: 起票前確認の batch 判定を処理中の Issue に束縛し、手順書側の配線をテストで固定する

## 対応した指摘

- test / HIGH: 修正本体（手順書の判定ブロック・helper 呼び出しの配線・完了報告の行）を固定するテストが無かった
- correctness / MEDIUM: batch 判定が run-queue の状態だけを見て、処理中の Issue を照合していなかった
- test / MEDIUM: 全件解消・書き出し失敗・空値の境界が未固定だった
- prompt / MEDIUM: 本文確認の表示が利用者に届かない書き方だった

## 修正

兄弟スキルと同じく cursor の Issue と対象 Issue の一致を条件に加えた。手順書の bash ブロックを抽出して fixture で実行するテストと、呼び出し行・判定表の行を固定するテストを加え、配線を外す・束縛を外す・表の行を消す等の変異がすべて検出されることを確かめた。

## 知見

- ERE で Markdown の表の行を固定するときは `|` をエスケープする。`^  | ...` は「行頭が空白 2 つ」または「...」の選択になり、表の行を消しても一致し続ける（空振りの assert）。変異で表の行を消し、assert が落ちることを確かめて初めて気づいた。
- grep のパターンが `-` で始まると、オプションとして解釈されて一致しない。`[-]-name` のように先頭を文字クラスにする。
