### Fix Patterns

cycle 3 の修正は「前 cycle で足した構造を消す」方向だった。ここに一般化できる型がある。

1. **同じ失敗クラスが 2 cycle 続いたら、境界ではなく構造を疑う**: cycle 2 は override 条件を `-ge` → `-gt` に直した（境界の位置の修正）。cycle 3 の指摘は「そもそも可変値との相対比較で終端状態を表している」という構造の問題だった。**1 度目の修正が「条件式の中の定数・演算子」に留まったとき、2 度目の指摘は同じ場所の構造を指している可能性が高い**。境界を動かして直る問題と、表現方法を変えないと直らない問題を区別する。

2. **新しい状態変数を足す前に「覚えておく必要があるか」を問う**: 「発火済み」を次回起動まで持ち越すために marker を導入したが、発火した瞬間にリセットすれば覚える必要が無かった。既存の不変条件（発火時に handoff が default-clear されるので自動再入場経路が無い）が、そのタイミングでのリセットを安全にしていた。**持ち越しをやめられないか**を先に検討すると、marker・override 分岐・デッド変数・設定値依存が一度に消える（実際 -15 行）。

3. **canonical パターンを参照するときは分岐まで写す**: 「canonical な stderr 退避パターン」と称して tempfile 方式を写したが、参照先が持つ「mktemp 失敗時の `2>&1` フォールバック」を落としていた。結果、mktemp が失敗すると実在する診断を自分で捨てる。**参照先の失敗経路まで読む**。なお今回は tempfile をやめて `2>&1` capture に統一したほうが単純で、mktemp・rm・縮退トークンの 3 点が同時に不要になった。

4. **1 つの操作に複数の契約を背負わせたら、失敗時の開示も契約ごとに分ける**: fire 分岐の単一 set が handoff クリアと counter リセットの 2 契約を持つのに、失敗時の WARNING が結果を一括して「安全側」と断じた。ブレーカーには真、AC-2 には偽で、停止通知が虚偽を述べる。契約が増えたら開示も増やす。

5. **enum の値集合は相互に非接頭辞に保つ**: `failed-refire` が `failed-refire-nodiag` の接頭辞になり、prose 照合（LLM の grep）が誤分岐しうる状態だった。「完全一致で照合せよ」と指示するより、そもそも接頭辞関係を作らないほうが強い。今回は値を減らすことで構造的に解消した。
