### Fix Patterns

- **pattern 層の積み増しをやめ、行をセルに分割して「列と列の対応」を検査する**: markdown の表を静的 pin で守るとき、行全体に対する `grep -E 'A.*B'` はトークンの**出現順**しか見ないため、セルの意味（極性）を反転されても本数が変わらない。`awk -F'|'` で Condition 列と Action 列に分割し、「Condition が X を述べる行の Action は Y で始まり Z を含まない」という**対応関係**を 2 値で検査すると、文言の言い換えと極性反転の双方に耐える。3 巡した再発（下限判定 → 厳密等値 → 共起要求 → 極性未固定）は、いずれも「出現を見て意味を見ない」同じ根から来ていた。

- **pin のコメントに「保証しないこと」を明記する**: 保証と実装の乖離（#2030 F-09 型）が繰り返し指摘の源になるのは、コメントが pin の守備範囲を過大に書くから。「本 pin が保証しないこと」を節として置き、そこに漏れる経路と、なぜそれを許容するのか（例: 散文は判定の実体ではなく、判定を決める表の側を構造的に固定してある）を書いておくと、次の reviewer が同じ穴を「隠れた欠陥」ではなく「宣言済みの境界」として読める。

- **mutation は「軸 × row class」の直積で当てる**: 削除・部分削除・意味反転・移動の 4 軸を揃えても、**どの行に当てるか**が漏れると死角が残る。実例: pass 行の極性反転は実測したが ERROR 行の極性反転は当てておらず、まさにそこが次 cycle の CRITICAL になった。pin が覆う row class（pass / ERROR / legitimate-skip）を列挙し、各軸を各 class に当てること。テストの fixture も同様で、境界値（1 桁 / 多桁）を 1 種類しか持たないと、抽出正規表現の桁退行を検出できない。

- **pin を強めるときは、その pin が凍結する対象の「変更手順」が文書のどこかに書かれていないか確認する**: 厳密等値 pin は対象を事実上凍結するため、実行手順書が謳う保守手順（「順序規定に 1 行足すだけでよい」）と両立しなくなる。pin と手順書は同じ commit で更新すること。pin を緩めて手順書に合わせるのは、mutation 検証済みの pin を無効化するので誤り。

- **denylist を SoT で禁じておきながら実装で使うと自己矛盾になる**: 「現行表記への係留を避けるため denylist ではなく allowlist で書く」という規約を新設した PR が、次の cycle で denylist を第 1 層として導入した。allowlist で向きを固定できないなら、allowlist の書き方を詰めるか、判定の実体（表）側を構造的に固定するべきで、denylist で補うのは規約の実質的な放棄になる。

- **degraded 経路は「2 分岐」で書く**: lookup が縮退したとき、件数 > 0 なら新規作成で重複、件数 0 なら投稿自体を省いて前 cycle の記録が stale で残る。文書が前者しか書いていないと、後者（収束したのに古い件数が PR に残る）が運用上見えなくなる。縮退の帰結を書くときは全分岐を列挙すること。
