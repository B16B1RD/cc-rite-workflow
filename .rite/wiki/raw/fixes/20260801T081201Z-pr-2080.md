### Fix Patterns

cycle 1 で「限界」を散文で書いた箇所が cycle 2 で 2 件指摘され、どちらも修正した。主張は両方とも正しく、外れていたのは主張を支える具体例と数え方だった。

**限界説明に添える例は、その検出器に実際に食わせてから書く。** 「同一行しか見ない」という限界の例に同一行の形を挙げてしまい、例が主張を否定していた。修正では差し替えた 2 例（2 行形 = 非検出、行末コメント形 = 検出）を両方とも検出器に食わせて挙動を確認してからコミットした。散文の主張は頭の中で検証できるが、例は実行しないと逆を書く。

**「〜としてのみ使う」型の断定は grep で数えてから書く。** consumer 経路を 2 箇所取りこぼしていた。結論は変わらなくても、列挙の取りこぼしは「この値は誰が読むのか」を後から判断する読み手を誤らせる。

**scope=nit-noted でも、受け流しの記録が残らない構成なら同 cycle で直す。** rite の reviewer は subagent で PR に inline comment を投稿しないため、nit reply の投稿先 thread が存在しない。つまり「nit として認知した」痕跡が PR 上に残らない。1 語で直る不正確さをこの状態で受け流すと、記録も修正も残らないまま次 cycle の再指摘リスクだけが残る。reply 経路が実在する構成とは判断が変わる。

**Target Files 制約でスコープ外の指摘は、修正せず follow-up の受け皿を明記して返す。** 「専用スキャナへ移設すべき」という指摘は正当だが移設先が Non-Target。reviewer 自身も「本 PR では現状維持」を推奨対応の第一候補に挙げていた。走査面を先に広げると現存違反サイトが即 FAIL して AC が破れるため、移設と実体修正は 1 つの follow-up に束ねる必要がある。
