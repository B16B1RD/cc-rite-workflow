- **散文への substring 検査は 4 世代強化しても収束しない — canonical 文字列の完全一致へ転換する**: 合計下限 → セクションごとの下限 → 厳密等値+共起 → セル分割の構造述語、と 4 世代にわたり pin を強化したが、各世代とも「実測された穴は塞ぐが隣の穴を開ける」を繰り返した。4 世代目のセル分割ですら (a)「違反 0 件」期待の述語は対象行が 0 本でも 0 を返す、(b) `一致` を含み `不一致` を含まない否定形言い換えを通す、(c) Action 列の先頭を固定していない、の 3 経路が残った。**解は pin の強化ではなく設計転換** — canonical なセル文字列そのものを期待値としてリテラル固定すれば、言い換えも極性反転も原理的に通らない。意図的な変更は期待値の更新という形で必ず人手を経る。「毎回落ちて煩わしい」のは欠点ではなく、それが「不変条件を再確認せよ」の強制になる。

- **「違反 0 件」を期待する pin は domain の非空性も同時に固定する**: `count(violations) == 0` 形は検査対象が存在しないときも 0 を返し、対象行の削除と全件正常が観測上同一になる。対象行数を厳密等値で別途固定すること。

- **区間 pin の終端は「次の同レベル見出しまで」を動的に求める**: 終端を特定の次節へハードコードすると、その手前に新節が挿入されたとき区間が新節を飲み込み、`assert_grep_in_section` 系は新節の該当行を拾って vacuous に pass する（元の節から当該行を削除しても検出できなくなる）。awk で「開始行の次から最初に現れる同レベル以上の見出しの直前まで」を切り出す idiom に統一し、同一ファイル内に 2 つの idiom を混在させないこと。区間解決そのものの健全性（行数が想定範囲に収まること）も別 assertion で固定すると、開始 anchor 消失と終端の閉じ損ねの両方が loud になる。

- **手順を書いたら、その手順どおりに実行して緑になることを実測してから commit する**: 「新 gate 追加は (1)(2)(3) の 3 点」と手順を明記しても、実測すると 4 点目が必要だった、という over-claim が 2 cycle 連続で起きた。手順そのものが検証対象であり、書いた手順を実行する mutation（変異ではなく手順の実行）を matrix に含めるべき。
