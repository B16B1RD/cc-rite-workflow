### Lessons

1. **テンプレートへ値を埋める設計では「引用符で囲んだ」は防御にならない**。`--branch "{branch_name}"` の
二重引用符は単語分割とグロブを止めるだけで、`$(...)` とバッククォートはその内側でも展開される。
`--` も argv 分割にしか効かない。したがって防御線は**値がテンプレートへ入る前**（昇格の側）にしか
置けない。委譲先 helper の入力検査はすべて展開後の値に走るので、いくら厳しくても効かない。

2. **上流のバリデータを防波堤と見なす前に実測する**。`git check-ref-format` が ref 名を検証している
から安全な文字しか来ない、という前提は誤りだった（`refs/heads/feat/issue-2493-$(id)` は rc=0）。
「別レイヤが弾いてくれるはず」は、そのレイヤの契約を読むか実行するかで確かめてから使う。

3. **ガードの分岐順は、上流が失敗したときに何が観測できなくなるかで決める**。4.2.0 の Issue 束縛
ガードは空パス判定から始まっていた。detect helper が失敗すると marker の `worktree=` ごと出ないため、
「分類できていない」が「worktree 記録なし」と同じ空文字として現れ、削除続行の枝へ落ちる。
**上流の失敗が下流の入力を「無害な既定値」に化けさせる形**は、空文字・0・null を既定値に使う設計で
繰り返し出る。分類値そのものを先に見る分岐を前置すれば構造的に消える。

4. **分岐を前段へ移したら、後段に残った同名の行は消す**。4.2.1 の判定表には `unknown` 行が残って
いたが、4.2.0 が先に逸らすので到達しない。到達しない規則は「二重に守られている」ではなく
「どちらが効くか読み手が判定できない」を意味する。
