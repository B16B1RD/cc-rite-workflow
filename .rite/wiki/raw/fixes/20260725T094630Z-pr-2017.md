### Fix Patterns

**外部コマンドを移植性のために差し替えるときは「値の受け渡し経路が持つ暗黙の正規化」まで比較する**。`realpath`（カーネル内解決）を `readlink`（シェル文字列処理）へ移した結果、コマンド置換 `$(cmd)` が末尾 LF を全除去する性質により、hook が評価するパスとカーネルが辿るパスが乖離してセキュリティガードが allow に倒れた。解決セマンティクス（何を辿るか）だけを比較して、値がシェルを経由する時の変形を比較しなかったのが根本原因。バイト厳密に受け取るには sentinel 方式 `$(cmd && printf 'X')` → `${v%X}` → `${v%$'\n'}` を使う。`$(dirname X)` も同じ理由で `${X%/*}` に置き換える必要がある。

**「新規に導入した分岐」ごとに mutation を当てて初めてカバレッジ欠落が見える**。テストが 41 passed / 0 failed でも、新設した 2 分岐（相対 target の絶対化、hop cap）はどちらも潰して green のままだった。追加した TC が非 vacuous であることの検証と、実装分岐が pin されていることの検証は別作業であり、後者は mutation を当てないと分からない。本 PR では 7 種の mutation（旧実装への差し戻し / 1 ホップ化 / 分岐 stub / cap 削除 / 素の捕捉 / dirname 復帰 / floor 撤去）がすべて kill されることを実測した。

**deny 系 TC は「deny したか」ではなく「どの kind で deny したか」を assert する**。相対 target 分岐を stub しても、hook の cwd が別 repo 内にあると parent-tree で deny してしまい `assert_deny` は生き残る。分岐消失を検出できるのは `assert_deny_gitdir` だけだった。同様に「allow になること」だけを assert する TC はブロック全削除でも通るため vacuous になり、cycle の TC では termination（timeout の rc=124 を fail 扱い）を assert する必要があった。

**skip ガードの撤去と新設が同一 PR 内で起きると規約からの後退が見えにくい**。platform gap 解消により無条件実行になった TC 群の floor は正しく撤去できたが、同時に新設した capability ゲート（`command -v realpath` 不在時 skip）には floor を付け忘れていた。撤去した floor が守っていた対象と、新設した skip 分岐が晒す対象は別物として個別に評価する。

**deny 系 TC のハーネスは control ケースで健全性を先に確認する**。検証用の親リポジトリを `rite-review-mutation-*` 配下の一時ディレクトリに作ると、guard がそれを sanctioned isolation worktree と判定して全 allow になり、attack ケースも control ケースも「deny しない」で揃ってしまう。isolation 判定に使う命名規約は検証ハーネスの配置場所にも影響する。

**reviewer 間で帰属が割れたら分析ではなく revert test の実測で決める**。同一現象について「本 PR 由来の退行」と「旧実装も同性質だから既存」で結論が割れたが、origin/develop 版と PR HEAD 版に同一入力を投入する直接比較で決着した。
