### Fix Patterns

- **marker 衝突は「改名」より「照合のアンカー化」で class ごと塞ぐ**: 新設 marker が既存 marker を部分文字列包含する問題に対し、(a) 改名 (b) 判定ルールを `[CONTEXT] ` prefix 込みでアンカー、の 2 案があった。(b) を選んだのは、同一リストの別 check が既にアンカー形式を使っており規約統一になること、および今後同じ prefix 族の marker を足しても構造的に衝突しなくなること。(a) はこの 1 件しか塞がない。**教訓: 同型の欠陥が将来も起きうるなら、個別の名前ではなく照合規約を直す。既存コードに正しい先例があればそれに揃える。**
- **散文ルールの pin は「救済文言」を要求すると堅い**: 判定値そのもの（`` ` ` `` / `` `x` ``）を grep するのは literal が曖昧で脆い。未完了判定にのみ現れる救済文言（「手動削除」「削除を試行していません」）を要求すると、判定値を `x` に反転させた瞬間に文言ごと消えるため確実に落ちる。**教訓: 状態を pin するときは、その状態に固有で他状態には存在し得ない文字列を選ぶ。**
- **negative control の precondition は「その TC の主張が依存する命題」そのものを assert する**: 「不在ブランチにも push が走る」ことを示す mutation TC が、precondition として無関係な「origin 到達性」を検査していた。前段の後始末が失敗すると mutant は別の理由で push を呼び、非 vacuity を証明するはずの TC 自身が vacuous 化する。**教訓: precondition は「setup が整っているか」ではなく「この TC の結論が意味を持つ条件が成立しているか」を書く。前段の後始末を `|| true` で握り潰さない。**
- **awk による section 抽出は両端を検査する**: 開始アンカー消失は空抽出→全 grep 失敗で loud fail するが、閉じアンカー消失は EOF まで走って section スコープが実質無効化される（over-capture）ため silent に緩む。**教訓: `END{exit !found}` で閉じアンカー到達を rc に反映させ、非空チェックと両方入れる。**
- **修正した設計原則を、その修正を検証するテスト自身にも適用する**: production 側で「rc=2（不在）と rc=128（到達不能）を混同するな」と直した直後に、テストの precondition guard が同じ混同（一律「到達不能」と表示）をしていた。**教訓: 原則を直したら、テスト・診断メッセージ・ドキュメントに同じ混同が残っていないか横断で見る。**
- **伝播スキャンで見つけた同型パターンでも、スコープ規律で止める判断がある**: 同じ非アンカー照合が別 check にも存在したが、そちらには部分文字列で衝突する相手が存在せず、レビュアーの revert テストも No（既存問題）だった。**教訓: 伝播スキャンの結果を機械的に全適用しない。実害の有無と revert テストで判断し、止めた理由をコミットに残す。**
