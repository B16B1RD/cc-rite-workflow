- **PR**: #3397 — fix(hooks): /exit 後の resume で、作業途中の Issue を batch-run が open からやり直さず、pr-review も構成確認で止まらないようにする
- **Type**: fix

### Findings Addressed
- F-01 (CRITICAL, AC-6): SessionStart(resume) の再有効化に失敗したとき、WARNING が stderr にしか出ていなかった。失敗分岐に stdout の 1 行（state のパスと /rite:recover の案内）を足し、テストで固定した

### Fix Strategies
- exit 0 で終わる hook では、stderr はデバッグログにしか残らない。モデルやユーザーの行動につなげたい失敗通知は、stdout にも出す必要がある
- pipefail 下のテストでは、`grep | grep -q` のようなパイプは避ける。上流が SIGPIPE で落ちたときの rc が混ざり、リポジトリの lint（pipefail-grep-q-check）に検出されるため、bash のパターン一致 `[[ "$out" == *"$a"*"$b"* ]]` に置き換える
- skill の bash ブロックのプレースホルダを機械置換するときは、`{key}` だけでなく `${key}` の中まで置換されないよう、直前の `$` を除外する。除外しないとシェル変数展開が壊れ、状態ファイルが別名で書かれる
