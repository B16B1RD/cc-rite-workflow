1. **同じ if の反対分岐を取り残す**: 前 commit が「reset 成功時に述語を再評価しないと自己矛盾 marker が出る」と気づいて成功分岐を直したが、同じ理由が成立する失敗分岐（永続 counter が残っているのに表示値だけ 0 にする）を直していなかった。修正が「気づいた側」で止まり鏡像へ伝播していない。**教訓: 自己矛盾を理由に片方の分岐を直したら、同じ理由が成立する反対分岐を必ず対で確認する。**

2. **「追加せよ」だけを書いて、追加により偽になる既存行の扱いを書かない**: エラー経路用の注意行を「理由行の直後に追加する」とだけ指示したため、同一通知内の「再開方法」1 行目（counter はリセット済みと約束）と注意行（上限のまま即再発火する）が数行の距離で矛盾した。散文が実行契約である以上、「追加」の指示は「追加によって偽になる既存行をどうするか」まで書いて初めて完結する。**教訓: LLM 向けテンプレートに条件付きの追加行を定義するときは、その行が既存行を偽にするかを検査し、するなら差し替え指示まで同じ場所に書く。**
