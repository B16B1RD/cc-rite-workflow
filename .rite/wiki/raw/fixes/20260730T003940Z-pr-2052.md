### Fix Patterns

1. **セル区切り文字の制約は placeholder 単位ではなくセル単位で書く**（CRITICAL、2 レビュアーが独立検出）
   構造化データ（GFM テーブル行）を LLM に生成させる指示で、区切り文字の禁止規約を 1 つの placeholder にだけ書くと、同じセルへ verbatim 埋め込みされる別 placeholder が無防備に残る。修正では制約を「全セル共通」へ格上げし、**禁止（omit）ではなくエスケープを正規形として固定**した。禁止だと他の literal 一致規約（frontmatter 値との同値要求）と衝突して逃げ場がなくなるが、エスケープならレンダリング後に元の文字へ戻るため衝突しない。既存コーパスに慣習（`\|` 使用 14 行）があったので、それを正規形として明文化した。
   加えて **コードスパン内も対象**である旨の明記が必須だった（GFM はコードスパン内の生 `|` もセル区切りとして解釈する）。実測: エスケープ済み 14 行はすべてコードスパン内で、13 行が 5 セルを維持していた。

2. **「実体に合わせる」是正では実体が複数世代あることを確認する**（MEDIUM）
   成熟リポジトリの実ファイルだけを「実体」として指示を書き換えると、テンプレート生成直後の初期状態（対象セクション自体が無い）の分岐が消える。改修前の指示が偶然テンプレート実体と一致していた場合、是正 PR がその経路の退行を持ち込む。修正では節不在の分岐を明示し、節 + ヘッダ行 + 区切り行を新設してから 1 行目を追加する手順を書いた。**同一 PR 内で片方の不在ケース（統計節）だけを明示ハンドリングして他方（一覧節）を落とすと非対称が残る** — 不在ケースの網羅は節ごとに確認する。

3. **形式収束の帰結（読み手が使えなくなること）を指示に併記する**（MEDIUM）
   書き手の生成規約を新形式へ移すとき、その構造を機械 parse する consumer が新形式を受理するか `Grep` で確認する。今回は読み手が旧形式専用のままだったため、書き手側ドキュメントの「consumer がこれを使う」という断定が誤記述になっていた。修正では断定を実装状態へ限定する caveat に置き換えた。さらに **初期状態を新形式へ収束させる分岐を足すと、それまで動いていた新規リポジトリでも読み手が使えなくなる** — この帰結は silent にせず指示本文に明記した（意図した挙動であることと、読み手対応が別 Issue であることを添える）。

4. **伝播スキャンでスコープ外と判断した箇所は件数と理由を残す**
   同種の欠陥（自由テキストを GFM テーブルセルへ埋める指示に区切り文字規約がない）が他 skill に 8 箇所あったが、出力先が作業メモリ・Issue 本文・レポートで、複数 consumer が読む長寿命カタログではないため本 PR では適用せず報告に留めた。silent に落とさず件数と理由を残すことで、後から「なぜ伝播しなかったか」が追える。
