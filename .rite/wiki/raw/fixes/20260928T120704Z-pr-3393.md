### Fix Patterns
- 保留の寿命は、候補がほかに残るかどうかで kind ごとに決める。ほかに残らない候補（スコープ外処分）は commit を問わず持ち越して判定し直し、ほかに残る候補（sweep の出典はレビュー結果 JSON で、follow-up が作り直す）は古い commit の保留をゲートで退役させる。一律の規則にすると、片方で候補を失うか、もう片方で二重起票を招く。
- 「保留を消す側を止める」修正と「保留を解く入口」は必ず組で直す。候補 0 件の入口がゲートを通らないと、保留は誰にも解かれない。
- held の run は何も書かないので、その run で決まった候補も保存しないと処分の機会ごと失われる。
- 停滞診断の replan は非 blocking の指摘も含めて全指摘を計画に載せることを求め、登録後は計画のパスを変えられない。登録前にテストの pin（件数を数える assert を含む）まで洗い出して、変更先の上位集合を確定させる。
