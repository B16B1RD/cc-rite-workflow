### Fix Patterns

**手動回復コマンドは「どこで実行するか」を書かないと連鎖が自分を壊す**: worktree 削除の案内をその worktree 内にいるセッションへ出力すると、remove が cwd を消して後続コマンドが rc=128 で止まる。しかも worktree が消えた時点で遅延回収の反復対象が失われ、ブランチが dead-letter に戻る。既存の sibling コマンドがすべて場所・時機の限定句を持っていたのに、新設分だけが落としていた。**回復手順を書く前に、同じファイルの既存 sibling がどんな限定句を持つかを読む**。

**「自動で回収されます」型の断定は、その自動化を gate している条件をすべて書き出してから書く**: 記録は `{pr_merged}=true` gate 配下、reap は dirty guard 配下という 2 条件があり、どちらも外れると手動になる。同ファイルは別経路で `recovery=auto` / `manual` の出し分けを既に持っていたが、委譲経路は個別判定を行わないためその出し分けが届かなかった。**条件付きの結果を無条件の予測として書かない**（fail-loud）。

**件数固定の negative control は「追加」を捕まえるが「移設」は捕まえない**: `grep -c` による出現数固定では、同じ marker を別分岐へ移す変異が総数不変のため素通しする。排他性を主張するテスト名を付けるなら、範囲抽出 + その範囲内での出現数 0 を別 assert で固定する。テスト名が検証内容より強い主張を名乗っていると、次の読み手が「排他性は pin 済み」と誤認する。
