### Fix Patterns
判定を helper へ一本化する変更では、helper が no-op になる経路（source 種別で早期 return する guard）を
必ず列挙する。委譲元の call site 集合と、その判定が必要な経路の集合を突き合わせないと、一部経路だけ
旧来の LLM 裁量に残り、しかも「一本化した」という記述だけが先に入る。

移送・降格の記録先が呼び出し側の tempfile になる経路では、記録が消える。永続化先の実在を経路ごとに
確認し、無い経路では fail-loud で止める（黙って捨てない）。

自己検証を追加するときは「本変更が壊したもの」に検査対象を限定する。入力時点から存在した欠陥まで
hard fail にすると、同じ条件を意図的に非ブロッキングと決めている別レイヤと enforcement level が逆になる。

diagnostic 行へ外部入力（finding id 等）を通す前に書式で allowlist する。改行を含む値は marker 行を
分断し、呼び出し側の reason 抽出が別の値を拾う。
