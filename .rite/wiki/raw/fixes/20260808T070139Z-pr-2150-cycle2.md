### Fix Patterns

**【前 cycle の記録を訂正】回復経路の「成立しない」判定は、回復側セッションの実行経路を最後まで辿ってから下す**: 同 PR の cycle 1 で「発火条件と回復条件が同一の状態変数に依存する委譲設計は、回復経路が構造的に成立しない」と記録したが、これは**誤りだった**。実際には回復側（main checkout 再実行）セッションでは委譲判定そのものが発火せず、通常経路のステップ 5 が別の manifest エントリ（`branch`）を記録して既存の age guard バイパスを arm していた。委譲側の記述だけを読んで「回復できない」と結論したため、機能していた経路を不発の経路へ置き換え、案内文で唯一機能する経路を明示的に否定する修正を導いた。**回復経路を評価するときは、回復側セッションで「その分岐が発火するか」から辿り直す** — 発火条件を共有していても、回復側では分岐に入らないために別経路が働くことがある。3 名の reviewer が cycle 1 で同じ誤診断に到達し、cycle 2 で 2 名が実測により覆した。役割横断の合意は「同じ読み方の共有」でもあり、正しさの保証ではない。

**consumer 側の受理条件を読まずに producer 側へ record を足すと不発コードになる**: reap manifest への記録を追加する際、consumer（`pr-cycle-cleanup.sh`）の bypass 条件が `_corpse -eq 1`（削除試行が失敗した痕跡）を要求することを確認していなかった。委譲経路は削除を一度も試行しないため worktree は健全で、記録は永久に参照されない。**新しい type / key を既存機構へ流し込む前に、consumer が何を条件にそれを消費するかを読む**。

**`assert_grep_in_section` の start/end パターンは正規表現メタ文字を二重エスケープで書く**: `awk -v` は C 風エスケープを 1 段階解釈するため、`'^  \*\)$'` の `\*` は量化子 `*` に潰れ、レンジが EOF まで伸びて assert が無関係な箇所で充足される（実測: pin 対象の行を削除しても全 assert green）。`\\*` `\\)` `\\[` と二重に書く。同ファイル内に規約コメントがあっても、新規 assert に適用されないことがある。
