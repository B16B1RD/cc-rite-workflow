### Fix Patterns

blocking 2 件を修正。いずれも「安全機構が劣化した局面でだけ壊れる」型の欠陥で、通常経路のテストでは surface しない。

1. **診断を運ぶ経路にフィルタを挟むときは stream のロケールを固定する**: helper stderr を capture して `neutralize_ctrl --keep-newline` に通す idiom は、0x80-0x9f をバイト単位で `?` 置換するため UTF-8 の多バイト診断が原因語ごと判読不能になる。修正は capture 側に `LC_ALL=C` を付けて stream を ASCII に固定すること。`--c0-only` への切り替えは端末へ書くサイトでは採らない (raw 8-bit C1 = 0x9b CSI の素通しが端末乗っ取りの実損になる)。実測での確認が有効: 書き込み不能な state root で helper を叩き、`mktemp: ... 許可がありません` が `LC_ALL=C` で `Permission denied` に変わることを見る。判定を分けるべきは「スクリプト自身の echo (ロケール非依存、LC_ALL=C では変わらない)」と「外部コマンドの診断 (ロケール依存)」で、後者だけが唯一の原因行になる経路 (helper が rc しか返さない write 失敗) が修正の要否を決める。

2. **marker を emit する側の空値 guard は、消費側にも同じ想定を書く**: `[ -n "$x" ]` で空を想定している値を `[CONTEXT] KEY=$x` として emit し、消費側 (人間向け復旧コマンドの placeholder 置換) に同じ想定が無いパターン。空値が置換されると `--session --phase` のようにオプションが次のフラグを値として食い rc=1 で即失敗する。さらに悪いのは、空になる根本原因 (session 解決失敗) が、その復旧コマンドを提示する分岐の発火条件 (state write 失敗) と**共通の関数に由来する**ケース — 両者が同時に成立するため「最後の安全網が劣化した局面でだけ復旧手順が壊れる」形になる。修正は marker の非空/空で文面を出し分け、空時は state file を特定して値を補う手順を案内すること。
