### Fix Patterns

クロスプラットフォーム CI（macOS/BSD）緑化 PR のレビュー指摘 8 件を修正した際の、rite プロジェクト固有の有効な修正戦略:

1. **「環境差異の吸収」は fail-open の温床**: macOS 対応で入れた 4 つの修正がいずれも「失敗時に成功へ倒れる」形だった（canonical 化の `|| true`、`cd "$(mktemp -d)"` のネスト、否定アサーションへの `|| true`、degrade 出力と同一の期待値）。共通の根本原因は「検証できなかった」と「検証して問題なかった」を出力で区別していないこと。移植性対応をレビューするときは、各修正について「この環境チェックが偽になったとき、テストは fail するか pass するか」を必ず問う。

2. **fallback ではなく失敗の表面化で解く**: 4 件すべて、防御コードを足すのではなく (a) 2 段階に分けて exit code を検査する、(b) `soft_fail` 分岐へ落とす、(c) exit code を assert する、(d) 既存の機械可読な判別子（`stale_check_ok=true`）をアサートに加える、という「失敗を可視化する」方向で解決した。rite の `no_unnecessary_fallback` 原則が、移植性対応というドメインでも同じ形で効く。

3. **shim は契約を全部再現しないと fail-open になる**: GNU ツールの代替 shim を書くときは (a) 全 exit code 契約（正常・タイムアウト・シグナル死・実行不能）、(b) 依存コマンドの `command -v` ガードと不在時の明示 abort、(c) shim 自身の自己テストで fallback 分岐を強制実行、の 3 点セットが必要。特に (c) は、fallback がどの blocking CI leg でも実行されない（primary が存在する環境でしか CI が回らない）場合に決定的。PATH に primary を含めない fixture ディレクトリを作って強制実行するのが確実。

4. **再現できないプラットフォーム固有バグは静的ガードで pin する**: 非 UTF-8 ロケール依存の修正（`${sv}→` のブレース）は glibc のどのロケールでも再現せず、振る舞いテストが書けなかった。代わりに「非 ASCII バイトに隣接する未ブレース変数を禁じる」静的ガード TC を書くことで、blocking leg でも revert を検出できるようになった。振る舞いを再現できないときは、修正の**形**を pin する。

5. **重複コピーを編集したら drift テストをセットで入れる**: `_timeout` は 6 コピー（5 ファイルが helper を source できない）存在し、シグナル契約の修正を 1 コピーだけ直す事故が現実的リスクだった。関数本体を awk で抽出して byte 一致を assert する drift TC を同じ PR で入れた。リポジトリには `reviewer-registry-drift-check` 等の前例が 3 件あり、同じ形式に揃えられる。

6. **修正の検証は mutation で行う**: 追加した TC が本当に regression を検出するかは、修正前の実装に戻す mutation を隔離コピーに適用して該当 TC が fail することを確認する。この PR では 3 種の mutation すべてで検出を確認した。レビュアー側でも `git worktree add --detach` した隔離 worktree で同じ手法を使い、`|| true` が否定アサーションの crash signal を消すことを実証している。

7. **skip には追跡 Issue を必ず紐づける**: 環境依存で skip したテストのうち 1 件だけ追跡 Issue が無く、さらに skip 根拠が hook 自身の設計方針（undocumented harness 挙動に依拠しない）と衝突していた。skip 台帳を作るときは「追跡不要」と「未起票」を明確に区別する。
