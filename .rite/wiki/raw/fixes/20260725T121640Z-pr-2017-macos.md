### Fix Patterns

**プラットフォーム分岐を 1 つ消すとき、置き換え先の外部コマンドが別の分岐を持ち込んでいないか確認する**。`realpath`（dangling symlink の扱いが GNU/BSD で割れる）を `readlink` に置き換えたが、`readlink` は「末尾に改行を付けるか」で GNU/BSD が割れる。置換によって分岐の**位置が移動しただけ**で、しかも新しい分岐は「解決セマンティクス」ではなく「出力の区切り文字」という、レビューで意識されにくい層にあった。**外部コマンドを差し替える際は、解決結果だけでなく出力フォーマット規約も両プラットフォームで比較する**。

**事後補正より発生源での抑止**。`$(readlink ...)` の末尾改行を「1 個剥がす」で補正すると、改行を付ける実装と付けない実装で結果が食い違う。`readlink -n`（GNU/BSD 双方が持つ）で区切り文字を出させなければ、sentinel の `%X` だけでバイト厳密になり「改行が付くか」への依存自体が消える。**曖昧さは補正するのではなく発生させない**。

**Linux だけで検証した「移植性修正」は移植性を保証しない**。5 サイクル・4 reviewer・20 種超の mutation をすべて Linux 上で回して 0 findings に到達したが、macOS 固有の失敗は CI の macOS leg が唯一の検出手段だった。**対象プラットフォームの挙動を shim で再現する TC を blocking gate 側に置く**ことで、次回からは Linux でも同じ分岐を踏める（本 PR では BSD realpath shim に加えて no-delimiter readlink shim を追加）。

**shim の floor 判定に `$( )` を使うと、まさに検証対象のバイトを失う**。「shim が末尾改行を出さないこと」を `$(readlink ...)` の結果で判定しようとすると、コマンド置換自体が末尾改行を剥がすため常に「出していない」と判定される。sentinel（`$(cmd; printf 'X')` → `%X`）で受けるか、probe target を LF 終端でないものにする必要がある。
