### Fix Patterns

**SoT の規則を consumer へ転記しない。転記は必ず lossy になる。**

- **要約すると分岐が落ちる**: SoT のエラー処理表が 2 つの signal（`gh` の `Could not resolve` と `git` の `unknown revision` / `bad object`）で分岐しているのを、consumer 側で「`Could not resolve` → CONTRADICTED, otherwise UNVERIFIED」と要約したところ、git 側の失敗が逆判定へ落ちた。consumer にはポインタだけを置き、条件は書かない。
- **「複製しない」と宣言した節を grep で検算する**: 「エラー処理は reference にのみ存在し本体には複製しない」と宣言した同じ節の表に、エラー処理の行が残っていた。宣言と実体の乖離は、宣言を信じた読み手が reference を見に行かない経路を作る。宣言したら宣言どおりに削り、`grep` で 0 件を確認する。
- **SoT を直したら転記先を全部 grep する**: SoT に判別子を足した cycle で、同じ規則を転記していた consumer 2 箇所のうち 1 箇所しか同期していなかった。SoT 変更は「SoT を引用・要約している全箇所」の同期とセットで 1 commit にする。
- **条件式には SoT の定義語ではなく観測可能な事実を使う**: 「nothing was surfaced」は SoT が `surface = 1 項目 = 1 question` と定義しているため、質問を出さない付記経路が条件から漏れた。「本検査が本文を変更したか」のように、定義語に依存しない observable な述語にすると解釈のぶれが消える。
- **ループバックの終了条件を本文マーカーに置かない**: ユーザーが「そのまま続行」を選ぶと本文にマーカーが残らないため、マーカー基準の再入ガードは効かず同じ質問が毎周再発行される。決定はセッション状態に持つ。
- **下位節を持つステップの「再描画」は「再実行」と読まれる**: `#### 3.1.1` は `### 3.1` の下位節なので「3.1 の差分を再描画する」は「3.1.1 も再実行」と読める。表示の再描画なのか処理の再実行なのかを明示する。
