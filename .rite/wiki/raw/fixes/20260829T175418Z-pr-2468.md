### Fix Patterns

SKILL.md（プロンプト実行体）の新規セクションで、LLM 層の判定結果を隣接 fenced block の
シェル変数で helper へ渡す設計にしたところ、Bash tool 呼び出し間でシェル状態が保持されない
ため引数が常に空へ解決され、機能全体が no-op になった。同ファイル内の既存 helper 呼び出しが
6 引数すべてをリテラル置換で渡し、35 行前で解決済みの state root をわざわざ再解決していた点が
「各ブロックは自己完結」という既存慣行の証拠だったが、新規節はそれに倣わなかった。
さらに `${var:-}` の既定化がその失敗を無言化し、helper は全件処理する一方で完了報告は
「処理済み N 件」と報告する誤報告になった。受け渡しはリテラル置換のみを経路とし、marker は
監査記録に留めるのが正しい形。

テスト側では、Markdown テーブル行を `assert_grep '^| \`value\` |'` で pin したところ ERE の
bare `|` が alternation として解釈され、`^` 単独の枝が全行にマッチして常に PASS する空振りに
なった。テストヘルパーの docstring がこの罠を名指しで警告していたが、新規 assert がそのまま
踏んだ。pin を書いたら削除方向の mutation で落ちることまで確認しないと、検証網の存在自体が
確認できない。

失敗モードへの対処として「ガードを足す」より「失敗モード自体を消す」が優れる例も出た。
`jq -R` の行単位処理が改行入力で複数 JSON 連結を生み、非空判定を通過した後で `--argjson` が
落ちて WARNING が無言で消える経路に対し、型ガードの追加ではなく `jq -Rsc` で入力全体を
1 文字列として読む形に変えると、経路そのものが消えて WARNING が正しく成立した。
