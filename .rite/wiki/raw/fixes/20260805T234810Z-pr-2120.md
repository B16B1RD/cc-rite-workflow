### ロケールが assert の検出能力を殺す (本 cycle の実測)

最も見つけにくかったのは、**既存の「列 0 非漏出」assert が vacuous pass だった**こと。`neutralize_ctrl` は 0x80-0x9f を**バイト単位**で潰すため、ロケール依存の診断 (日本語の "許可がありません" 等) が**不正な UTF-8 列**になる。GNU grep は UTF-8 ロケール下でその行に対して一切マッチしないため、`assert_not_grep` は「漏出が無い」ではなく「grep が読めない」で pass していた。実際に漏出を起こす mutation (グループスコープ `{ ...; } 2>&1` を単純コマンドへ落とす) を当てても検出されなかった。`LC_ALL=C` を付けた raw grep へ変えた途端に検出されるようになった。

**教訓**: 制御文字中和・バイト置換・エンコード変換を通した出力に対する assert は、`LC_ALL=C` を付けない限り検出能力を持たない可能性がある。同種の先例 (`review-result-state-root.test.sh` TC-8) は最初から `LC_ALL=C grep -cE` で書かれており、共有ヘルパー (`assert_grep` / `assert_not_grep`) にはロケール上書きが無い。**中和済み出力を検査するときは共有 assert ヘルパーを使わず raw grep + `LC_ALL=C` で書く**。この非対称は先例側に既に現れていたが、ヘルパーを使う側からは見えなかった。
