### Fix Patterns

cycle 1 で 12 件の blocking 指摘を解消した。修正の過程で出た一般則を 3 つ記録する。

**1. 「規約」と「その規約を検査する検出器」を同一 PR で入れると、規約側が検出器の盲点に落ちる**

本 PR は (a)「新規 helper は tempfile lib を使え」という規約と (b) lib で消せない残余を拾う検出器を同時に導入したが、検出器の正規表現は raw `mktemp` 由来のハンドルしか追跡しておらず、**規約に従って lib で書いた helper の派生パスを検出しなかった**。規約に従うほど盲点に入るという反転。

一般則: **規約と検出器を同時に入れるときは「規約が推奨する書き方が検出器の入力ドメインに含まれるか」を明示的に確認する。** 検出器の正規表現は「今ある書き方」に対して書かれるので、同じ PR が導入した新しい書き方は自然には視野に入らない。テスト側にも negative control（規約どおりに書いたコードで欠陥があれば検出される）を置く。

**2. 免除規則は「proxy で判定していること」を文書に書かないと、次の書き手が proxy を真の軸だと信じる**

`printf`/`echo` 起点のパイプラインを SIGPIPE 免除にしたが、根拠は「短い in-memory 文字列がパイプバッファに収まる」であるのに、判定は**コマンド名**で行っていた。payload がリポジトリ規模に比例する `printf` は根拠が成立しないまま無警告になる（payload 70000B で rc=141 を実測）。さらに判定が「パイプライン先頭」を見ており「`grep -q` の直前段」を見ていなかったため、`printf | jq | grep -q` が丸ごと免除されていた。

一般則: **proxy で判定するなら proxy が成立する条件を文書に書く。** そして「どのプロセスが実際に死ぬのか」を判定軸にする — パイプラインでは consumer の直前段。

**3. 変数名の接頭辞一致を「派生」と読むと、bash の変数名規則に負ける**

派生パスの綴りを広げる際 `$tmp_bak` を派生として扱ったところ、`$pr_view_err` に対して `$pr_view_err_oneline` が誤検知した。**bash は `$` の後の `[A-Za-z0-9_]` 連続を 1 つの変数名として読む**ので、無括弧の `$v_suffix` は派生ではなく別変数。`${v}_suffix`（波括弧で区切る）と `$v-suffix`（`-` は変数名に使えない）だけが派生。

一般則: **シェルの字句規則に沿わないパターンを書くと、誤検知の形で必ず表面化する。** 検出器を書くときは「bash がこの文字列をどう parse するか」を先に確認する。

**4. signal 経路のテストは EXIT trap に吸収される**

bash は untrapped な INT/TERM/HUP で死ぬときも EXIT trap を実行し、終了コードも 128+signum を返す。したがって「INT を送って rc=130、tempfile が消えている」を assert しても EXIT trap 1 本で両方満たされ、**signal handler を削除した mutant でテストが全件 green のまま通る**。

一般則: **signal 経路を pin するなら、child 側で `trap - EXIT` してから signal を送る。** あるいは `trap -p INT` の出力に cleanup 関数名が現れることを直接 assert する。rc と副作用だけを見る assertion は signal handler の存在を判別できない。

**5. 検出器の「走査できなかった」を「見つからなかった」に潰さない**

`awk ... 2>/dev/null || true` は awk の失敗を rc ごと飲み、`findings: 0` / rc=0 を返す。lint は rc=0 を `success` に写して出力すら surface しないため、操作者には「検査して問題なし」としか見えない。同じ握りつぶしが 1 ファイル内に 4 箇所（find の stderr / pipefail 判定 grep の rc=2 / target 不在の continue / awk の rc）あった。

一般則: **検出器を新規に書くときは `SKIPPED` カウンタを持ち、findings 0 かつ SKIPPED>0 で exit 2 にする**（findings があれば 1 が勝つ）。既に正解の先例（`dollar-zero-check.sh`）がある場合、**より古い実装ではなくレビューを経た最新の実装を写す** — 本 PR は古い `bash-heaviness-check.sh` の形を写したため教訓が伝播しなかった。
