### Fix Patterns

1. **「末尾で一致」を suffix 検査で実装すると接頭辞を吸収する**

   `endswith(sentinel)` は本文全体の suffix を見るため、`> sentinel`（引用接頭辞付き）も true になる。
   「最終**行**が X と等しい」を意図するなら、行に分割してから等値比較する必要がある。
   suffix 検査と行等値は別物で、前者は引用・インデント・任意の接頭辞をすべて通す。

2. **read と write を「対称」と書くだけでは対称にならない — 述語そのものを共有する**

   cycle 2 はコメントに「read/write を対称に保つ」と書きながら、read は suffix 検査、write は
   行等値という別実装だった。**同じ述語を 2 か所に別々の言語 (jq と shell) で書くときは、
   同値であることを実測で確かめる**。今回は 4 形状 (通常 / 引用付き末尾 / 末尾空行 / 行末空白) で
   両側の判定が一致することを表にして確認した。

3. **fixture が非実在形状だと、load-bearing な 1 行が pin されない**

   lookup fixture の body に末尾改行が無かったため、実 write 経路 (`jq --rawfile` は必ず改行で終わる)
   では効いている「空白のみの行を除く」処理が、どの assertion にも触れられていなかった。
   **fixture は production が実際に生成する形状に揃える** — 簡略化した形状は、その簡略化で
   消えたコードパスを丸ごと検証対象外にする。CRLF・末尾空行のような「増減しうる」要素は
   fixture 側に明示的に入れて pin する。

4. **`IFS=$'\t' read` はタブを IFS *空白* として扱い、先頭の空フィールドを食う**

   `read -r a b c <<< $'\t0\t0'` は a=0 b=0 c=空 になる。タブ区切りで**空になりうる先頭
   フィールド**を扱うならパラメータ展開 (`${v%%$'\t'*}` / `${v#*$'\t'}`) で位置を固定する。

5. **pin のラベルと検査対象を突き合わせる — 「生成行」と「代入行」は別物**

   `pending_marker=...` という**代入**行を pin して「生成行を pin した」と称していたため、
   実際に marker を作る `: > "$pending_marker"` は無防備だった。生成文と emit を削除しても
   suite は緑のまま。**pin が謳う保証を 1 語ずつ検査対象と照合する**。

6. **存在/不在が判定値になるファイルは `set -C` で作る**

   予測可能パスへの `: >` は symlink を追随して任意ファイルを truncate でき、他者が作った
   既存ファイルも掴む。gate の判定値そのものであるファイルは `( set -C; : > path )` にして
   O_CREAT|O_EXCL 相当にする。拒否時は既定義の degraded 経路へ落ちるので新規分岐は要らない。

7. **同じ症状でも原因が違うなら marker を分ける**

   「記録コメントが複数並ぶ」には (a) sentinel を持たない旧コメントの孤児化 と
   (b) 過去の degraded 縮退が生んだ canonical 重複 の 2 原因があり、復旧手順 (どちらを消すか) が
   違う。件数を合算すると WARNING の文面が事実と異なり、operator を誤った削除対象へ誘導する。

8. **点修正をやめて「述語を 1 回変えてから全 artifact を横断 sweep」に切り替える**

   cycle 1 → 2 → 3 と「実装を直したが、それを主張している文が旧状態のまま」が 3 連続した。
   個々の指摘に個別対応すると、指摘されなかった箇所が次 cycle の指摘として戻ってくる。
   述語を変えたら `grep` で関連語彙 (今回は「末尾 anchor」「contains」「3 段」) を全ファイル
   横断で洗い出し、**一度に**揃える。
