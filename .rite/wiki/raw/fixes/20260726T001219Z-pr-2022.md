### Fix Patterns

- **3 分岐ガード導入時に「状態を変更する分岐」だけ失敗 marker を置き忘れる**: `git ls-remote` の rc を 3 分岐（存在 / 不在 / 判定不能）にして後 2 者には marker を付けたが、実際に `git push --delete` を実行する rc=0 分岐だけ成否を捨てていた。下流が「marker 不在 = 成功」と解釈する契約だったため、削除失敗が完了として報告される false-success になった。**修正の型: 状態変更を伴う分岐には必ず失敗 marker を置く。「marker が無い = 成功」と書く前に、その分岐が本当に失敗し得ないかを確認する。**
- **「いずれの marker も無いとき」を marker family でスコープしない**: 同じ出力ストリームに 2 系統（ローカル / リモート）の marker が流れる場所で無条件の「いずれの `[CONTEXT]` 行も無いとき」を書くと、正常系で片方の marker が必ず存在するためリテラルには常に偽になり、判定オペランドが未定義になる。**修正の型: fallback 条件は必ず marker family（`FOO_*`）でスコープする。**
- **emitter だけテストして consumer（散文の判定ルール）を pin しない**: SKILL.md の bash block を抽出実行するテストは厚く張れるが、同じ PR が新設した完了報告の判定ルールは散文なのでテストが無いまま残りやすい。consumer ブロックを丸ごと削除する mutation で全スイート green になっていた。**修正の型: marker を新設したら emit 側と解釈側の両方を pin する。散文ルールも `assert_grep_in_section` 相当で静的検証できる。**
- **静的 grep テストが「修正前の一字一句」だけを pin して言い換えを通す**: 禁止表現（「保証する」）の literal 不在のみを検査していたため、「必ず残ることを保証します」への書き換えでテストが通った。**修正の型: 禁止表現の不在ではなく、要求される性質（できないことの明示）を肯定形で assert する。**
- **周辺コードの stderr 捕捉規約から外れる**: 同一ブロックの既存コードが `err=$(cmd 2>&1)` で原因を WARNING に載せているのに、新規追加コマンドだけ `2>&1` で捨てて rc だけを出した。ユーザーに手作業を要求する唯一の経路で原因が伝わらない。**修正の型: 新規コードは同一ファイル内の既存エラー処理規約を先に読む。stderr のみ退避したいときは `2>&1 >/dev/null` の順序。**
- **レビュアー間で revert テストの解釈が割れたときの決着**: 「結果は PR 前と同じだから既存問題」と「その断定を書いた行は本 PR の `+` 行だから新規」で blocking 判定が分かれた。SKILL.md が定める revert テスト手順（diff-line inspection: バグが `+` 行に依存するなら pass）に従うと後者。**修正の型: revert テストは結果の同一性ではなく documented された手順（diff 行の帰属）で判定する。対応が一致し severity だけ割れる場合は高い方を採る。**
