### Fix Patterns
- consumer 側の入力検証を producer の出力契約に合わせるときは、形の検査を足すのではなく「判定に要る本文が無い」ことだけを停止条件にし、形の違う値は原文のまま運ぶ方が停止を増やさない
- 既存の重複除去 key に新しい種類の行を合流させるときは、同一 JSON 内の出現順を key に付けて行ごとに一意にする（1 行だけの位置の key は変えず既存の台帳照合を壊さない）
- 「原文を失った記録行」で止める検査は、照合範囲（同じ PR の出典に限る、今読んでいる JSON に同じ位置の指摘があれば原文はそこにある）を絞らないと、Issue 単位で共有される台帳の別 PR 行や、原文の残る通常行まで止めてしまう。実データの archive に当てて停止件数を測ると誤停止が見つかる
- 新しい停止検査の jq はプロセス置換 + 2>/dev/null で書くと失敗時に素通りする。変数へ取り終了コードを見てから while read に流す
