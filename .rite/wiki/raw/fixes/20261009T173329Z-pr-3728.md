### Fix Patterns
- skill の手順に実行ブロックを足すときは、その skill のシェルブロック形の契約（helper を通した top-level の単一 bash 呼び出し）に合わせ、本体は helper のサブコマンドへ置く。複合コマンドを手順書に書くと、形の契約のテストが落ち、worktree 隔離のセッションではホストのガードに拒否される。
- 修正の検証には、変更した skill の形を検査する hooks のスイートを含める。scripts のスイートだけでは形の契約違反を見逃し、CI で初めて見つかる。
- 外部への書き込み（gh pr edit 等）は、成功の印と失敗の印を helper が対で出し、失敗の印を判定表の fatal 行（[fix:error]）に置く。成功時だけ印を出す形では、失敗が「何もしなかった」と区別できない。
- 判定表に条件を足したとき、その条件を言い換えた要約の散文も同時に直す。ただし既存テストが pin している文言は、計画外の変更を避けて意味が変わらない範囲に留める。
- 新しい helper は、本物の PR に対しても 1 回実行して印が出ることを確かめると、手順書の配線と実装の両方を確認できる。
