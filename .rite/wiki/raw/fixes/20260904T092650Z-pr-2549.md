### Fix Patterns

**ゲートを足すのではなくゲートの自由度を削る**: 新設した commit 前ゲートに対し 7 件の指摘（placeholder 残留 / heredoc 終端子衝突 / 完了レポートの受け皿欠落 / 呼び出し元ゲート欠落 / hit 時の Edit 契約矛盾 / blob 相対の行番号 / raw ラベルによる無条件 clean）が集中した。個別にガードを 3 つ足す修正は、指摘 1 件ごとに新しい検査面を増やして次サイクルで再生産する。実際に効いたのは逆で、ゲートが持っていた自由度（対象の列挙・ラベル・本文・marker routing を実行者が選べること）を削り、未 commit の差分を 1 回走査する形へ単純化する修正だった。heredoc と per-target ループが消えることで 5 件が構造的に成立しなくなり、error を fail-loud にしたことで「検査していないのに commit へ進む」経路が消え、完了レポートに受け皿を足す必要もなくなった。

**ゲートの anchor を強制される側が渡すと自己無効化する**: 委譲先の `--label` はパス除外判定にも使われるため、呼び出し側が raw のパスを渡すと内容に番号があっても無条件 clean が返る。判定基準をゲートされる側が選べる値に取った形で、対象を git の差分から取ることで消えた。

**placeholder 残留の検査は名前ではなく形状で書く**: 残留検査のパターンに placeholder 名（`*"{plugin_root}"*`）を書くと、literal substitute がパターン側まで書き換えて検査が自分を無効化する。ブレースの形状（`"{"*"}"`）で検査する sibling の書き方が正しい。この欠陥は、静的 grep から実行 pin へ引き上げた直後のテストが捕まえた — 実行可能ブロックを grep だけで守ると、ブロック自身の論理的欠陥は素通りする。

**rc と件数は独立に検査する**: 委譲先の exit code は clean/hit/error の信号で件数ではない。件数側だけを見ると、hit を主張しながら findings を 1 行も出さない状態（計数経路の破損）が「実測済みの 0 件」として通る。両者の矛盾を検出失敗へ倒す 1 行が要る。

**awk の `close()` は追記を truncate に変える**: `> file` は初回オープンで truncate、以降は追記だが、`close()` を挟むと次の `> file` が再オープン＝再 truncate する。END の `exit` を落とす変異に対する二重検出が、この 1 行で失われていた。

**到達不能文字列を検査する否定 assertion は常時緑**: 診断値の arity を 4→3 に変えた際、肯定 assertion は追随したが `assert_not_grep '4 値を返しませんでした'` が残り、実装が何を出しても緑になる pin へ退化した。3 名の reviewer が独立に検出。

**mutation の共通後処理は vacuity ガードの後に置く**: mutant に共通の後処理（委譲先の絶対パス固定）を `assert_mutant_changed` より前に適用すると、本来の変異が 1 文字も適用されなくても mutant は原本と異なるため「変異セレクタが何にも一致しなかった」を検出できなくなる。

**スクリプト自身の位置は cd より前に確定する**: `$(dirname "${BASH_SOURCE[0]}")` を `cd` の後で評価すると、相対起動時に解決先が cwd 相対へずれる。ずれた先に同名ファイルがあれば別の実装を無言で使う。
