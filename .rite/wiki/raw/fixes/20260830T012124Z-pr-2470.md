### Fix Patterns

- **sibling helper から骨格を写すとき、その helper の前提条件ごと写してしまう**: 新設した gate は既存の board 検査 helper から config 探索・trap・GraphQL の作法を写したが、同時に「盤面未登録は drift ではない」という判断も持ち込んだ。写し元は auto_add を使わない文脈で正しいが、写し先は `auto_add: true` の直後に走るため item の不在は「未実行の証拠」になる。**骨格の再利用と判断の再利用は別物**で、後者は呼び出し文脈が同じかを確認しないと、新 helper が塞ぐべき当の状態を素通しする分岐を最初から持って生まれる。

- **静的 pin だけのテストは「文書」を守り「挙動」を守らない**: 259 行の helper に対し、テストは SKILL.md の表行を grep する pin と、外部コマンドを無条件失敗させる 1 経路だけだった。件数は充実して見えるが、中心ロジック（verdict の振り分け）を一度も実行していないため、`emit missing` → `emit ok` の書き換えでも全件緑のまま通る。**mutation を 1 回かけると、テストが何を守っていないかが件数と無関係に分かる**。

- **`jq -r '.x // "default"'` の fallback は「JSON が来たとき」しか効かない**: 入力が空文字・非 JSON なら jq は何も出さずに exit 0/5 で終わり、fallback は発火しない。可視化のために足した marker が、最も必要な失敗時にだけ空になる。**変数へ落とした直後の `[ -z ] && x=default` が要る**。

- **marker を出す関数はファイルの先頭で定義する**: 引数解析ループより後に `emit()` と中和 helper の source を置くと、ループ内のエラー分岐だけが raw echo になり、同一ファイル内で保護の有無が非対称になる。関数定義とその依存を引数解析の前へ移すだけで、marker 出力経路が 1 本に戻る。

- **走査条件を変える diff は、その条件を説明する定点コメントを同時に嘘にする**: draft skip を削除した結果、直上のセクション見出しが実装と正反対になった。ヘッダー本文は正しく更新されていたのに、ループ直前の見出しだけが取り残された。**「何を走査するか」を述べる箇所は本文とループ直前の 2 箇所ある**。
