### Fix Patterns

ネガティブ assertion のみのテストは「対象が正しい形で存在する」と「対象が丸ごと存在しない」を区別できない。「列 0 に漏れていないこと」を数えるチェックは、原因行が正しく字下げされている場合も一切出力されていない場合も同じく 0 件を返すため、機能が消えた退行を検出できない。同種の pin は必ず正負を対で置く（`indented >= 1` かつ `bare == 0`）。

本 fix ではミューテーションテスト（production コードの当該行のみを削除して suite を実行）で「修正前は rc=0 で通過、修正後は当該 assertion が FAIL」を実測してから commit した。テスト追加の妥当性を主張する際、追加した assertion が実際にその退行を捕まえることを空振りしない形で確認する手順として有効。

同一リポジトリ内に既に正しい先例（`review-result-state-root.test.sh` TC-8 の `indented>=1 && bare==0`）が存在しており、新規テストがその片側だけを写していた。既存の同型 assertion を先例として探す工程を挟めば、レビュー往復を 1 回減らせた。

なお `LC_ALL=C` は原因文字列が locale 依存の OS メッセージであるため必須。UTF-8 locale ではデコードできない行を grep が諦めるため、ASCII の anchor まで拾えなくなる。
