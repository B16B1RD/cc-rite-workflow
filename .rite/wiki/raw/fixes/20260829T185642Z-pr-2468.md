### Fix Patterns

marker を「値を運ぶため」に新設したなら、運ぶ値が無くなった時点で marker 自体を消す。
cycle 2 で件数運搬用に足した marker が、cycle 3 で件数機構を畳んだ後も名前を変えて残り、
運ぶものが無いまま 2 つの害だけを残した — 0 件時にそれが最後の marker になって下流が
「未完了」と誤報告し、値が既存値の前置詞だったため判定表の前方一致で誤った行に吸われた。
機構を畳むときは、その機構のために作った付随物（marker・専用 reason・報告文言）も
同時に棚卸しする。名前を変えて残すと、動機を失った構造だけが次 cycle の欠陥面になる。

marker 値の照合規約は「前方一致」を既定にしない。既存値の前置詞になる値を後から足した
瞬間に、新値が既存行へ吸われる。照合は区切り文字（`;` または行末）まで含めた完全一致で
規定する。

テストの pin はキーだけでなく極性・帰結まで含める。`「X は必ず Y」` という散文を
`X` だけで pin すると、`Y` を反転させる変異が生存する。同様に、機構の後半（surface 側）
だけを pin すると前半（捕捉側）を切る変異が生存し、機構全体が無効化されても緑のまま通る。

negative assert（`assert_not_grep`）で `\s` を使うと GNU 拡張依存になり、BSD の ERE では
未定義に落ちてパターンが恒常的に不一致 = fail-open する。positive assert は同じ事故で
FAIL して露見するが negative は静かに通る。`[[:space:]]` を使う。
