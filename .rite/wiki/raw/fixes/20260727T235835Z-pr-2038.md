### Fix Patterns

- **「弱い述語を 1 段細かくする」だけの修正は同型の穴を残す**: 合計下限 `-ge N` が削除軸に無反応だったとき、セクションごとの `-ge 1` に分割しても下限判定であることは変わらず、対象が複数行を持つ場合に「意味のある 1 本」の削除を他の行が吸収する。塞ぐには (a) 期待本数を**厳密な等値**で固定し、(b) 判定語 (`Gate passes`) と規約フレーズの**共起**を要求する。(b) が無いとフレーズを残したまま行の意味を反転（pass → ERROR）する変異を見逃す。厳密等値にすると対象表を変更するたび pin が落ちるが、それは「変更したなら不変条件を再確認せよ」という正しい強制になる。

- **pin の除外条件は実物で裏を取ってから書く**: 「終端要素は次を持たないから対象外」のような一見自明な除外理由が、実際の文書では成立しないことがある（規約統一のため終端側も同じフレーズを持っていた）。裏取りせずに書いた除外理由は、そのまま「pin のコメントが謳う保証と実装の乖離」になる。除外を入れる前に `grep` で対象がその性質を持つか確認すること。

- **散文の「向き」は allowlist では固定できない**: トークンの出現順を並べた正規表現は、判定を否定形へ反転しても全トークンが同順に残るため通る。2 層で塞ぐ — (a) 否定形の **denylist**（表を触らない反転を捕まえる）、(b) 判定の向きが**構造として現れる別の場所**（Routing 表の「不一致 → ERROR」行の実在）の pin（文言の言い換えに強い）。denylist は未知の否定表現をすり抜けるので単独では不十分。

- **assertion のラベルが表明する scope と検査範囲を一致させる**: 「〜セクションに 1 箇所」というラベルでファイル全体を数えると、対象を遠方の無関係な節へ移動しても通る。位置の前後関係（`A < B`）だけでは「B より前ならどこでもよい」になる。区間限定は `sed -n "/^開始見出し/,/^終了見出し/p"` の idiom で書ける。**この欠陥は 1 箇所直すと同型が他にも見つかることが多い** — 実際、指摘された 1 件を直した後の伝播スキャンで同型が 2 件見つかった。

- **mutation は 4 軸で当てる — 削除 / 部分削除 / 意味反転 / 移動**: 削除軸と移動軸だけで「落ちる」と確認しても、部分削除（複数ある同種行の 1 本だけ削除）と意味反転（pass 行を ERROR 行へ書き換え）の死角が残る。pin を追加・変更した本人が 4 軸すべてを当て、結果を PR 本文の matrix に残すこと（commit message だけでは、matrix を唯一の検証根拠として指す AC の参照先が最新 pin を網羅しなくなる）。

- **単一入力からの一般化は誤った finding を生む**: 「この reason には到達しえない」という主張が、1 種類の入力でしか検証されておらず別の入力では到達可能だった例がある。到達不能を主張するなら、入力空間を分割して各領域を潰したことを示すこと。統合側は相反する 2 reviewer の主張を実コードで突き合わせて決着できる。

- **仕様文の述語はレイヤを明示する**: 同じ概念 (`measured`) が複数レイヤで別のソースから解決される場合（レビュー時は本文アンカー、fix 時は JSON フィールド）、レイヤを書かない仕様文は片方のレイヤで正反対の結論を導く。「判定時点でそのフィールドはまだ存在しない」といった時系列の制約は、仕様文の側に明示しないと読み手が復元できない。
