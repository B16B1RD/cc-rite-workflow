### Fix Patterns

レビュー指摘の修正そのものが新たな回帰を生んだ事例と、その一般化:

1. **「degrade と正常を区別する」修正は、判別子を片側の値で固定すると degrade する環境を壊す**: cycle 1 で「`n_stale=0` + rc 0 は degrade 出力と同一だから判別子 `stale_check_ok=true` を要求する」と直したところ、GNU date 非互換ホスト（= その PR が緑化しようとしていた macOS そのもの）が必ず fail するようになった。判別すべきは「検証が走ったか」であって「GNU かどうか」ではない。正しい形は probe で期待値を切り替え、GNU なら `true`、BSD なら `skipped_no_gnu_date` を**要求する**こと。degradation 契約も pin されるので両環境で fail-closed のまま緑になる。「vacuous green を潰す」修正が「恒久 RED」に振れたら行き過ぎのサイン。

2. **否定アサーションには positive control を必ず添える**: 「canary が作られないこと」で pass する TC は、子プロセスがそもそも動かなかった場合も pass する。同じ fixture で「canary が作られる」ことを先に確認する control を置くと、fixture 破損と検証成功が区別できる。cycle 1 で `|| true` の crash signal 破棄を潰しておきながら、新規テストの fixture に同型の fail-open を持ち込んでいた。

3. **fixture 構築の `|| continue` は silent skip と同じ**: `tool_path=$(command -v "$tool") || continue` はツール欠落を握り潰す。テスト fixture は本体コード以上に fail-closed であるべきで、必要なツールが無いなら即 exit 1 する。あわせて `command -v kill` はシェルビルトイン名を返すため、`ln -sf` で自己参照 symlink になる（絶対パス検証を入れて弾く）。

4. **drift 検査の対象ファイル一覧はハードコードしない**: 重複コピーの byte 一致を検査する TC で対象をリテラル配列にすると、7 個目のコピーが検査から完全に不可視になる。`grep -rl '<定義行>'` による discovery に置換し、「発見件数の下限」と「reference が発見集合に含まれること」も併せて assert する（discovery 自体の破損で vacuous green になるのを防ぐ）。

5. **skip はカウントして summary に出す**: プラットフォーム依存 skip を増やした PR で `print_summary` が PASS/FAIL しか出さないと、31 アサーションが実行されないまま "All tests passed!" が出る。既存の `skip()` + `SKIP` カウンタ規約がリポジトリにあるなら helper 側に昇格させ、全 skip サイトを置換する。「緑」の意味を痩せさせない。

6. **セキュリティの残余リスク記述は実測で裏を取る**: 「別のガードが独立に塞ぐから安全」と書く前に、そのガードが同じ経路を通るかを確認する。今回は Bash ツールの gate（`_gd_fileverb`）を Edit/Write 経路の backstop として引用していたが、両者は経路が異なり、当該 gate 自身がヘッダで verb list を「COMMON-SET, deliberately NOT exhaustive」と明記していた。過小評価した残余リスクは follow-up Issue のトリアージを誤らせる。

7. **capability probe による skip には blocking gate 側の床を入れる**: `realpath` の挙動で skip するテストは、Linux で realpath が shadow / 不在なら blocking gate 上でも無言 skip される。`[ "$(uname -s)" = "Linux" ] && probe 失敗 → fail` の 1 行で、プラットフォーム固有 skip が blocking gate に漏れるのを防げる。

8. **blocking leg で観測できない production 修正はテストで pin できているか確認する**: GNU mktemp は bare 呼び出しでも TMPDIR を尊重するため、テンプレート化の revert は leak count では検出できない（mutation で検出ゼロを確認）。basename アサートのようなプラットフォーム非依存の観測点を足す。
