### Fix Patterns
- 判定規則を「最初に空でない段だけを見る」順序づけへ変えると、根拠が複数の経路に分かれる正しい主張を不支持にする。根拠の候補は和で判定し、段の順序は判定不能を決めるときだけに使う。
- git show の既定出力はマージコミットで変更ファイルが 0 件になる。コミットの変更ファイルを根拠に使うときは --first-parent を付け、作業先に無いときの取得手段と、どちらも失敗したときの判定不能を明記する。
- 外部コマンドが rc=0 で想定外の形式を返したとき、解析例外の文言をそのまま記録すると原因が残らない。「出力が JSON でない」と応答の先頭を error に残す。
- 指摘を出す側だけを足すと、その指摘を直す手段が修正側に無い場合、修正できない blocking になる。指摘の出所（ここでは PR 本文）ごとに、直す手段と直した内容を照合し直す経路を修正側にも置く。
- 境界の判定（totalCount と件数の比較）は、印が付く側だけでなく付かない側もテストで固定しないと、> と >= の取り違えを検出できない。
