### Fix Patterns

ワークフロー定義（skills/*.md の散文＋埋め込み bash）に対する fix で、3 件の blocking 指摘が
すべて同型の根本原因に帰着した: **実装を知る書き手の視点で散文を書き、その散文だけを読む
消費者（LLM / 人間）が参照を解決できるかを検証していなかった**。

具体的な発現形:

1. **置換マニフェストと実テンプレートの乖離**。「これらをリテラル置換せよ」と列挙する散文と、
   実テンプレート中のトークン名が食い違う。LLM は列挙側を権威として扱うため、テンプレート側の
   トークンが未置換のまま人間へ出力される。**復旧手順のコマンドで起きると最悪** — 未置換の
   `--session {SID}` は `_validate_session_id` を通過して rc=0・無出力で別の state を作るだけで、
   本来直したい state は手つかずのまま残る。「実行しても何も起きない」形の失敗は事後の
   `get` でも判別できない。
   **有効だった修正**: 略記側（`{ROOT}` / `{SID}`）を Placeholder Legend の命名規約
   （lowercase-snake）へ改名する。列挙側に追記するより修正点が少なく、pre-fill 表・
   テンプレート・置換指示の 3 箇所が同時に整合する。**命名規約から外れた略記は乖離の兆候**
   として grep で検出しやすい。

2. **条件節の先行詞が同一文書内に無い**。"provided **either** X succeeds" と書きながら、
   either が指す 2 項をその節で導入していない。しかも数行後に単数形の指示語（"that write"）で
   別の対象を指すと、読者は両者を同一物と誤読する。**「本 PR が是正対象とした当の文」で
   起きると、是正前と同じ『読んでも真偽を確かめられない保証』に戻る**。
   **有効だった修正**: 2 項を使用箇所で名指しする（詳細は SoT へ委譲したままでよい）。
   同時に後続の指示語も具体化する。

3. **宣言の適用範囲を書いていない**。「両分岐は同構造」が停止時の挙動については正しくても、
   失敗記録の永続性については成り立たない、といったケース。**概要節と詳細節の両方に同じ宣言が
   あると、但し書きを詳細節にだけ足しても概要節の単独読者は救えない** — 伝播スキャンで
   概要節も補正する必要があった。
