### Fix Patterns
- 出口の新設は「その出口を読む消費者がすべての停止経路にいるか」で開く条件を決める。修正ループが続かない review（受入条件未検証の停止・単独実行）では、呼び出し元の明示フラグで閉じ、従来の保留に倒す
- 自分で書いた台帳行の前提の起点は、書いた時点の判定 commit を行に残して使う。入力側の commit を起点にすると、判定前の変更だけで自分の行が失効し、再実行のたびに判定と追記を繰り返す
- 書き手が読む名前の集合（壊れて改名された入力を含む）と、読み手・追記側の正規表現をそろえる。1 行の不一致で全行を捨てる契約では、網羅漏れが記録の全損になる
- 固定文字列の表行は grep -cxF の全行一致で照合する。grep -E に生のパイプを含む文字列を渡すと選言になり恒真になる。mutation を 1 つ当てて落ちることを確かめる
- 機構を撤去したら、機構名と帰結語で配布文書・設定テンプレート・reference・再開案内を全文検索し、長い 1 行の段落の中も確認する。テストは旧文の存在 pin を現行文の pin と旧語の不在 pin に置き換える
- dogfooding では commit 前 hook が main checkout の版で動く。検査記録のハッシュ計算を変えた PR では、hook と同じ版で check / verify を取り直す
