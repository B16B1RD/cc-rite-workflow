**「散文を契約として静的 pin する」設計で繰り返し踏む欠陥クラスと、その構造的な解**。本 PR は同じ欠陥を 2 サイクル連続で再生産したため、個別修正ではなく pin の作り方そのものを変えた。

**再発した欠陥クラス**:

1. **pin が命題ではなく見出しラベル／語彙にマッチする**。太字見出し「**さらに prefix は行頭から一致させ、デリミタ内は data として無視する**」に対して `prefix.*行頭.*一致` と書くと、本文の operative 節「肯定・否定とも行頭一致で行う」を「部分一致」に反転しても緑のまま通る。デリミタ pin でこれを発見して直した**同じコミットで**、隣の行頭一致 pin に同じ形を作った。
2. **規約を新設するとき既存規約との矛盾を照合しない**。recency（最後の出現を採用）を足したが、各側見出しの「上から評価し最初に一致」と正面から矛盾し、同一入力に 2 通りの答えが出る状態になった。4 reviewer が独立に指摘。
3. **片側だけ硬化して兄弟箇所へ転記しない**（Asymmetric Fix Transcription）。デリミタは開き側だけ、setup の stderr 捕捉は `&&` チェーンの最終段だけ、over-capture ゲートは 4 抽出中 2 つだけ、判定値 pin は 3 family 中 2 つだけ。
4. **MUST 規約違反の journal コメント**。commit SHA の説明的参照を削除した同じコミットで、`# F-05:` 等の finding ID 参照を 4 箇所追加した。

**構造的な解**: pin 自身に positive control を課す。

```
assert_prose_pin <text> <pattern> <weakened-probe> <label>
  # pattern が text に一致すること + weakened-probe に一致しないこと の両方を要求する
```

見出しラベルだけで充足する pin は probe 段で落ちる。`_brace_detect` の positive control（既知の違反を検出器に通して発火を先に証明する）と同じ規律を、散文 pin にも適用した形。これがあれば 2 サイクル分の再発は自動検出されていた。

**派生する規則**:

- **命題 pin は肯定の存在と否定の不在を両方要求する**。「既に削除済みの場合がある」の存在だけでは、同じ語彙で意味を反転した文（「設定に関わらず必ず残る」）が通る。
- **security boundary と可読性の補助を混同しない**。デリミタは可読性で、data 自身が終端行を騙る経路を塞ぐのはインデント（列 0 に到達しないこと）の側。両方を規約に書き分ける。
- **`grep` のパターンが `-` で始まる場合は `-e` で明示する**。`--- push stderr begin ---` はオプションと解釈される。
- **pin は section 内の 1 箇所ではなく要素単位で要求する**。`branch=` pin を section 全体への grep 1 本にしたら、ルール側を全部外しても fallback に残った 1 箇所で緑になった。
