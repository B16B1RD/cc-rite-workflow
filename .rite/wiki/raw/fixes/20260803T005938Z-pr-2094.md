blocking 5 件に対応。前 cycle の修正が新たな指摘を生んだケースが 1 件あり、そこで方針転換した。

**1. 列挙の補完は 2 回目で機構ごと撤去する**。前 cycle で docs の「値の出所」列挙に欠けていた 1 ケースを補完したが、次 cycle で別の欠落が実測で出た。**同じ機構への 2 度目の指摘は、パッチではなく機構の撤去を検討する合図**（fix.md の Simplification-First Escalation trigger）。今回は列挙を撤去し実装 header への SoT ポインタへ差し替えた。副次的に、前 cycle の編集が持ち込んだ英日ケース数の非対称も同時に消えた — **列挙を 2 言語で並行維持すると、片方だけ更新した瞬間に非対称が生まれる**。

**2. sentinel を持つ上流から値を引き継ぐ機構は、sentinel を実値として拾う**。flow-state は「PR 未作成」を `0` で表すが、carry-forward のガードが env の空 / 非空しか見ないため `0` を実値として恒久化していた。除外は片側だけに置く — 同じ `0` でも loop_count 側は「まだ 1 周もしていない」という実値なので、除外を波及させると別の退行になる。**この非対称を回帰テストで固定する**（除外の適用側と非適用側を両方 assert する）。

**3. stderr を捨てた pipeline で rc を 1 つだけ載せると、診断が能動的に嘘をつく**。前段と後段の stderr を両方捨てたうえで WARNING に前段の rc だけを載せると、後段が失敗した経路で「前段は成功した」と表示する。**沈黙より悪い** — triage が誤った component へ誘導される。修正は姉妹 hook の既存実装をそのまま写せば済んだ（リポジトリ内に doctrine があるか先に探す価値がある）。

**4. 静的 pin は「行があるか」ではなく「行が機能する形か」を照合する**。skill markdown の env 代入行を pin するテストが行末の行継続を照合していなかった。継続が落ちると代入列が非 export のシェル変数に退化し、次行のコマンドが env を受け取らずに実行される。**行削除の mutant は捕捉できるが 1 文字削除の mutant は素通りする**。照合 literal に構造上必須の文字（行継続・閉じ括弧など）を含める。

**5. fix が PR 本文を stale にする**。テストを追加すると PR 本文のテスト件数が実体とずれる。前 cycle で指摘されて直した箇所を、今 cycle の修正が再び壊す構造なので、**テストを触った fix では PR 本文の検証記録も同一コミットの成果物として扱う**。Red baseline の測り方（どのファイルを revert したか）を本文に明記しておくと、次のレビュアーが別の測り方をして phantom discrepancy を報告するのを防げる。
