### Fix Patterns

**定数の既定値を変更する PR では、数値置換だけを行って「その数値から導出されていた散文」を再計算し忘れる退行が起きる**。本 cycle の指摘 7 件中 4 件がこの型だった。しかも退行は 1 箇所では止まらず、同じ誤りが設計判断セクションにも複製されていた（Asymmetric Fix Transcription が「正しい修正」ではなく「誤り」の側に働いた形）。境界則（`cc >= max_cycles` で `cc` は完了済み cycle 数 → max=N は N cycle を許容し N+1 以上を止める）のような **N と N+1 の区別**は、置換時に最も落ちやすい。

**negative 検査（「旧値が残っていない」）だけで契約を守ろうとすると表記揺れの分だけ穴が残る**。本 PR の T-04 は「既定 5」「default: 5」の 2 形しか見ておらず、英文の `at the default of 15` と半角スペース無しの `（既定5）` を素通しした。修正は positive count pin（「この文字列がこの数だけある」）で、表記が増えても壊れない不変条件に置き換える方向を採った。negative パターンを継ぎ足す方向は 1 ケース専用の追加を再生産する。

**ERE の `?` を多バイト文字に掛けると LC_ALL=C で失効する**。`既定値? 5` は `値` を optional にする意図だが、C ロケールではバイト単位評価となり「既定 5」を検出できない。`既定(値)? 5` のグループ化で解決する。現行環境（ja_JP.UTF-8 / C.UTF-8）では発現しないため、レビューの mutation testing なしでは見つからなかった。

**シェル変数の直後に多バイト文字が来る箇所はブレースで囲む**。fix 中に `"（既定 $DEFAULT_CYCLES）"` を書いて既存 lint（flow-state.test.sh TC-8b-h）に検出された。非 UTF-8 ロケールで後続バイトが変数名に畳み込まれ `set -u` を踏む。fix-introduced regression を既存スイートが即座に捕まえた例。
