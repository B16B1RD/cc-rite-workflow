### Fix Patterns
- 次の実行へ持ち越す候補の id は、出典と元の key を組にした安定したキー（`<元の JSON>#<key>`）にする。今回の候補とだけ照合して接頭辞を付け直す方式は、持ち越しが重なると衝突する。
- 持ち越し候補の置き場（hold）は、外部への書き込み（起票・台帳・申し送り）がすべて済んだ後に呼び出し側が消す。判定を出した時点で消すと、書き込みの途中で止まった再実行が候補を失う。
- 中断からの再開で「どの実行の途中成果物か」を判別するときは、成果物自身にその実行の識別子を 1 行持たせる。行ごとの属性（出典など）で判別すると、属性が混在する正当な成果物を誤って古いものと判定する。
- 処分を次の cycle で再利用させたいなら、処分を書く全経路が同じ台帳に、cycle をまたいで安定したキーで書く。cycle ごとに振り直す id はキーにしない。
