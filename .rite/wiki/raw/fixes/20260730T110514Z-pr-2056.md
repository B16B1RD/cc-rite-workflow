## Review + Fix Results

- **PR**: #2056 (cycle 4)
- **Type**: fixes

### Fix Patterns

- **「いつ発行するか」を書かない観測性義務は実行不能になりうる**: WARNING の発行を「裏取りコマンドと同じ Bash 呼び出し内」と場所で縛った結果、値が確定するのがその呼び出しより**後**（ユーザーの選択結果）である欄と、そもそも呼び出しを持たないクラスで、義務を果たす手段が消えた。**観測性の義務は「誰が・どの経路で・いつ」まで指定する**。特に「ユーザーの選択」を含む欄は、選択より前の時点に発行を固定できない。
- **判定を出すためのコマンドと、訂正案を作るためのコマンドを分ける**: 「コマンドの非ゼロ終了はすべて UNVERIFIED」という網羅的な規則が、**判定確定後に訂正案を組み立てる追加実行の失敗まで拾い**、確定した CONTRADICTED を降格させた。降格先が無承認で本文を書き換える経路だったため、承認下に置く不変条件まで破れる。**「判定に効くコマンド」と「提示内容を作るコマンド」を規則の対象として区別する**。
- **ある行を到達不能にする変更は、その行が唯一持っている情報を移す**: 「gh pr view を開始点にしてはならない」と順序を変えたことで、その失敗を条件とする行が死文化した。行自体は無害でも、その行にしかない訂正案の構築手順と保護文が生きた経路から失われた。**到達不能化は削除と同じ**なので、行が持つ固有情報の移設まで含めて 1 セットで行う。
- **「直交する軸」は判定の軸だけで、発火条件は上書きしない**: クラス 3 を「他クラスの判定と直交」と書いた際、括弧書きの「3 クラスすべてで検出 0 件のときのみ評価しない」が Complexity 発火条件を上書きし、対象外のはずの XS/S でも検査が走る状態になった。**直交性を宣言するときは「何と直交し、何とは直交しないか」を両方書く**。
- **同一 SoT を要約する箇所は、量化のしかたまで揃える**: consumer 側の要約が「非 VERIFIED の**判定**に義務づけられた」と判定値で量化していたため、判定値を持たないクラス 3 が構造的に要約から漏れた。SoT 側で同じ取りこぼしを直した直後に、要約側で同型の取りこぼしが起きている。
- **自分の実測値の再検算を怠らない**: PR 本文に書いた「行頭アンカー化で正当な解決 4 件を失う」は、実際には別パターン（複合条件）の測定値で、素の行頭アンカーでは **294 件**を失う。reviewer が全番号で再測定して桁違いの過少申告を検出した。**測定条件を変えたら数値の帰属先も更新する**。
