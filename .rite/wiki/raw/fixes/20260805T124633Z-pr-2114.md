### Fix Patterns

blocking は 13 → 10 → 5 → 7 と cycle 4 で初めて増え、増分はすべて cycle 3 が新設した 1 つの
機構 (保存先への `.gitignore` 同梱) が持ち込んだものだった。cycle 4 の修正はその機構を
「守りたい不変量」へ結び直す作業に収束し、3 つの一般則が出た。

**(1) guard の述語は「守りたい状態」と同じものを測る**

`[ ! -f ]` で守ろうとしたが、守りたいのは「除外が効いていること」。`printf > F` は redirect が
先に truncate するため ENOSPC で 0 バイトのファイルが残り、存在 guard はそれを「作成済み」と
読んで以後の全 cycle が無音で skip する。marker も二度と出ない。

`[ ! -s ]` にすると次回の実行が必ず書き直しを試みるので、guard が自己修復と再通知を同時に
担う。**post-write の追加検査は要らない** — redirect + rc 検査が既に失敗を捕捉しており、
3 つ目の検査は次 cycle に「機構が多い」と指摘される面が増えるだけ。

判定の目安: guard の述語を文にしたとき、それが finding の failure scenario をそのまま
否定できるか。「ファイルがある」は「除外が効いている」を否定できない。

**(2) 「先例と同型」を名乗る前に、先例の redirect スコープまで読む**

`printf ... > F 2>/dev/null` は**単純コマンド**なので、bash は redirect 自身の失敗 (EACCES) を
`2>/dev/null` 適用**前**に報告する。捨てられるのは `printf` の書き込み失敗 (ENOSPC) だけで、
原因が最も要る側だけが漏れて列 0 に着地する。先例として引いた形は `{ printf ... > F; } 2>&1` の
**グループスコープ**で、挙動が逆だった。

この差は「エラーメッセージが出るか」ではなく「どこに出るか」でしか観測できないため、
pin は文言ではなく**列位置**に取る (`^  .*/\.gitignore: ` が 1 本、列 0 の同型行が 0 本)。

**(3) 同じディレクトリを複数の経路が作るなら、保護は全経路に置く**

保存経路にだけ同梱し、退避経路 (cleanup) に置かなかった。保存を挟まずに cleanup が走る
既存インストールでは保護が一度も効かない。

抽出 (lib helper 化) と複製 (両経路にインライン) のどちらを採るかは、**実処理の行数と
caller 固有部分の量**で決めた。実処理は 1 行、診断文と marker 名は caller 固有、そして
同種の保護の先例もインラインだったので複製を選び、非対称の再発は TC 側で落とす形にした。
helper 化は「同じ考えの 3 つ目の形」を増やすコストの方が大きい。

なお置き場所には別の罠がある: ループ**前**だと結果ファイルが 0 件の PR で毎回失敗して
無意味な marker が出るし、ループ内**無条件**だと 1 つの状態に対して N 本の marker が出る。
「ループ内で 1 回だけ」が唯一正しい。

### Pin の測り方について

- **replaced pin にも負の対照が要る**。新規 pin だけでなく、置換した pin も「旧 pin では
  この mutation が見えなかった」ことを実測する。cycle 4 では旧 `grep -cF` の caller pin が
  呼び出しのコメントアウトを素通しすること、旧 `^  mv` pin が BSD 相当の `mv` (rc=0 / 無 stderr)
  では mutation の有無に関わらず落ちることを、それぞれ shim で実測した。
- **platform 限定の assert は shim で置き換える。chmod では置き換えない**。実コマンドを
  chmod で失敗させる形は root leg で無効化され、避けようとした穴 (特定環境でだけ無検査) を
  別の軸で再生産する。PATH shim なら platform にも uid にも依存しない。
- **診断 pin は locale に依存させない**。`Permission denied` に結合させると ja_JP 環境で
  1 件も拾えない。構造 (`<path>: `) に anchor する。さらに診断を neutralize_ctrl に通す経路では
  0x80-0x9f がバイト単位で潰れて行が invalid UTF-8 になり、**UTF-8 locale の grep はその行への
  match を諦める**。`LC_ALL=C` を付けないと ASCII の anchor すら空振りする (実測)。

**(4) 「委譲」は委譲先が測れる量に限る**

allowlist assert のコメントが「literal な散文だけで再掲載する形は下の pin が担う」と射程を
委譲していたが、委譲先は placeholder の出現回数しか数えない。ただし正しい修正は pin の追加
ではなくコメントの訂正だった — テンプレートは finding ごとの全文を placeholder 経由でしか
受け取らないので、散文だけの再掲載は**構造的に起こりえない**。存在しないケースに pin を
足すのは speculative structure になる。
