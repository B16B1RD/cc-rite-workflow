### Fix Patterns

- **前 cycle の fix が導入した箇所への再指摘は「削除」で応じる**: cycle 1 で足した rationale 散文が cycle 2 でも事実誤認を指摘され、2 reviewer が独立に削除を推奨した。書き直すたびに別の主張が偽になるのは、散文が call site の実態について全称・唯一性の主張をしているためで、主張を持たない状態 (削除) にすると指摘面ごと消える。削除の安全性は「その行を pin しているテストがあるか」で確認する — 本件は静的 pin が bash 行だけを対象にしていたため削除で Red にならなかった。
- **観測性を足すときは「発火条件が縮退のケースだけに一致するか」を先に決める**: cycle 1 で足した WARNING は parse の exit code を条件にしていたが、parser が corrupt 判定でも .data を埋めて非ゼロ終了する設計だったため、carry-forward が成功する経路でも発火する誤報になった。しかも同 PR のテストがその成功経路を正常と固定しており、テストと WARNING が同じ経路で矛盾していた。**追加した warning のたびに既存 TC の fixture と突き合わせる**。
- **判定値は「既定値を持たない field」から取る**: jq の `//` 既定値を持つ field を抽出結果の空判定に使うと、データが空でも非空文字列になり判定に使えない。`(.data | length)` のように既定値のない値を 1 つ足すほうが、分岐を増やすより正確で短い。
- **mutation は構文検査を通してから走らせる**: `grep -v` で行を消す mutation は `if`/`else` を孤立させて構文エラーになり、「全 TC が Red」という無意味な結果を出す。mutation 適用後に `bash -n` を挟むと、無効な mutation を「テストが弱い/強い」の判断材料から除外できる。
- **スコープ外の指摘は「helper 側で限界を明記 + Decision Log」で閉じる**: call site 7 件の是正が Issue の Target/Non-Target どちらにも属さない場合、helper の header に観測性の限界を書いて非黙示化し、Issue の Decision Log に別 Issue とする判断を記録すると、指摘を握り潰さずスコープも守れる。
