### Fix Patterns

インタフェース差し替えの後始末と、タイミング依存バグの修正で見えた型:

1. **シンボルを消したら「そのシンボルを説明する散文」も grep する** — 実装から `--old-option` を消しても、gate の診断文 2 箇所が旧名と削除済み機構を案内し続けた。しかも診断どおり操作すると helper が `unknown option` で落ちる非収束経路になる。完了条件を「`grep -rn -- '--old-option'` が 0 件」のような機械条件にする
2. **テストが誤記述を固定していると、正しく直した瞬間にテストが落ちる** — 「区間内に prefix リテラルが 1 回出る」pin は、その prefix を含みうるのが診断文字列だけの区間では「診断の drift を検出せず、診断の修正だけを検出する」逆向きの pin になる。**pin は実装の不変条件に張る**（判定式・exit code）。文字列の出現回数は不変条件ではない
3. **bash の trap は foreground コマンドの完了まで遅延する** — 「コマンド成功 → フラグ代入」の間には必ず窓がある。フラグを見て分類する handler は、代入を前へ動かしても閉じない。**フラグではなく成果物の実在**を確認するか、実行の事実を別フラグで持って AND を取る。片方だけだと別経路（本件では collision 解決経路）で誤判定へ反転する
4. **タイミング窓を固定 sleep で狙い、外れた run を `pass` で埋めると退行注入時も green になる** — 窓は通知ファイルのポーリングで決定論化し、前提未成立は `fail`（または skip 専用計上）にする。「skip を pass と同一視する」構造そのものが穴
5. **fixture は実装が実際に触る場所に置く** — 実装が `${TMPDIR}` から導出するのに fixture を別ディレクトリへ置くと、実装がどう振る舞っても fixture は残るため「削除しない」assertion が恒真になる
6. **テストは production の緩和策を自動では継承しない** — production が `set -C` で symlink 追随を塞いでいても、テストが素の `: >` で共有 `/tmp` に固定名ファイルを作れば同じ攻撃面が開く。`export TMPDIR="$TMP_ROOT"` のように**導出元ごと隔離**すると、fixture の式を変えずに塞げて後片付けも既存 trap に載る
7. **機械可読 sentinel は状態数だけフィールド値を持つ** — 「消した」と「対象が無かった」を同じ出力にすると、gate が落ちた原因を下流のどの層も名指しできない
8. **「N 種すべて X」は 1 例外の追加で全箇所が同時に嘘になる** — 内訳表記（「N 種のうち M 種は X」）で書けば以後の増減で腐らない
