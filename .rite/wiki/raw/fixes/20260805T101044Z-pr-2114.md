### Fix Patterns

本 cycle の 13 件は 2 つの root cause に収束し、修正戦略もそれぞれ 1 つに収束した。

**(1) pin / assertion の anchor が「守る対象に固有の形」になっていない**

- `assert_grep ... "$ERR" 'mkdir'` が、直前の assert が既に見ている reason marker 行
  (`reason=..._archive_mkdir_failure`) にも match していた。守っている対象 (helper の stderr
  転送) を削除しても緑。**有効な修正は「転送経路に固有の形へ anchor する」** — `sed 's/^/  /'`
  由来の先頭 2 スペース + program-name prefix (`^  mkdir`)。locale 非依存であることを実測で確認する。
- placeholder allowlist の抽出正規表現 `\{[^}[:space:]]+\}` が、空白を含む placeholder
  (`{finding full description}`) を 1 件も拾わなかった。pin が守る対象の反例が、pin の抽出
  regex の外側に落ちていた形。**mutation matrix が「pin が拾える形の mutation」だけで
  構成されると、この抜けは mutation 実測でも露見しない** — 負の対照 (旧 regex + 同一 mutation
  で全 green) を取って初めて blind であることが示せる。
- **一般化**: assert の pattern を書いたら「同じチャネル (同じファイル / 同じ stderr) に出る
  別の行に当たらないか」を必ず確認する。substring が別の marker 名の部分文字列になっている
  ケースが最頻。

**(2)「安全側に倒す」をデータ保全だけで実装し、fail-loud の「出力する」側を実装しない**

- 「判定不能はすべて退避側へ倒す」と docstring で宣言しながら、jq の rc が 0/1 以外のとき
  診断も marker も出さず、退避メッセージも正常系と同一文言だった。結果、壊れた JSON と正常な
  JSON が archive/ 内で区別不能になる。**保全 (消さない) と観測 (loud に出す) は別の要件で、
  前者だけ実装しても fail-loud にはならない。**
- `X_err=$(mktemp ... 2>/dev/null) || X_err=""` → `2>"${X_err:-/dev/null}"` の組は、mktemp
  失敗時に後続の診断を丸ごと `/dev/null` へ落とす。**mktemp が失敗する条件 (ENOSPC /
  read-only TMPDIR) は mkdir/mv の失敗条件と相関する**ため、診断が最も要る場面でだけ診断が
  消える。**有効な修正は tempfile をやめて command substitution (`err=$(cmd 2>&1)`) にすること** —
  失敗する余地が無く、trap も orphan tempfile も同時に不要になる (機構の追加ではなく削除で
  2 指摘を同時解消)。mkdir / mv / rm はいずれも成功時 stdout を持たないため捕捉で情報は落ちない。

**(3) inline → helper 委譲リファクタが生む新しい失敗モード**

旧 inline コードが持っていた error handling は helper 側へ完全に転写されていた。落ちていたのは
「移した処理」ではなく **「委譲という行為そのものが新たに生む失敗モード」** = helper を起動
できなかった場合 (`{plugin_root}` の未解決置換 / helper 欠落で rc=127)。caller が rc を検査
していないため marker が 1 本も出ず、marker 不在を「完了」と読む判定表が silent に成功を報告した。
**委譲リファクタでは「移した処理の error handling」だけでなく「委譲が新たに生む失敗モード」を
数えること。**

**(4) bash 引数 parse の `shift 2` 無条件呼び出し**

値のない末尾オプション (`--pr` で終わる等) では `shift` が失敗して `$#` が減らず、
`while [ $# -gt 0 ]` が無限ループする。出力ゼロで永久にハングし、docstring が宣言する exit 1 に
到達しない。`"${2:-}"` を使っていると `set -u` にも引っかからないため完全に無音。
**各 arm に `[ $# -ge 2 ]` guard を置く。TC 側は `timeout` で囲む** (ランナーが per-file timeout を
持たない場合、退行時にスイート全体が止まる)。

**(5) 同一契約を述べる複数箇所の drift — anchor 参照先を先に grep する**

cleanup の挙動を「一律削除」から「条件付き退避」へ変えた際、6 ファイルには伝播したが同一
ファイル内の別節が旧記述のまま残り、しかもそこは Acceptance Criteria の双方向 anchor 先だった
(4 reviewer が独立に検出)。**契約を変えたら、その契約を anchor として参照している箇所を先に
grep する** (同一ファイル内でも別節なら drift する)。

**(6) 判定不能の扱いが同一ブロック内で割れる**

「判定不能は保全」を宣言した直後の行で `.corrupt-*` を無条件削除していた。corrupt は
「中身を判定できない」状態そのものなので、2 ポリシーが並置される。**有効な修正は別経路を
足すことではなく glob を統一して経路を 1 本にすること** (`.json` → `.json*`)。判定は既存の
jq 分岐が自然に「判定不能 → 退避」へ落とす。
