### Fix Patterns
- 書き込みに失敗した state を「中断として扱わない」要件は、state を書く全経路（SessionEnd だけでなく後片付けの reap）に及ぶ。書き込み自体が失敗する経路では、別ディレクトリに失敗の記録を残し、読み手（resume）がそれを参照する形にするしかない。
- 失敗の記録は「state のバイト単位の複製」とし、読み手は現在の state と cmp で比べる。以後の書き込みで state が変われば自動的に一致しなくなるため、記録の消去処理が要らず、正当な中断を妨げない。
- in-place の上書きで失敗を「成功」に変える fallback は、非 atomic で失敗経路を隠すため採らなかった。
- 検証は mutation で行った: 抑止の分岐・同一性の照合・記録の書き込みをそれぞれ外した mutant がすべてテストで落ちることを確かめた。
