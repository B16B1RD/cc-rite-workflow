### Fix Patterns

- **外部ツール制約を理由にした不変条件の例外は逆進性を生む**: 「付記もユーザー承認下に置く」不変条件が AskUserQuestion の 4 問上限を超えた経路にだけ適用されず、結果として CONTRADICTED が最も多い body ほど無承認の書き換えが起きる形になっていた。**上限を持つ外部ツールに依存する MUST は、上限超過時の挙動まで同じ規定の中で決める**。今回は「4 問目の description に溢れ分の一覧を載せ、同じ 1 問で一括承認を取る」形にして例外を消した (質問数を増やさずに承認経路へ寄せる)。
- **判定の強さと観測可能性を逆相関させない**: 最も強い判定 (CONTRADICTED) が stderr WARNING を要求せず、弱い判定 (UNVERIFIED) だけが要求していたため、確定した矛盾が検証不能と判別できない記録に落ちていた。**強い判定ほど永続かつ判別可能な痕跡を持たせる**。
- **分岐述語は「同じ観測値を複数箇所で使う」前に定義する**: 同一の観測 (`gh issue view` の url が /pull/) が、一方では「PR として検証続行」、他方では「CONTRADICTED」に写っていた。両者を分ける述語 (「Issue として引用した」) が bare `#N` について未定義だったのが原因。**同じ観測値を複数箇所で消費する規定を書くときは、分岐述語の定義を先に置く**。
- **規定の追加先は SoT 節を選び、表の行へ複製しない**: CONTRADICTED の WARNING 義務はエラー処理表の 3 行それぞれではなく「3 値の処理」節 (CONTRADICTED 語彙の SoT) に 1 回だけ置いた。行へ複製すると、後から CONTRADICTED を出す行が増えたときに転記漏れが起きる。
- **共有 reference を新設するときは「どの規則が全 consumer に効くか」を節として切り出す**: 本 cycle では未修正で残したが (実測なしで non-blocking)、再入時ガードが consumer 側 (issue-edit) にのみ書かれ、もう一方の consumer (issue-create 5.1.1) が継承できない乖離が指摘された。「同一 reference を参照し複製しない」という MUST があっても、reference に書かれていない規則は構造的に共有されない。
- **PR 説明文は挙動を変える fix commit と同 cycle で更新する**: レビュー修正で挙動を反転させたのに PR 本文の「設計判断」節が追随せず、squash merge 後の履歴に実装と正反対の記述が残る経路が成立していた (reviewer が実測 grep で検出)。
