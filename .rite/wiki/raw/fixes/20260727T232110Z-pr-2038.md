### Fix Patterns

- **markdown テンプレートの「表示上の字下げ」は消費側の行頭 anchor と衝突する**: 手順を番号付きリスト項目にすると、その内側の fence は全行が 3 スペース字下げされて提示される。生成物を `head -n 1` の前方一致や `grep -E '^...'` で検査する helper に渡す設計だと、LLM が表示どおり転記した瞬間に毎回 fail する。テンプレート側を `^[[:space:]]*` で照合する静的 pin を置いていると、pin 自身が字下げを許容するためこの乖離をどの層も検出できない。塞ぎ方は「本文は列 0 から書き出すこと」を**テンプレートより前**に明示し、その指示の存在と位置を pin すること。指示をテンプレートより後ろに置くと、読み手が本文生成を終えた後に現れるので用をなさない。

- **静的 pin の「合計下限」と「同一集合由来の等値判定」はどちらも削除軸に無反応**: `assert count -ge N` を複数セクションの合算に対して置くと、1 セクション分が丸ごと消えても他セクションの行数で閾値を満たして通る。`assert "$total" "$conforming"` の両辺を同じ集合から導出すると、行を削除しても両辺が同時に減って等値が保たれる。結果として pin のコメントが謳う「各セクションが最低 1 本のデータ行を持つ」を実装が保証しない状態になる。正しい規律はセクションごとに区間を切り出して個別に assert すること。

- **gate 列の pin は「実在」だけでなく「後続への hand-off」も固定する**: 評価順序を持つ gate 群では、中間 gate の pass 行が消えると後続 gate が構造的に到達不能になる。データ行の実在検査だけでは pass 行の削除を捕捉できないため、終端でない gate については「次の gate へ進む」規約文言を持つ行が 1 本以上あることを別 assertion で固定する。終端 gate は「次の gate」を持たないため対象外にする。

- **mutation は軸ごとに網羅する**: 置換軸 (述語の書き換え・文言の差し替え) の変異だけを当てて「pin は落ちる」と結論すると、削除軸 (行の削除・節の全削除) への無反応が残る。pin 追加時は最低でも「置換」「削除」「位置移動」「死に分岐化」の各軸で実測すること。実測は $TMPDIR への複製に対して行い、リポジトリの working tree は変更しない。
