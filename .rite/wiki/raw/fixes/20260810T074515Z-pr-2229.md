### Fix Patterns

**「複製の同期漏れ」を指摘されたら、同期ではなく複製の削除を先に検討する** — これが cycle 2 で最も効いた判断だった。cycle 1 は「4 箇所に複製された誤った根拠を直せ」という指摘に同期で応え、複製構造を残したまま新たに 3 サイトの複製を作り、1 箇所（宣言済み SoT）を掃き残して同じ欠陥クラスを再生産した。cycle 2 では定義を単一述語（「結果を回収できたか」）に置き換えることで、経路ごとの除外規則（確認 UI での増減、spawn 失敗マーク）を書き足す必要自体を消した。**経路ごとに規則を足す形になっていたら、全経路の帰結を 1 つの述語で表せないかを問う。**

同じ判断がテスト側でも効いた。実装が同じ述語を「強制用」と「診断用」に複製すると、ファイル全体 grep の pin は診断側の複製で満たされ、強制側を削っても緑のまま通る。ここでテストを区間限定 grep へ賢くする案を試したが、**mutation で検出できないことを実測して棄却**し、代わりに実装側の複製を消した（判定を 1 箇所にし、pass/fail も診断もそこから導く）。テストの検出力は複製を消した結果として自然に回復した。**pin が効かないときは、pin の書き方より先に「pin する対象が 1 箇所か」を疑う。**

否定 assert (`assert_not_grep`) は、対応する肯定 assert が同じリテラルを固定していないと、リテラルを書き換えるだけで黙って空振りする。**否定 assert は必ず肯定側の双子と同一リテラルにする。**

修正の妥当性判断には mutation 実測が決定的だった。3 種の変異（強制条件の削除 / ラベル語の書き換え / SoT 片側の巻き戻し）を隔離 worktree で流し、修正前は 0 件 fail・修正後は 2/2/1 件 fail を確認してから commit した。**「テストを直した」は主張ではなく実測で示す。**
