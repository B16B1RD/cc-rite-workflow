### Fix Patterns

前サイクルの修正が CRITICAL 退行を生み、方針を「guard を足す」から「インタフェースを戻す」へ
転換した回。修正側の教訓が濃い:

1. **同一箇所に複数サイクル指摘が出続けるときは、パッチではなくインタフェースを疑う** — 2 サイクルで
   出た 8 件（sentinel 偽造 / traversal / errno / 文字集合 wedge / 各 guard 条件の pin 不足）は
   すべて「caller から full path を受け取る」という 1 つの選択に由来していた。個別に塞ぐと
   guard が増え、その guard 自体が次の指摘面になる。**sibling が同じ処理を別の形で解いているなら、
   まずその形に揃えられないかを見る** — 揃えた結果 guard 群ごと消えて net マイナスになった
2. **入力を狭める防御は、その値を作る側の値域と突き合わせない限り必ず wedge を作る** — 消費側だけに
   allowlist を足すと、生成側が正当に作れる値まで拒否する。しかも拒否の帰結が「消さない」＝ gate の
   残存判定と噛み合うと、**成功しているのに永久に失敗と判定される**非収束になる。防御を足す前に
   (a) 生成側の値域、(b) 拒否時の帰結が既存 gate とどう合成されるか、を必ず確認する
3. **fixture が安全側に偏っていると防御の穴は構造的に見えない** — 全 fixture が `mktemp -d` 由来
   だったため、空白・非 ASCII を含む path での wedge は全 assertion green のまま素通りした。
   **入力を狭める変更を入れたら「弾かれる側の正当な入力」を fixture に必ず 1 本入れる**
4. **signal handler は「何が完了済みか」を見てから分類する** — 中断は「失敗」ではなく「未完了かもしれない」。
   完了フラグを見ずに一律 failure を宣言すると、成功済みの処理を下流が失敗として扱い、
   「保存に失敗したら止めない」より強い「保存に成功したのに止める」違反を作る
5. **`-e` は dangling symlink を偽と返す** — ファイルの存在そのものが判定値である gate では
   `-e || -L` にしないと fail-open する。gate の意味が「実行されたか」であるほど致命的
6. **件数を書いた記述は 1 語彙の追加で一斉に腐る** — reason を 1 つ足しただけで「14 種」と書いた
   5 箇所が同時に stale 化した。件数ではなく内訳（「15 種のうち exit 0 は 14 種」）か、
   件数を持たない表現（「既存語彙を増やさない」）へ寄せる
7. **禁止句の除去は番号を消すだけでは終わらない** — 過去イベントの叙述（「先行 PR では〜だった」
   「かつて〜だった」）は番号を消しても違反として残る。主語を機構側に移して現在形の制約散文へ
   書き換える。lint が裸の `#NNNN` を拾わないため lint clean は完了の証明にならない
