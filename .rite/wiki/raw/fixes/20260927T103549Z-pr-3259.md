### Fix Patterns
- 起動時の案内が読む state がセッション単位のとき、案内の対象 source は「同じ session_id で起動する入口」を基準に選ぶ。既存の別経路（リセット）の対象 source を流用すると、停止した run に戻る実際の入口（resume）が抜ける。
- hook のテストはホストと同じ入力の形（ホスト種別と payload の session_id）で呼ぶ。harness が sid を事前設定する呼び方だけで固定すると、実入口で到達しない分岐も green になる。新しい session_id の起動では出ないことも対照として固定し、案内の範囲をテストで示した。
