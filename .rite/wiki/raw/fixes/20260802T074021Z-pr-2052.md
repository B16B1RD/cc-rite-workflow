### Fix Patterns

1. **書き換える単位は「文」ではなく「主張が閉じる範囲」**: bullet の前半だけを新契約へ移し後続 2 文を旧契約のまま残す誤りが、4 レビュアーから独立に指摘された。しかもそれが operator 向け remediation で、永続する手当てを否定して非永続な手当てを勧める状態になっていた。**段落・bullet 単位で読み直してから書き換える**。

2. **pin されている表に行を足すときは pin も同時に足す**: 前サイクルで pin 語句を壊して CI を赤にした反省から文言を復元したが、同じ表に**新しく足した行**には pin が無く、削除しても全テストが緑のまま通ることが変異注入で実測された。「唯一の下流検出器」と自称する行が無 pin という非対称。

3. **pin は「その行に固有な文字列」で張る**: 最初に張った pin (`WIKI_INGEST_STATS=aborted`) は同じ文字列が bash ブロック内にも出現するため、表の行を削除しても検出できなかった。変異注入で kill しないことを確認して固有文字列へ差し替えた。**pin を足したら必ず変異注入で kill を確認する** — 張っただけでは守れていない。

4. **限定句はスコープと対で書く**: 冪等化のための限定を「両経路共通」の位置に書いたため、掛かるべきでない frontmatter 由来の値にも掛かり、前サイクルでは列崩れとして loud に露見していた壊れ方が silent 化した。限定を足すときは「どの入力に掛かるか」を同じ文で明示する。

5. **サイクル単位のセマンティクスを per-item ループに置かない**: 全体の状態を前提にする手順を item ごとのループ本体に置くと、guard が評価不能・カウンタが N 倍・レポート行が N 行並ぶ。同一ファイルに先例（push を全 item 後の 1 回へ集約）があった。

6. **成功経路にも marker を出す**: 中止経路にだけ marker を出す設計は marker 不在を「成功」と「未実行」の両義にする。同じ表の別 marker が既に 3 値設計（ok / failed / 不在 = 未確認）だったので、非対称を解消した。

7. **カウンタは「定義・実行地点・表示・等式」の 4 点セット**: 前サイクルで 3 点に配線したが実行地点への加算指示が漏れ、しかもその手順が加算対象を明示列挙していたため列挙が網羅的に読めて新カウンタは加算されない解釈になっていた。
