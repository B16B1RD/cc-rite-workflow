**1. read 経路を差し替えるときは、旧経路が明示していなかった不変条件を列挙する**

同定手段を「本文照合 (`issues/{PR}/comments` の列挙)」から「durable id (`issues/comments/{id}` の直接 GET)」へ移したとき、旧経路が構造的に持っていた **PR スコープ** が落ちた。旧経路は PR 番号をパスに含むため「当該 PR のコメントである」ことを検証する必要すらなかったが、新経路は repo スコープで issue 非依存のため author 一致だけでは別 PR の自コメントを掴める。application と security が独立に検出し、security は「PR body は書き込み権限を持たない PR 作成者でも編集できる」ことから権限昇格として評価した。

再発防止: **同定子・キー・参照の取得経路を差し替えるときは、旧経路がパスやクエリの形で暗黙に保証していた制約 (スコープ・順序・一意性) を明示的に列挙し、新経路で個別に検証する**。旧経路が「検証していない」ことは「検証が不要」ではなく「構造的に保証されていた」を意味しうる。

**2. 新分岐の帰結を理由ごとに分けると、周辺状態との交差ごとにガードが要る**

404 だけを「削除済み → 新規作成 (recreate)」として他の失敗理由と別扱いにしたところ、3 つの実害が出た: (a) 本文照合が実在の canonical を見つけていても無視して 2 通目を作る、(b) 0 件 cycle で収束クリアが成立しない、(c) list lookup 失敗と重なると degraded 判定が非対称になり縮退が転記条件のどれにも載らない。3 reviewer が別角度から検出した。

修正は **ガードを 3 本足すのではなく分岐を 1 本削除する**方向を採った (simplification-first)。理由 (reason) は復旧手順が違うので分けたまま残し、帰結 (action) だけを 1 種に畳んだ — **分けるのは診断であって帰結ではない**。この分離が効くのは、reason が増えても交差の組合せが増えないため。

**3. mutation matrix は「実装の全副作用」で軸を設計する**

初回の mutation matrix (M1〜M7) はすべて「PATCH 先を決める read 側の判断ロジック」に当たっており、(a) write 側パス (marker strip / body 読取 guard) と (b) stub の error-shape 忠実性に 1 つも当たっていなかった。test reviewer が指摘した 4 件はすべてこの 2 軸に属していた。

さらに重要な実測: **修正後に追加した「STRIP_SED を pin する assertion」は、当初 mutation で 1 件も落ちなかった**。fixture に「散文中に marker と同形の文字列がある」ケースがなく、行アンカーの効果が観測できていなかったため。指摘の実害そのものを再現する fixture を 2 つ (marker 行と散文行の順序を入れ替えたもの) 追加して初めて識別力が出た。

再発防止: **pin を追加したらその場で mutation を当て、落ちなければ fixture が failure mode を再現していないと判断する**。assertion の文面が正しくても、fixture が欠陥の条件を満たしていなければ検出力はゼロ。
