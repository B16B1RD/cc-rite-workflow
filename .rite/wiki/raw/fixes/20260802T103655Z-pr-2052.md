### Fix Patterns

本 cycle の 2 件はいずれも「配布成果物と rite 内部の境界」に関する同一の根本原因に帰着し、片方は伝播スキャンで自動的にもう 1 箇所を掘り当てた。

1. **配布テンプレートへの内部参照流入は 1 箇所直しても閉じない**: `templates/wiki/**` は `/rite:wiki-init` が placeholder 置換または単純 cp でユーザープロジェクトへ展開する成果物であり、repo 相対パスや Issue 番号を書くと展開先で解決できない。指摘は `schema-template.md` の 1 箇所だったが、伝播スキャン (同一パターンで sibling を走査) が `index-template.md` にもう 1 箇所を検出した。**develop 時点で全 4 テンプレートが 0 件だったことを `git show develop:<path>` で確認できたため、「0 件」が暗黙の不変条件だったと確定でき、伝播範囲を推測ではなく機械的に決められた**。配布成果物への変更をレビューするときは、指摘箇所だけでなく同じ配布単位の sibling を必ず同一 grep で走査し、base branch 側の件数と比較して不変条件を復元する。

2. **cp fixture は「テンプレートが持たない構造」を pin できない**: 配布テンプレートを `cp` して fixture にするテストは、テンプレート実体が変わると pin 対象も一緒に消える。本 PR はテンプレートに 5 列テーブルを新設したが、テストは前文しか見ておらず、ヘッダー列名の改称も表ブロックの全削除も suite 緑 (PASS:182 FAIL:0) のまま通った。**同一コミットが「cp fixture は持たない形式を pin できない」原則を自ら明文化して literal fixture を 1 本追加していたのに、その原則を自分が追加した構造には適用していなかった** — 原則を書いた側の変更にこそ、その原則を適用したか確認する。

### 有効だった検証手法

- **assertion を書く前に fixture の実挙動を実測する**: 「パーサは行単位だから末尾 append でも拾われるはず」という推測を、assertion を書く前に sandbox で確かめた (`hits=2 / skipped=0`)。既存の類似 fixture (箇条書き append) は**負のケース** (drift 検出=1 を期待) であり、正のケースの根拠にはならなかった。先に assertion を書いて失敗をデバッグすると、helper の実挙動に合わせて assertion を弱める方向に倒れ pin が壊れる。
- **修正の完了条件を「指摘の Verification アンカーが red になること」に置く**: 指摘が `repro sed -i 's/サマリー/概要/' ... => PASS:182 FAIL:0` を添えていたので、修正後に同じ変異を再実行して FAIL:2 になることを確認した。clean HEAD で緑なだけのテストは、行が増えただけで穴は残る。テンプレートの backup/restore は `cp` + trap で行い、検証後に `git diff` が空であることまで確認した。
