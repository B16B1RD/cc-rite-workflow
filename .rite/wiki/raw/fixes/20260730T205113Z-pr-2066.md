### Fix Patterns

**抽出範囲を広げる修正は、抽出先が変わっていないかを確かめる**: drift test の抽出パターンを「語彙 alternation」から「regex 全体」へ広げた結果、被テスト対象の**ヘッダコメント**（同じ regex を `…` で省略して例示していた）にも一致するようになり、`head -1` がコメント側を拾った。2 つのコメントを比較する test になったため、実行コードの drift を 1 クラスも検出しなくなった。**修正前より識別力が下がる修正がありうる。** 変異で赤くなることを毎回確かめる。

**commit message に書いた変更が landed しているとは限らない**: 「TC-9 の 2 ページ版も足した」と書いたが、置換のアンカー文字列が実ファイルと一致せず no-op になっていた。複数の置換を 1 スクリプトにまとめて末尾で `assert s != o` を 1 回だけ掛けると、**一部が no-op でも通る**。置換ごとに個別検証するか、適用後に必ず assert 数の増加を確認する。

**診断本文を運ぶ変数にセンチネル値を入れない**: パストラバーサル gate が `_polluted=1` と代入したため「検出行: 1」と出て、どのパスが弾かれたか失われた。sed インジェクション修正（同 PR）が守ろうとした「なぜ弾かれたかが消える」状態そのものを、その修正と同じ commit で作っていた。

**片方だけ中和して契約側を残す**: stderr の診断行に `neutralize_ctrl` を通す一方、隣接する **stdout の契約行**は生のまま残した。advisory コピーを直して契約コピーを残す形は、リポジトリ自身が Asymmetric Fix Transcription として記録している型。

**positive control は「何を歩いたか」まで測る**: `--all` の走査結果が 1 件以上あることだけを測ると、複数ある走査 root のうち 1 つが落ちても充足する。除外 assert はその root を歩いていることを前提にしているので、前提ごと無言で消える。**root ごとに 1 件ずつ置いて個別に測る。**

**報告文字列の assert に部分一致 glob を使わない**: `*"PR #2047"*` は末尾に残余があっても一致するため、語境界のための trim を削除しても緑のまま通る。完全一致にし、かつ行頭一致だけでなく**行中一致**の fixture も置く（行頭 fixture だけだと左 trim が常に no-op になる）。

**「共有 SoT」を名乗る reference は、共有先の全員から到達可能にする**: 2 実装が共有する設計背景として新設した reference が、片方の実装からは 1 本もリンクされておらず、その側は同じ内容の第 2 コピーを別ファイルに保持し続けていた。実測値の更新が 3 箇所同時を要する構造になり、実際に 1 つが取り残された。**退避は「移動」であって「複製」ではない。**
