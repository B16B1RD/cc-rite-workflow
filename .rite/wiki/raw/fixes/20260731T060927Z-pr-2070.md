### Fix Patterns

blocking 2 件はいずれも「本 PR 自身が作った非対称を、それを記述する散文が表現できていない」という同一の根に帰した。修正はどちらも既存散文への 1 句追記で、新しい分岐・ガード・規約・セクションを持ち込んでいない。

抽出できた経験則:

1. **委譲表現は「同じ規則」を伝えられても「自分だけが通る経路」を伝えられない** — 「ステップ N と同一」と書いた契約は、委譲元だけが通る新経路が生まれた時点で前提を落とす。委譲先が持つ前提のうち、委譲元でのみ実際に発火するものは委譲では届かない。**適用条件: あるステップの実行条件を「他ステップが skip される場面でも実行する」方向に変えたとき、そのステップの委譲型契約文を必ず見直す。**

2. **規範文と既知の非適合は同じ文書に隣接させる** — 要求 (consumers must accept both forms) を上位仕様書に、現況 (既知の非適合 consumer) を rationale に分けて同一 PR で書くと、上位文書だけを読む読み手には「既に満たされている」と読める。上位文書ほど例外の併記が要る。**適用条件: 規範文を追加する PR では、同じ PR が別ファイルに書いた例外・現況記述と突き合わせる。**

3. **修正方針の選択で削除・単純化を先に検討する（Simplification-First）** — 今回は (a)「空 HEREDOC 契約を共通セクションへ hoist して 3 箇所の複製を一本化」案を、新構造の持ち込みと 4 箇所書き換えを理由に退け、(b)「規範文自体を削除して事実記述だけ残す」案を、設計意図の喪失を理由に退けた。いずれも退けた理由を commit message に明示した。**適用条件: 1 句追記で済む指摘でも、hoist / 削除案を一度は評価し、退けた理由を残す。**

4. **実測アンカーに raw pipe を書くと実測済みでも non-blocking へ落ちる** — test reviewer は変異注入で実測していたが、`Verification:` の repro に awk regex 由来の `\|` が残り Anchor detection regex に full match せず measured=false へ降格した。bash/jq 中心のリポジトリでは repro にパイプが入るのが常態であるため頻発しうる。**適用条件: repro を書くときはパイプを `¦` (U+00A6) へ置換する。markdown のエスケープ `\|` でも検出側の `[^|]` は通らない。**

5. **PR 本文の実測値は cycle ごとに陳腐化する** — 6 reviewer 中 4 名が独立に「PR 本文の数値が実測と食い違う」ことを検出した (テスト件数 97 → 実測 144、hits 228 → 230、合計 250 → 252、skipped_rows 1 → 0)。**適用条件: AC 検証表に数値を書くなら最終 cycle で再実測してから ready 化する。**
