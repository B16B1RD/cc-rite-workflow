### Fix Patterns

否定形アサーションを肯定形へ移したとき、その理由を「旧形式は X を受け入れていた」と書くとコメントの主語が変更イベント（過去の行為）になる。同じ情報は「素の `!= X` テストではこの契約を表現できない: …はいずれも抽出値が空になるため通ってしまう」という現在形の制約文で完全に保持でき、退行防止の価値も落ちない。

削除したコードを定冠詞で指す表現（"as strict as **the parse** was"）は、差分を見ない未来の読み手にとって指示対象が存在しない。不定冠詞 + 仮定法（"as strict as a `permissionDecision` parse would be"）へ移すと自己完結する。

コメント規約の違反は lint が緑でも成立する。プロジェクトの規約自身が「このサブ分類は regex で機械検出できないため reviewer の LLM 判定で扱う」と明記している場合、機械検出 0 件は適合の証拠にならない。

コメントのみの変更では、非コメント行の md5 が変更前後で一致することを示すとロジック不変性を機械証明できる（`git show HEAD:file | grep -vE '^[[:space:]]*#' | md5sum` の前後比較）。レビュー側の検証コストが大きく下がる。
