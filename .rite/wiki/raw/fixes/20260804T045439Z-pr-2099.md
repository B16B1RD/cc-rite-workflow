### Fix Patterns

blocking 推移 6 → 8 → 7。cycle 3 の指摘は cycle 2 の「是正」作業が生んだ 3 型に集約された。
**「fix が drift を生む」の中でも、是正作業に固有の型**として記録する:

1. **誤りを直す変更が同じ段落に同じクラスの誤りを作る**。cycle 番号の off-by-one を直した同じ文の
   末尾に別の off-by-one を書き足し、前半節と後半節が同時に真になれない一文にした
   （4 reviewer が独立に CRITICAL 検出）。**予防: 直した文を前後の節と突き合わせ、
   両者が同時に真になるか確かめる。** 数値・順序・因果を含む散文の是正は 1 行では終わらない。

2. **削除した誤った主張を別ファイルへ移設する**。A から誤因果を削った同一コミットで、
   B に同じ主張を新規記入した。欠陥の除去ではなく移動であり、同一 PR 内の 2 文書が
   正面から矛盾する状態になる。**予防: 削除した主張の文字列を、削除後に全文書へ grep する。**

3. **伝播確認の grep が言語をまたげていない**。「8 サイトへ atomic に伝播し git grep で
   残存ゼロを確認した」と commit message に書いたが、検索語が日本語側だけで英語側を拾えず
   2 サイトを取りこぼした。**予防: 日英が同じ invariant を述べるリポジトリでは、
   伝播確認の検索語に必ず両言語を含める。** 片方だけの語では残存を検出できない。

**3 cycle 連続で現れた「fix の rationale を pin していない」型への実効的な対処**:
本 cycle は **fix で新しい観測点（WARNING / rc 検査 / gate）を足したら、その観測点自体を pin する**
を全件に適用し、5 変異すべてがスイートを赤にすることを実測した。決定論的に窓を突く手法として:

- **引数で選ぶ shim**（呼び出し回数ではなく `"$@"` の内容で対象を選ぶ）— 序数だと
  「1 ファイルあたり n 回」という実装詳細に依存し、呼び出しが 1 つ増えた瞬間に
  別 site を静かに叩きながら緑を維持する
- **mktemp shim で trap 武装前の窓を再現**（数マイクロ秒の窓は時間では突けない）。
  rc が順序に依らず同じになる場合は、残骸の有無が唯一の判別子になる
