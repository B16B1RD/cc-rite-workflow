### Fix Patterns

cycle 1 の blocking 7 件は、根が 1 つだった — **新設した検査層を既存層の「付録」として設計し、既存層の分岐条件をそのまま継承させた**こと。ここから 4 系統の欠陥が同時に出た。

1. **層の従属化が、守るべき Given でだけ機械強制を降ろす**: 新しい positive 検査を、既存 marker 検査の「marker 不在」arm の内側に置いた。ところが守るべき failure mode（区間ごと skip）では marker 値そのものが空文字 / 未置換になり、marker 層が degraded に降りるため positive 検査が一度も走らない。新層の入力は既存層に一切依存していなかったのに、配置だけで従属していた。**新しい判定層は、既存層の分岐の外に置き、入力の依存関係だけで実行可否を決める**。

2. **層を混ぜると marker の意味論が壊れる**: 独立させた結果、helper が `GATE=pass` を名乗ると degraded に降りた層の直後に pass が重なり、「degraded を pass と読み替えるな」という caller 規則と観測値が食い違う。**層ごとに別の marker 名を持たせ、gate 全体の可否は `*_FAILED` の不在で決める**。

3. **degraded と fail の境界は「契約の語彙」で引く**: Issue が degraded に置いたのは「解決できない / 読めない」だったが、実装は「存在しない」を degraded に、「読めない」を fail に振っていた（find の rc 未検査）。両方向とも害がある — 前者は守るべき Given で機械強制を降ろし、後者は permission 起因を差し戻し先で直せない非収束ループにする。**「差し戻して直るか」で振り分ける**: 直らないもの（置換漏れ・permission・環境不備）だけが degraded。

4. **等値比較を load-bearing にしたら、両辺の生成規約を先に確認する**: 40 桁 SHA と JSON の値を厳密一致で比較して不一致を blocking にしたが、schema の正典例は 7 桁短縮で、書き手側に形状検査も値源の指示も無かった。同一 commit が「不在」と判定され、差し戻しても同じ値が再生成される。**prefix 一致 + 入力側の形状検査**で塞ぎ、書き手側の SKILL.md に値源を明記した。

5. **parameterized 表面の網羅は production 経路の被覆ではない**: helper のテストは全 leg で `--results-dir` / `--since` を明示していたが、本番の呼び出しはどちらも渡さない。既定解決経路（run pin の読み取り）を壊す変異が無検出で通った。**「本番が実際に使う唯一の引数形」を通す arm を必ず 1 本置く**。

6. **観測値の偽造可能性は、自分のテストが pin した不変条件を壊す**: `[CONTEXT]` marker を機械契約に使う設計では、走査対象の値に改行が入ると桁 0 に marker 行を偽造できる。脅威モデル上は同一 principal でも、**pin 済み不変条件が破れる**こと自体が欠陥。読み手側で無改行化する。
