# 計画セルフレビュー — agent prompt と判定出力形式

open ステップ 3.3.1 が Task（`subagent_type: general-purpose`）で spawn する単一 agent の prompt SoT。
pr-review の reviewer 選定・named agent とは混ぜない。計画ファイルは編集しない。指摘の計画反映は orchestrator（3.3.1）の責務。

## Prompt（spawn 時にこの節を渡し、続けて 3.3 の計画本文を添付する）

ステップ 3.3 の実装計画を、次の 4 視点だけで 1 回レビューする。方式選定の好みやスタイルは対象外。指摘は「計画への修正提案」として返す。blocking / 再レビュー要求は出さない。

1. **検証網設計** — 計画のテスト / ガードレールが何を pin するか具体化されているか。総数だけ pin して形（順序・隣接・合成）を pin していない、空振り経路が残っていないか。T-xx と実装ステップの対応が「実行した」以上の観測条件を持つか。
2. **文書同期スコープ** — 変更が触れる既存記述（README・隣接 SKILL / reference・ユーザー向け手順）が、変更対象またはドキュメント影響調査の対象として列挙されているか。
3. **CI・統合配線** — テスト / ガードの実行経路（既存 runner の glob、呼び出し元）と失敗時挙動が計画にあるか。新規テストが runner に載るか。
4. **regression 面** — 変更が削除 / 弱体化しうる既存のガード・記述・慣習は何か。保全手段が計画にあるか。

視点は上記 4 つのみ。予約枠を足さない。

## 判定出力形式

agent は次の形だけを返す。前後の解説・推測補完・別形式は禁止。

```
## 計画レビュー結果

指摘件数: {n}

| # | 視点 | 指摘 | 反映先 |
|---|------|------|--------|
| 1 | 検証網設計 | {何が不足か} | 実装ステップ {N} に「{追記する文}」を追加 |
```

- `{n}` は 0 以上の整数。`指摘件数:` 行が必須。
- `視点` は 検証網設計 / 文書同期スコープ / CI・統合配線 / regression 面 のいずれか。
- `反映先` は次のいずれか: 実装ステップ追記、変更対象ファイル追記、要判断ポイントへ昇格。
- 指摘なしは `指摘件数: 0` とヘッダだけの表。

orchestrator はこの形式を観測できない（spawn / 回収失敗、`指摘件数:` 欠落、視点が 4 種以外）場合、出力を推測補完せず 未実施として扱う。
