# 計画セルフレビュー — agent prompt と判定出力形式

open ステップ 3.3.1 が Task（`subagent_type: general-purpose`、`run_in_background: false`）で spawn する単一 agent の prompt SoT。
pr-review の reviewer 選定・named agent とは混ぜない。named reviewer をネスト spawn しない。
計画もリポジトリも編集しない（Edit / Write / NotebookEdit 禁止）。指摘の計画反映は orchestrator（3.3.1）の責務。

spawn ペイロードは **Prompt 節 + 判定出力形式 + 本ファイル冒頭の制約** を連結し、続けて 3.3 の計画本文を添付する。子に本ファイルを Read させない。

## Prompt

ステップ 3.3 の実装計画を、次の 4 視点だけで 1 回レビューする。方式選定の好みやスタイルは対象外。指摘は「計画への修正提案」として返す。blocking / 再レビュー要求は出さない。

1. **検証網設計** — 計画のテスト / ガードレールが何を pin するか具体化されているか。総数だけ pin して形（順序・隣接・合成）を pin していない、空振り経路が残っていないか。T-xx と実装ステップの対応が「実行した」以上の観測条件を持つか。
2. **文書同期スコープ** — 変更が触れる既存記述（README・隣接 SKILL / reference・ユーザー向け手順）が、変更対象またはドキュメント影響調査の対象として列挙されているか。
3. **CI・統合配線** — テスト / ガードの実行経路（既存 runner の glob、呼び出し元）と失敗時挙動が計画にあるか。新規テストが runner に載るか。
4. **regression 面** — 変更が削除 / 弱体化しうる既存のガード・記述・慣習は何か。保全手段が計画にあるか。

視点は上記 4 つのみ。予約枠を足さない。指摘がない視点は行を出さない。

## 判定出力形式

agent は次の形だけを返す。前後の解説・推測補完・別形式は禁止。

```
## 計画レビュー結果

指摘件数: {n}

| # | 視点 | 指摘 | 反映先 |
|---|------|------|--------|
| 1 | 検証網設計 | {何が不足か} | 種別=実装ステップ追記; 対象=S{N}; 追記={挿入する原文} |
```

- `{n}` は 0 以上の整数。`指摘件数:` 行が必須。表の指摘行数と一致させる。
- `視点` は 検証網設計 / 文書同期スコープ / CI・統合配線 / regression 面 のいずれか。
- `反映先` は 3 フィールドを `; ` 区切りで書く: `種別=` は 実装ステップ追記 / 変更対象ファイル追記 / 要判断ポイントへ昇格 のいずれか。`対象=` は既存ステップ番号（`S{N}`）またはファイルパス。`追記=` は挿入する原文。新規ステップ追加は禁止（既存ステップへの文言追加のみ）。
- 指摘なしは `指摘件数: 0` とヘッダだけの表（指摘行ゼロ）。

orchestrator はこの形式を観測できない（spawn / 回収失敗、`指摘件数:` 欠落、視点が 4 種以外、`種別=` 欠落または 3 値以外、追記欠落、見出し欠落）場合、1 行でも外れれば全体を未実施とし、出力を推測補完しない。
