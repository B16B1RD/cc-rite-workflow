# 文書の論証と読み手の負担

文書の作成前点検と tech-writer のレビューが共有する規則。既存の事実確認・受入条件・図の検査を併せて行う。書き手は「読み手用観点」を読み手の prompt にそのまま埋め込み、tech-writer は本ファイルを全文読む。

## 読み手用観点

### 言語に共通する観点

文書内の根拠と説明のつながりを確かめる。根拠が足りない場合は、足りない条件・根拠・対象を示し、推測で事実や解決方法を補わない。

- 確認した事実、推測、未確認の点を区別する。不確実な説明を断定に変えない。
- 因子と結果の対応を追えるか確かめる。複数の要因が記録されている場合は、それぞれが説明する結果を残す。何がどう作用するかを述べ、機構が未確認なら推定であることを残す。同時に起きたことや相関だけから因果関係を断定しない。原因を一つ挙げたことだけでは指摘せず、その原因を支える根拠と、説明する結果の範囲を確かめる。
- 主張の範囲を根拠に合わせる。ある条件下の観測から、すべての利用者・環境・期間への保証に広げない。成立条件、対象範囲、推定であることを該当する主張の近くに置く。
- 用語の定義と分類を途中で変えない。分類軸が異なるものを同じ対比に並べて、結論の根拠にしない。
- 否定や譲歩の対象を明示する。何を否定し、何を認めたうえで、どの結論を述べるのか追えるようにする。
- 必要な概念を使う前に導入する。指示語の参照先、動作の主体と対象を特定できるか確かめる。複数の候補が残る場合は、読み手が選ぶために要する推測を示す。
- 例がどの説明や判断を支えるか示す。例を増やす場合は、前の例との違いと追加する理由を示し、別の例で確認した性質をそのまま当てはめない。結論を確かめるために必要な具体的識別子や証拠を残す。ただし、冒頭要約の役割を超える詳細を要求しない。
- 読み手が意味を取れる慣用表現と用語を使う。単語だけで比喩や擬人化と判定せず、文中の使い方と説明への影響を確かめる。無生物を主語にした機能の記述（サーバーが応答する、など）は許容する。
- 中立的な問いかけは許容する。論証や説明の散文では読み手を「あなた」「君」と呼びかけず、役割や対象を主語にする。この制約はエージェントへの作業指示や引用文には適用しない。

指摘には該当箇所と、根拠との不一致または理解に必要な推測を添える。文体の好みだけで指摘しない。入力にない事実を加えずに解消できない場合は、未確認として残す。

### 日本語の説明文だけに適用する観点

この節は点検対象が日本語の説明文である場合だけ適用する。英語など他言語の自然な慣用表現や、作業指示・引用を日本語の基準で訂正しない。

- 直訳した比喩で関係や動作が曖昧になっていないか確かめる。言葉が比喩的であること自体を違反とせず、対象と関係を読み取れるかで判断する。
- 日本語の用法として意味が通じる術語を使う。外来語や内部用語を機械的に言い換えず、説明の対象を識別するために必要なら定義や具体名を残す。
- 主語の省略や指示語によって、誰の判断・動作か、何を指すかが変わる場合は明示する。参照先が文脈で一意なら、省略そのものを指摘しない。
