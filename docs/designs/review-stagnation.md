# レビュー停滞の診断と見直し

## 判定契約

時間は診断の契機であり、停止・merge・品質緩和の理由にはしない。実作業が前回診断から30分を超えたら、保存済み全指摘と最新仕様を照合する。時計は実作業、外部待機、中断を別々に記録する。再開時の未確定区間を実作業へ算入しない。

根因の同一性は欠陥、再現条件、違反契約の組で表現する。各観測は保存済み指摘IDと実測再現証跡へ結び付ける。表示名の一致だけで同一と扱わない。同じ根因が3観測に現れ、その間に対応する検証済み修正と異なるHEADが2回あれば見直す。同一HEADの再レビュー、未検証修正、別runの記録は再発回数を増やさない。

観測IDは既存review_context全体とする。同じ観測の再処理は冪等とし、異なる内容での上書きを拒否する。時間と根因再発が同時に成立しても、見直しは同じ観測に1件だけ結び付ける。時間診断の起点は保存された診断時点まで前進させる。

見直しはrun内で最大2回。全指摘と最新仕様から範囲内代替案を最低2案検討し、選択理由、棄却理由、予定パス、再発防止検証を一括修正計画へ保存する。既存の範囲検査を通ってから編集する。見直し後に根因が解消し受入条件の充足が進めば、時間に依らず通常の品質ゲートまで継続する。

見直し後にも同じ根因が2回の修正をまたいで再発し、その間に受入条件の充足が進まなければ非収束として停止する。見直し枠を使い切った事実や時間超過だけでは停止しない。範囲内で解決不能なら、検討した代替案と契約上の理由を保持して停止する。未検証・権限拒否を解決不能という意味判断に置き換えない。

## 優先順位と永続化

1. 現在session/run/PR/cycle/HEAD、全員回収と保存receipt、最新仕様、証跡の完全性を確認する。不一致・欠損・保存不能・権限拒否では停止し、見直しへ進まない。
2. 未完了レビューは同じcycleの回収・保存を再開する。完了済みcycleの欠損修復と既存の発散・回数breakerを優先する。
3. 上記を通過した保存済みレビューを停滞診断へ渡す。見直しが必要なら通常の範囲検査へ接続し、成功した場合のみ修正・次レビューへ進む。

既存 fatal triage は保存済み receipt を更新するため、観測時に元データと同じ分類 helper が生成する派生データのハッシュを固定する。この正規更新だけを許可し、証跡や処置対象の任意変更は拒否する。通常 iterate の全ゲートと sweep 完了後は `review-close` が完了 context を保存する。返信のみなら `review-defer` が別の終了 context と理由を保存し、未解決指摘と判定を保持する。default draft batch はこれらの終了境界から次 Issue へ移る際に旧 run を履歴へ移せる。返信のみを mergeable へ昇格させず、merge モードの失敗扱いを維持する。未回収・観測欠損・見直し未完了・停止済み run と別 cycle の終了記録では切り替えられない。

既存review-cycleの原子的保存を再利用し、runの時計・観測・修正検証・見直し理由と結果をreview_contextに結び付ける。通常のflow-state更新は履歴を維持する。同一runのrecoverや停止でcounterや見直し回数をリセットしない。停止済みrunを単に再起動しても同じ停止理由を返す。新しいIssue/PRへの遷移は既存の終了・所有権条件を満たす場合に限る。

停止には既存の失敗sentinelを用いる。batchはcursorを当該Issueに保持しactive=falseにして後続Issue、ready、mergeを実行しない。PR、branch、作業差分、履歴、最後の検証済み状態と復旧手順を保持する。

## 較正の根拠と境界

既存の実測・契約fixtureは `review-trend-divergence.test.sh` が保持する。収束列 `3,6,5,3,0`、`10,8,8`、`12,5,3,2,2` を件数の停滞だけで停止しない。発散列 `3,7,7`、`2,3,6`、`10,11,11,13` は既存breakerが優先する。件数が減っても根因が残る合成列、根因交代、見直し後の解消を追加する。

ローカル保存記録には `4→1→0` の収束例があり、保存間隔は47分48秒、29分34秒、レビュー起動から保存までは29分29秒、21分45秒、20分43秒である。記録には待機・中断の区分がないため、これを実作業時間や最適な閾値の実測とは扱わない。30分はそのような長い処理を早期診断でき、時間による誤停止を発生させない暫定値であり、時計制御fixtureで境界を固定する。元記録の追跡情報はPRメタデータに保存する。

3観測・2修正は単発の再確認を再発と誤認しない最小窓として採用する。見直し後も同じ長さの窓を使い、検証済み修正を2回試した結果で評価する。最大2回の見直しは別の根因に対する方針転換を許しつつ、同じ問題の無制限な再設計を防ぐ。これらの回数は合成fixtureで較正した判定方針であり、あらゆる課題での収束保証ではない。

## 検証範囲

時計制御fixtureで30分の境界、長い外部待機・中断、根因再発、根因交代、進展、非収束、同一HEAD、同時診断条件を検証する。保存receiptと履歴更新の境界で中断し、再処理で観測・修正・見直しを重複計上しないことを確認する。破損、欠損、保存失敗、別session/run/HEAD、caller省略、breaker優先、batchのcursor保持を実helperとSKILLの実行ブロックで検証する。

機械的保証は同梱helperを通る通常callerと明示的runtime境界に限定する。意味的な根因照合・契約解釈・代替案の妥当性は親LLMの責務で、再現と選択の根拠を保存する。任意のstate直接編集、自動hook未対応ホストでの予告なし中断検出、未実測の全ホスト動作は保証しない。未確定な経過時間を推測で実作業へ分類しない。
